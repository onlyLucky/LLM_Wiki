# 1.4 WGSL 语言核心

> Day 1 · 模块 4 · 约 60 分钟
> 理论对照：《Three.js 创意 3D 课程笔记》第 10–13 课「GLSL 基础 / 数学函数 / 噪声函数 / 高级 Shader 效果」——同一套着色语言知识，平移到 WGSL

demo 01 的 `triangle.wgsl` 第 25 行写着 `var positions = array<vec2f, 3>(...)`。写过 Three.js shader 的人第一反应往往是：这里为什么是 `var`，换成 `let` 不行吗。真换上就会收获一条经典报错——`let` 声明的数组不允许动态索引，而下一行 `positions[i]` 的 `i` 来自 `@builtin(vertex_index)`，每个顶点一个值。这一行浓缩了 WGSL 与 GLSL 的关系：血缘很近，但每个差异都值得专门记一笔。本模块把这门语言的核心面貌一次铺开，之后两天写任何着色器都回到这张地图。

## 为什么要新造一门着色语言

GLSL 的问题出在「方言」。浏览器把 WebGL 的 GLSL ES 交给各家的 ANGLE 层转译成 D3D / Metal / Vulkan，转译器各有脾气，报错格式、宽松度、边界行为都有微妙差异，驱动编译器的 bug 更是多年的重灾区。WGSL 作为 WebGPU 的伴生语言，把「单一大规范、精确到字节的内存语义、编译错误标准化」写进设计目标：同一段代码在任何后端要么以相同方式跑，要么以相同方式拒绝。你今天在这门课里遇到的每条 WGSL 报错，在别人的机器上是一字不差的同一条。

语言面貌上，WGSL 更像 Rust 减掉生命周期：强类型、无隐式数值转换、`let`（不可变）/`var`（可变）二分、struct 无继承。GLSL 的 `#version` 声明、精度限定符（`precision mediump float`）、全局函数式松散风格全部消失，取而代之的是显式类型与显式 IO 属性。

## 类型系统与表达式

标量四种：`f32`、`i32`、`u32`、`bool`。向量是主力：`vec2f / vec3f / vec4f` 是 `vec2<f32>` 等的别名，分量用 `x y z w` 或 `r g b a` 访问。矩阵 `mat4x4f` 表示 4 列、每列 `vec4f`，列主序存储——2.1 手写 MVP 矩阵时列主序会直接决定 JS 侧数组的排布。数组必须带长度：`array<vec2f, 3>`。struct 承担两种角色：顶点 IO 载体与内存布局单元（后者在 1.6 与 uniform 对齐纠缠）。

| 类别 | 写法 | 备注 |
|------|------|------|
| 标量 | `f32 / i32 / u32 / bool` | 无隐式转换，`f32(1)` 要显式 |
| 向量 | `vec2f / vec3f / vec4f` | 构造 `vec3f(1.0, 0.5, 0.0)` |
| 矩阵 | `mat2x2f / mat3x3f / mat4x4f` | 列主序，`mat4x4f(c0, c1, c2, c3)` |
| 数组 | `array<T, N>` | 长度写死；动态索引要求 `var` |
| 结构体 | `struct S { ... }` | 字段带属性即可作 IO |

swizzle 沿袭 GLSL 直觉：`v.xyz` 取前三分量，`v.bgr` 逆序，`vec4f(v.xy, 0.0, 1.0)` 拼装。所有 `f32` 字面量带小数点，`1` 是 `i32`、`1.0` 才是 `f32`，混用直接编译失败。

属性（attribute）是 WGSL 的 IO 语言，全表如下，写在哪一个位置决定它管什么：

| 属性 | 写在 | 含义 |
|------|------|------|
| `@vertex / @fragment / @compute` | `fn` 前 | 入口点声明 |
| `@workgroup_size(x, y, z)` | `@compute fn` 前 | 计算着色器线程块尺寸（Day 2） |
| `@builtin(名字)` | 参数 / struct 字段 | 内置语义输入输出（`position`、`vertex_index` 等，名字不可自创） |
| `@location(n)` | 参数 / struct 字段 | 用户自定义 IO 槽位，vs/fs 两侧编号必须对应 |
| `@group(g) @binding(b)` | `var` 前 | 资源绑定坐标：绑定组 g 的第 b 槽 |

入口点必须有显式 `return`，没有 GLSL 的「最后一个赋值即输出」约定。资源变量（uniform、纹理、storage）在全局作用域用 `var` 声明，地址空间写进尖括号：`var<uniform>`、`var<storage, read>`。

uniformity 是本模块唯一的新概念：有些值在一次调度里所有线程必须一致，有些天然逐线程不同。分清这两类，2.6 的 workgroup 同步与 2.2 的纹理导数才不会踩雷。

| 各线程一致 | 各线程不同 |
|-----------|-----------|
| uniform buffer 的内容 | `@builtin(vertex_index)` / `instance_index` |
| 管线状态、topology | 顶点属性（`@location` 输入） |
| const 与字面量 | 插值后的 varying（`@location` 片元输入） |
| `workgroupBarrier()` 的调用与否 | 各线程自己的局部计算结果 |

影响代码的硬规则：`textureSample()` 这类带隐式导数的调用必须发生在 uniform control flow 中——分支条件若依赖逐线程不同的值（比如插值颜色），采样就会报错；`workgroupBarrier()` 要求所有线程都执行到它，分支发散处放 barrier 是未定义行为。

## GLSL 读者的迁移对照表

学过第 10–13 课 GLSL 的读者，用这张表完成 90% 的迁移，剩下 10% 是上表的 uniformity 概念：

| GLSL | WGSL | 备注 |
|------|------|------|
| `attribute vec2 aPos;` | `@location(0) pos: vec2f`（vs 入参或 struct 字段） | 属性声明变为入口签名 |
| `varying vec3 vColor;` | vs 输出 `@location(0) color: vec3f`，fs 输入同 `@location(0)` | 两侧编号必须一一对应 |
| `gl_Position` | `@builtin(position) position: vec4f` | 语义内置，名字自定 |
| `gl_FragCoord` | 片元入参 `@builtin(position)` | 同一语义，vs 里是输出、fs 里是输入 |
| `uniform float uTime;` | `uTime: f32`（放进 `var<uniform>` 的 struct） | 资源集中到绑定组 |
| `texture2D(tex, uv)` | `textureSample(tex, samp, uv)` | 采样器与纹理分开绑定 |
| `vec3(1.0)` | `vec3f(1.0)` | 类型即构造器 |
| `precision mediump float;` | 不存在 | 精度固定，f32 即 32 位浮点 |
| `#version 300 es` | 不存在 | 单一规范无版本开关 |
| 入口末尾隐式输出 | 显式 `return out;` | 忘 return 是编译错误 |
| `const vec3 C = ...` | `const C: vec3f = ...` | 推荐都写类型 |

## How：demo 01 的 triangle.wgsl 逐段精讲

着色器一共 53 行，分四段读。第一段是资源声明，struct 描述 uniform 布局、一行 `var<uniform>` 把它挂到 `@group(0) @binding(0)`：

```wgsl
struct Uniforms {
  time: f32,      // 秒
  mouse: vec2f,   // 鼠标 NDC 坐标（-1..1）
  aspect: f32,    // 画布宽高比，用于把等腰三角形拉回视觉等边
};

@group(0) @binding(0) var<uniform> u: Uniforms;
```

`u` 是全局只读变量，三个字段在 JS 侧由一块 32 字节 buffer 提供——对齐细节 1.6 展开。第二段是输出布局，`VertexOut` 承载 vs 的全部输出契约：

```wgsl
struct VertexOut {
  @builtin(position) position: vec4f,
  @location(0) color: vec3f, // 顶点色，光栅化阶段自动插值
};
```

`@builtin(position)` 是管线的硬通货，永远是 `vec4f`（xyz 除以 w 得到屏幕坐标，2.1 的透视除法会解释为什么）。`@location(0)` 颜色会跨过光栅化变成 fs 侧的插值输入。第三段是顶点入口，开场那两行数组就住在这里：

```wgsl
@vertex
fn vs(@builtin(vertex_index) i: u32) -> VertexOut {
  var positions = array<vec2f, 3>(
    vec2f(0.00, 0.42),
    vec2f(-0.38, -0.26),
    vec2f(0.38, -0.26),
  );
  var colors = array<vec3f, 3>(BLUE, VIOLET, mix(BLUE, VIOLET, 0.5));

  let breathe = 1.0 + 0.02 * sin(u.time * 0.8);
  let parallax = u.mouse * 0.03;

  var out: VertexOut;
  out.position = vec4f(
    (positions[i] * breathe + parallax) * vec2f(u.aspect, 1.0) * 0.9,
    0.0, 1.0,
  );
  out.color = colors[i];
  return out;
}
```

`i` 是 `u32`，三个线程各领一个值。两个数组必须是 `var`，因为 `positions[i]` 是动态索引——WGSL 规定 `let` 值的索引必须编译期常量。`breathe` 与 `parallax` 是纯计算值，`let` 合适且语义更紧。`vec4f(xy, 0.0, 1.0)` 的 z 置 0（近平面）、w 置 1（不做透视除法缩放）。注意每一行的算术都是显式类型：`0.02 * sin(...)` 两个字面量都带小数点，`vec2f(u.aspect, 1.0)` 里的 `1.0` 同理。第四段是片元入口，输入输出都在签名里：

```wgsl
@fragment
fn fs(@location(0) color: vec3f) -> @location(0) vec4f {
  let pull = mix(VIOLET, BLUE, u.mouse.x * 0.5 + 0.5);
  let shifted = mix(color, pull, 0.15);
  let breathe = 1.0 + 0.06 * sin(u.time * 0.8);
  return vec4f(shifted * breathe, 1.0);
}
```

入参 `@location(0) color` 与 vs 输出的 `@location(0)` 精确对应，两侧名字可以不同、编号与类型必须相同。返回值 `@location(0)` 指颜色附件 0，alpha 固定 1.0 与 `alphaMode: 'opaque'` 呼应。

## 常见坑

| 报错/症状 | 原因 |
|-----------|------|
| `error: 'positions' ... must be constant / cannot be dynamically indexed` 一类 | 动态索引的本地数组用了 `let`；改 `var`，或索引换成编译期常量 |
| `error: type ... expected f32, found i32` 一类 | `f32` 字面量忘写小数点（`1` 是 i32），WGSL 不做隐式转换 |
| 管线创建报 location 相关 validation error | vs 输出与 fs 输入的 `@location` 编号或类型对不上；片元有输入、顶点却没输出同号变量 |
| `error: cannot find 'xxx' in module scope` 一类 | `@group/@binding` 声明的变量名与使用处拼写不一致；或 const 定义在入口点之后 |
| 入口报缺少 return | WGSL 入口必须显式 `return`；GLSL 的「末尾赋值即输出」不再存在 |
| `@builtin(position)` 相关报错 | builtin 语义名写错（拼成自创名字）；builtin 不可当 `@location` 用，反之亦然 |
