# 3.2 TSL 节点着色语言

> Day 3 · 模块 2 · 约 1.5 小时
> 理论对照：《Three.js 创意 3D 课程笔记》第 10–13 课（GLSL 基础 / 数学函数 / 噪声函数 / 高级 Shader 效果）——同一套着色数学，第三种表达

Day 2 demo 04 的 ocean.wgsl 第 18 行到 49 行是一个 32 行的 waveField 函数：三组正弦行波叠加，解析梯度一并算出，法线不用片元导数。Day 3 demo 02 做的是同一个波场，三组正弦、同样的解析梯度、同样的波高色带，写成 TSL 是 17 行 JS——没有 struct、没有 `@location` 契约、没有 128 字节的 uniform 布局注释。更重要的差别在两处：这 17 行是合法的 TypeScript，编辑器里就能查出类型错误；它还是一个普通的 JS 值，下个项目 `import` 就能用。

## Why：字符串拼接的三宗罪

回看 Day 1–2 的着色器代码，痛点集中在三件事上。第一，运行时才报错：WGSL 以字符串形式传给 createShaderModule，类型错误、拼写错误都要等到 GPU 编译那一刻才暴露，报错在控制台里，不带行号回溯到 TS 源文件。第二，无法复用：waveField 是字符串，跨项目只能拷文件；改成任何可组合的形态都做不到。第三，双份维护：想让效果覆盖没有 WebGPU 的用户，WGSL 之外还得写一份 GLSL，两份逻辑要保持同步。

1.4 建立过 GLSL 与 WGSL 的对照表，那是一级迁移；本模块补上第二级。三级链条每往右走一步，表达力上移一层，离硬件远一点、离 JS 近一点：

| 层级 | 载体 | 类型检查 | 复用 | 跨后端 |
|------|------|---------|------|--------|
| GLSL（第 10–13 课） | 字符串 | 无 | 拷文件 | 只限 WebGL |
| WGSL（1.4） | 字符串 | 无 | 拷文件 | 只限 WebGPU |
| TSL（本模块） | JS 表达式树 | 编辑器即查 | import / 组合 | WGSL 与 GLSL 自动生成 |

## What：节点图如何变成着色器

TSL 的核心机制一句话讲清：每一条链式调用都在 JS 侧立刻构造节点对象，拼出一棵表达式树；首次 render 时 NodeBuilder 遍历这棵树，按后端生成 WGSL 或 GLSL 源码（3.1 的 L2 到 L3 层）。`mouse.x.mul(0.2)` 执行的瞬间，得到的是一个乘法节点，它的两个子节点是属性访问节点和数值节点——没有任何像素被计算，构造的是「将来要算什么」的描述。

由此推出一条铁律：JS 的运算符在 JS 里就执行完了。`2 * node` 得到的是 `NaN` 或报错，只有 `node.mul(2)` 才会生成着色器乘法。JS 数字只能出现在节点方法的参数位上，方法链是唯一的构图语法。常用节点按角色分三类：

| 类别 | 节点 | 对应的 WGSL 概念 |
|------|------|-----------------|
| 输入 | `positionLocal` / `positionWorld` / `normalLocal` / `uv` / `time` | `@location` 顶点属性与 `@builtin`，时间节点每帧自动更新 |
| 数据 | `uniform(v)` / `storage(...)` / `attribute(...)` / `texture(t)` | `var<uniform>` / `var<storage>` / 采样器 |
| 构造与函数 | `vec2/vec3/vec4/float` / `Fn` / `mix` / `smoothstep` / `sin` / `cos` / `mx_noise_float` | 构造器与内建函数 |

`Fn` 是 TSL 的「着色器函数」：参数是节点数组，返回值也是节点，调用一次展开一次。`uniform(new THREE.Vector2(0, 0))` 返回一个 JS 侧可写的节点，改 `value` 就改了着色器看到的值——Day 2 那套 Float32Array 手动布局加每帧 writeBuffer 的流程，收敛成一个属性赋值。

给写过 GLSL 的读者一张直达迁移表，覆盖 90% 的日常写法：

| GLSL / WGSL | TSL | 说明 |
|-------------|-----|------|
| `vec3(0.2, 0.8, 0.7)` | `vec3(0.2, 0.8, 0.7)` | 构造函数同名，参数可为节点或 JS 数字 |
| `a + b` | `a.add(b)` | 运算符全部变方法，`a + b` 是 JS 加法 |
| `a * b` | `a.mul(b)` | 同上；`2 * node` 不会得到着色器代码 |
| `mix(a, b, t)` | `mix(a, b, t)` | 函数节点，参数自动包装 |
| `smoothstep(e0, e1, x)` | `smoothstep(e0, e1, x)` | 边界可以是 JS 数字 |
| `sin(x)` / `cos(x)` | `sin(x)` / `cos(x)` | 直接对应 |
| `pow(x, 4.0)` | `x.pow(4)` | 指数可以是整数 |
| `normalize(v)` | `v.normalize()` | 一元操作多为实例方法 |
| `clamp(x, 0.0, 1.0)` | `x.clamp()` | 无参 clamp 即夹到 0..1 |
| `v.length()` | `v.length()` | 节点上是方法，别与 JS 数组的 length 混淆 |
| `attribute vec3 position` | `positionLocal` | 内置输入节点，另有 positionWorld / normalLocal / uv |
| `uniform vec2 u` + writeBuffer | `const u = uniform(vec2())` | `u.value` 可写，自动上传 |
| `varying float vWave` + `@location(n)` | `const vWave = varying(node)` | 插值声明变成一次函数调用 |
| `fn f(p: vec2f) -> vec3f` | `const f = Fn(([p]) => vec3(...))` | 定义后 `f(x)` 调用，逻辑可导入复用 |
| `if (c) {...} else {...}` | `If(c, () => {...}).Else(() => {...})` | 分支也是节点，3.3 的 compute 会用到 |

## How：demo 02 的顶点波浪逐段拆

### 鼠标进着色器：一个 uniform 节点

Day 2 demo 04 里，鼠标参数住在 32 项的 Float32Array 中的固定下标，每帧 writeBuffer，注释比代码长。demo 02 的全部代码如下：

```ts
const mouse = uniform(new THREE.Vector2(0, 0));
chrome.canvas.addEventListener('pointermove', (e) => {
  const r = chrome.canvas.getBoundingClientRect();
  mouse.value.set(
    ((e.clientX - r.left) / r.width) * 2 - 1,
    1 - ((e.clientY - r.top) / r.height) * 2,
  );
});
```

渲染器在首次编译时发现 mouse 被着色器引用，自动生成对应的 buffer、绑定组与上传——1.6 花一整节讲的 16 字节对齐规则，在这里是内部实现细节。

### 波场：Fn 与方法链

waveField 与 ocean.wgsl 里的同名函数逐行同构，主浪、交叉浪、细浪的相位公式没变，变的是语法外壳：

```ts
const waveField = Fn(([p, t]: any[]) => {
  const freq = mouse.x.mul(0.2).add(1.0); // 鼠标横移：空间频率 ±20%
  const phase = mouse.y.mul(1.6);         // 鼠标纵移：整体相位推移

  // 主浪（沿 x 长波）、交叉浪（沿 y 中浪）、细浪（斜向短波）
  const ph1 = p.x.mul(1.35).mul(freq).add(t.mul(1.1)).add(phase);
  const ph2 = p.y.mul(2.6).mul(freq).sub(t.mul(1.6)).add(phase);
  const ph3 = p.x.add(p.y).mul(4.1).mul(freq).add(t.mul(2.2)).sub(phase);

  const h = sin(ph1).mul(0.3).add(sin(ph2).mul(0.18)).add(sin(ph3).mul(0.1));

  // d(a·sin(k·x))/dx = a·k·cos(k·x)：梯度与波同源，法线平滑不抖
  const dx = cos(ph1).mul(0.405).add(cos(ph3).mul(0.41)).mul(freq);
  const dy = cos(ph2).mul(0.468).add(cos(ph3).mul(0.41)).mul(freq);

  return vec3(h, dx, dy);
});

const wave = waveField(positionLocal.xy, time);
const waveH = varying(wave.x);
```

三个观察点。`p.x.mul(1.35).mul(freq)` 对应 WGSL 的 `p.x * 1.35 * freq`，读法是从左往右流水线。`waveField(positionLocal.xy, time)` 这一行才是「调用」：Fn 定义的是函数节点，不调用就不会出现在任何着色器里。`varying(wave.x)` 把顶点阶段算出的波高声明为插值变量，对应 WGSL 的 `@location(2) wave: f32`——顶点算一次、片元按像素插值，语义一模一样。

### 三个通道：positionNode / normalNode / colorNode

材质把节点图挂到通道上，每个通道接管渲染管线的一段：

```ts
material.positionNode = positionLocal.add(vec3(0, 0, wave.x));

material.normalNode = vec3(wave.y.negate(), wave.z.negate(), 1).normalize();

const hNorm = waveH.mul(0.86).add(0.5).clamp();
material.colorNode = mix(color(0x2dd4bf), color(0xe8ecf4), smoothstep(0.3, 0.95, hNorm))
  .mul(hNorm.mul(0.45).add(0.55));
```

positionNode 是替换语义：它给出的就是顶点的最终位置，所以必须把 `positionLocal` 加回来，只写位移项整张网格会塌到平面上。normalNode 挂的是解析法线——demo 04 里 `normalize(vec3f(-w.y, 1.0, -w.z))` 的三件事在这里是一行。colorNode 做波高色带，mix 与 smoothstep 的用法和 GLSL 逐字相同。至于 demo 04 的 fs 里手写的 Blinn 高光、菲涅尔、距离雾共 20 行——MeshStandardNodeMaterial 全部自带，两盏灯是场景里普通的 `DirectionalLight` 与 `AmbientLight`。

### 代码量对账

同一个波场，两条路线的完整账单：

| 部分 | Day 2 demo 04（原生 WGSL） | Day 3 demo 02（TSL） |
|------|---------------------------|----------------------|
| 文件构成 | main.ts 216 行 + ocean.wgsl 97 行 | main.ts 134 行，无 WGSL 文件 |
| 波场函数 | 32 行（含 struct 与 location 契约） | 17 行 Fn |
| 矩阵与相机 | 64 行手写 mat4 + lookAt + 射线求交 | PerspectiveCamera 4 行 |
| 鼠标 → 着色器 | Float32Array 手动布局 + 每帧 writeBuffer | uniform 节点 + value.set |
| 光照 | fs 手写 Blinn + 菲涅尔 + 雾 20 行 | 材质自带，两盏灯 6 行 |
| 管线与帧循环 | 管线描述 + bindGroup + encoder 编排约 50 行 | renderer.render 一句 |

账单里最值的一行是「无 WGSL 文件」：struct 定义、`@location` 两侧契约、字节对齐注释这些 Day 1–2 的主要出错点，整类消失了。省下来的行数是小事，少掉的出错面是大事。

## 常见坑

| 现象 / 报错 | 原因 |
|------------|------|
| 波浪毫无动静，画面是静止平面 | `Fn(() => {...})` 返回的是函数定义，语句式用法必须立即调用 `Fn(() => {...})()`；demo 02 的写法是定义后显式调用 `waveField(positionLocal.xy, time)` |
| `TypeError: node.mul is not a function` 或结果为 NaN | 写了 `2 * node`、`mouse.x * 0.2` 这类 JS 运算符；JS 数字只能出现在参数位，改成 `node.mul(2)` |
| 网格塌成一张平面 | positionNode 是替换语义，只写位移项没把 `positionLocal.add(...)` 加回来 |
| 顶点在动、颜色纹丝不动 | 想插值的值忘了 `varying()` 包裹；或把本该挂 colorNode 的节点挂到了 positionNode（挂错通道不报错，只是语义错位） |
| 光照闪烁、法线杂乱 | normalNode 用了波高而不是解析梯度，或忘了 `.normalize()` |
| `timerLocal is not exported from three/tsl` | 0.186.0 无此节点，时间统一用 `time`（见 3.1 的 TSL 变更注记） |
