# 2.5 几何生成与顶点动画

> Day 2 · 模块 5 · 约 60 分钟
> 理论对照：《GAMES101 现代计算机图形学课程笔记》第 6 章「几何」——参数曲线与曲面的表示、隐式与显式

lusion 首页那片起伏的黑色织物，网格上每一个顶点的高度都在逐帧变化。它的做法是在 Houdini 里离线烘焙顶点动画、导出序列数据、运行时逐帧插值；本模块的做法是把同一条公式搬进顶点着色器，让 GPU 每帧实时算出每个顶点的位置——前者换来艺术家的精细控制，后者换来零资产、无限分辨率的动态。你要在浏览器里复刻 lusion 气质，顶点动画是绕不开的一层，而它的地基是参数化几何。

## 为什么几何要自己生成

Day 1 的几何数据靠手写数组，画一个四边形没问题，画一片海面、一个星球、一条隧道就是几万个顶点的体力活。这些形状有共同点：它们都能用一条参数方程描述——给定 `(u, v)` 两个 0 到 1 的参数，公式直接吐出三维坐标。参数化几何就是把这个公式写进循环，顶点、索引、法线全部按规律生成，内存里不用存任何模型文件。

这条路线在创意网站里是主流选择，原因有三层。资产上，程序化生成的海面隧道不需要建模、不需要下载，首屏体积直接归零；控制上，网格分辨率是一个数字，想从 64×64 提到 128×128 改一个常量即可；联动上，顶点位置由公式驱动，而公式的参数（时间、鼠标、滚动进度）可以实时变化——这正是「画面会呼吸」的技术前提。DCC 软件里的细分曲面、NURBS 是同一思想的工业版，GAMES101 第 6 章对参数曲面的推导在数学上完全一致，这里直接用结论。

## 参数化几何的三个结论

三个最常用的形状，生成代码可以直接抄。平面是海面与地面的底子，球是星球与粒子的壳，环面（torus）是隧道与飘带。每个都回答同样三个问题：顶点怎么排、索引怎么连、法线怎么算。

格点平面最直接：双层循环枚举 `(i, j)`，映射到 `[-1, 1]` 再乘以半宽。demo 04 的版本还做了一个关键决定——顶点只存 `(x, z)` 两个 float，高度是时间函数，放进顶点着色器算，网格数据从此完全静态：

```ts
const SEG = 128;
const ROW = SEG + 1;
const PLANE = 6.0; // 平面半宽：x, z ∈ [-6, 6]，远处交给雾隐藏边界

const positions = new Float32Array(ROW * ROW * 2);
for (let j = 0; j < ROW; j++) {
  for (let i = 0; i < ROW; i++) {
    const k = (j * ROW + i) * 2;
    positions[k] = ((i / SEG) * 2 - 1) * PLANE;
    positions[k + 1] = ((j / SEG) * 2 - 1) * PLANE;
  }
}
```

索引把每个格子拆成两个三角形。相邻四点按 `a b c d` 编号，三角形取 `(a, c, b)` 与 `(b, c, d)`，绕向一致才不会一半朝上一半朝下：

```ts
const indices = new Uint16Array(SEG * SEG * 6);
let ptr = 0;
for (let j = 0; j < SEG; j++) {
  for (let i = 0; i < SEG; i++) {
    const a = j * ROW + i;
    const b = a + 1;
    const c = a + ROW;
    const d = c + 1;
    indices[ptr++] = a; indices[ptr++] = c; indices[ptr++] = b;
    indices[ptr++] = b; indices[ptr++] = c; indices[ptr++] = d;
  }
}
```

球与环面把「格点」从矩形卷成曲面。球用经纬度 `(u, v)` 映射到方向向量，环面把一个圆沿一个大圆扫一圈——`u` 绕大圈、`v` 绕管截面。三者的对照如下，公式的几何直觉（为什么这样卷）在 GAMES101 第 6 章有完整推导：

| 形状 | 参数方程（结论） | 法线 |
|------|-----------------|------|
| 平面 | `(u, 0, v) · scale` | `(0, 1, 0)`，位移后需重建 |
| 球 | `(cosθ·sinφ, cosφ, sinθ·sinφ) · r` | 与位置同向：`normalize(pos)` |
| 环面 | `((R + r·cosv)·cosu, r·sinv, (R + r·cosv)·sinu)` | 从管心指向表面点 |

球和环面的法线是白送的：它们的参数方程天然给出「从中心指向表面」的方向，normalize 后就是法线，一行不用差分。这也是参数化几何相对三角网格的隐性红利——解析法线比重建的法线平滑得多。

## 顶点动画与法线的两难

静态几何变成动画，最省事的位置在顶点着色器：JS 每帧只写一个时间 uniform，GPU 给上万个顶点各自算位置，数据零上传。代价藏在法线里——光照模型依赖法线（见 2.4），顶点位移之后法线不再正确，不更新的后果是波峰波谷一样亮、整片海面像一块死塑料。

demo 04 的答案是解析梯度。波场函数同时返回高度与两个偏导数，法线由梯度拼出：

```wgsl
fn waveField(p: vec2f, t: f32) -> vec3f {
  var h = 0.0;
  var dx = 0.0;
  var dz = 0.0;

  let ph1 = p.x * 1.9 + t * 1.05;
  h += 0.10 * sin(ph1);
  dx += 0.19 * cos(ph1);
  // ……交叉浪、细浪、鼠标环形波同理叠加
  return vec3f(h, dx, dz);
}

out.normal = normalize(vec3f(-w.y, 1.0, -w.z));
```

位移函数能求导，解析法线就是最平滑的方案；不能求导的场合（顶点动画来自烘焙数据或噪声纹理），退路是片元着色器里的屏幕空间导数：WGSL 的 `dpdx` / `dpdy` 对世界坐标取导，叉乘两个切向量重建法线。选择标准一句话：位移梯度小到肉眼可忽略时直接沿用原法线，看得出来就必须重建。demo 04 波峰高差 0.4，属于必须重建的那一档。

## How：demo 04 逐段精讲

```bash
npm run dev
```

数据侧的三个决定已经看完：顶点只存 `(x, z)`、静态网格一次上传、索引连接。渲染侧先看顶点缓冲布局——`arrayStride: 8`，一个 `float32x2` 属性：

```ts
buffers: [{
  arrayStride: 8, // 每顶点一个 vec2f
  attributes: [{ shaderLocation: 0, offset: 0, format: 'float32x2' }],
}],
```

顶点着色器是整个 demo 的发动机。三组正弦波叠加出海面主体（沿 x 的主浪、沿 z 的交叉浪、斜向细浪），鼠标波源是第四项——`sin(d·k − ωt)·exp(−d·σ)` 的环形波从光标处扩散，指数衰减保证它只影响附近：

```wgsl
// 鼠标波纹：从光标扩散的环形波，指数衰减保证只影响附近
let d = max(distance(p, u.mouse.xy), 1e-4);
let att = exp(-d * 1.4);
let ph4 = d * 16.0 - t * 6.0;
h += 0.22 * att * sin(ph4);
```

波源坐标的来路值得留意。鼠标在 JS 里是屏幕坐标，着色器里的波场在世界坐标系，中间的换算在 JS 侧完成：沿相机射线与地平面求交。不用求逆矩阵，用相机基向量直接拼出射线方向，交点经 uniform 传入：

```ts
function ndcToPlane(nx: number, ny: number, aspect: number): Vec3 | null {
  const fwd = normalize3(sub3(TARGET, EYE));
  const right = normalize3(cross3(fwd, UP));
  const up2 = cross3(right, fwd);
  const halfH = Math.tan(FOV / 2);
  const halfW = halfH * aspect;
  const dir = normalize3([
    fwd[0] + right[0] * nx * halfW + up2[0] * ny * halfH,
    fwd[1] + right[1] * nx * halfW + up2[1] * ny * halfH,
    fwd[2] + right[2] * nx * halfW + up2[2] * ny * halfH,
  ]);
  if (dir[1] > -0.05) return null; // 射线掠过地平面：保持旧波源
  const t = -EYE[1] / dir[1];
  return [EYE[0] + dir[0] * t, 0.0, EYE[2] + dir[2] * t];
}
```

片元着色器收尾：波高映射「深海底 → 电蓝 → 青」三段色带，Blinn 高光加菲涅尔做「湿」的质感，距离雾把网格边界藏进画布底色。这套光照是 2.4 的直接复用，新东西只有色带与雾。

## 常见坑

| 报错/症状 | 原因 |
|-----------|------|
| `Index buffer index is out of bounds` | 索引值 ≥ 顶点数；129² = 16641 没超 65535，把 SEG 加大到 255 之前先换 `Uint32Array` 配 `'uint32'` |
| 海面一片死灰、高光位置诡异 | 顶点位移了但法线还是 `(0,1,0)`，光照失去起伏信息——必须按本模块的策略重建法线 |
| 波浪是「台阶」不是「波」 | 分辨率低于波长：每个波长至少要 6–8 个格子才能成形，SEG 与波的频率要一起调 |
| 帧率掉到个位数，顶点数并没有多 | 索引没合并共享顶点，`6n²` 个顶点全量跑顶点着色器；索引绘制只需 `(n+1)²` 个 |
| 鼠标波纹在屏幕角落疯狂抖动 | 射线掠过地平面时交点飞到无穷远，`dir[1]` 接近 0 必须判空并保留上一次有效波源 |

## Checkpoint

- 能写出格点平面的顶点与索引双层循环，说清 `(n+1)²` 顶点与 `6n²` 索引的来历
- 能列出球与环面的参数方程结论，并解释它们的法线为什么白送
- 能说出顶点动画放在 vs 里的原因（每帧零数据上传），与它带来的法线问题
- 能按「梯度小 → 沿用原法线；可解析 → 解析梯度；否则 → dpdx/dpdy」三档选择法线策略
- 能解释鼠标屏幕坐标到世界坐标的换算思路（相机基向量拼射线 + 平面求交）
