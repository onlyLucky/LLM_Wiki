# 2.3 纹理采样与 Mipmap

> Day 2 · 模块 3 · 约 1 小时
> 理论对照：《GAMES101 现代计算机图形学课程笔记》第 5 章「着色」（5.3 纹理映射 / 5.4 纹理放大与缩小）

24 个顶点能携带的信息量到此为止了。想让立方体的每个面有网格、刻度、同心圆，顶点色的分辨率根本不够用——一个面只有 4 个顶点，而屏幕上这块区域有上万个像素。纹理映射的思路在笔记 5.3：给每个顶点多带一个坐标 (u, v)，指向一张 2D 图上的位置，片元着色器按插值出来的坐标去图里查颜色。demo 02 走完整条链：用 canvas 2D 现场画一张 512×512 的「深空蓝图」，上传进 GPU，在 GPU 上生成十级 mipmap，再以三线性采样贴满立方体六个面；滚轮把相机拉远，你还能亲眼看到网格线在 mip 级之间平滑糊掉。

本模块的落点在 WebGPU 侧的三组 API：纹理对象的创建与上传、采样器的过滤与寻址模式、以及最容易被漏掉的「mipmap 要自己生成」这件事。

## texture 与 sampler 为什么分家

WebGPU 里「一张可采样的图」被拆成两个对象。`GPUTexture` 是数据：一块显存里的像素矩阵，带格式、尺寸、mip 级数。`GPUSampler` 是策略：采样时怎么取邻近纹素、怎么越界寻址、怎么在 mip 级之间混合。两者在 bind group 里各占一个 binding，自由组合。

这个拆分直接继承了 WebGPU 的显式资源哲学。同一份纹理数据，配 `nearest` 是像素艺术，配 `linear` 是平滑贴图；一张 `repeat` 平铺的墙面和一张 `clamp` 的 UI 面板可以共享同一块显存。反过来，多个材质共享同一个采样器状态也是 bind group 层面的组合自由。如果采样策略长在纹理身上，这两种复用都得靠拷贝数据实现。

## UV 坐标与顶点数据

纹理坐标 (u, v) 定义在 [0, 1] × [0, 1]：u 向右、v 向上，原点在纹理左下角。它是顶点 attribute，从 vs 的 `@location` 进来、往 fs 的 `@location` 出去——上一模块讲的透视校正插值对它完全适用，硬件保证你拿到的片元 UV 已经除过 w。demo 02 的每个顶点变成 8 个 float：position(3) + uv(2) + normal(3)，normal 此刻闲置，是给 2.4 的光照预埋的。

六个面要各自铺满整张纹理，四个角点的 UV 从外侧看按「左下 → 右下 → 右上 → 左上」排布：

```ts
// 每面铺满整张纹理：ids 顺序从外侧看是「左下 → 右下 → 右上 → 左上」
const QUAD_UV = [
  [0, 1], [1, 1], [1, 0], [0, 0],
] as const;
```

v 在下缘取 1、上缘取 0，看着别扭，其实是两套 y 方向打架：纹理的 v 向上、canvas 像素源的 y 向下，上传时图像行序被翻转过一次，UV 侧对齐的是「最终被采样的样子」。这半行注定的别扭会在 mipmap 生成时再出现一次，到时细说。

## 过滤模式：放大与缩小是两个问题

采样器要回答「像素坐标落在纹素之间时取什么值」。方向不同，答案不同。放大（magnification）是纹理比屏幕区域小：一个纹素被拉到几个像素，`magFilter` 决定过渡；缩小（minification）反过来：多个纹素挤进一个像素，`minFilter` 决定怎么压缩信息。

| 模式 | 邻域 | 效果 | 典型场景 |
|------|------|------|---------|
| `nearest` | 1 个纹素 | 硬边、块状 | 像素艺术、调试 |
| `linear` | 4 个纹素双线性加权 | 平滑 | 默认选择，demo 02 用它 |

双线性的推导（两次水平 lerp + 一次垂直 lerp）在笔记 5.4。缩小方向的正确解法更激进：单个像素覆盖了几十上百个纹素时，逐纹素加权已经不现实，需要预先把「一段范围内的平均值」算好——这就是 mipmap，笔记 5.4 的重头戏。构建规则一句话：每级把边长减半，每 2×2 纹素取平均；512×512 的纹理一共 10 级，额外存储开销只有原图的 1/3。

| 级数 | 分辨率 | 内容 |
|------|--------|------|
| 0 | 512 × 512 | 原图 |
| 1 | 256 × 256 | 每 2×2 取平均 |
| 5 | 16 × 16 | 远处仍然可辨的粗结构 |
| 9 | 1 × 1 | 全图平均色 |

运行时硬件按屏幕像素在纹理空间的足迹（笔记 5.4 的 D = log₂ L 公式）选出层级，`mipmapFilter: 'linear'` 再让相邻两级之间线性混合——两级内各做一次双线性、级间再做一次线性，合称三线性插值。代价可控、过渡平滑，是 3D 场景的标准配置。寻址模式是采样器最后一个自由度：UV 超出 [0, 1] 时怎么办，`repeat` 平铺、`mirror-repeat` 镜像、`clamp-to-edge` 拉住边缘像素。demo 02 选 `clamp-to-edge` 有具体理由：蓝图纹理的边缘有细线和角标，`repeat` 会把对边卷进本级 mip 污染平均色。

## How：demo 02 全链路精讲

### 第一步：canvas 2D 画出「设计过的」纹理

纹理内容是教学上最容易敷衍的一步——随手填个随机噪点，mipmap 的演示效果会一塌糊涂，因为噪点在低级 mip 平均后只剩一片灰。demo 02 的 512×512 蓝图按「远看有图章、近看有细节」两个尺度设计：深底 `#0D1322` 上，32px 细网格与 128px 主网格给近距离层次，青色同心圆与十字给远距离一个可辨识的图章，琥珀对角带与四角取景框提供方向感。

```ts
// 中心十字与同心圆（青）：给远距离的低 mip 一个可辨识的图章
g.strokeStyle = '#2DD4BF';
g.lineWidth = 3;
g.beginPath(); g.arc(256, 256, 118, 0, Math.PI * 2); g.stroke();
g.lineWidth = 1.5;
g.beginPath(); g.arc(256, 256, 96, 0, Math.PI * 2); g.stroke();
g.beginPath(); g.moveTo(256 - 140, 256); g.lineTo(256 + 140, 256); g.stroke();
g.beginPath(); g.moveTo(256, 256 - 140); g.lineTo(256, 256 + 140); g.stroke();
```

生产环境同理：程序化纹理要为「每个 mip 级都值得看」设计，否则拉远就是一摊均值。

### 第二步：createTexture，三个 usage 一个都不能少

```ts
const TEXTURE_SIZE = 512;
const MIP_LEVELS = 10; // 512 → 256 → … → 1：log2(512) + 1

const texture = device.createTexture({
  size: [TEXTURE_SIZE, TEXTURE_SIZE],
  format: 'rgba8unorm', // 与 canvas 像素源天然匹配（8bit 无符号归一化）
  mipLevelCount: MIP_LEVELS,
  // RENDER_ATTACHMENT：每一级 mip 都要被「渲染进去」，少这个标志
  // mipmap 生成会直接 validation error
  usage:
    GPUTextureUsage.TEXTURE_BINDING |
    GPUTextureUsage.COPY_DST |
    GPUTextureUsage.RENDER_ATTACHMENT,
});
```

四个字段各有一课。`size` 是 `GPUExtent3D`，必须写 `[512, 512]`——写成 `[512]` 意味着高和深都是默认值 1，上传立刻越界报错。`format` 选 `rgba8unorm`：每通道 8 位、无符号、采样时归一化到 [0, 1]，与 canvas 2D 的像素内存逐字节对齐，免转换。`mipLevelCount` 为整条链预留显存。`usage` 三个标志对应三种身份：被采样（`TEXTURE_BINDING`）、被写入（`COPY_DST`）、被当作渲染目标（`RENDER_ATTACHMENT`）——第三个专供下一步的 mipmap 生成，漏掉它是最常见的翻车点。

### 第三步：把 canvas 拷进第 0 级

```ts
// canvas 直接拷进第 0 级：copyExternalImageToTexture 吃 canvas/ImageBitmap
device.queue.copyExternalImageToTexture(
  { source: createTextureSource() },
  { texture },
  [TEXTURE_SIZE, TEXTURE_SIZE],
);
```

`copyExternalImageToTexture` 接受 `HTMLCanvasElement`、`ImageBitmap`、`HTMLImageElement` 等外部图像源，属于 queue 上的便捷通道。第三个参数是拷贝尺寸，仍然要 `[512, 512]`。此步之后只有第 0 级有内容——WebGPU 没有自动生成 mipmap 的 API，剩下的九级全靠你自己渲染进去。

### 第四步：在 GPU 上生成 mipmap 链

思路是逐级降采样：把上一级当纹理采样、渲染进下一级。采样器用 `linear`，恰好就是「4 邻域取平均」的盒式降采样，与笔记 5.4 的 mipmap 定义严丝合缝。

```ts
{
  const encoder = device.createCommandEncoder();
  for (let level = 1; level < MIP_LEVELS; level++) {
    // bind group 挂「上一级」的视图：createView 选定单个 mip 层
    const bindGroup = device.createBindGroup({
      layout: mipPipeline.getBindGroupLayout(0),
      entries: [
        {
          binding: 0,
          resource: texture.createView({ baseMipLevel: level - 1, mipLevelCount: 1 }),
        },
        { binding: 1, resource: mipSampler },
      ],
    });
    const pass = encoder.beginRenderPass({
      colorAttachments: [
        {
          // 本级作为 render target；viewport 默认就是整张附件
          view: texture.createView({ baseMipLevel: level, mipLevelCount: 1 }),
          clearValue: { r: 0, g: 0, b: 0, a: 1 },
          loadOp: 'clear',
          storeOp: 'store',
        },
      ],
    });
    pass.setPipeline(mipPipeline);
    pass.setBindGroup(0, bindGroup);
    pass.draw(3); // 大三角形铺满当前级
    pass.end();
  }
  device.queue.submit([encoder.finish()]);
}
```

`createView({ baseMipLevel: level, mipLevelCount: 1 })` 是关键调用：view 只「看见」一层 mip，于是同一张纹理既当本级渲染目标、又当上一级的采样源。九个 pass 全部录进同一个 encoder，一次 submit 完成。采样着色器 `mip.wgsl` 只有大三角形与一行采样，但藏着上一模块埋的 y 方向问题：

```wgsl
@vertex
fn vs(@builtin(vertex_index) i: u32) -> VertexOut {
  // 一个大三角形盖满整个 render target（比 4 顶点少一半顶点着色）
  var pos = array<vec2f, 3>(
    vec2f(-1.0, -1.0),
    vec2f(3.0, -1.0),
    vec2f(-1.0, 3.0),
  );
  var out: VertexOut;
  let p = pos[i];
  out.position = vec4f(p, 0.0, 1.0);
  // v 要翻转：render target 的 +y 在上方，而纹理的 v = 0 在上方，
  // 两个「上」方向相反，不翻会把每级 mip 上下颠倒着传下去
  out.uv = vec2f(p.x * 0.5 + 0.5, 0.5 - p.y * 0.5);
  return out;
}
```

顶点摆成 NDC 大三角形（三个顶点盖住整个视口），UV 需要手工从 NDC 折算。v 分量的 `0.5 - p.y * 0.5` 里那个减号就是翻转：render pass 的坐标系 y 向上，纹理的 v 轴原点在上方，两个「上」不在一起。漏掉这一翻转，第 0 级还正常、从第 1 级起每一级都上下颠倒地平均下去，最终立方体近处正常、远处上下错乱——一个极好的人肉插值练习题。

### 第五步：三线性采样器与 bind group

```ts
// 三线性采样器：minFilter 在两级 mip 内各自线性，mipmapFilter 在两级之间线性
const viewSampler = device.createSampler({
  magFilter: 'linear',
  minFilter: 'linear',
  mipmapFilter: 'linear',
  // 蓝图纹理的边缘有细线，repeat 会把对边卷进来污染低级 mip
  addressModeU: 'clamp-to-edge',
  addressModeV: 'clamp-to-edge',
});

// bind group：uniform + sampler + texture（不带参数的 view = 整条 mip 链）
const bindGroup = device.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [
    { binding: 0, resource: { buffer: uniformBuffer } },
    { binding: 1, resource: viewSampler },
    { binding: 2, resource: texture.createView() },
  ],
});
```

注意两处 view 的对比：生成 mip 时用 `createView({ baseMipLevel, mipLevelCount: 1 })` 限定单层，采样时用无参 `createView()` 暴露整条链——硬件选级混合的全部依据就在这个 view 的可见范围里。着色器侧的采样只有一行，`textureSample(cubeTexture, texSampler, uv)`；滚轮把相机从 2.1 拉到 11.0，uv 的屏幕足迹随之放大，选级公式自动从 0 级滑到 5 级左右，网格线平滑糊掉而闪烁消失。

## 常见坑

| 报错/症状 | 原因 |
|-----------|------|
| `Texture usage (...) does not include RENDER_ATTACHMENT` | mipmap 生成把 mip 层当 render target，usage 少了 `GPUTextureUsage.RENDER_ATTACHMENT` |
| `... copySize (512x1) ... out of bounds` 之类 | `GPUExtent3D` 写错：要 `[512, 512]`（宽、高），只写 `[512]` 时高按 1 处理 |
| `Destination texture format ... is not copy-compatible` | 目标格式与外部图像源不匹配：canvas 上传用 `rgba8unorm`，别用带 sRGB 后缀的格式（会二次编码） |
| 远处网格闪烁（摩尔纹） | 没建 mipmap，或 `mipmapFilter` 忘了设 `linear`；回到笔记 5.4 的「范围查询」看原因 |
| 贴图上下颠倒，远处错乱 | mip 生成 pass 里 v 没翻转：render target 与纹理的 y 方向相反 |
| 立方体边缘出现对边的细线 | `addressMode` 用了 `repeat`，边缘细线被卷进低级 mip；换 `clamp-to-edge` |
| 采样返回全黑 | bind group 挂的是单层 view（`baseMipLevel` 版本）而不是全链 view，或采样格式与 `texture_2d<f32>` 类型不符 |

## Checkpoint

- 能说出 texture 与 sampler 分离后各自管什么，以及两种复用方向（同数据配多策略 / 多材质共享策略）
- 能默写三线性插值的组成：两级内各一次双线性 + 级间一次线性，对应 `minFilter` 与 `mipmapFilter` 两个开关
- 能解释 mipmap 为什么把额外存储控制在 1/3，以及「为每级 mip 设计内容」对程序化纹理意味着什么
- 能列出 `createTexture` 三 usage 各自服务的后续操作
- 能说清 `copyExternalImageToTexture` 之后还需要哪九步（九个 render pass）以及为什么（WebGPU 无自动 mipmap）
- 能解释 mip 生成着色器里 v 翻转的两个「上」为什么相反
