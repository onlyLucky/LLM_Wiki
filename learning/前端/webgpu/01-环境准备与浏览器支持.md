# 01 环境准备与浏览器支持

2026 年 9 月的 WebGPU 已经跨过了「三大浏览器齐活」的门槛，但各家实现仍有差异。开课前的十分钟用来确认你的环境，之后三天就不会被工具问题打断。

## 浏览器支持现状

| 浏览器 | 状态 | 备注 |
|--------|------|------|
| Chrome / Edge | 113+ 全平台 | Windows 走 D3D12，macOS 走 Metal，Android 121+ |
| Safari | 26+ | macOS Tahoe / iOS 26 / iPadOS 26 / visionOS 26 起支持 |
| Firefox | 已支持 | 桌面端默认开启 |
| Baseline | 未标记 | MDN 尚未给 WebGPU 标记 Baseline，线上产品仍需能力检测 |

课程在 macOS + Chrome / Edge 下开发验证。Safari 可以学，但个别扩展特性（如 `f16` shader 特性）需要 Safari 26.4+，遇到问题优先换 Chrome 排查，先排除浏览器因素再怀疑代码。

## 十分钟环境检查

### 第一步：确认 GPU 加速开启

地址栏打开 `chrome://gpu`，搜索 WebGPU 一节，状态应为 `Hardware accelerated`。如果显示 `Software only`，去 `chrome://settings/system` 打开「使用图形加速（若可用）」再重启。

### 第二步：跑能力检测脚本

在任意页面的控制台里贴这段（它也会出现在 Day 1 的 demo 页错误面板里，逻辑同源）：

```ts
async function probe() {
  if (!('gpu' in navigator)) return '不支持：navigator.gpu 不存在';
  const adapter = await navigator.gpu.requestAdapter();
  if (!adapter) return '支持 API 但拿不到适配器：检查 chrome://gpu';
  const info = adapter.info;
  return `OK · ${info.vendor} ${info.architecture} · features: ${
    [...adapter.features].slice(0, 3).join(', ')
  }`;
}
probe().then(console.log);
```

输出 `OK · ...` 即可开工。想看完整细节，访问 [webgpureport.org](https://webgpureport.org/)，它把当前浏览器的 limits、features、兼容模式状态全部可视化。

### 第三步：无 GPU 环境的降级路径

在虚拟机、远程桌面或没独显的老机器上，`requestAdapter()` 可能返回 null。两条路：

```ts
// 路径一：显式请求软件适配器（CPU 模拟，速度慢但能跑通全部课程）
const adapter = await navigator.gpu.requestAdapter({ forceSoftware: true });
```

路径二是换台机器——软件适配器跑 Day 1 没问题，Day 2 的粒子系统会明显掉帧，属于预期行为。课程所有 demo 在 M 系列芯片的集显上都能满帧。

## compatibility mode 是什么

Chrome 提供一个受限子集模式（compatibility mode），只保证 WebGPU 核心功能，砍掉 storage buffer 在片元着色器中的写入等高阶能力，面向安全性与移植性要求更高的场景。课程内容全部落在核心子集内，不需要关心它；你在 MDN 上看到「not part of Baseline / compatibility mode」的标注时，知道这是浏览器实现层的安全阀即可。

## 工程环境

课程仓库就是一个 Vite 工程：

```bash
cd 前端/webgpu
npm install      # 安装 vite / typescript / @webgpu/types / three
npm run dev      # http://localhost:5173/
npm run typecheck  # 讲义代码有改动时可随时校验类型
```

TypeScript 的 WebGPU 类型来自 `@webgpu/types` 包（`tsconfig.json` 里已配置），它比 `lib.dom.d.ts` 更新更快，`three` 的类型则由包内自带。编辑 WGSL 时建议装 VS Code 的 wgsl-analyzer 插件，课程把着色器独立为 `.wgsl` 文件正是为了配合它。

## 常见环境问题对照

| 症状 | 原因 | 处理 |
|------|------|------|
| demo 页弹出 `WEBGPU NOT AVAILABLE` | 浏览器过旧或非安全上下文 | 升级 Chrome/Edge；确认地址是 localhost 或 https |
| `NO ADAPTER` 面板 | 硬件加速被禁用 / 虚拟机 | 开启图形加速，或 `forceSoftware: true` |
| 控制台报 `Device lost` | 系统休眠 / 驱动重置 | 刷新页面重建资源即可 |
| `uncaptured validation error` | 代码问题，不是环境问题 | 看错误面板里的提示，Day 1 讲义 1.3 有对照表 |

环境就绪后，从门户页（`http://localhost:5173/`）进入 Day 1 的第一个 demo，同时打开讲义 `1.1-GPU架构与WebGPU全景.md`，正式开始。
