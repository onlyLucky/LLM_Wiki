## 🎯 核心概念

### 1. Draw Call

Draw Call = CPU 向 GPU 发送一次渲染指令。

**类比**：餐厅点餐——你每点一个菜，服务员就跑一次厨房（Draw Call）。如果你点了 100 个菜，服务员要跑 100 次，很慢。更好的做法是把 100 个菜写在一张单子上，服务员只跑一次（InstancedMesh）。

**为什么 Draw Call 是瓶颈？**
- 每次 Draw Call，CPU 需要：设置渲染状态（材质/纹理/混合模式）→ 发送顶点数据 → 通知 GPU 绘制
- 这些"状态切换"有固定开销，GPU 本身画得很快，但 CPU 准备数据慢
- 典型瓶颈：1000+ Draw Call 时 CPU 帧率开始下降

### 2. InstancedMesh

一次 Draw Call 渲染成千上万个**相同几何体**的实例。

```typescript
const mesh = new THREE.InstancedMesh(geometry, material, 1000)
for (let i = 0; i < 1000; i++) {
  dummy.position.set(...)
  dummy.updateMatrix()
  mesh.setMatrixAt(i, dummy.matrix)  // 每个实例独立变换
  mesh.setColorAt(i, color)          // 每个实例独立颜色
}
```

**对比**：

| | 普通 Mesh × 1000 | InstancedMesh × 1000 |
|--|--|--|
| Draw Call | 1000 | 1 |
| GPU 内存 | 1000 份几何体 | 1 份几何体 |
| 独立控制 | ✅ 完全独立 | ✅ 位置/颜色/缩放 |
| 适用 | 不同物体 | 相同物体的不同实例 |

### 3. 性能监控

```typescript
const info = renderer.info
// info.render.calls    → Draw Call 数量
// info.render.triangles → 三角形数量
// info.memory.geometries → 几何体数量
// info.memory.textures   → 纹理数量
```

### 4. 优化策略汇总

| 策略 | 方法 | 效果 |
|------|------|------|
| 减少 Draw Call | InstancedMesh / 合并几何体 | ↓ CPU 开销 |
| 纹理压缩 | KTX2 / Basis / WebP | ↓ 显存 ↓ 加载 |
| LOD | 远处低面数模型 | ↓ 三角形 |
| Shader 优化 | 减少分支/采样 | ↓ GPU 时间 |
| Tree-shaking | Vite 自动移除未用代码 | ↓ 包体积 |

### 5. 移动端 3 大性能要点

1. **Draw Call < 200**：移动端 CPU 更弱
2. **纹理尺寸 < 1024**：移动端显存有限
3. **Shader 简单**：移动端 GPU 算力低

## 费曼学习法

**概念：Draw Call**

**AI 用大白话讲**：
> 想象你在一个餐厅，点了 100 道菜。如果服务员每道菜都跑一次厨房（100 个 Draw Call），那服务员会累死（CPU 瓶颈），即使厨师做得很快（GPU 快）。
>
> 更好的做法：你把 100 道菜写在一张菜单上，服务员只跑一次厨房（1 个 Draw Call = InstancedMesh）。厨师看到菜单后，一次性把所有菜做好。
>
> 但有个限制：菜单上的菜必须是同一种类型（相同几何体）。如果你点了 100 种不同的菜（不同材质），那就没办法合并成一张菜单了。
