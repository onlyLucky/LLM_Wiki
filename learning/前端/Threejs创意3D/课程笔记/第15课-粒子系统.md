## 🎯 核心概念

### 1. 粒子系统基础

粒子系统用 `THREE.Points` 渲染，每个粒子是 BufferGeometry 中的一个顶点。

**核心区别**：普通 Mesh 每个物体是一个完整的几何体（三角形面），粒子系统每个"物体"只是一个点（顶点），GPU 自动把它渲染成屏幕上的小方块。

```typescript
const positions = new Float32Array(count * 3)  // 每个粒子 xyz
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3))
const particles = new THREE.Points(geometry, material)
```

### 2. gl_PointSize — 控制粒子大小

在顶点着色器中设置，决定粒子在屏幕上的像素大小。

```glsl
vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
gl_PointSize = size * (300.0 / -mvPosition.z);
```

**为什么要除以 `-mvPosition.z`？**
- `mvPosition.z` 是粒子在相机空间的深度（负值）
- 除以它实现**透视衰减**：远处的粒子看起来更小
- 如果不除，所有粒子一样大，没有远近感

### 3. gl_PointCoord — 粒子内部 UV

在片元着色器中获取，范围 [0, 1]，左下角为 (0,0)。

```glsl
float d = distance(gl_PointCoord, vec2(0.5));
if (d > 0.5) discard;  // 圆形粒子
```

**类比**：gl_PointCoord 就像每个粒子自带一个小 UV 贴图，(0.5, 0.5) 是中心。

### 4. 生命周期（Birth Time + Age）

每个粒子有 `aBirthTime` 属性，记录它"出生"的时间。Shader 用 `uTime - aBirthTime` 计算年龄。

```glsl
float age = mod(uTime - aBirthTime, uMaxLife);  // 循环
float lifeRatio = age / uMaxLife;                // [0, 1]
float size = aSize * sin(lifeRatio * 3.14159);   // 先大后小
vAlpha = 1.0 - lifeRatio;                        // 淡出
```

**视觉效果**：粒子诞生→变大→缩小→消失→重新诞生。

### 5. AdditiveBlending（叠加混合）

重叠粒子的颜色**相加**，越重叠越亮。

```typescript
material.blending = THREE.AdditiveBlending
material.depthWrite = false  // 必须禁用深度写入
```

**为什么适合火焰/烟雾？**
- 火焰叠加会越来越亮（模拟光的叠加）
- NormalBlending 会遮挡后面的粒子（看起来像固体）

**`depthWrite: false` 为什么必须？**
- 粒子是半透明的，不能写入深度缓冲
- 否则前面的粒子会挡住后面的粒子，看起来像方块

### 6. GPU 粒子 vs CPU 粒子

| | CPU 粒子 | GPU 粒子 |
|--|--|--|
| 更新方式 | JS 每帧更新 position 属性 | Shader 中计算（Transform Feedback） |
| 每帧数据传输 | 整块缓冲上传显存（10 万粒子 ≈ 1.2 MB/帧） | 只传 uniform（一个 uTime，4 字节） |
| 数量上限 | ~1 万（JS 性能瓶颈） | ~100 万（GPU 并行计算） |
| 灵活性 | 高（JS 可以做任意逻辑） | 低（只能用 GLSL 数学） |
| Three.js 方案 | `BufferAttribute` + JS | WebGPU Transform Feedback |

**类比**：CPU 粒子像"一个人管理 1 万个弹珠"，GPU 粒子像"1 万个弹珠各自按规则运动"。

**本课的对照实测**：不是看表格背结论，而是同一批粒子、同一套绕圈规则（`angle = aAngle + uTime * uSpeed`）做两条执行路径，面板一键切换：

- **GPU 模式**：位置公式写在顶点着色器里，JS 每帧只更新 `uTime`（4 字节）。10 万个顶点着色器并行执行——GPU 天生擅长「同一条规则、海量数据」
- **CPU 模式**：JS 每帧循环全部粒子重算位置写入 position 数组，`needsUpdate = true` 触发整块缓冲从内存上传显存

把粒子数拖到 10 万、切到 CPU 模式，FPS 实测差距一目了然（面板底部有 FPS 显示）。

```glsl
// GPU 路径：一份 shader 两种模式，uIsCpu 在两个位置来源之间插值
float angle = aAngle + uTime * uSpeed;
vec3 gpuPos = vec3(cos(angle) * aRadius, aHeight, sin(angle) * aRadius);
vec3 pos = mix(gpuPos, position, uIsCpu);  // CPU 模式下 position 已由 JS 写好
```

```typescript
// CPU 路径的核心：写完数组必须手动标记上传
positions[i * 3] = Math.cos(angle) * radii[i]     // JS 循环 10 万次
geometry.attributes.position.needsUpdate = true   // 整块缓冲上传显存
```

### 7. 聚合动画（形态插值）

两个目标形态之间用 `uProgress` 插值，`mix` 在顶点着色器里一次完成：

```glsl
// 流动位置（噪声场算出）与球面目标点之间插值：0 = 纯流动，1 = 完全聚合
vec3 finalPos = mix(flowPos, aTargetPos, uProgress);
```

设计要点：

- **目标位置预计算**：aTargetPos 在初始化时算好存进 attribute，运行时只插值不重算
- **斐波那契球面均匀分布**：y 从 1 匀速降到 -1，方位角按黄金角（2.399963 弧度 ≈ 137.5°）递增——比随机采样均匀得多，聚合出的球没有疏密斑驳
- **透明度也要插值**：流动模式「高度越高越透明」，聚合后应整体可见，`vAlpha = mix(flowAlpha, 0.9, uProgress)`

```typescript
// 斐波那契球面均匀分布
const y = 1 - (i / (count - 1)) * 2
const r = Math.sqrt(1 - y * y)
const theta = i * 2.399963  // 黄金角
targets[i * 3] = Math.cos(theta) * r * R
```

## 💻 代码实现要点

### 1. 星空粒子（基础 PointsMaterial）

最简单的粒子系统：随机位置 + 白色点 + 缓慢旋转。

- 5000 个粒子，随机分布在 20×20×20 空间
- `PointsMaterial` 的 `size: 0.05` 和 `sizeAttenuation: true`

### 2. 自定义 Shader 粒子

用自定义属性 `aSize`、`aBirthTime`、`aColor` 驱动生命周期动画。

- 大小随 `sin(lifeRatio * π)` 变化（先大后小）
- 颜色从蓝变白变红
- 透明度随 `1 - lifeRatio` 淡出

### 3. 流动粒子（噪声场驱动 + 聚合）

在顶点着色器中用噪声计算流动方向，`uProgress` 拖动可聚拢成斐波那契球面：

```glsl
float n = noise(pos.xz * 0.5 + t * 0.1);
pos.x += sin(n * 6.28) * 0.5;
pos.z += cos(n * 6.28) * 0.5;
pos.y = mod(pos.y + t * 0.3, 8.0) - 4.0;  // 循环上升

vec3 finalPos = mix(vec3(pos.x, pos.y, pos.z), aTargetPos, uProgress);
```

### 4. CPU/GPU 对照粒子（FPS 实验台）

3 万起步、滑块可调最高 10 万，配 FPS 实测：

- 同一套绕圈规则（角度、半径、高度存进 attribute），两种模式共用一份 shader
- GPU 模式：shader 算位置，只传 uTime
- CPU 模式：JS 每帧循环写 position + `needsUpdate = true`
- 面板：计算位置下拉（GPU/CPU）+ 粒子数量滑块（1000~100000）+ FPS 显示

### 5. 改粒子数量 = 重建 geometry

BufferGeometry 的顶点数创建后不可变，改数量必须整体重建。**重建前必须 dispose 旧的 geometry 和 material**（否则泄漏，详见第 20 课），并把直通 attribute 数组的引用刷新到新实例上：

```typescript
function rebuildCompareParticles(count: number) {
  scene.remove(oldPoints)
  oldPoints.geometry.dispose()
  ;(oldPoints.material as THREE.Material).dispose()
  // 新建 → scene.add → 刷新 positions/angles/radii/heights 引用
}
```

## 费曼学习法

**概念：粒子系统**

**AI 用大白话讲**：
> 想象你在放烟花——烟花弹升空后炸开，变成成千上万个小火花。每个火花就是一个「粒子」。粒子系统就是告诉 GPU："这里有一万个点，每个点有自己的位置、大小、颜色、寿命，你帮我把它们画出来"。
>
> 粒子的大小就像火花的亮度——刚炸开时很大很亮，然后越来越小越来越暗，最后消失。Additive blending 就像火花重叠时更亮——两束烟花交叉的地方特别耀眼。
>
> **CPU/GPU 对照就像带团旅游的两种方式**：CPU 模式是导游挨个给 1 万名游客打电话通知下一站去哪（每帧循环 + 打包数据上传），人越多导游越崩溃；GPU 模式是出发前发给每人一张日程表（attribute），之后导游只喊一声"现在几点了"（一个 uTime），所有游客自己看表走路——不管多少人，导游的工作量都一样。聚合动画则像烟花倒放：拖动滑块，漫天流萤慢慢收拢成一颗规整的珠子（斐波那契球面保证珠子上没有稀疏斑驳的"秃斑"）。
