## 📚 课程内容

本课学习如何让 Three.js 3D 场景响应鼠标和触摸输入，实现创意交互效果。核心工具是 **Raycaster**（光线投射器），它能将 2D 屏幕坐标"投射"到 3D 场景中，检测鼠标指向了哪个物体。配合平滑插值和空间加速结构，可以实现鼠标跟随、物体悬停高亮、涟漪扩散等丰富交互。

### 主要内容

1. **Raycaster 基础**
   - `THREE.Raycaster` 从相机出发穿过鼠标位置发射射线
   - `setFromCamera(mouse, camera)` 将屏幕坐标转为射线
   - `intersectObjects(objects)` 检测射线与物体的交点

2. **鼠标坐标归一化**
   - 屏幕坐标 → NDC（Normalized Device Coordinates）：`[-1, 1]` 范围
   - `x = (event.clientX / width) * 2 - 1`
   - `y = -(event.clientY / height) * 2 + 1`（注意 y 轴翻转）

3. **鼠标跟随与平滑**
   - `lerp`（线性插值）让物体平滑追赶鼠标，避免抖动
   - `current.lerp(target, 0.1)` 每帧向目标靠近 10%
   - 调节 lerp 因子控制响应速度：小值更平滑，大值更灵敏

4. **涟漪效果**
   - 用 `sin(dist - age)` 生成波纹
   - `exp(-age)` 控制涟漪随时间衰减（新涟漪强，旧涟漪弱）
   - `exp(-dist)` 控制涟漪随距离衰减（中心强，边缘弱）
   - 两者相乘得到自然的涟漪扩散效果

5. **性能优化**
   - 射线检测的 CPU 成本：O(n) 逐物体检测
   - 空间加速结构：BVH（Bounding Volume Hierarchy）、Octree、THREE.Mesh.bvh
   - 视锥体剔除（frustum culling）减少待检测物体
   - 节流（throttle）射线检测频率

6. **多输入设备处理**
   - 鼠标（mousemove）和触摸（touchmove）事件统一处理
   - Pointer Events API 统一鼠标/触摸/触控笔
   - 避免 mousemove + touchmove 同时触发导致重复计算

7. **物理引擎接入（Rapier）**
   - `@dimforge/rapier3d-compat`：Rust 编译的物理引擎，wasm 以 base64 内嵌进 JS，import 即用
   - `await RAPIER.init()`：先解码编译 wasm，必须 await 完才能用其他 API
   - `world.step()` 每帧推进物理模拟，然后把刚体位置"抄写"回 Mesh
   - 点击地面生成新球：掉落、弹跳、堆积全由物理引擎接管，与拾取/涟漪交互共存

## 🎯 核心概念

### 1. Raycaster 的工作原理

Raycaster 就是"从相机眼睛发出的激光笔"：

```
相机 (近裁剪面)
  \
   \  ← 射线方向
    \
     \
      ● 交点 (intersection.point)
     / \
    /   \
   物体表面
```

**关键属性**：
- `ray.origin`：射线起点（相机位置）
- `ray.direction`：射线方向（从相机穿过鼠标位置）
- `intersection.point`：交点的世界坐标
- `intersection.object`：被击中的物体
- `intersection.distance`：从射线起点到交点的距离

### 2. NDC 坐标系

屏幕坐标 → NDC 的转换是必须的，因为 Raycaster 期望的坐标范围是 `[-1, 1]`：

```
屏幕坐标系:          NDC 坐标系:
(0,0) → (w,h)       (-1,1) → (1,-1)
  ┌─────────┐         ┌─────────┐
  │         │         │    ↑    │
  │    ●    │    →    │ ← ● →  │
  │         │         │    ↓    │
  └─────────┘         └─────────┘
     左上角(0,0)        中心(0,0)
```

**注意**：y 轴必须翻转，因为屏幕坐标向下增长，NDC 坐标向上增长。

### 3. Lerp 平滑的本质

`lerp(current, target, factor)` 每帧把 current 向 target 移动 factor 比例：

```
frame 0: current = 0, target = 100
frame 1: current = 0 + (100-0)*0.1 = 10
frame 2: current = 10 + (100-10)*0.1 = 19
frame 3: current = 19 + (100-19)*0.1 = 27.1
...
```

这是一个**指数衰减**过程，永远不会完全到达目标，但无限接近。这就是为什么它看起来很"丝滑"——没有突然的加速度变化。

**为什么不用直线移动（匀速）？** 因为匀速移动会在到达目标时突然停止，产生"撞墙"感。Lerp 在接近目标时自动减速（缓出），天然具有美学上的舒适感。

### 4. 涟漪效果的数学

```glsl
float ripple = sin(distance - age) * exp(-age) * exp(-distance * 0.3);
```

| 分量 | 控制什么 | 类比 |
|---|---|---|
| `sin(distance - age)` | 波纹的形状（正弦波向外扩散） | 水面波纹的起伏 |
| `exp(-age)` | 波纹随时间衰减 | 水波越传越弱 |
| `exp(-distance * 0.3)` | 波纹随距离衰减 | 离中心越远波纹越小 |

三者相乘：只有**刚发生不久**（age 小）且**距离中心不远**（dist 小）的地方，涟漪才明显。

### 5. 空间加速结构

当场景有 1000+ 物体时，逐个检测太慢：

| 方法 | 原理 | 适用场景 |
|---|---|---|
| **BVH** | 层次包围盒树，先检测大盒子再检测子物体 | 静态几何体 |
| **Octree** | 八叉树空间分割 | 均匀分布的物体 |
| **Kd-tree** | k维空间分割 | 点云、粒子 |
| **视锥剔除** | 只检测相机能看到的物体 | 大型场景 |
| **LOD** | 远处物体用简化模型 | 开放世界 |

**THREE.js 内置**：`renderer.info.render` 可查看实际渲染的物体数量。`three-mesh-bvh` 库可以给任意 Mesh 添加 BVH 加速。

### 6. 物理引擎与渲染循环的同步

物理引擎和渲染引擎是**两个互不感知的世界**：

```
┌─────────────────┐          ┌─────────────────┐
│   Rapier 物理世界  │   每帧抄写   │  Three.js 渲染世界 │
│                 │  ───────→  │                 │
│  刚体（位置/速度）  │  位置/旋转   │  Mesh（负责画）    │
│  碰撞体（球/盒）    │            │  灯光/材质        │
└─────────────────┘          └─────────────────┘
      ↑                            ↑
  world.step() 推进模拟        renderer.render() 绘制
```

**木偶剧类比**：物理引擎是幕后的提线师傅，Mesh 是台前的木偶。师傅每秒拨 60 次（`world.step()`），木偶每帧摆出师傅给的动作（`mesh.position.set(...)`）。木偶自己不会动——如果哪帧忘记"抄写"，木偶就僵在原地，但幕后师傅还在继续演。

**本课的接入代码骨架**：

```js
import RAPIER from "@dimforge/rapier3d-compat"

await RAPIER.init()                       // 解码编译 wasm，必须最先 await

const world = new RAPIER.World({ x: 0, y: -9.81, z: 0 })  // 重力
world.timestep = 1 / 60                   // 固定时间步长

// 动态刚体（被物理驱动）：地面用 RigidBodyDesc.fixed()
const body = world.createRigidBody(
  RAPIER.RigidBodyDesc.dynamic().setTranslation(x, y, z)
)
// 碰撞体挂到刚体上；cuboid 用"半尺寸"；restitution 弹性、friction 摩擦
world.createCollider(
  RAPIER.ColliderDesc.ball(0.3).setRestitution(0.6).setFriction(0.5),
  body
)

// 渲染帧里：推进物理 + 把刚体状态抄写回 mesh
world.step()
const p = body.translation()    // Rapier 自己的 {x,y,z}，不是 THREE.Vector3
const r = body.rotation()       // {x,y,z,w} 四元数
mesh.position.set(p.x, p.y, p.z)
mesh.quaternion.set(r.x, r.y, r.z, r.w)
```

**为什么返回值不能直接 `copy()`**：`body.translation()` 返回的是 Rapier 自己的 `{x,y,z}` 对象，类型上不是 `THREE.Vector3`，`mesh.position.copy(...)` 会被 TypeScript 拒绝。用 `set(p.x, p.y, p.z)` 逐分量赋值最稳。

**固定时间步长 vs rAF 可变步长**（本课最容易忽略的知识点）：

| 方案 | 做法 | 问题/优点 |
|---|---|---|
| 一帧一步（本课） | `world.timestep = 1/60`，每帧 step 一次 | 简单；但 120Hz 屏幕上物理跑两倍速 |
| 累加器（严谨） | 攒真实流逝的 dt，攒够 1/60 才 step，可能一帧多步或零步 | 任意刷新率下物理表现一致；实现稍复杂 |

rAF 的回调间隔 = 屏幕刷新间隔，是"可变的"（60Hz/120Hz/掉帧时的 33ms）。物理引擎内部用固定步长做数值积分最稳定——这就是为什么两者需要"翻译"（累加器）。本课为了聚焦交互，采用最简单的一帧一步，知道局限即可。

## 💻 代码实现要点

### Raycaster 基础设置

```js
const raycaster = new THREE.Raycaster()
const mouse = new THREE.Vector2()

window.addEventListener("mousemove", (event) => {
  // 归一化到 [-1, 1]
  mouse.x = (event.clientX / window.innerWidth) * 2 - 1
  mouse.y = -(event.clientY / window.innerHeight) * 2 + 1
})

// 在 rAF 中检测
function animate() {
  raycaster.setFromCamera(mouse, camera)
  const intersects = raycaster.intersectObjects(scene.children)
  
  if (intersects.length > 0) {
    // 命中第一个物体
    const hit = intersects[0]
    hit.object.material.color.set(0xff0000)
  }
  
  renderer.render(scene, camera)
  requestAnimationFrame(animate)
}
```

### 鼠标跟随 + Lerp 平滑

```js
const target = new THREE.Vector3()
const current = new THREE.Vector3()

window.addEventListener("mousemove", (event) => {
  target.x = (event.clientX / window.innerWidth) * 2 - 1
  target.y = -(event.clientY / window.innerHeight) * 2 + 1
})

function animate() {
  // 每帧向目标靠近 10%
  current.lerp(target, 0.1)
  
  // 将 current 映射到 3D 空间
  mesh.position.x = current.x * 5
  mesh.position.y = current.y * 5
  
  renderer.render(scene, camera)
  requestAnimationFrame(animate)
}
```

### 涟漪着色器（顶点着色器）

```glsl
uniform float uTime;
uniform vec2 uMouse;       // 鼠标在 3D 平面上的位置
uniform float uClickTime;  // 点击发生的时刻

varying float vElevation;

void main() {
  vec3 pos = position;
  
  float dist = distance(pos.xz, uMouse);
  float age = uTime - uClickTime;
  
  // 涟漪公式
  float ripple = sin(dist * 10.0 - age * 5.0) 
               * exp(-age * 2.0)       // 时间衰减
               * exp(-dist * 0.5);     // 距离衰减
  
  pos.y += ripple * 0.3;
  vElevation = pos.y;
  
  gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
}
```

### 统一指针事件处理

```js
// 用 Pointer Events 统一鼠标/触摸
canvas.addEventListener("pointermove", (event) => {
  mouse.x = (event.clientX / canvas.clientWidth) * 2 - 1
  mouse.y = -(event.clientY / canvas.clientHeight) * 2 + 1

  handleClick(event.clientX, event.clientY)

// 如果需要区分输入类型
canvas.addEventListener("pointermove", (event) => {
  if (event.pointerType === "mouse") {
    // 鼠标：实时追踪

  }

```

### BVH 加速（使用 three-mesh-bvh）

```js
import { MeshBVH, acceleratedRaycast } from "three-mesh-bvh"

// 替换默认的 raycast 方法
THREE.Mesh.prototype.raycast = acceleratedRaycast

// 为几何体构建 BVH
const geometry = new THREE.BufferGeometry()
// ... 设置顶点 ...

geometry.computeBoundsTree()

// 现在 raycaster.intersectObject() 自动使用 BVH 加速
```

### 节流射线检测

```js
let lastRaycastTime = 0
const RAYCAST_INTERVAL = 16 // ~60fps

function animate(time) {

    raycaster.setFromCamera(mouse, camera)

    handleHits(hits)
    lastRaycastTime = time
```

## 苏格拉底问答

> 以下问题用于自测和深度思考，不提供答案。

**Q1：Raycaster 的 setFromCamera 需要什么格式的鼠标坐标？**

需要 **NDC（Normalized Device Coordinates）** 格式，x 和 y 都在 `[-1, 1]` 范围内。x = -1 是屏幕最左边，x = 1 是最右边，y = -1 是最下边，y = 1 是最上边。注意 y 轴与屏幕坐标相反——屏幕坐标向下增长，NDC 向上增长。转换公式：`x = (clientX / width) * 2 - 1`，`y = -(clientY / height) * 2 + 1`。如果忘记翻转 y 轴，射线方向会上下颠倒。

**Q2：为什么鼠标跟随要用 lerp 平滑？**

因为原始鼠标事件的频率和精度不稳定——鼠标移动可能有抖动，事件触发频率取决于系统（通常 60-120Hz）。如果直接把鼠标坐标映射到物体位置，物体会跟着鼠标"跳动"。Lerp 做的是每帧向目标靠近一小步，相当于一个**低通滤波器**——过滤掉高频抖动，保留低频趋势。结果是物体的运动轨迹变成平滑曲线，有"惯性"和"质量感"，视觉上更高级。

**Q3：涟漪效果中 exp(-age) 和 exp(-dist) 分别控制什么？**

`exp(-age)` 控制**时间维度的衰减**——涟漪刚产生时最强（age=0, exp(0)=1），随着时间推移指数级衰减。类比：往水里扔石头，波纹会逐渐消失。`exp(-dist)` 控制**空间维度的衰减**——离波纹中心越远，振幅越小。类比：波纹从石头落点向外扩散，越远越弱。两者相乘，只有在"时间上刚发生"且"空间上离中心近"的区域，涟漪才明显——这正是真实物理中水波的行为。

**Q4：1000 个物体每帧 Raycaster.intersectObjects 检测很慢，有什么空间加速结构？**

主要加速方案：(1) **BVH（Bounding Volume Hierarchy）**——为物体构建层次包围盒树，先检测大盒子，命中后再检测子物体，将 O(n) 降到 O(log n)。three-mesh-bvh 库可直接使用。(2) **Octree（八叉树）**——将 3D 空间递归分割成 8 个子区域，只检测鼠标射线经过的区域。(3) **Kd-tree**——适合点云和粒子系统。(4) **视锥剔除**——先用 `Frustum.intersectsObject()` 过滤掉相机看不到的物体。(5) **分层检测**——先检测粗粒度的代理物体（bounding sphere），命中后再检测精细模型。

**Q5：鼠标和触摸混合输入时，事件处理架构怎么设计避免重复触发？**

(1) **首选 Pointer Events API**——`pointermove`/`pointerdown` 统一处理鼠标、触摸、触控笔，浏览器自动去重，不会触发两次。(2) 如果必须用 Mouse/Touch Events，用 `event.preventDefault()` 在 touchstart 中阻止后续的 mousemove 模拟事件。(3) 用状态标记区分当前输入类型：`let activePointerType = null`，在 pointerdown 时设置，pointerup 时清除。(4) 节流更新频率——不管什么输入类型，每帧最多处理一次射线检测。(5) 触摸设备上隐藏鼠标光标，避免视觉混淆。

**Q6：为什么物理引擎和渲染引擎是两个独立的世界？渲染循环里怎么把两者连起来？**

**为什么分离**：职责不同。物理引擎做的是"数值模拟"——用碰撞检测 + 积分器算出每个刚体下一刻的位置速度，它完全不知道屏幕、相机、材质的存在；渲染引擎做的是"画"——拿到一堆变换矩阵和几何数据画到屏幕上，它不关心这些数据是怎么来的。分离带来的好处：(1) 各自独立演进（Rapier 换成 cannon-ammo 不影响渲染代码）；(2) 物理精度可调（固定步长、迭代次数）而不影响渲染帧率；(3) 同一套物理数据可以喂给渲染、音频、网络多个消费方。

**怎么连接**：一条单向数据流——渲染帧里先 `world.step()` 推进物理，然后把每个刚体的 `translation()/rotation()` 抄写回对应 mesh 的 `position/quaternion`。这是"物理为渲染供数"，反过来渲染层永远不直接改物理数据（要给刚体施力就用 `applyImpulse` 等 API）。忘记抄写的帧，物体在画面里会僵住，但物理世界还在继续算——这就是"幕后师傅还在演，台前木偶僵住了"。另外注意两个引擎的向量类型不互通（Rapier 的 `{x,y,z}` vs THREE.Vector3），TypeScript 会拦住直接 `copy()`，用 `set` 逐分量赋值。

## 费曼学习法

### 用"手电筒照物体"理解 Raycaster

想象你在一个漆黑的房间里，手里拿着一个**手电筒**：

🔦 **手电筒的类比**

- **你的眼睛** = 相机（Camera）
- **手电筒的光束** = Raycaster 发出的射线
- **你把手电筒指向哪里** = 鼠标在屏幕上的位置
- **光束照到的第一个物体** = `intersectObjects` 返回的第一个交点

**射线检测的过程**：

1. 你在黑暗中移动手电筒（移动鼠标）
2. 光束从你的眼睛出发，穿过手电筒指向的方向（`setFromCamera`）
3. 光束碰到第一个物体就停下来（`intersectObjects` 返回第一个命中）
4. 你看到了那个物体的颜色和位置（读取 `intersection.object` 和 `intersection.point`）

**为什么叫"光线投射"？** 因为它和光线追踪（ray tracing）的原理一模一样——从一个点向一个方向发射一条虚拟的线，看它碰到什么。区别是光线追踪发射百万条线来渲染画面，Raycaster 通常只发一条线来检测"鼠标指着谁"。

**Lerp 平滑 = 手臂的惯性**：

如果手电筒直接"瞬移"到鼠标位置，就像机器人手臂——精确但僵硬。Lerp 让手电筒像人的手臂一样有惯性——你挥手时，手臂不会瞬间到达目标位置，而是有一个减速的过程。`lerp(current, target, 0.1)` 中的 0.1 就是"手臂的肌肉刚度"——值越大手臂越"硬"，值越小手臂越"软"。

**实践检验**：如果把 `lerp` 的因子从 0.1 改成 1.0，物体会怎样？答案：物体瞬间到达鼠标位置，没有平滑过渡——和不用 lerp 一样，回到了"机器人手臂"。
