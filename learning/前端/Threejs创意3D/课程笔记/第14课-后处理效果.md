## 🎯 核心概念

### 1. 什么是后处理

**核心思想**：不直接把场景渲染到屏幕，而是先渲染到一张"中间纹理"（RenderTarget），然后对这张纹理做全屏图像处理。

```
传统渲染:  场景 ──────────────→ 屏幕
后处理:    场景 ──→ RenderTarget ──→ Shader(全屏) ──→ 屏幕
```

**为什么需要后处理？**
- 有些效果只能在"整个画面"层面做（Bloom、景深、运动模糊）
- 着色器只能处理单个片元，后处理能"看到"相邻像素
- 可以叠加多个效果，像 Photoshop 的滤镜链

**类比**：
- 普通着色器 = 给每件衣服单独染色
- 后处理 = 拍完照片后加滤镜——滤镜能"看到"整张照片

---

### 2. EffectComposer

**Three.js 的后处理管理器**：管理一系列 Pass（处理步骤），按顺序执行。

**基本架构**：
```
场景渲染到 RenderTarget
        ↓
    Pass 1（如 Bloom）
        ↓
    Pass 2（如 色彩校正）
        ↓
    Pass 3（如 Vignette）
        ↓
      屏幕输出
```

**基础用法**：
```javascript
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';

const composer = new EffectComposer(renderer);

// 第一步：渲染场景到 RenderTarget
const renderPass = new RenderPass(scene, camera);
composer.addPass(renderPass);

// 后续 Pass 在此基础上叠加效果
// ...

// 在动画循环中替代 renderer.render()
composer.render();
```

**关键概念**：
| 概念 | 说明 |
|------|------|
| `RenderPass` | 第一个 Pass，把场景渲染到内部 RenderTarget |
| `ShaderPass` | 通用 Pass，用自定义 Shader 处理上一步的输出 |
| `readBuffer` / `writeBuffer` | 双缓冲，Pass 间交替读写 |
| 最后一个 Pass | `renderToScreen = true`，输出到画布 |

### 3. Bloom（泛光）效果

**物理原理**：现实中极亮的光源会在相机镜头中产生光晕扩散。Bloom 模拟这个效果。

**实现流程**：
```
1. 提取亮区：只保留亮度 > threshold 的像素
2. 高斯模糊：对亮区做模糊扩散
3. 叠加合成：把模糊后的亮区加回原图
```

**UnrealBloomPass**（Three.js 内置）：
```javascript
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';

const bloomPass = new UnrealBloomPass(
  new THREE.Vector2(window.innerWidth, window.innerHeight),
  1.5,    // strength: 泛光强度
  0.4,    // radius: 模糊半径
  0.85    // threshold: 亮度阈值
);
composer.addPass(bloomPass);
```

**三个核心参数**：
| 参数 | 含义 | 典型值 | 效果 |
|------|------|--------|------|
| `strength` | 泛光强度 | 0.5~2.0 | 值越大，光晕越亮 |
| `radius` | 模糊半径 | 0.2~1.0 | 值越大，光晕扩散越远 |
| `threshold` | 亮度阈值 | 0.7~0.9 | 值越低，越多物体泛光 |

**为什么 threshold 通常设在 0.8 以上？**
- 物理上只有光源和高反射面才会"溢出"光线
- threshold 太低 → 整个场景都在发光，不真实
- 0.8 以上 → 只有 HDR 亮度 > 1.0 的高光区域才泛光

### 4. 色彩校正（Color Correction）

**核心操作**：对画面的亮度、对比度、饱和度进行调整。

**Shader 实现**：
```glsl
uniform sampler2D tDiffuse;    // 上一个 Pass 的输出纹理
uniform float uBrightness;     // 亮度: -1 ~ 1
uniform float uContrast;       // 对比度: 0 ~ 2
uniform float uSaturation;     // 饱和度: 0 ~ 2

varying vec2 vUv;

void main() {
  vec4 color = texture2D(tDiffuse, vUv);

  // 亮度
  color.rgb += uBrightness;

  // 对比度 (以 0.5 为中心缩放)
  color.rgb = (color.rgb - 0.5) * uContrast + 0.5;

  // 饱和度 (灰度 ↔ 原色 之间插值)
  float gray = dot(color.rgb, vec3(0.299, 0.587, 0.114));
  color.rgb = mix(vec3(gray), color.rgb, uSaturation);

  gl_FragColor = color;
}
```

**三个操作的数学本质**：
| 操作 | 数学 | 直觉 |
|------|------|------|
| 亮度 | `color + offset` | 整体平移色值 |
| 对比度 | `(color - 0.5) × factor + 0.5` | 以中灰为中心拉伸/压缩 |
| 饱和度 | `mix(gray, color, factor)` | 在灰度和彩色之间插值 |

### 5. Vignette（暗角）效果

**视觉效果**：画面四角变暗，引导视线聚焦中央。

**Shader 实现**：
```glsl
uniform sampler2D tDiffuse;
uniform float uOffset;    // 暗角起始位置: 0.5~1.5
uniform float uDarkness;  // 暗角深度: 0~2

varying vec2 vUv;

void main() {
  vec4 color = texture2D(tDiffuse, vUv);

  // UV 从中心到边缘的距离
  vec2 uv = (vUv - 0.5) * 2.0;  // 映射到 [-1, 1]
  float dist = length(uv);

  // 暗角衰减
  float vignette = smoothstep(uOffset, uOffset - 0.5, dist);
  color.rgb *= mix(1.0 - uDarkness, 1.0, vignette);

  gl_FragColor = color;
}
```

**参数解释**：
- `uOffset`：暗角开始的位置（值越大，暗角越小，中央亮区越大）
- `uDarkness`：四角压暗的程度（值越大，角落越黑）

### 6. 自定义 ShaderPass

**ShaderPass 的约定**：
```javascript
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';

const myShader = {
  uniforms: {
    tDiffuse: { value: null },  // 必须有！EffectComposer 自动传入上一步输出
    uTime:    { value: 0.0 }
  },
  vertexShader: `...`,
  fragmentShader: `...`
};

const myPass = new ShaderPass(myShader);
composer.addPass(myPass);
```

**tDiffuse 的来历**：
- `EffectComposer` 在执行每个 Pass 时，自动把上一步的输出纹理绑定到 `tDiffuse`
- 这是 Three.js 的**内部约定**，不是 GLSL 关键字
- `RenderPass` 渲染场景 → 写入 writeBuffer → 下一个 Pass 的 tDiffuse 指向 readBuffer

**ShaderPass vs ShaderMaterial**：
| | ShaderMaterial | ShaderPass |
|--|--|--|
| 用途 | 渲染 3D 几何体 | 全屏后处理 |
| 输入 | 顶点属性 + 自定义 uniform | tDiffuse（上一步输出）+ 自定义 uniform |
| 顶点 | 3D 几何体的顶点 | 全屏三角形（2 个三角形覆盖屏幕） |
| 坐标 | `position`, `uv` | `vUv`（0~1 的屏幕 UV） |

## 💻 代码实现要点

### 1. EffectComposer 完整配置

```javascript
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';

// 1. 创建 Composer
const composer = new EffectComposer(renderer);

// 2. RenderPass（必须第一个）
composer.addPass(new RenderPass(scene, camera));

// 3. Bloom
const bloomPass = new UnrealBloomPass(
  new THREE.Vector2(window.innerWidth, window.innerHeight),
  1.5, 0.4, 0.85
);
composer.addPass(bloomPass);

// 4. 色彩校正
const colorCorrectionPass = new ShaderPass(ColorCorrectionShader);
composer.addPass(colorCorrectionPass);
```

### 3. Pass 顺序的影响

**正确顺序**：RenderPass → Bloom → 色彩校正 → Vignette

**为什么？**
- Bloom 需要原始亮度信息来提取亮区 → 放在色彩校正之前
- 色彩校正会改变亮度值，如果先做，Bloom 的 threshold 判断会不准
- Vignette 只是"最后盖一层暗"，放最后不影响其他效果

**如果 Vignette 放在 Bloom 前面？**
- Bloom 的模糊会扩散到 Vignette 的暗角区域
- 暗角的边缘会变模糊，失去锐利感
- 最终效果：暗角被 Bloom "侵蚀"，看起来不自然

### 4. 与 renderer.render() 的关系

```javascript
// ❌ 错误：同时使用
renderer.render(scene, camera);  // 渲染到屏幕
composer.render();               // 又渲染一遍

// ✅ 正确：二选一
// 有后处理时，用 composer.render() 完全替代 renderer.render()
composer.render();
```

## 费曼学习法

### 后处理链——用手机拍照滤镜来理解

**生活类比：手机拍照加滤镜**

你用手机拍了一张照片，然后打开修图 App：

1. **第一步：拍照片**（RenderPass）
   - 手机相机把真实场景"捕捉"成一张数字照片
   - 这就是 `RenderPass` 做的事——把 3D 场景渲染成一张 2D 图片

2. **第二步：加"发光"滤镜**（Bloom）
   - 你选了"梦幻发光"滤镜
   - App 自动找出照片中最亮的地方（灯、反光），让它们"溢出"光芒
   - 就像晚上看路灯——灯本身不大，但周围一圈光晕

3. **第三步：调亮度/对比度/饱和度**（Color Correction）
   - 你拉高了"鲜艳度"（饱和度）
   - 调了"亮度"让暗部细节出来
   - 调了"对比度"让明暗更分明
   - 这些都是对**整张照片**的数学运算

4. **第四步：加暗角**（Vignette）
   - 你选了"复古暗角"效果
   - 照片四角变暗，视线自然被吸引到中间
   - 这是最简单的后处理——只是根据像素到中心的距离压暗

**关键洞察**：

后处理链就像一排滤镜，**顺序很重要**：
- 如果你先调了亮度再加"发光"，App 不知道哪些是"真正的亮"——因为你调高了亮度，很多本来不亮的东西也变亮了
- 所以要**先加发光，再调亮度**——让"发光"滤镜看到最原始的亮度信息
- 暗角只是最后"盖一层黑纱"，放最后不影响前面的效果

**EffectComposer = 滤镜管理器**

想象你有一台"自动修图机"：
- 你把原始照片塞进去（RenderPass）
- 告诉它："先帮我加发光"（addPass Bloom）
- "再帮我调颜色"（addPass 色彩校正）
- "最后加暗角"（addPass Vignette）
- 它自动按顺序处理，每一步的输出就是下一步的输入
- 最后从出口拿到最终照片

**tDiffuse = 上一步的"处理结果"**

每个滤镜步骤都需要知道"上一步处理到哪了"：
- 第一个滤镜看到的是原始照片
- 第二个滤镜看到的是第一个滤镜处理后的照片
- 第三个滤镜看到的是第二个滤镜处理后的照片
- `tDiffuse` 就是"上一个滤镜递给你的那张照片"

**为什么不能用普通着色器做后处理？**

普通着色器（ShaderMaterial）是给"单件衣服"染色的——它只能看到当前这一件。
后处理是给"整张照片"加滤镜——它需要看到所有像素，包括相邻的。

Bloom 需要知道"附近有没有很亮的像素"才能做光晕扩散——单个着色器做不到这一点。
