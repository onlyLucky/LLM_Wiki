## 📚 课程内容

本课学习如何将页面滚动行为与 Three.js 3D 场景动画绑定，实现"滚动到哪里，动画就播放到哪里"的效果。核心工具是 **GSAP ScrollTrigger** 插件，它能将滚动进度映射为动画进度，让 3D 场景随用户的滚动行为流畅变化。

### 主要内容

1. **GSAP + ScrollTrigger 基础**
   - 引入 GSAP 核心库和 ScrollTrigger 插件
   - `ScrollTrigger.create()` 配置滚动触发区域（scroller、start/end 标记）
   - `scrub` 参数将滚动位置与动画进度绑定

2. **Canvas 全屏固定布局**
   - `position: fixed` 让 canvas 覆盖整个视口
   - 用一个空的 `<div>` 撑出滚动高度（通常 `height: 500vh`）
   - canvas 始终在最前，滚动的是背后的占位元素

3. **滚动进度驱动 GSAP Timeline**
   - 创建 `gsap.timeline()` 封装所有动画步骤
   - 通过 ScrollTrigger 的 `scrub` 将 timeline 与滚动绑定
   - 在 timeline 中控制相机位置、物体旋转、材质透明度等

4. **章节式滚动动画**
   - 不同滚动区间对应不同的动画段落
   - 用 `labels` 或多个 ScrollTrigger 实现多段式叙事
   - `pin` 选项可以在某段滚动时"钉住"页面

5. **相机路径动画**
   - 滚动驱动相机沿预设路径移动
   - 用 `lookAt` 确保相机始终面向目标
   - 结合 `lerp` 实现平滑过渡

## 🎯 核心概念

### 1. ScrollTrigger 的 scrub 机制

`scrub` 是 ScrollTrigger 最关键的参数，它控制动画与滚动的绑定方式：

| 值 | 行为 |
|---|---|
| `false`（默认） | 动画在触发时立即播放，与滚动无关 |
| `true` | 动画进度严格等于滚动进度，0→1 映射 |
| `0.5` | 动画延迟 0.5 秒追赶滚动位置（带惯性平滑） |
| `1` | 动画延迟 1 秒追赶（更平滑但延迟更大） |
| 数值越大 | 追赶越慢，感觉越"漂浮" |

**本质**：`scrub` 是一个"橡皮筋"——`true` 是刚性绑定，数值越大橡皮筋越松。

### 2. 固定 Canvas + 滚动占位

```
┌─────────────────────┐
│  canvas (fixed)      │  ← 始终覆盖视口，z-index 高
│  渲染 3D 场景         │
└─────────────────────┘
┌─────────────────────┐
│  占位 div            │  ← 实际产生滚动，height: 500vh
│  (透明，撑高度)       │
└─────────────────────┘
```

这种模式让 3D 场景"悬浮"在页面上，用户滚动时看到的是场景变化而非页面位移。

### 3. 滚动进度的归一化

ScrollTrigger 内部将滚动位置归一化到 `[0, 1]`：

```
progress = (scrollY - start) / (end - start)
```

所有 GSAP 动画的 `.progress()` 方法也是 `[0, 1]`，所以天然对齐。

### 4. 多段式滚动叙事

将整个页面分成多个"章节"，每段对应不同动画：

```js
// 第一段：相机接近
gsap.timeline({ scrollTrigger: { scrub: 1, start: "top top", end: "30% top" } })
  .to(camera.position, { z: 5 })

// 第二段：物体旋转
gsap.timeline({ scrollTrigger: { scrub: 1, start: "30% top", end: "60% top" } })
  .to(mesh.rotation, { y: Math.PI })
```

### 5. rAF 与 ScrollTrigger 的协调

- ScrollTrigger 在滚动事件中更新 `timeline.progress()`
- rAF 循环负责每帧渲染（`renderer.render()`）
- 两者分工明确：ScrollTrigger 管"状态"，rAF 管"绘制"
- 不需要在 rAF 中读取 scrollY，GSAP 已经处理了

## 💻 代码实现要点

### 基本设置

```js
import gsap from "gsap"
import { ScrollTrigger } from "gsap/ScrollTrigger"
gsap.registerPlugin(ScrollTrigger)

// 创建 timeline 并绑定滚动
const tl = gsap.timeline({
  scrollTrigger: {
    trigger: ".scroll-container",  // 触发元素
    start: "top top",              // 滚动开始位置
    end: "bottom bottom",          // 滚动结束位置
    scrub: 0.5,                    // 0.5 秒延迟追赶
    // pin: true,                  // 可选：钉住触发元素
  },
})

// 在 timeline 中添加动画步骤
tl.to(camera.position, { x: 10, y: 5, z: 3, duration: 1 })
  .to(mesh.rotation, { y: Math.PI * 2, duration: 1 }, "<")  // "<" 表示同步
  .to(material, { opacity: 0, duration: 0.5 })
```

### Canvas 固定布局

```css
.webgl {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  height: 100vh;
  z-index: 1;
}

.scroll-container {
  position: relative;
  height: 500vh;  /* 5 屏滚动高度 */
  z-index: 0;
}
```

### 性能优化

```js
// 1. 使用 will-change 提示浏览器
canvas.style.willChange = "transform"

// 2. 避免每帧重新创建对象
const tempVec = new THREE.Vector3()

// 3. 用 gsap.quickTo 做高频更新
const updateCamera = gsap.quickTo(camera.position, "x", { duration: 0.3 })
```

### 章节标记

```js
// 用 timeline.label() 标记关键帧
tl.addLabel("intro", 0)
  .addLabel("zoom-in", 0.3)
  .addLabel("rotate", 0.6)
  .addLabel("fade-out", 0.9)

// 也可以用 ScrollTrigger 的回调
ScrollTrigger.create({
  trigger: ".section-2",
  start: "top center",
  onEnter: () => console.log("进入第二段"),
  onLeaveBack: () => console.log("退回第一段"),
})
```

## 苏格拉底问答

> 以下问题用于自测和深度思考，不提供答案。

**Q1：ScrollTrigger 的 scrub 参数是什么意思？scrub=true 和 scrub=0.5 的区别？**

scrub 控制动画进度是否跟随滚动。scrub=true 是刚性绑定——滚动到 50% 动画就到 50%，完全同步，没有延迟。scrub=0.5 表示动画会用 0.5 秒的时间"追赶"到当前滚动位置，产生一种有惯性的平滑感。类比：scrub=true 是齿轮直连，scrub=0.5 是通过弹性皮带连接。

**Q2：为什么 canvas 要用 position:fixed 而不是 position:absolute？**

position:fixed 相对于视口定位，不随页面滚动而移动，所以 canvas 始终"悬浮"在屏幕上方。如果用 position:absolute，canvas 会随父元素滚动，滚出视口后就看不见了。fixed 让 3D 场景成为"常驻画布"，背后的占位 div 才是真正产生滚动位移的元素。

**Q3：滚动驱动动画时如何避免性能抖动？**

几个关键策略：(1) 滚动回调中只更新 GSAP timeline 的 progress，不直接操作 Three.js 对象；(2) 用 `scrub` 而非 `onScroll` 手动更新；(3) rAF 循环只负责渲染；(4) 对相机/物体的更新使用 `lerp` 平滑；(5) 避免在滚动回调中创建新对象或调用昂贵方法；(6) 启用 `will-change: transform` 提示 GPU 加速。

**Q4：快速滚动时多个 ScrollTrigger 同时触发会不会卡顿？GSAP 内部怎么处理的？**

GSAP 内部用统一的 scroll 事件监听器（而非每个 ScrollTrigger 各自监听），并通过 `requestAnimationFrame` 批量更新所有触发器状态，避免多次重算。即使有 10 个 ScrollTrigger 同时活跃，每帧也只做一次滚动位置计算 + 一次批量更新。快速滚动时，scrub 带数值的（如 0.5、1）会自动做插值平滑，不会一帧跳太多。真正卡顿通常是 Three.js 渲染本身的问题，而非 ScrollTrigger 的问题。

**Q5：滚动驱动和 rAF 基于时间的动画混合使用时，时间基准怎么同步？**

核心原则：让 ScrollTrigger 管"状态"，让 rAF 管"渲染"。ScrollTrigger 通过 scrub 控制 timeline 的 progress（0→1），这个 progress 就是你的"状态基准"。rAF 中不需要关心时间，只读取当前的 progress 值来决定渲染什么。如果同时有基于时间的动画（如粒子系统），它们各自独立运行，不需要同步时间——因为滚动动画的进度取决于滚动位置而非时间流逝。

## 费曼学习法

### 用"翻书动画"理解滚动驱动

想象一本**翻页动画书（flipbook）**：

📖 **翻书动画书的类比**

- **书的每一页** = 3D 场景的一帧状态
- **你的手指翻页** = 页面滚动（scrollY）
- **翻到第几页就看到第几幅画** = scrub=true（严格同步）
- **翻页时画面有模糊过渡** = scrub=0.5（延迟追赶）

**关键洞察**：

1. **ScrollTrigger 就是翻书的手指**——它把"滚动了多少"翻译成"动画走了多少"
2. **timeline 就是动画书本身**——所有帧按顺序排列好
3. **canvas 是画框**——它固定不动（position:fixed），变化的是画框里的内容
4. **占位 div 是书的厚度**——它让页面能滚动那么长

**为什么用翻书而不是自动播放？**

自动播放的视频 = 用户被动观看，2 倍速跳过  
翻书动画 = 用户控制节奏，想看哪里就翻到哪里

这就是**交互式叙事**的本质：把控制权交给用户，让每一屏都是一个"章节"。

**实践检验**：如果把 scrub 去掉，改成 `scrollTrigger: { trigger: "..." }`（不带 scrub），动画会怎样？答案：动画会在滚动到触发点时一次性播完，不再跟随滚动——从"翻书"变成了"翻到某页自动播放视频"。
