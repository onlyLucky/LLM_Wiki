# 实例网站清单

这份清单是课程与真实创意网站的接线板。课程的终点是复刻 Awwwards 获奖网站的核心 3D 效果，而第 17-19 课（滚动驱动、创意交互、网站架构）正是从「学会技术」走向「看懂作品」的转折段。每站给出气质、技术拆解、课程关联与观察要点——技术拆解只写有公开来源支撑的内容（官方复盘、awwwards 案例页、Codrops 文章、作者自述），不确定的一律标注「据公开访谈/技术分享」。用法有两种：学到第 17-19 课时对照拆解结构找对标，结营后按「技术同构」原则挑一站复刻其中一种效果（见 00-学习地图的结营标准）。

观察一个站的标准姿势：用桌面 Chrome 打开，先不动鼠标看 10 秒入场动画，再慢速滚动全程一遍，最后开着 DevTools 的性能面板重滚一遍，看帧率掉在哪里。下面每站的「观察要点」就是这三个阶段各自该盯什么。

## lusion.co

| 项目 | 内容 |
|------|------|
| URL | https://lusion.co/ |
| 一句话气质 | 布里斯托工作室 Lusion 的门面——别人还在做「网页里有 3D」，他们做的是「3D 里有网页」 |
| 技术拆解 | 全站跑在 three.js 上；据公开访谈与技术分享，角色的顶点动画在 Houdini FX 里模拟后烘焙成纹理回放，布料与流体走 GPGPU；社区逆向分析还指出其「液体玻璃」质感来自单个片元着色器里融合了斯涅尔折射与波长色散的写法 |
| 课程关联 | 顶点动画与形变 → 第 11-12 课（顶点着色器的数学与噪声扰动）；布料与流体的 GPGPU 模拟 → 第 15 课（粒子）；「液体玻璃」质感 → 第 13 课（高级 Shader：菲涅尔与折射）；整站工程化与降级策略 → 第 19-20 课（网站架构、性能调优） |

观察要点

- 首页加载阶段：入场不是淡入而是「长出来」——几何从无到有的过程用了什么变形
- 缓慢滚动全程：注意每一屏的相机是怎么被滚动接管又交还的，没有任何一屏是「纯静态贴图」
- 把鼠标划过主体：布料/粒子对光标的响应延迟有多少毫秒——Lusion 的交互调参是行业标杆
- 性能面板：中端设备也流畅，观察他们为低端设备准备了什么降级（粒子数、纹理尺寸）

## igloo.inc

| 项目 | 内容 |
|------|------|
| URL | https://igloo.inc/ |
| 一句话气质 | 整个网站就是一块冰——导航、文字、过渡全部冰封在同一个世界观里 |
| 技术拆解 | 据公开技术分享（webgpu.com 案例拆解），由 Abeto 制作，全站 WebGL：冰块用自研的「容器内晶体生长」算法程序化生成——指定容器形状，让冰在里面长，每次都得到独一无二的结晶；UI 文字由着色器驱动；另涉体积数据处理 |
| 课程关联 | 程序化生成（由函数描述形状的思想）→ 第 16 课（RayMarching 与 SDF）与第 12 课（噪声）；冰的折射质感 → 第 13 课（高级 Shader）；滚动叙事与页面过渡 → 第 17 课（滚动驱动） |

观察要点

- 站在首页别动：冰的内部在缓慢变化，那不是视频循环而是实时渲染的折射
- 刷新两次对比：冰晶的形状每次都不同——程序化生成的签名特征
- 注意文字与 3D 的关系：文字不是贴在 DOM 上，而是被着色器「冻」进画面里
- 滚动时的过渡：页面之间的切换不是淡入淡出，是冰的形态变化

## haoqi.design

| 项目 | 内容 |
|------|------|
| URL | https://haoqi.design/ |
| 一句话气质 | 产品设计师的作品集，DOM 文字与 WebGL 舞台咬合得像一台复古未来主义的机器 |
| 技术拆解 | 作者 Haoqi Wen（TikTok 设计工程师）。据 Codrops 官方技术复盘：Next.js + Three.js，核心是「DOM 与 WebGL 共享一个舞台」——滚动同步、玻璃着色器、DOM/CSS 与 WebGL 三层交织；FWA 案例页还提到镜头光晕、动态光照与光标触发的涟漪 |
| 课程关联 | 滚动同步（DOM 与 WebGL 共享舞台）→ 第 17 课（滚动驱动动画）；玻璃着色器 → 第 13 课（高级 Shader）；光标涟漪 → 第 18 课（创意交互）；镜头光晕与后处理氛围 → 第 14 课（后处理） |

观察要点

- 慢速滚动一段文字区：DOM 段落和 3D 背景谁在跟随滚动、谁在被滚动「驱动」
- 找到玻璃材质的物件：背景透过它发生了什么——折射、模糊还是色偏
- 光标快速划过：涟漪的半径与衰减速度，这是交互手感调参的直接参考
- 切换几个主题（如果有）：同一舞台换材质参数就是换情绪

## iyO

| 项目 | 内容 |
|------|------|
| URL | https://www.iyo.ai/ |
| 一句话气质 | 给「世界第一台音频计算机」写的视觉诗——160 万颗粒子先组成克拉尼图形，再散开重组成一句俳句 |
| 技术拆解 | 据 awwwards 官方案例复盘（Matteo Donini / Federico Valla / Enrico Deiana 制作，SOTD 2026-04）：首页是最高 160 万粒子的 GPGPU 模拟——粒子先形成克拉尼图案（声波在振面上画出的图形），随后着色器读取每个词的暗像素、把同一批粒子吸附成文字，再溶解进入下一句，全程不换粒子池；光标划过有涟漪。性能分级到设备：旧手机粒子数降到四分之一，视网膜屏略降像素比（shader 负载省约 44%）；产品页的爆炸图由 CAD 减面 + Draco glTF 驱动，随滚动分解 |
| 课程关联 | GPGPU 粒子与文字成形 → 第 15 课（粒子）；粒子的「呼吸感」→ 第 12 课（噪声扰动）；CAD 减面 + Draco glTF 的滚动爆炸图 → 第 8 课（模型加载）与第 17 课（滚动驱动）；设备分级（粒子数、像素比）→ 第 20 课（性能调优） |

观察要点

- 首页盯着一个字看 15 秒：粒子不是静止的贴图，每颗都在微微呼吸——保持生命感的噪声扰动
- 等一句俳句变成下一句：中间的过渡不是淡入淡出，是同一批粒子的重新排队
- 光标慢慢划过文字：涟漪推开粒子后它们如何归位（吸附力的弹簧感）
- 用手机打开对比粒子密度：分级策略肉眼可见

## Aurelia 水母

| 项目 | 内容 |
|------|------|
| URL | https://holtsetio.com/lab/aurelia/ （源码开放：[github.com/holtsetio/aurelia](https://github.com/holtsetio/aurelia/)） |
| 一句话气质 | 一只完全由代码长出来的水母——没有一张贴图，没有一段烘焙动画 |
| 技术拆解 | 作者 Niklas Niehus。据作者自述与 WebKit 博客：three.js WebGPURenderer + TSL 全程序化——半球「钟体」网格做正弦收缩模拟脉动，触手是 GPU 驱动的 verlet 链，半透明组织、假体积光照与假焦散（基于 Dave Hoskins 的 Shadertoy）全部实时算出；被 WWDC25 Session 236 选作 Safari WebGPU 的演示案例 |
| 课程关联 | 正弦收缩脉动 → 第 11 课（GLSL 数学：用正弦驱动形变）；全程序化组织 → 第 12 课（噪声）；假体积光照与假焦散 → 第 16 课（RayMarching 的思想）；verlet 链触手 → 第 18 课（物理模拟）；虹彩（IOR 与菲涅尔）→ 第 13 课（高级 Shader） |

观察要点

- 看钟体的收缩节奏：两次收缩之间的间隔与幅度在缓慢变化， procedural 动画的高级感来自「不完美」
- 触手跟随钟体的延迟：这是 verlet 链的物理延迟，不是动画曲线
- 光从侧面掠过时的虹彩：IOR 与菲涅尔怎么在 TSL 里组织（读源码，仓库开放）
- 在 Safari 26+ 里打开：同一份 TSL 编译到不同后端的效果

## Samsy

| 项目 | 内容 |
|------|------|
| URL | https://samsy.ninja/ （实验场：http://lab.samsy.ninja/） |
| 一句话气质 | 创意开发者 Samuel Honigstein 的名片——一片可以开车穿行的霓虹城市，帧率稳得像主机游戏 |
| 技术拆解 | 据公开访谈与社区拆解（webgpu.com）：赛博朋克城市世界以 WebGPU 渲染，社区实测 120+ FPS；交互层由 Vue 编排，动画走 GSAP，渲染层是自定义 WebGPU 管线；作者此前在 Google Creative Lab |
| 课程关联 | 大场景的帧率控制（LOD、雾、距离衰减）→ 第 20 课（性能调优）；GSAP 动画编排 → 第 17 课（滚动驱动）；渲染层与 UI 层（Vue）的分工 → 第 19 课（网站架构） |

观察要点

- 开车穿行时开着性能面板：注意帧率曲线，全城霓虹与实时反射下的开销控制
- 看远处的楼：LOD / 雾 / 距离衰减怎么把细节预算花在刀刃上
- UI 与 3D 的交互（菜单、导航）：Vue 层和渲染层怎么分工
- lab 子站里翻小实验：单个效果的 isolated 版本最适合学习

## IVRESS「SPIN A TALE」

| 项目 | 内容 |
|------|------|
| URL | https://brand.ivress.co.jp/ |
| 一句话气质 | 一部「拒绝光的世界」的浏览器短片：小旅人走向地平线，你负责陪他走完 |
| 技术拆解 | 日本公司 Utsubo 为自家品牌 IVRESS 制作，awwwards SOTD（2026-06）。据 webgpu.com 专访：three.js WebGPURenderer + WebGL 自动回退，Node Materials 承担质感，TSL 着色器一次编写、双后端编译，代码库不分叉；据同文，其 CTO 同时参与维护 three.js 的 WebGPU 侧 |
| 课程关联 | 低光环境下的材质与雾 → 第 3-4 课（材质、灯光）与第 13 课（高级 Shader）；叙事节奏与滚动 → 第 17 课（滚动驱动）；「一次编写、双后端、代码库不分叉」的兼容性思路 → 第 19 课（架构分层与回退策略）与第 20 课（部署兼容性） |

观察要点

- 在不支持 WebGPU 的浏览器（或强制 WebGL）里再开一次：同一个站两种后端，你能找出差别吗
- 全片的「光」都很少：低光环境下材质与雾怎么撑住画面——克制的教材
- 旅人的行走节奏与滚动/时间的关系：动画的「预算感」而非「堆料感」
- 转场：场景切换时的过渡是渲染层面的，不是 DOM 层面的

## awwwards 检索建议

上面的八站是课程的锚点，结营之后要自己找食。awwwards 是主矿脉，用法比「随手刷」重要：

- 分类页 https://www.awwwards.com/websites/webgl/ ——WebGL/WebGPU 类目的最新获奖站，每周扫一次就够
- 搜索框直接搜 `webgpu` 或 `three.js`——WebGPU 站点 2025 年起集中出现，搜索比分类更准
- 每个站点页看两处：**Technologies & Tools**（技术栈标签，判断是 three.js 系还是裸 WebGL/WebGPU 系）与 **Elements**（单点交互的短视频拆解，比如 iyO 的「Chladni Patterns WebGL Haiku」就是独立条目）
- 有 **DEV AWARD** 标记的站优先看——评的是代码质量，不是只有视觉
- 配合两处补充：FWA（https://thefwa.com/，与 awwwards 收录互补）与 Codrops 文章（https://tympanus.net/codrops/，一线作者的第一手技术复盘，本清单里 haoqi.design 的拆解就来自这里）

判断一个站值不值得拆的标准：关掉它你还记得哪个画面。记得住的，就去把那个画面的技术路径拆出来——这正是第 17-19 课与结营复刻要练的事。
