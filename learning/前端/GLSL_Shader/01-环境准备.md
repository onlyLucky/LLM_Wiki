# 01 环境准备

本课的环境焦虑比 webgpu 课小得多：WebGL2 从 2017 年起就在全平台铺开，2026 年的任何一台开发机都不需要为它做特殊设置。开课前的十分钟用来确认工程能跑起来、GPU 加速没被关掉，之后三天就不会被工具问题打断。

## 浏览器支持现状

| 浏览器 | 状态 | 备注 |
|--------|------|------|
| Chrome / Edge | 56+ 全平台 | 2017 年起默认开启，Windows 走 D3D11+，macOS 走 Metal |
| Firefox | 51+ | 2017 年起默认开启 |
| Safari | 15+ | macOS / iOS / iPadOS 15（2021）起默认开启 |
| 移动端 | iOS Safari 15+ / Android Chrome 全系 | 本课 demo 均为单屏画布，移动端可看可玩 |

WebGL2 已经是「不需要讨论兼容性」的基线技术：所有现代浏览器默认开启、无需 flag、无需 polyfill。与 webgpu 课不同，你不需要能力检测降级路径——`canvas.getContext('webgl2')` 拿不到上下文只剩一种可能：硬件加速被人为关闭。

课程在 macOS + Chrome 下开发验证。遇到画面异常，先换 Chrome 排查，确认不是浏览器因素再怀疑代码。

## 十分钟环境检查

### 第一步：确认 Node 版本，把工程跑起来

课程仓库是一个 Vite 工程，Vite 8 要求 Node.js 20.19+ 或 22.12+（与 Vite 7 相同的最低线）：

```bash
node -v            # v20.19+ 或 v22.12+，推荐 22 LTS
cd 前端/GLSL_Shader
npm install
npm run dev        # http://localhost:5174/
```

端口固定为 5174（webgpu 课占用了 5173），两个课程工程可以同时开着跑。

### 第二步：打开第一个 demo

浏览器访问 <http://localhost:5174/> 进入门户页，点开 Day 1 的「渐变三角形」。看到四样东西即环境就绪：

- 深色画布上一枚玫红到天青的渐变三角形，随时间轻微呼吸
- 左上角 `DAY 1 · 01 — GRADIENT TRIANGLE` 角标，右下角实时 FPS 与分辨率
- 移动鼠标时三角形偏移色相（`u_mouse` 已通电）
- 页面无错误面板弹出

### 第三步：控制台跑一遍能力检测

在 demo 页的控制台里贴这段（与课程 `shared/chrome.ts` 的 initGL 判空同思路，这段多查一层驱动型号，方便报障时贴截图）：

```ts
const c = document.createElement('canvas');
const gl = c.getContext('webgl2');
if (!gl) {
  console.log('WebGL2 不可用：检查浏览器版本与硬件加速设置');
} else {
  const dbg = gl.getExtension('WEBGL_debug_renderer_info');
  const gpu = dbg ? gl.getParameter(dbg.UNMASKED_RENDERER_WEBGL) : '未知 GPU';
  console.log(`OK · WebGL2 · ${gpu}`);
}
```

输出 `OK · WebGL2 · ...` 即可开工。GPU 型号只用于让你心里有数——本课所有 demo 在 M 系列芯片的集显上都能满帧。

## 工程环境

依赖与脚本一览，全部已配置完毕，无需改动：

| 项 | 版本 | 说明 |
|----|------|------|
| vite | 8.3.0 | 开发服务器 + 多页面入口，端口 5174 |
| typescript | 7.0.2 | `npm run typecheck` 随时校验全部 demo / 作业 / 答案 |
| three | 0.186.0 | Day 3 主角；包内不自带类型，类型来自下一条 |
| @types/three | ^0.186.0 | three 的类型包，与 three 版本对齐；缺失会报 TS7016 |
| lenis | 1.1.13 | Day 3 滚动平滑（讲义 3.3） |
| gsap | 3.12.5 | Day 3 转场编排备选（讲义 3.3） |

```bash
npm run dev        # 开发服务器
npm run typecheck  # TS 类型检查（讲义代码有改动时可随时校验）
npm run build      # tsc --noEmit + vite build
```

着色器独立为 `.glsl` 文件、以 `?raw` 导入（`import fsSource from './shaders/fragment.glsl?raw'`），改动即触发 Vite 热更新——编辑体验与改 TS 无差别。想加语法高亮可装 VS Code 扩展 `vscode-glsl-linter`，可选；Vite 热更新加页面错误面板已经够用。

## 常见环境问题对照

| 症状 | 原因 | 处理 |
|------|------|------|
| 画布黑屏但无报错 | 硬件加速被禁用 / 虚拟机 GPU 白名单 | `chrome://settings/system` 开启图形加速后重启；虚拟机换实体机 |
| 错误面板出现 GLSL 编译错误 | 着色器语法问题——这不是环境问题，是课程的第一教学设施 | 看面板里的行号；对照讲义 1.3 的报错文化段与 1.4 的最小闭环 |
| 编译错误提到 `#version` | `#version 300 es` 必须是文件第一行 | 检查是否被空行、注释或 BOM 顶下去 |
| TS 报 TS7016（three 模块无类型） | `@types/three` 缺失或版本不对齐 | `npm i -D @types/three@0.186.0`，与 three 版本保持一致 |
| FPS 读数持续低于 30 | DPR 过高或片元过贵 | chrome 已把 DPR 限制在 2 以内；先降分辨率再查 shader，对照各 demo README 的性能红线 |
| `npm run dev` 端口变了 | 5174 被其他工程占用 | Vite 自动换端口，以终端输出为准；不影响任何功能 |

环境就绪后，从门户页进入 Day 1 的第一个 demo，同时打开讲义 `1.1-为什么前端要学GLSL.md`，正式开始。
