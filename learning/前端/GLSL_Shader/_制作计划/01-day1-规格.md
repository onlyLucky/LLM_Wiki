## 讲义 1.2 GLSL 语法基础（一）：类型与变量

```markdown
# 1.2 类型与变量：GLSL 的世界观是「向量优先」

> Day 1 · 模块 2 · 约 50 分钟
> 理论对照：《WebGPU 三天实战课程》1.4「WGSL 语言核心」——类型系统对照着看，事半功倍
```

**章节大纲**：
- 导语：上一模块你跑通了第一个页面，但 fragment.glsl 里那些 `vec3`、`precision` 还像外语；这个模块和下个模块把语言一次学扎实，之后写 shader 只剩创意问题
- `## 标量：只有四种`：`float` / `int` / `uint` / `bool`；**没有 string，没有 null，没有 undefined**——GPU 每个周期都在做算术，语言里就不该有别的
- `## 向量是主角：vec2 / vec3 / vec4`：声明与构造的六种姿势代码段（`vec3(1.0)`、`vec3(1.0, 0.0, 0.5)`、`vec3(uv, 1.0)`、`vec4(color, alpha)`…）；向量就是「并排的数字」，位置、颜色、坐标全用它——**一个类型打通图形学全部概念**
- `## swizzle：向量分量的摩斯密码`：`.xyzw` / `.rgba` / `.stpq` 三套等价分量名；代码段：`color.rgb`、`uv.xy`、`pos.xz`；规则：可重复可乱序（`v.yx` 交换分量），**读是复制，写只能写未重复的**
- `## 矩阵：mat2–mat4`：本课 99% 场景只用手写 mat2（2D 旋转）与 Three.js 传入的 mat4；构造代码段：`mat2 rot = mat2(c, -s, s, c);`；列主序提醒一句话（详细推导在 webgpu 2.1）
- `## 精度限定符：highp 的执念`：为什么片元着色器必须写 `precision highp float;`；medip/lowp 什么时候用（移动端性能、后处理中间值）；「precision 是你跟 GPU 签的性能条款」
- `## 与 TypeScript 对照表`（表格，10 行）：`number → float`、`[x,y] → vec2`、`{r,g,b} → vec3`、模板字面量无对应、可选参数无对应（函数必须重载声明）、`as` 断言无对应（类型转换全部显式函数）……
- `## 常量与作用域`：`const float PI = 3.14159265;`；块级作用域与 JS 一致；**没有 var/let 之分**，声明即定
- `## How：在 demo 01 里找出今天学的每个语法点`：给出 fragment.glsl 全文，逐行标注类型/精度/构造——「这 31 行里没有一行是陌生的了」
- `## 常见坑`（表格）：`1` 与 `1.0` 不是一回事（int/float 不隐式转换，`float x = 1;` 编译报错）/ swizzle 写入重复分量报错 / 忘写 precision highp / `vec3(0, 0, 0)` 传 int 报错
- `## Checkpoint`：能徒手写出六种 vec 构造；能解释 swizzle 读与写的差异；能说出为什么必须有 precision 声明

## 讲义 1.3 GLSL 语法基础（二）：表达式与结构

```markdown
# 1.3 表达式与结构：控制流、函数与预处理

> Day 1 · 模块 3 · 约 50 分钟
> 理论对照：《WebGPU 三天实战课程》1.4「WGSL 语言核心」——分支/循环的 SPVC 编译逻辑同源
```

**章节大纲**：
- 导语：类型是词汇，这一讲是语法——把词汇组成「句子」。最后你会得到一页可裁下来的 GLSL 速查表
- `## 运算符与分量级运算`：`+ - * /` 对向量逐分量进行（`vec * scalar` 每个分量都乘、`vec * vec` 对应分量相乘——**不是点乘！**）；点乘 `dot()` 叉乘 `cross()` 是函数不是运算符；`length()` / `normalize()` / `distance()`
- `## 控制流：if 与 for，没有 while 的位置`：if/else 与 JS 相同；for 循环**循环次数必须在编译期可确定**（GPU 要展开或预留寄存器）；while/do-while 部分驱动支持，课程内禁用；分支发散的代价一段（同一批线程走不同分支＝两边都执行）——引用 webgpu 1.1 的 SIMT 深讲
- `## 函数：值传递的世界`：声明/定义/调用代码段；**没有闭包、没有 this、没有递归保证**；参数限定符表（`in` 拷入 / `out` 拷出 / `inout` 双向）——「out 参数就是 JS 里 return 多个值的官方姿势」；函数必须先声明后用（或文件顶部给原型）
- `## struct：给数据一个名字`：定义与成员访问代码段；uniform 打包成 struct 是 Three.js 内置风格，先在这里学会读
- `## 数组：定长，别想着 push`：`float arr[5];` 声明即定长；初始化列表；**没有 length 属性、没有方法**；循环索引必须是编译期可展开或 uniform 驱动
- `## 预处理器：#define 才是常量的正牌写法`：`#define PI 3.14159` vs `const`（前者编译期文本替换、无类型检查，后者有类型——**课程约定：数字用 const，宏开关用 #define**）；`#ifdef` 条件编译在跨端降级时的用法
- `## 一页速查表`（表格：GLSL vs TypeScript 全对照，含本讲全部语法点——这是学员未来贴在显示器旁的那一页）
- `## How：把 demo 01 的 fragment 改造成函数化版本`：重构成 `vec3 gradient(vec2 uv)` + `void main()` 的结构，行数对账——「31 行变 38 行，换来的是每个函数都能单独复用到明天」
- `## 常见坑`（表格）：if 里给未初始化变量赋值再在外面用（某些驱动下 undefined）/ 循环边界用 varying（必须 uniform 或常量）/ out 参数忘传已声明变量 / `#version` 前有空行（最常见的编译错误，报错行号还是 1）
- `## Checkpoint`：能用 out 参数写出返回两值的函数；能解释为什么禁用 while；能说出 const 与 #define 的取舍

```markdown
# 1.4 原生 WebGL2 最小闭环：从 canvas 到渐变三角形

> Day 1 · 模块 4 · 约 60 分钟
> 理论对照：《WebGPU 三天实战课程》1.2「对象模型与初始化」+ 1.3「渲染管线全解」——对象名不同，生命周期哲学同构
```

**章节大纲**：
- 导语：webgpu 课你写过 device→pipeline→pass 的仪式代码；WebGL2 的仪式是另一套「编译–链接」，多了一个你在 WebGPU 里没见过的东西：**着色器编译错误**——它将成为你整个学习期最常打的交道，所以本篇把「读报错」当正式教学内容
- `## 五个对象，一条流水账`：canvas → `getContext('webgl2')` → `createShader` ×2（编译）→ `createProgram`（链接）→ VAO/VBO（顶点数据）→ `drawArrays`；配一张对象关系 ASCII 图；对照表：WebGPU 的 device/renderPass ↔ WebGL2 的 context/draw call（「WebGPU 是录制-提交，WebGL2 是直接调用」）
- `## 编译与链接：GLSL 的 tsc`：`gl.shaderSource` → `gl.compileShader` → `gl.getShaderInfoLog` 检查；`gl.linkProgram` → `gl.getProgramInfoLog`；错误日志长什么样、行号怎么读（**报错行号是 shader 源文件内行号**，与 main.ts 无关）；chrome.createProgram 已封装，但手写一遍才能记住
- `## VAO 与 VBO：顶点数据的行李箱`：`createVertexArray`（布局描述）+ `createBuffer`（数据本体）；`vertexAttribPointer` 的 stride/offset——与 webgpu 1.5 的 bufferLayout 对照表
- `## attribute 与 location：顶点输入的地址`：`layout(location=0) in vec2 a_position;`；JS 侧 `getAttribLocation`；为什么课程固定手写 `location=0`（省一次查询，且示教更清晰）
- `## drawArrays：go 按钮`：TRIANGLES / TRIANGLE_STRIP / LINES / POINTS 四种图元表；本课 demo 全部用 TRIANGLES 与 TRIANGLE_STRIP
- `## How：demo 01 的 main.ts 逐段精讲`：六段代码段全部贴出并逐段拆解（chrome / GL / program / 几何 / uniforms / loop），每段标注「这段在 webgpu 课里对应谁」

## 讲义 1.5 数据流与全屏四边形

```markdown
# 1.5 数据流与全屏四边形：varying 插值与 UV 坐标系

> Day 1 · 模块 5 · 约 55 分钟
> 理论对照：《WebGPU 三天实战课程》1.5「顶点缓冲与几何数据」——插值语义完全同构，本篇补 GLSL 侧的 in/out 语法与 UV 工程约定
```

**章节大纲**：
- 导语：你有没有想过——三角形只有三个顶点、三种颜色，中间那些像素的渐变是谁算的？答案是光栅化阶段的免费服务：插值。理解它，你就理解了 varying；理解 varying，你就拿到了 fragment shader 最重要的输入：UV
- `## attribute → varying → fragment：一条数据的两次交接`：代码段（vertex 的 `out vec2 v_uv;` ↔ fragment 的 `in vec2 v_uv;`，名字必须一致）；「uniform 是广播，varying 是插值」——传给所有像素同一个值 vs 传三个顶点值让硬件插
- `## 插值是线性的，屏幕上的世界是非线性的`：透视校正插值一句话点到（w 分量加权，推导在 webgpu 2.2）；本课 2D 全屏四边形不受影响，但要知道边界
- `## UV：像素的身份证`：三种坐标域对照表——gl_FragCoord（像素，左下原点）/ UV（0–1 归一化）/ 居中 NDC（-1–1）；代码段：`vec2 uv = gl_FragCoord.xy / u_resolution;` 与 `vec2 p = uv * 2.0 - 1.0;`；**宽高比陷阱**：`uv.x` 在宽屏被拉伸，等比公式 `p.x *= u_aspect`
- `## 全屏四边形：创意网站的地基`：为什么 fragment 效果都画在一个大四边形上（两个三角形覆盖全屏，之后一切在片元着色器里算）；两种画法代码段：TRIANGLES × 6 顶点 / TRIANGLE_STRIP × 4 顶点（**课程约定用后者**，少两个顶点且好读）；顶点直接写 clip space（-1..1），省掉矩阵
- `## How：demo 02「全屏四边形与UV」逐段精讲`：fragment 里画「UV 调色板」（R 通道 = uv.x，G 通道 = uv.y）+ 十字参考线 + 鼠标位置坐标显示——它是你未来调试任何 shader 的第一块仪表盘
- `## 常见坑`（表格）：uv 拉伸忘乘 aspect / varying 名字两边不一致（链接失败：unresolved symbol）/ 用 uv 做 SDF 半径忘了它不是正方形域 / gl_FragCoord 原点在左下而鼠标事件在左上（y 要翻转）
- `## Checkpoint`：能画出 attribute→varying→fragment 的数据流图；能写出等比居中坐标；能解释全屏四边形为什么不需要 MVP 矩阵

## 讲义 1.6 时间与动画

```markdown
# 1.6 时间与动画：让画面活过来

> Day 1 · 模块 6 · 约 50 分钟
> 理论对照：《WebGPU 三天实战课程》1.6「Uniform 与绑定组」——uniform 概念同源；本篇专注「时间」这一个 uniform 的全部工程学
```

**章节大纲**：
- 导语：到目前为止你的画面是静态的。给它加上一个 float，一切开始流动——这个 float 叫 u_time，是创意网站「活着的」全部秘密
- `## 动画三要素：清屏、状态、时间`：GPU 是健忘的（每帧重画一切）；所以 shader 动画的正确心智模型是「**纯函数 f(time) → 画面**」——不是 CSS 那种「改属性」，而是「时间决定画面」；与 rAF 的关系（`chrome.startLoop` 已包好）；为什么这个模型天然可逆、可暂停、可录屏
- `## u_time 的单位与精度`：秒（不是毫秒）；`sin(u_time * 0.8)` 的频率直觉（0.8 ≈ 8 秒一个完整呼吸周期）；**精度红线**：u_time 超过几分钟后 highp float 开始抖（IEEE 754 尾数位数耗尽），讲义给出 `u_time = time % 3600.0` 的工程处理
- `## 循环动画三件套：sin / fract / 模长`：代码段 ×3——`sin` 呼吸（-1..1 映射到 0..1：`0.5 + 0.5 * sin(t)`）、`fract` 锯齿往复（`abs(fract(t) * 2.0 - 1.0)` 三角波）、`mod` 相位错峰（多元素动画各错 `i * 0.25` 的层次感）
- `## 相位与频率：让动画有编排`：多个元素不同频率与相位 → 「层次延迟」表格（主元素周期 3s、次级 4.5s、背景 6s——awwwards 动效的默认节奏表）
- `## GLSL 缓动函数：easing 的 shader 写法`：为什么 CSS easing 搬不进来（时间不是 DOM 事件）；四个标准实现代码段（`easeInOutCubic`、`easeOutQuint`、`easeOutElastic`、`easeOutBack`），配曲线图；`smoothstep` 本身就是内置 easeInOut 的表亲
- `## How：demo 03「时间的画面」逐段精讲`：四格动画并列（呼吸圆 / 三角波条 / 弹性方块 / 缓动进度条），一个 fragment 文件里四个函数各占一格——「这是你自己的 easing 速查可视化」
- `## 常见坑`（表格）：毫秒当秒传（动画快 1000 倍）/ 忘映射 sin 的负值（画面半黑）/ 用 dt 而不是绝对时间做循环（帧率改变节奏、且 shader 无状态）/ elastic 用在背景大元素上（眩晕，easing 也要看场合）
- `## Checkpoint`：能写出呼吸动画完整三行；能解释纯函数动画模型与 CSS 动画的心智差异；能背出「主 3s / 次 4.5s / 背景 6s」节奏表
- `## 相关材料`

**SVG**：`animation-easing.svg`（四条缓动曲线并列对比）

**章节大纲**：
- 导语：同一个 shader，鼠标跟不跟随、跟得顺不顺滑，是 demo 级与 awwwards 级的分水岭。这一讲把浏览器事件翻译成 uniform 的完整工程讲透——从此交互对你是一个「模式」而不是「技巧」
- `## 事件桥：浏览器世界与 GPU 世界的翻译官`：核心图（interaction-event-bridge.svg）——事件（pointermove/down/up、wheel、click、touch）→ JS 状态对象（chrome.pointer，课程已内置）→ 每帧写 uniform → shader 响应；**为什么不在事件回调里直接 draw**（事件频率 ≠ 帧率，且 GPU 侧无事件概念）；「事件更新状态，帧循环消费状态」——这句话是整个模式的全部
- `## 五类输入的 uniform 方案表`（表格，每行：事件 / JS 状态 / uniform 形态 / 典型效果）：
  - pointermove → 平滑坐标 `vec2 u_mouse`（0–1 或居中域）→ 视差、光晕跟随
  - pointerdown/up → `float u_isDown` → 按压涟漪、吸附
  - 拖动（down+move 组合）→ 位移增量 `vec2 u_drag` → 扭曲、惯性
  - wheel → 归一化累积 `float u_scroll`（Day1 用「缩放」语义，Day3 换「页面进度」语义）→ 缩放、推进
  - click → `float u_clickTime`（触发时刻）→ 扩散波
- `## lerp 平滑：顺滑感的全部秘密`：`smooth += (raw - smooth) * 0.08` 逐参数拆解（0.08 ≈ 60fps 下 0.5s 收敛，系数表：0.04 慢丝滑 / 0.08 默认 / 0.15 跟手）；「CSS transition 之于直接赋值，lerp 之于事件桥」；代码段：chrome.pointer 的 sx/sy 实现（已内置，学员读懂即可）
- `## 坐标域的换算：一次讲清不再糊涂`：鼠标 clientXY（左上原点、CSS 像素）→ 除以画布尺寸得 0–1 → 可再转居中域；y 轴翻转（DOM 向下、GL 向上）代码段 `1.0 - uv.y`；宽高比再次出镜
- `## 点击涟漪：一个 uniform 的完整动画`：`u_clickTime` + `u_time` 推算 elapsed → `sin(elapsed * PI / DURATION)` 一次性衰减波；代码段完整给出（这将是作业 challenge 的核心考点之一）
- `## 触摸：pointer events 一把抓`：`pointermove` 在移动端即 touch；`touch-action: none` 的 CSS 前置；双指缩放留到 Day 3 不展开
- `## How：demo 04「光标的追随」+ demo 05「点击的涟漪」+ demo 06「滚轮的浪潮」三连精讲`：三个 demo 共享同一事件桥模式，只是 uniform 语义不同——逐个过 fragment 里的响应段
- `## 常见坑`（表格）：事件回调里直接渲染（拖一帧画一帧，掉帧根源）/ 鼠标坐标没除画布尺寸（值域错乱）/ 忘 y 翻转（光标在画面里反着走）/ lerp 系数每帧不固定（帧率敏感：应按 dt 换算，课程简化为固定系数并注明）/ 移动端没设 touch-action: none（页面滚动抢占事件）
- `## Checkpoint`：能默画事件桥五环节；能写出带 y 翻转的鼠标归一化代码；能解释为什么不在事件回调里 draw；能背 lerp 三档系数
