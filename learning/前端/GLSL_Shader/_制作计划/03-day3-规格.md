## 讲义 3.1 ShaderMaterial：从原生到 Three.js 的迁移

```markdown
# 3.1 ShaderMaterial：把两天的 shader 装进工程框架

> Day 3 · 模块 1 · 约 55 分钟
> 理论对照：《Threejs创意3D》课程笔记中「材质系统」相关课次（执行时先 ls 目录按标题匹配）；《WebGPU 三天实战课程》3.1「WebGPURenderer 架构与迁移策略」——同一件事在两代渲染器上的做法
```

**章节大纲**：
- 导语：手写 WebGL2 你已经能打 90 分，但真实项目没有人为你维护 200 行脚手架——Three.js 就是那层「工业化的 chrome.ts」。好消息：两天的 GLSL 一行不用重学
- `## 为什么迁移：Three.js 帮你写掉的 150 行`：对照表（renderer / scene / camera / 几何 / uniform 上传 / draw 循环 ↔ 你 Day 1 手写的每一段）——「你昨天写的脚手架就是 Three.js 的源代码级缩微版」
- `## ShaderMaterial 最小闭环`：完整代码段（`new THREE.ShaderMaterial({ vertexShader, fragmentShader, uniforms })` + PlaneGeometry + Scene/Camera 三件套）；GLSL 里**必须**写的两个矩阵乘法 `gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0)`
- `## 内置注入：你免费拿到的 uniform 和 attribute`：表格——`projectionMatrix / modelViewMatrix / normalMatrix / cameraPosition`（uniform）与 `position / normal / uv`（attribute）；**v_uv 还是要自己 varying 一遍**（最常见的第一次迁移失败点）；svg：threejs-uniform-mapping（注入清单图形化）；RawShaderMaterial 与 ShaderMaterial 的分界（前者全手写、后者送内置——课程约定：用 ShaderMaterial）
- `## uniform 的 TS 侧管理`：`uniforms: { u_time: { value: 0 } }` 声明 + 帧循环 `material.uniforms.u_time.value = t`；与原生 `uniform1f` 对照表；`u_mouse` 迁移时**别忘了 DPR 与 y 翻转**（Day 1 讲义 1.7 的老朋友再现）
- `## 什么时候根本不该迁移`：纯 fragment 全屏效果（Day 2 的丝绸背景）原生 WebGL2 更轻——「没有 3D 物体就没有 Three.js 的理由」；一段工程判断（效果类型 → 技术选型表：全屏背景→原生 / 混合 DOM 与 3D→Three.js / 需要生态（加载器/后期/R3F）→Three.js）
- `## How：demo 01「ShaderMaterial初见」逐段精讲**：把 Day 2 的 SDF 徽章搬进 ShaderMaterial，前后代码并排（原生 87 行 vs Three.js 34 行的行数对账）
- `## 常见坑`（表格）：忘写 projectionMatrix 乘法（全屏黑）/ varying 名不一致（链接错误老朋友）/ uv 用了但没 varying（读到 0）/ `#version 300 es` 与 three 默认前缀冲突（three 自动注入版本声明——**你的 glsl 文件不要再写 #version**；课程 glsl 文件约定此处特例：ShaderMaterial 版本的着色器不写 `#version`、用 `varying`/`attribute`（three 会转译）……**注意**：这里存在两种写法争议，课程统一采用「three 默认 GLSL1 风格 + 自动升级」路线，讲义需用一小节讲清这个坑）
- `## Checkpoint`：能背内置注入表；能徒手写出 ShaderMaterial 五件套；能说出三种效果类型的选型结论
- `## 相关材料`

## 讲义 3.2 图片失真与鼠标视差：awwwards hero 图卡标配

```markdown
# 3.2 图片失真与鼠标视差：每一张获奖站图卡的下沉手法

> Day 3 · 模块 2 · 约 60 分钟
> 理论对照：Day 2 讲义 2.7「纹理」——采样与失真的 GLSL 基础全在那一讲；本篇是它的工程完整版
```

**章节大纲**：
- 导语：CyD 的作品卡片、Orage 的网格视频格——鼠标滑过，图片像液体一样让开。拆开看只有三件事：纹理、视差、失真量。今天全部接通
- `## TextureLoader：Three.js 的一行上传`：`new THREE.TextureLoader().load(url)` vs 原生五步；CORS 一句话（本地 public/ 目录图片无此问题）
- `## 位移图思路：把 Day 2 噪声接到 UV 上`：`uv + flow * warp`；`flow` 从哪来——三种方案表：程序化噪声（fbm）/ 数据纹理（G 通道存方向）/ 鼠标局部场（`u_mouse` 距离衰减）；**hover 语义**：`u_hover` 0→1 的 lerp 渐进（1.7 的 lerp 在 three 侧的对应写法）
- `## RGB shift：色差三行的生意`：讲义 2.7 的三行直接迁移 + 参数联动（hover 越强 shift 越大）——「失真是一种强调」
- `## 视差层：三层速度差`：前景图 5% / 标题反方向 3% / 背景 2%（Day 2 challenge 的参数表复用）；**parallax 的正确实现**：目标位置 lerp 而不是直接偏移（又是 lerp）
- `## DPR 与纹理尺寸`：`renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`；纹理 anisotropy 一行（斜视角清晰度）
- `## How：demo 02「hover失真图卡」逐段精讲**：一张 4:5 图卡完整实现——hover 时 fbm 波纹从光标扩散、RGB shift、边缘微光；离开时缓动回零
- `## 常见坑`（表格）：hover 状态直接 0/1 切换（生硬——必须 lerp）/ 失真量不乘 hover 强度（常驻失真像坏屏）/ 图卡 aspect 与 PlaneGeometry aspect 不一致（拉伸）/ 纹理没 `flipY` 处理（three 默认翻转，与原生相反）
- `## Checkpoint`：能写出「噪声→UV 偏移→采样」三行链路；能说出视差三层参数表；能解释 hover 为什么要 lerp

## 讲义 3.3 滚动驱动：u_scroll、Lenis 与转场遮罩

```markdown
# 3.3 滚动驱动 shader：把叙事交给滚轮

> Day 3 · 模块 3 · 约 60 分钟
> 理论对照：《Threejs创意3D》课程笔记中「滚动与相机控制」相关课次——Lenis/GSAP 的系统性用法在那里；本课只讲「滚动进度如何变成 uniform」这一段桥
```

**章节大纲**：
- 导语：2026 年的 awwwards 年度报告把「scroll-driven storytelling」列为第一大趋势——Cartier 六个房间、Shopify Editions 的产品揭示全靠它。技术核心一句话：**把页面滚动进度归一化成 0–1 的 float，喂给 shader**
- `## u_scroll：一个 float 的叙事学`：`scrollY / (docHeight - viewportHeight)` 归一化；分段进度表（0–0.3 hero / 0.3–0.7 转场 / 0.7–1 定格）——「剪辑思维」；shader 侧 `smoothstep(u_s1, u_s2, u_scroll)` 做区间动画
- `## Lenis：平滑滚动的标准件`：为什么原生滚动会抖（滚动事件离散 + shader 每帧渲染）；`new Lenis({ lerp: 0.1 })` + rAF 集成五行；**与 1.7 lerp 的同构性**（滚动界的手感 = 鼠标界的手感）
- `## GSAP timeline：编排 uniform 的一生`：`gsap.to(material.uniforms.u_progress, { value: 1, duration: 1.2, ease: 'power2.inOut' })`——把 1.6 的 GLSL 缓动交给 JS 侧编排的取舍表（连续滚动→shader 内算；离散场景切换→GSAP timeline）
- `## 转场遮罩：两页之间的一片噪声`：`step(noise, u_progress)` 的揭幕式转场（Day 2 噪声 + Day 3 进度的合体）；平滑版 `smoothstep` 带噪声边缘；「遮罩转场 = 用噪声当 mask，progress 当阈值」
- `## 性能：滚动渲染的帧预算`：滚动中主线程忙于布局，shader 帧预算更紧——「滚动场景优先降 octave、defer 非关键 pass」
- `## How：以作业 challenge「滚动驱动的英雄时刻」为蓝本的前置 demo 精讲**：三段式（0–0.3 粒子聚集 / 0.3–0.7 噪声揭幕转场 / 0.7–1 文字聚合）的时间轴逐段拆——**本讲不配独立 demo，其实现直接进 homework challenge 与 solution**（solution 将成为可对照的完整工程参考）
- `## 常见坑`（表格）：scroll 事件里直接渲染（又是那个错误）/ 忘 Lenis 的 `requestAnimationFrame` 接线（完全不滚动）/ 转场阈值穿到 1.0 之外（clamp）/ GSAP 与帧循环双重驱动同一 uniform（打架，选一个主人）
- `## Checkpoint`：能写出归一化 scroll 一行；能配置 Lenis 五行；能背「连续滚动 shader 内算、离散切换 GSAP」的取舍

## 讲义 3.4 粒子：Points、gl_PointSize 与噪声粒子场

```markdown
# 3.4 粒子场：Day 2 噪声的 3D 化身

> Day 3 · 模块 4 · 约 55 分钟
> 理论对照：《WebGPU 三天实战课程》3.3「TSL Compute Particles」——GPGPU 路线的粒子（计算着色器驱动）；本课讲 GLSL 顶点着色器路线（无状态、更简单，中小规模首选）
```

**章节大纲**：
- 导语：iyO 首页的文字由粒子聚合而成、igloo 的 footer 是一整片星尘。两条实现路线：GPU 计算状态（webgpu 课已见过）或**顶点着色器即时计算**（本课）——后者不需要 ping-pong，一万个粒子轻松跑
- `## Points：一个几何类型，两种着色器分工`：`THREE.Points` + BufferGeometry（position attribute 存「出生位置」）；顶点着色器里**即时计算位移**——`无状态动画`模型复习（1.6 的纯函数哲学在 3D 粒子上的完全体）
- `## gl_PointSize：粒子的体积感`：顶点着色器输出 `gl_PointSize`；透视衰减公式（`size * (300.0 / -mvPosition.z)`）；`gl_PointCoord`（片元内 0–1 坐标）画圆点（`length(gl_PointCoord - 0.5)` 裁圆）
- `## 噪声位移：把 fbm 接到 xyz`：`pos + curl 噪声 * amplitude`；简化版：三维 fbm 太贵，用两路 2D 噪声组合（课程工程取舍示范）；时间让场「呼吸」——「粒子场就是三维的丝绸（2.4）」
- `## 交互：粒子避让鼠标`：鼠标世界坐标 → 距离衰减推力（`u_mouse` 射线投影一句话带过，链接 Threejs创意3D 相机课）
- `## 加法混合发光：particles + additive = 星系`：`blending: THREE.AdditiveBlending` + `depthWrite: false`——2.6 的 add 合成模式在三维的再现
- `## How：demo 03「粒子星云与bloom」逐段精讲**：两万粒子星云（噪声驱动 + 鼠标扰动）+ 后期 bloom——「Day 2 全部知识的 3D 汇报演出」
- `## 常见坑`（表格）：`gl_PointSize` 忘透视衰减（远近一样大，假）/ 粒子方形（忘裁 `gl_PointCoord`）/ additive 后忘关 depthWrite（黑框）/ 噪声每帧算 fbm 五倍频 × 两万粒子（帧率崩——顶点噪声降 octave 到 2–3）
- `## Checkpoint`：能说出两条粒子路线的分界与规模；能写 gl_PointSize 透视行；能解释为什么粒子动画可以无状态
- `## 相关材料`

## Day 3 技术细节备忘（生成代码时的硬约束）

1. **three 版本**：`three@0.186.0`；addons 导入用 `three/addons/...`（如 `three/addons/postprocessing/EffectComposer.js`）；package.json 已含依赖，demo 里直接 import
2. **ShaderMaterial 内 GLSL 风格**：着色器源码**不写** `#version`（three 自动注入）；attribute 用 `position/uv/normal` 内置名；矩阵用内置注入；自定义仍守 `u_/v_` 前缀。讲义 3.1 必须包含「3.1 版 GLSL 风格差异」小节（原生 WebGL2 版本 vs three 版本的着色器写法对照表）
3. **Lenis**：`import Lenis from 'lenis'`（包名 `lenis`，非旧 `@studio-freight/lenis`）
4. **GSAP**：`import { gsap } from 'gsap'`；只用 core（不引插件）
5. **图片资源**：demo/作业需要图片时放各自目录 `public/` 子文件夹（或直接引 `demos/day3/02-hover失真图卡/public/`）——用程序化 canvas 生成的占位图也可接受（生成代码用离屏 canvas 画渐变再 `CanvasTexture`），**不引用外部图床**
6. **raycaster 或 DOM 事件**：图卡 hover 统一用 DOM mouseenter/leave（简单、够用），讲义 3.2 提 raycaster 属于 Threejs创意3D 的领地
