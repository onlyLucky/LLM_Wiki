## 一、P0 · 运行时缺陷（8 页，全部 Day3）

### 1. demo 02 片元着色器编译失败
- 文件：`demos/day3/02-hover失真图卡/shaders/fragment.glsl`
- 现象：浏览器实测 `ERROR: 0:89: 'v_uv' : undeclared identifier`，画布只剩清屏色 + DOM 文案（截像素标准差 2.8，正常页 17–46）
- 根因：第 33 行 `vec2 uv = v_uv;` 使用了 varying，但片元侧没有声明（顶点侧 L2 有 `varying vec2 v_uv;`；同款结构的作业 A / 答案 A / 答案 B 片元都正确声明了）
- 修复：在 fragment.glsl 头部（如第 5 行 uniform 区前）补一行 `varying vec2 v_uv;`

### 2. demo 03 配方 ShaderPass 编译失败
- 文件：`demos/day3/03-粒子星云与bloom/main.ts`（L84–93 内联 fragmentShader）
- 现象：浏览器实测 `ERROR: 0:62: 'tDiffuse' : undeclared identifier`，整条后期链断在收尾配方上，画面平坦
- 根因：内联 fragment 声明了 `varying vec2 v_uv;` 与 `uniform float u_time;`，唯独漏了 `uniform sampler2D tDiffuse;`（L89 直接使用）
- 修复：L86 前补 `uniform sampler2D tDiffuse;`

### 3. Day3 全部 6 个作业/答案页模块级崩溃（整页空白）
- 文件：`homework/day3/{basic,advanced,challenge}` 与 `solutions/day3/{basic,advanced,challenge}` 的 main.ts
- 现象：`Cannot access 'renderer' before initialization`，页面整屏单一背景色（uniq=1，连 HUD 都未淡入——`startLoop` 从未执行）
- 根因（两层）：
  1. `createChrome({ onResize: syncSize })` 在 `let renderer` 声明之前调用。`shared/chrome.ts` L177 的 `applySize()` 同步回调 `onResize`，此时 `syncSize` 读取处于暂时性死区（TDZ）的 `renderer` → ReferenceError → 模块顶层崩溃，场景/渲染器/帧循环全部没有创建。六个文件的间距：hw basic L13→L43、hw adv L13→L64、hw ch L22→L154、sol basic L11→L37、sol adv L12→L63、sol ch L19→L147
  2. 连错误面板都没弹出来：`chrome.ts` L116 的 window error 监听调用 L125 `pointerChrome.fail(...)`，而 `pointerChrome` 在 L195 才声明，同处 TDZ——初始化期间抛错会把错误处理自身也炸掉
- 对照：三个 Day3 demo 恰好都是「先 `let renderer` 后 `createChrome`」（L20→L26、L68→L83、L49→L60），所以幸免
- 修复：六个文件把 `let renderer: THREE.WebGLRenderer | null = null;` 上移到 `createChrome` 之前（demo 的既有模式）；建议同步给 `chrome.ts` 的全局错误监听加保护（注册移到 `pointerChrome` 声明之后，或 `failInternal` 内先判空）

## 三、P1 · 讲义技术错误（已逐一实锤原文行号）

### 高危（照抄即错）
1. **2.3 L61–62**：`mix(vec3(0.02), vec3(0.9,0.75,0.35), blink * win)` 把原始 SDF 当 mix 系数——窗内 win 为负 → 亮窗渲染成黑块、微光出现在窗外，与 2.1 坑表第 1 行自相矛盾。应为 `win = 1.0 - smoothstep(0.0, fwidth(win), win)`。配套 demo 02（voronoi）无此问题，仅讲义示例错
2. **1.6 L192**：`p.x *= u_aspect * 0.5;` 多乘 0.5——格内居中域的等比修正因子就是 `u_aspect`，乘 0.5 后圆变 2:1 横向椭圆，与注释「圆才是圆」相反
3. **3.4 L61–64**：`pos` 先用后声明（n1/n2/n3 三行使用、L64 才 `vec3 pos = ...`），照讲义敲直接编译失败；demo 03 的 vertex.glsl 是正确顺序（先 `vec3 pos = position;` 再采样），讲义抄录出错，且漏了 demo 的 `- 0.5` 居中
4. **3.1 L154**：`import { fragmentShader } from './shaders/fragment.glsl?raw';`——Vite `?raw` 只有默认导出，命名导入是错的，与 `01-环境准备.md` L79 及全部 demo 实际写法矛盾

### 中危（择要）
- 1.2 L105/111：`mat2(c, -s, s, c)`（列主序实为顺时针）与紧随展示的 R(θ) 逆时针公式互为转置，坑表「旋转方向总是反的」恰是本条活体
- 1.2 L222：「`vec3(0, 0, 0)` 编译报错」为错误断言（构造器允许 int→float 转换），且与 1.5 L233「`vec2(1)` 恰好合法」直接矛盾；同篇 L226「`vec3(255,0,0)` 纯白亮瞎」实为纯红
- 1.1 L100/L225：「忘写 precision 多数驱动静默降 mediump / 编译成功但全黑」——ES 3.00 片元缺 float 精度是编译期错误（1.2 的表述才是对的），排查方向会带偏
- 1.7 L190–191：尾焰 `length(p - vel)` 把中心放在速度正方向，与注释「往反方向退」相反（应 `length(p + vel)`）
- 2.1 L198：2 行网格 y 偏移 `vec2(1.5, 0.5)` 应为 `vec2(2.0, 1.0)`，现值使陈列变成「半行/整行/半行」，上排被裁
- 2.2 L107：居中域 `vec2(uv.x * aspect, uv.y) * 2.0 - 1.0` 写法错误（原点偏移），正确为 `(uv.x * 2.0 - 1.0) * aspect`，与 2.1 L193–194 的正确写法自相矛盾
- 2.6 L46 与坑表：lightOffset 方向注释与正文自相矛盾（正确机制：采样坐标朝光源方向偏移）
- 3.1 L93/L188：「fragment 里直接写 uv，编译能过、画面读到 0」——实为 undeclared identifier 编译错误，与「varying 声明了但未赋值」两种坑混为一谈
- 3.1 L181：How 段对 demo 01 的描述失实（讲的是 `u_mouse` + DOM 监听，实际是 `u_parallax` + `chrome.pointer`，翻转与阻尼在 chrome.ts）
- 3.3 L130：「批6 生成于」内部制作流程术语泄漏进学员文本
- 「三 pass」计数矛盾：实际后期链四 pass（含 OutputPass）——3.4 L102、3.5 L132 Checkpoint、index.html L229 三处均写「三 pass」

### 低危（约 20 条，择要）
2.2 L97「二十二分之一」应为二十四；2.1 L140「k 太于」缺「大」字；gamma 位置表述 2.5 L96「最后一步」与 2.8 L72「必须最前」需统一语境；2.6 L17–24 两段等价法线代码符号相反未说明；2.6 L111 与 2.8 L103 同一 demo 的 vignette 一处线性一处平方；2.7 L72「边缘不动」不准确（静止圈在 |c|=0.5，外圈反向）；2.7 L112 RGBA32F+LINEAR 需 `OES_texture_float_linear` 坑表未提；3.2 L20「所有图 load 完再启动」与 demo 实际的 CanvasTexture 同步实现不符；3.2 L104 NPOT/mipmap 建议是 WebGL1 口径（WebGL2 完整支持，demo 02 自用 1024×1280）；「#version 前连空行都不允许」的绝对化表述（规范允许空白与注释，作课程纪律可辩护）；递归「部分驱动拒绝」应为规范明确禁止；1.2 L115「int 默认 highp」在片元语境不成立（mediump）；1.5 L137「两条 UV 路数值完全一致」（gl_FragCoord 是像素中心坐标，差半像素）；3.5 L143 延伸阅读标签与 URL 不匹配；1.1 内置注入表漏 modelMatrix/viewMatrix。
