# Demo 02 · UV 观测台（全屏四边形与UV）

对应讲义：`1.5 数据流与全屏四边形`（TRIANGLE_STRIP 与坐标域）· `1.7 交互输入`（鼠标 uniform）

## 运行

```bash
npm run dev
# http://localhost:5174/demos/day1/02-全屏四边形与UV/index.html
```

## 画面构成

一块测量仪器：网格是刻度盘，鼠标是测头，取样环读取像素身份。

- **底片**：UV 调色板全画布 10% 暗显——画面暗处也保留 R/G 通道的坐标语义
- **刻度盘**：0.1 细网格 + 0.5 主网格 + 四边刻度尺（短刻每 0.1、长刻每 0.5）
- **游标准线**：跟随测头的两条贯穿虚线（天青），像测量仪器的十字游标
- **取景十字**：画布中心静态参考系，中段留空
- **测头**：玫红取样环 + 环上四向刻 + 中心点；**环内调色板 85% 显影**——环内任一像素的颜色就是它的坐标
- **读数**：右下角 DOM 角标实时报出 `UV x.xxx / y.yyy`

## 关键点

- 全屏四边形只需 4 顶点 + `TRIANGLE_STRIP`：条带按 左下→右下→左上→右上 连成两个三角形，顶点直接写 clip space（-1..1），省掉 MVP 矩阵（讲义 1.5）
- UV 的来历只有一行：`uv = gl_FragCoord.xy / u_resolution`——gl_FragCoord 是物理像素、左下原点，除以同域的画布尺寸才得到 0–1
- 调色板即身份牌：R 通道 = uv.x、G 通道 = uv.y——取样环把这个调试语义具象化：环内 85% 显影，读色即读坐标；左下角原点必须是黑的（shader 里那枚玫红原点标记就是试金石）
- 鼠标取 `chrome.pointer.sx/sy`（已 lerp、已 y 翻转），与 uv 同在 0–1 域，`distance()` 直接可比——坐标系对齐了，shader 里才不需要换算

## 视觉规格

- 色板：底色 `#0B0E14`；刻度盘暗青 `#394960`；参考系天青 `#4CC9F0`；测头与原点玫红 `#FF4D6D`
- 层次：底片 10% → 网格 → 边缘刻度 → 游标 30% → 取景十字 40% → 测头；取样环内调色板 85%
- 宽高比：测头与原点做了 `p.x *= aspect` 校正（屏幕真圆）；网格与调色板刻意**不**校正——对比观察就是 1.5 的宽高比陷阱现场
- 动效：无——这是一台静态观测仪，唯一的变量是鼠标
- 性能：单 draw call、DPR ≤ 2，预计 60fps

## 常见报错

| 报错 | 原因 |
|------|------|
| 调色板左上角是黑的 | y 轴没翻转或翻转了两次：gl_FragCoord 左下原点，鼠标事件左上原点 |
| 测头圆环在宽屏被拉成椭圆 | 忘了宽高比校正：`toM = (uv - u_mouse) * vec2(aspect, 1.0)`——圆要真圆必须乘 aspect |
| 游标虚线滞后明显 | 正常——`pointer.sx/sy` 带 0.08 阻尼 lerp（讲义 1.7 的默认手感档），要跟手可换 `nx/ny` |
| `u_resolution` 除出来不是 0–1 | JS 侧传了 CSS 尺寸而 gl_FragCoord 是物理像素（含 DPR） |
| `ERROR: 0:1: ... #version` | `#version 300 es` 之前有空行或注释——必须是文件第一行 |
