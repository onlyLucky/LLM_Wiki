# Demo 05 · 调色板实验室

> 对应讲义 [2.5 色彩工程](../../../讲义/day2-片段着色器视觉算法/2.5-色彩工程：余弦调色板与配色直觉.md) · 点击切换槽位、滚轮调值

## 运行

`npm run dev` 后访问 `http://localhost:5174/demos/day2/05-调色板实验室/index.html`。

## 关键点

- **九宫格是「同一配色的九种命运」**：纵向三行信号源（fbm 云 / SDF 距离 / voronoi F1——前三讲产出复用），横向三列 t 再分布（原值 / smoothstep / pow）——四参数固定时对比「t 的分布学」，比任何文字都直观。
- **四参数各自一个手感齿轮**：a/b 亮度振幅走 ±0.02 步进、c 频率走 ×1.06 乘法（对数手感）、d 相位走 +0.02 循环——同一个滚轮，四种物理量各按各的尺度调。
- **角标即参数面板**：右上 `.tag--tr` 常显四行当前值、左下 hint 显示当前调的槽位与语义——不依赖任何 UI 库，chrome 的角落标注系统直接当 HUD 用。
- **iq 蓝橙卡起步**：A/B/C/D 初始值就是讲义 2.5 的第一张经典卡——「起步抄卡、改 d 微调」的工作流从默认值开始。

## 视觉规格

- 色板：用户自定（本 demo 的意义就在此）——起步蓝橙卡；底 `#0B0E14`、格缝 60% 深
- 构图：3×3 等分九宫格、格缝极细（`fwidth` 自适应）
- 动效：fbm 行流速 0.1；调参即时生效无过渡（工作台语义：所见即所得）
- 细节：入场 800ms 淡入；四行参数常显
- 性能：单 pass、九格共用一次像素遍历（分格在 shader 内判别，无九次 draw），60fps 富余

## 常见报错

| 症状 | 原因 |
|------|------|
| 九宫格只有中间亮 | `row/col` 从 id2 取错行列（`int(id2.x)` 是列不是行）；本 demo x 是分布、y 是信号源 |
| 调 d 槽位画面不动 | d 的三分量被同步加了同一个增量但显示没刷新；或 `fract01` 忘写，d 越界后 cos 出怪色 |
| 点击没反应 | 监听挂在 `document` 而不是 `chrome.canvas`——canvas 覆盖全屏，事件要挂在它上面 |
| c 调到 0 后画面纯色 | c 的下限没 clamp（0.5 起）——频率为零，整条色带退化为常数 |
