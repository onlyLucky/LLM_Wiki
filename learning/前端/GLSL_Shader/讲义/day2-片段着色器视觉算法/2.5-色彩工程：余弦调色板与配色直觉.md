# 2.5 色彩工程：mix、余弦调色板与配色直觉

> Day 2 · 模块 5 · 约 45 分钟
> 理论对照：无直接章节——配色属于 shader 工程的「设计侧」，母本是 iq 的 cosine palette 文章（[iq · Palettes](https://iquilezles.org/articles/palettes/)）

你已经能画形状、铺格子、造噪声，但颜色还是手写 `vec3(1.0, 0.3, 0.5)` 两个来回——画面的「高级感」八成卡在配色上。给 SDF 上个什么色？云海从什么色过渡到什么色？这两个问题没直觉，算法再多也是工程毛坯。这一讲给你设计师的调色公式：**一个函数、四个参数、一整套配色**。

## mix：颜色世界的呼吸阀

`mix(c1, c2, t)` 在 1.6 当过动画的缓动工具，今天换个身份：它是颜色世界唯一的控制流。t 可以是任何 0–1 信号——噪声值、SDF 距离、时间相位、鼠标位置——**mix 是 if-else 的连续版**：

```glsl
vec3 col = mix(deepBlue, cyan, noiseValue);   // t 是噪声：云海
vec3 col = mix(col, rose, edgeGlow);           // t 是 SDF 光晕：边缘提亮
vec3 col = mix(night, dawn, smoothstep(0.3, 0.7, u_time * 0.1)); // t 是时间：晨昏线
```

「如果靠近边缘就发亮」写成 if 是灾难（2.1 的分支发散），写成 `mix(col, glowColor, t)` 是一行。「条件是数据」的配色版：**你以为你在选颜色，其实你在选 t**。

## 余弦调色板：一个公式装下一整套配色

手写三个颜色的缺陷不在难，在死：改一个色要改三处，色与色之间的过渡全靠 mix 的直线性——**线性 RGB 插值走「泥灰色」中间带**，这就是「渐变不脏」的反面教材。iq 的余弦调色板用一条公式替代所有手写：

```glsl
// 余弦调色板：t ∈ 0..1，a/b/c/d 都是 vec3
vec3 palette(float t) {
  return a + b * cos(6.2831853 * (c * t + d));
}
```

四个参数各管一摊：

| 参数 | 身份 | 视觉作用 | 调法 |
|------|------|---------|------|
| a | 基线 | 整条色带的平均亮度 | 提亮提暗不动配色关系 |
| b | 振幅 | 对比的强弱 | 拉大出赛博感，压小出莫兰迪 |
| c | 频率 | 0–1 里循环几轮 | 1 是渐变，2+ 是条纹 |
| d | 相位 | 从色环哪个位置起步 | 微调配色的主旋钮 |

四参数各自改变什么，看这张图——四条色带只动一个参数：

![余弦调色板图：顶部标题「余弦调色板：一个公式装下一整套配色」与公式「col(t) = a + b · cos( TAU · (c · t + d) )」；其下是四参数图例行——玫红方块 a 基线（整条色带整体亮暗）、天青方块 b 振幅（对比的强弱）、琥珀方块 c 频率（循环几次）、灰色方块 d 相位（从哪开始）；主体是四条横向色带：第一条「基准 iq 彩虹卡」为按公式计算的橙红-紫-蓝-青-绿-黄-橙循环色带；第二条「a + 0.12 基线上移」为同色带加白色半透明罩层整体变亮；第三条「b × 1.4 振幅拉大」为经对比增强滤镜的更鲜艳版本；第四条「d + 0.15 相位平移」为同色带整体向左平移 15% 的错位版本；另有 c × 2 的文字说明（频率翻倍循环两次，是纹理密度旋钮）；底部两行要点：「为什么是余弦不是线性插值：RGB 三通道错开相位（d 三个分量不同）→ 过渡自然带色偏，渐变不脏的秘密」「t 可以是任何 0–1 信号：噪声值、SDF 距离、时间——你调的从来不是颜色，是 t 的分布」，以及「收尾别忘了 pow(col, vec3(0.4545)) —— gamma 校正」](../../assets/diagrams/palette-cosine.svg)

对着图从上往下扫四条带：基线上移整条变亮但关系不变；振幅拉大对比更凶；相位平移是同一条带挪了个位置——**你调的从来不是颜色，是 t 的分布**（图底第一行）。

为什么余弦优于线性插值？秘密全在 d 的三个分量：R、G、B 各自从色环的不同相位出发（比如 d = (0.0, 0.33, 0.67)），过渡时三通道错峰到达——中间色自然带色偏，绕开了线性的泥灰带。**渐变不脏的全部秘密就是「错峰」二字。**

## iq 的三张经典色卡

四参数太多调不动？直接抄 iq 文章里的三组经典——**起步抄卡，改 d 微调**是本讲给出的工作流：

| 风格 | a | b | c | d | 画面印象 |
|------|---|---|---|---|---------|
| 蓝橙（电影感） | (0.5, 0.5, 0.5) | (0.5, 0.5, 0.5) | (1.0, 1.0, 1.0) | (0.0, 0.33, 0.67) | iq 全站默认，橙青对比 |
| 熔岩 | (0.5, 0.5, 0.5) | (0.5, 0.5, 0.5) | (1.0, 1.0, 1.0) | (0.0, 0.1, 0.2) | 暗红→金，岩浆与余烬 |
| 彩虹 | (0.5, 0.5, 0.5) | (0.5, 0.5, 0.5) | (1.0, 1.0, 1.0) | (0.0, 0.15, 0.3) | 全色相循环，慎用于大面积 |

```glsl
// 蓝橙卡的课程版（demo 03 云海就是它的改造）
vec3 palette(float t) {
  vec3 a = vec3(0.5, 0.5, 0.5);
  vec3 b = vec3(0.5, 0.5, 0.5);
  vec3 c = vec3(1.0, 1.0, 1.0);
  vec3 d = vec3(0.0, 0.33, 0.67);
  return a + b * cos(6.2831853 * (c * t + d));
}
```

抄完卡立刻验货——一条水平色带从 t=0 扫到 t=1，上下分屏对比 gamma 前后，这一屏就是你此后的验收标准：

```glsl
#version 300 es
precision highp float;

uniform vec2 u_resolution;

out vec4 fragColor;

vec3 palette(float t) {
  vec3 a = vec3(0.5), b = vec3(0.5), c = vec3(1.0);
  vec3 d = vec3(0.0, 0.33, 0.67);         // 错峰相位：蓝橙卡的全部灵魂
  return a + b * cos(6.2831853 * (c * t + d));
}

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  vec3 col = palette(uv.x);               // t 就是横坐标：整条卡一眼扫完
  col = mix(col, pow(col, vec3(0.4545)), step(0.5, uv.y)); // 上半 gamma、下半原样
  fragColor = vec4(col, 1.0);
}
```

上下两半的差异肉眼立判：过校正的那半通透、原样的那半发闷——gamma 不是美化滤镜，是把颜色从「物理亮度」翻译到「感知亮度」（下节展开）。t 直接取 `uv.x` 也是一课：调试色卡时横坐标就是最顺手的 t 源，Shadertoy 圈的色带预览全都这么写。

## 把信号映射成色彩：配色即函数设计

palette 手里有了，t 从哪来？一切 0–1 信号皆可——这才是调色板的正确打开方式。同一份 fbm 云，t 的三种处理三张脸：

| t 的来源 | 效果 | 气质 |
|---------|------|------|
| `t = n`（原值） | 云层灰度过渡平缓 | 阴天，蒙 |
| `t = smoothstep(0.3, 0.7, n)` | 过渡压缩到窄带，亮暗分明 | 晴天，戏剧 |
| `t = pow(n, 2.0)` | 暗部压缩、亮部稀疏 | 夜晚，对比强 |

三行表给气质，数值表给手感——同样四个输入点走一遍三条路，调参之前结果就能算出来：

| n（fbm 原值） | t = n | t = smoothstep(0.3, 0.7, n) | t = pow(n, 2.0) |
|--------------|-------|------------------------------|-----------------|
| 0.2 | 0.20 | 0.00 | 0.04 |
| 0.5 | 0.50 | 0.50 | 0.25 |
| 0.65 | 0.65 | 0.96 | 0.42 |
| 0.8 | 0.80 | 1.00 | 0.64 |

smoothstep 列先看两个端点：0.2 在过渡带 0.3 之下归零、0.8 在 0.7 之上归一——它把 0.3–0.7 这四成输入拉宽成整个输出域，云的「亮暗分明」就是这一拉。pow 列看 0.2 那行：0.04，暗部被压掉五倍——夜晚画面七成是暗的，靠的就是这一压。两个函数都在重排 t 的住户，颜色一个没动。

```glsl
float n = fbm(p + flow);
vec3 col = palette(pow(n, 1.8));           // pow 让暗部占比更大——夜晚占七成
// 三种 t 处理都试一遍再定——这一步叫「配 t」不叫「配色」
```

SDF 距离也能当 t：「离边缘越近越亮」= `palette(1.0 - smoothstep(0.0, 0.2, abs(sd)))`——注意吃 `abs(sd)`：带符号的 sd 在形状内部恒为负，t 会整个饱和（2.6 的边缘光同款）——边缘光、描边渐变、发光体的色彩过渡，全是同一行的不同参数。**你调的从来不是颜色，是 t 的分布**——这句在 2.4 的 How 段彩排过，今天正式成为主旋律。

Day 2 的手艺到这里能串成一条完整的链——voronoi 出信号、smoothstep 做再分布、palette 出色、gamma 收尾，四步全走一遍：

```glsl
#version 300 es
precision highp float;
uniform vec2 u_resolution;
out vec4 fragColor;

vec2 hash22(vec2 p) { p = fract(p * vec2(234.34, 435.345)); p += dot(p, p + 34.23); return fract(vec2(p.x * p.y, p.x + p.y) * 998.0); }
vec3 palette(float t) { return vec3(0.5) + vec3(0.5) * cos(6.2831853 * (t + vec3(0.0, 0.1, 0.2))); } // 熔岩卡

void main() {
  vec2 p = (gl_FragCoord.xy / u_resolution) * 2.0 - 1.0;
  vec2 g = p * 3.0, id = floor(g);
  float f1 = 8.0;
  for (int y = -1; y <= 1; y++)
  for (int x = -1; x <= 1; x++) {
    vec2 o = vec2(float(x), float(y));
    f1 = min(f1, length(g - id - o - hash22(id + o))); // 只留 F1：这张脸是波纹
  }
  float t = 0.35 + 0.55 * smoothstep(0.0, 0.9, f1);     // 再分布：0.35 起步，避开死黑端
  vec3 col = palette(t);
  fragColor = vec4(pow(col, vec3(0.4545)), 1.0);        // gamma：全链的收尾一步
}
```

调色板这里故意从蓝橙换成熔岩卡（d = 0.0/0.1/0.2）：同一份 F1，换 d 就是换世界——细胞从水面变岩浆，这就是四参数里 d 被叫做主旋钮的原因。`0.35 +` 是暗部保底：F1 在细胞核处趋近 0，t 直接进 palette 会一直踩在最暗端，画面一半死黑。

## 亮度与对比的最后一公里

收尾一步永远欠着：gamma 校正。人眼对暗部敏感、对亮部迟钝，显示器按物理亮度线性输出——线性空间的「一半亮度」看起来远不止一半暗，画面整体发闷。修正：**输出前把颜色过 `pow(col, 1/2.2)`**：

```glsl
// 收尾一行：线性 → 感知（sRGB 近似）
fragColor = vec4(pow(col, vec3(0.4545)), 1.0); // 0.4545 ≈ 1 / 2.2
```

记不住原理就记住位置：**色彩计算的收尾、指数 0.4545**（接 2.8 的完整配方时它站五步之首，gamma 之后只走对比/饱和/grain/vignette——两处说的「位置」不矛盾：线性空间的计算到此为止）。加了它，暗部细节浮出来，色彩通透一档——它不是滤镜，是把你的劳动成果从「显示器的物理空间」翻译回「人眼的感知空间」。

0.4545 的威力用数字看最直接——同一批线性值过一遍校正，暗部被抬起的倍数是亮部的十几倍：

| 线性值 | 校正后 pow(x, 1/2.2) | 抬升 | 直觉 |
|-------|---------------------|------|------|
| 0.02 | 0.169 | ×8.5 | 淹没在黑里的细节浮出来 |
| 0.05 | 0.256 | ×5.1 | 近黑变成可见的深灰 |
| 0.25 | 0.532 | ×2.1 | 四分之一亮度看着像一半 |
| 0.5 | 0.730 | ×1.5 | 中灰大幅上移 |
| 1.0 | 1.0 | ×1.0 | 亮端不动 |

人眼对暗部的分辨力远高于亮部，校正把数值资源按人眼的敏感度重新分配——0.02 这种物理上的近黑，感知上其实是深灰。「不做 gamma 画面发闷」的数学就在这张表里：你的暗部全被压死在 0–0.1 的窄带，而人眼恰好在这条带里分辨力最强。

## How：demo 05「调色板实验室」逐段精讲

demo 05 是本讲的实操台：a/b/c/d 四个 uniform 实时可调，画面九宫格同时预览 t 的三种分布——**这是你自己的配色工作台**，参数不是写死的，是玩出来的。

它的 fragment 核心只有两段：

```glsl
// —— 段 1：四参数全 uniform 化 ——
uniform vec3 u_a; // JS 滚轮选择当前调的参数，键盘或拖动改值
uniform vec3 u_b;
uniform vec3 u_c;
uniform vec3 u_d;

vec3 palette(float t) {
  return u_a + u_b * cos(6.2831853 * (u_c * t + u_d));
}

// —— 段 2：九宫格——t 的三种分布 × 三种信号源 ——
// 横向：t 原值 / smoothstep(0.3, 0.7, t) / pow(t, 2.0)
// 纵向：信号源 = fbm / SDF 距离 / voronoi F1
// 每格同一个 palette，只有 t 的「再分布」不同——九宫格对比同一配色的九种命运
```

九宫格的纵向是 2.1–2.4 三讲产出的复用（fbm、SDF、F1 各来一排），横向是本讲的 t 分布学。**demo 05 的正确用法不是「看」，是「调」**：把 a 拉高、b 压半，找莫兰迪；d 转一圈，看色带平移；然后挑一组你自己的参数抄进 demo 03 云海——两张脸合在一起，才叫配色工作流。

JS 侧的四参数联动用 chrome 的滚轮与点击事件桥（1.7），当前参数与数值以四行小字常显在角标里——你调出来的每一组都值得截图记下来，那就是你的色卡库第一页。

## 常见坑

| 症状 | 原因 |
|------|------|
| 画面发灰发闷、暗部一坨 | 输出没过 `pow(col, vec3(0.4545))`——gamma 校正是收尾必备不是可选美化 |
| 调色板出现诡异的荧光色 | t 没 clamp：负数与超 1 的值进 cos 后会撞上你不认识的色相——clamp 后是 bug 不 clamp 是 feature（故障艺术常用这招） |
| 三个通道饱和度全拉满，画面互相打架 | 保留一个主色，其余两个通道降振幅（b 的对应分量调小）；高饱和三色同屏是新手画面的头号死因 |
| 用 sRGB 十六进制值直接进公式 | hex 色是感知空间的：先平方（`c * c`）转线性再参与运算，输出前再 pow 回去；直接用会偏亮 |
| 渐变中间有一段泥灰 | 用的线性 mix 而不是余弦错峰——给 d 的三分量不同的相位（0 / 0.33 / 0.67 起步） |
| 云海的 t 调了半天没变化 | t 再分布写在 palette 外面了——pow/smoothstep 要作用在「t 上」再喂 palette，顺序反了等于没调 |
| 色带亮端过曝死白、暗端压死 | a 与 b 的分量之和超过 1：a + b·cos 的峰值就是 a + b；iq 三卡全用 (0.5, 0.5) 正是为了 a + b = 1 恰好贴边 |
| 拿 palette 做循环动画，t 从 1 绕回 0 跳出一条缝 | c 不是整数：t 走满 0–1 时色环只转了 c 圈的零头，palette(0) ≠ palette(1)；无缝循环 c 取整数 |
| mix 的 t 直接喂了信号原值 | t 没归一到 0–1：SDF 是带符号无界值、fbm 挤在 0.35–0.65——值域不对，mix 只用到颜色的一小截；先 smoothstep 再进 mix |

## Checkpoint

- 能默写余弦调色板公式，并说出 a/b/c/d 各自控制什么
- 能解释「渐变不脏」的原因：RGB 三通道错峰（d 三分量不同相位）
- 能背出 gamma 收尾：`pow(col, vec3(0.4545))`，并说出不做时的画面症状
- 能对同一信号写出三种 t 的再分布（原值 / smoothstep / pow）并预测各自的明暗结构
- 能把 iq 三张经典色卡的参数默写进代码，并说明改哪个参数做微调最安全（d）
