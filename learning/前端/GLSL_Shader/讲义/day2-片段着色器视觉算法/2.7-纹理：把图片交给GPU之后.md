# 2.7 纹理：把图片交给 GPU 之后

> Day 2 · 模块 7 · 约 45 分钟
> 理论对照：《WebGPU 三天实战课程》2.3「纹理采样与 Mipmap」——采样器状态、过滤与 mipmap 的硬知识（[2.3-纹理采样与Mipmap.md](../../../webgpu/讲义/day2-渲染进阶与GPU计算/2.3-纹理采样与Mipmap.md)）；本篇讲 GLSL 侧的用法与失真手法

到今天为止，所有画面都是「算出来的」：SDF、噪声、调色板——程序化图形的完整武器库。但创意网站一半的画面素材是设计稿给的图：hero 的大图、产品的照片、艺术家的插画。**把图片交给 GPU 之后能干什么**——这一讲引入第一张外部纹理，失真、色差、遮罩、数据通道，全是 awwwards 站 hover 效果与 hero 轮播的底层零件。Day 3 的 3.2「图片失真与视差」会在 Three.js 里把这套手法工业化，今天先在原生 WebGL2 里过一遍手。

## 采样最小闭环（JS 侧五步）

纹理在 JS 侧的准备只有五步，比 WebGPU 的 `copyExternalImageToTexture` 少一层队列语义、多一层绑定仪式：

```ts
// 1. 建纹理并绑定到 0 号单元
const tex = gl.createTexture();
gl.activeTexture(gl.TEXTURE0);
gl.bindTexture(gl.TEXTURE_2D, tex);

// 2. 上传：图片（Image 元素）解码后进 GPU
gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, image);

// 3. 参数：WRAP 决定 uv 越界行为，FILTER 决定放大缩小的取样
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.LINEAR);

// 4. uniform 绑定：sampler 类型传的是「纹理单元号」，不是纹理本身
const uTex = gl.getUniformLocation(program, 'u_tex');
gl.uniform1i(uTex, 0);

// 5.（一次性的）UNPACK_FLIP_Y_WEBGL：图片的 y 向下，UV 的 y 向上
gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, 1); // 注意要在 texImage2D 之前设
```

与 WebGPU 2.3 的对照表：

| 环节 | WebGL2（本课） | WebGPU（先验课） |
|------|---------------|-----------------|
| 上传 | `texImage2D(target, level, ..., image)` | `copyExternalImageToTexture` + 队列 |
| 参数 | `texParameteri`（改活对象状态） | `createSampler`（不可变对象） |
| 绑定 | activeTexture + uniform 单元号 | bind group 布局显式声明 |
| y 翻转 | `pixelStorei(UNPACK_FLIP_Y_WEBGL)` | 上传时传 `flipY: true` |

最大的心智差异在**状态机 vs 对象**：WebGL2 的纹理参数是「当前绑定纹理」的活状态（忘了绑定就改到别人头上），WebGPU 把它固化成 sampler 对象。写惯 React props 的你对后者天然亲切——前者要靠纪律。

过滤参数要单独一张四格表——它是「图片为什么糊、为什么闪、为什么黑」的总病根：

| 参数 | LINEAR | NEAREST |
|------|--------|---------|
| `TEXTURE_MAG_FILTER`（放大取样） | 双线性插值，4 texel 加权——照片放大仍平滑 | 最近邻，单 texel 复制——像素风、马赛克块 |
| `TEXTURE_MIN_FILTER`（缩小取样） | texel 混合，缩小不闪烁 | 单 texel 抽样，缩小后高频闪烁（摩尔纹） |

两个默认值你必须背：**MAG 默认 LINEAR**（省心），**MIN 默认 NEAREST_MIPMAP_LINEAR**（埋雷）——后者要求 mipmap 链齐才判纹理「完整」，而本课单 pass 没有上传 mip 层级，采样直接输出黑。五步里 `MIN_FILTER` 必须显式设 `LINEAR` 的真正原因就在这：不是口味偏好，是「不设就黑」（坑表第 7 行）。

排障时你照表走：先查黑（MIN 没显式设）、再查糊（MAG 用了 NEAREST）、再查闪（缩小时 aliasing——LINEAR 只治放大，缩小的正解是 `gl.generateMipmap` + `LINEAR_MIPMAP_LINEAR`，那是进阶选项）。三个症状各对一格，不用瞎猜。Day 3 上 Three.js 后，`TextureLoader` 会替你生成 mipmap，这颗雷由框架排掉。

## texture()：一行拿颜色

GLSL 侧的采样是全课程最短的 API：

```glsl
uniform sampler2D u_tex; // 声明

vec4 c = texture(u_tex, uv); // 采样：uv 处的 RGBA
```

`texture()` 返回 RGBA 四个 float（0–1），三个通道之外 alpha 白送。uv 越界的行为由 WRAP 参数决定：**REPEAT** 是平铺（uv=1.3 取的是 0.3 的图——无缝贴图铺墙），**CLAMP_TO_EDGE** 是拉边（越界全取边缘像素——人像照片不会自己重复）。选错模式的症状很典型：hero 大图边缘出现「叠影」，就是把 CLAMP 该用成了 REPEAT（坑表第 4 行）。

采样拿到的「值」还有两层默认值要交代——y 翻转与色彩空间，原生 WebGL2 与 Day 3 的 Three.js 各一套，提前对表免得你到时候怀疑人生：

| 默认项 | WebGL2 原生（本课） | Three.js（Day 3 会用） |
|--------|----------------------|------------------------|
| y 翻转 | `UNPACK_FLIP_Y_WEBGL` 默认 **false**（不设图就是倒的） | `texture.flipY` 默认 **true**（图天然是正的） |
| 色彩空间 | 无此参数：浏览器把 PNG 的 sRGB 编码值原样交进 texel | `texture.colorSpace` 默认 `NoColorSpace`，照片要手动设 `SRGBColorSpace` |

原生侧的隐患在第二行：**PNG/JPG 存的是 sRGB 编码值，shader 默认当线性值用**——你把它直接乘暗角、叠发光（`col * k` / `col += glow`），运算位置就错了，症状是「图片比设计稿灰一截」（坑表第 9 行）。修法与 2.8 配方卡第一步互逆：进运算前 `pow(tex.rgb, vec3(2.2))` 转线性，出画面时配方卡再 `pow(col, vec3(0.4545))` 转回感知——2.5 的 gamma 纪律在纹理上的落点。

顺带排一颗旧教程的雷：WebGL1 时代非 2 次幂（NPOT）纹理不能开 REPEAT、不能配 mipmap，你搜「纹理黑屏」会搜到大量拿这条说事的老答案——本课是 WebGL2，NPOT 与 REPEAT、mipmap 全部放开，设计稿给的 1920 × 1080 直接上传，不用裁成 2 的幂。

## UV 失真：先改坐标再采样

纹理手法的心法与 2.2 黄金法则一脉相承：**不改编码，只改坐标**。采样前的 uv 过一道变换，画面就是「液态」的：

```glsl
// —— 液态玻璃：噪声偏移 uv ——
vec2 off = vec2(
  fbm(p * 3.0 + u_time * 0.1),
  fbm(p * 3.0 + vec2(5.2, 1.3) - u_time * 0.08)
);
vec3 col = texture(u_tex, uv + (off - 0.5) * 0.04).rgb; // 偏移 ±2%

// —— 漩涡：极坐标旋转 uv ——
vec2 c = uv - 0.5;
float a = atan(c.y, c.x) + 0.6 * (1.0 - length(c) * 2.0); // 中心转得多；|c|=0.5 是静止圈，外圈反向
float r = length(c);
vec2 sw = vec2(cos(a), sin(a)) * r + 0.5;
vec3 col = texture(u_tex, sw).rgb;

// —— 圆形遮罩：length 裁 UV ——
vec2 m = (uv - 0.5) * 2.0;                  // 居中
float d = length(m);
vec3 col = texture(u_tex, uv).rgb;
col *= 1.0 - smoothstep(0.9, 0.95, d);     // 圆窗淡出——轮播图的进出场
```

三种失真对应三种产品语境：液态玻璃是 hover 微交互（鼠标贴图轻晃）、漩涡是转场（页面切换的吸走感）、圆形遮罩是轮播（焦点图进出场）。**失真幅度都在 2–10% 之间**——失真的美在「克制」，拉到 30% 是马赛克不是风格。

**RGB shift：赛博故障 / 色差**三行配方，awwwards 出镜率最高的一招：

```glsl
// RGB shift：三通道各自微移采样再重组
vec2 shift = vec2(0.003, 0.0); // 偏移量：2–5 个千分点起步
float r = texture(u_tex, uv + shift).r;
float g = texture(u_tex, uv).g;
float b = texture(u_tex, uv - shift).b;
vec3 col = vec3(r, g, b);
// 鼠标 hover 时 shift 随 u_vel 拉大——「故障感」跟手
```

色差的物理原型是镜头色散（不同波长折射率不同），仿造它就等于给画面加了一层「光学真实」——即使偏移量肉眼几乎看不见，视网膜也会报告「这是拍出来的不是画出来的」。

## 通道复用：一张纹理四个数据源

RGBA 四通道是四个独立 float——图片纹理只用 RGB，**第四个通道是免费的仓库**。更激进的做法是整张纹理不当图用，当数据用（data texture）：

```glsl
// 通道复用：一张图四个图层
float mask  = texture(u_tex, uv).r;  // R：亮度遮罩——文字浮在哪
float flow  = texture(u_tex, uv).g;  // G：流速图——扰动往哪流
float alpha = texture(u_tex, uv).b;  // B：透明度——哪里显哪里隐

// JS 侧造 data texture：三个 float 打包进 RGB
const data = new Float32Array([0.7, 0.2, 1.0,  0.1, 0.8, 1.0, /*…*/]);
gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA32F, w, h, 0, gl.RGBA, gl.FLOAT, data);
// 注意：RGBA32F 配 LINEAR 过滤要先拿 OES_texture_float_linear 扩展，否则纹理不完整（采样得黑）；NEAREST 无此要求
```

Samsy 的 Medium 文章把这套叫「通道即图层」——设计稿在 Photoshop 里分通道画好，shader 里各取所需。**一张 4K 纹理 = 四张 4K 数据图**，显存和带宽都省四分之三，这是 GPU 思维对「素材」二字的重构。

data texture 还有一重身份是**查找表**：你往 shader 里塞一张 128 × 1 的 RGBA32F，就是一张 128 点的曲线表（R 存曲线值即可），一次上传、常数级采样；对比 uniform 数组（有硬上限——规范保底仅 224 个 vec4，且每次 draw 都要 CPU 侧重传），大表进纹理是 GPU 侧的标准解法，后处理调色的 LUT（颜色查找表）走的就是这条路。

## How：纹理手法并入作业链

本日不设独立纹理 demo（六页 demo 已被算法母题占满），纹理手法的落点在两个方向：

**其一，今晚 C 档作业的进位**：深海回响的主视觉是程序化的，但加分项允许你把背景层换成一张纹理图（深海照片压暗后叠进海雪层，透明度守住 25% 的纪律，warp 偏移用 2.4 的 fbm）——UV 失真与 RGB shift 都能直接挂进去。

**其二，Day 3 的 3.2「hover 失真图卡」**：Three.js 的 `ShaderMaterial` 里 `sampler2D` 接法完全同构，JS 侧的五步被框架收编成两行。本篇的 fragment 手法（液态偏移 / RGB shift / 圆窗遮罩）在 3.2 里原样复用——**今天写的失真行，第 3 天一行不改地搬进工程**。

练习路径建议：把本篇的「液态玻璃」六行贴进 demo 03（云海）的 fragment，替换调色板段，纹理用任意 4K 图（本地 `import imgUrl from './tex.jpg'` 经 Vite 走 asset 管线）；跑通后再换 RGB shift 三行。两个六行各花十分钟，失真手法就过了手。

起步模板直接给全——液态偏移 + RGB shift + 圆窗遮罩的完整 fragment，uv 用 gl_FragCoord 现算、不依赖顶点侧插值，配好 1.7 的管线，你贴任意一张图就能跑：

```glsl
#version 300 es
precision highp float;

uniform sampler2D u_tex;    // JS 侧五步上传的图
uniform vec2  u_resolution;
uniform float u_time;
out vec4 fragColor;

void main() {
    vec2 uv = gl_FragCoord.xy / u_resolution;
    // 液态偏移：双 sin 当「便宜的 fbm」——先跑通闭环，换 2.4 的 fbm 只改这一处
    vec2 off = vec2(sin(uv.y * 14.0 + u_time * 0.6),
                    cos(uv.x * 12.0 - u_time * 0.5));
    vec2 suv = uv + off * 0.02;                     // 幅度 2%：克制区间起步
    // RGB shift：三通道各自微移采样再重组——色散的仿造
    vec2 shift = vec2(0.004, 0.0);
    vec3 col = vec3(texture(u_tex, suv + shift).r,
                    texture(u_tex, suv).g,
                    texture(u_tex, suv - shift).b);
    // 圆窗淡出：遮罩认输出域 uv、不认偏移后的 suv——裁的是「画框」不是「图」
    float win = 1.0 - smoothstep(0.88, 0.97, length((uv - 0.5) * 2.0));
    fragColor = vec4(col * win, 1.0);
}
```

三段手法的接线关系在这份模板里一目了然：偏移改的是**采样坐标**（图「液态」的原因），shift 只加在两个通道上（色差的原因），遮罩乘在**输出**上（与图无关的画框）——三者互不纠缠，删掉任何一段、其余照跑，这正是你往 demo 03 里搬代码时的模块边界。

## 常见坑

| 症状 | 原因 |
|------|------|
| 纹理整块纯黑 | 图片跨域没 CORS：canvas 被「污染」，texImage2D 静默失败；`img.crossOrigin = 'anonymous'` 且服务器回 `Access-Control-Allow-Origin` |
| 图片上下颠倒 | `pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, 1)` 没设或设晚了——它必须在 texImage2D **之前**，而且影响的是「上传时的翻转」不是「采样时的翻转」 |
| hero 大图边缘出现叠影 | WRAP 用了 REPEAT：uv 略超 1 就把对边卷进来；大图用 CLAMP_TO_EDGE，只有平铺贴图才 REPEAT |
| 每帧都调 texImage2D | 图片只上传一次（STATIC）——每帧重新上传是把 8MB 显存搬来搬去，帧率直接躺下；动态视频纹理才每帧传 |
| RGB shift 一开就晕 | 偏移量超过 0.01（1%）：色差的美在若隐若现，2–5 个千分点起步，hover 时才放大 |
| 图片发糊（近距离） | MAG_FILTER 用了 NEAREST 或没设 LINEAR——放大取样时最近邻会出马赛克块 |
| 上传成功、无报错、采样全黑 | MIN_FILTER 没显式设：默认 NEAREST_MIPMAP_LINEAR 要 mipmap 才判纹理「完整」，单 pass 没传 mip 就黑——五步的第 3 步不是可选项 |
| 失真一开，图片边缘拉出一条亮/暗条纹 | CLAMP_TO_EDGE 的「拉边」遇上 uv 偏移：越界处全取边缘像素、被拉成线；幅度压回 2–10%，或采样前给 uv 留 margin |
| 图片颜色比设计稿灰一截 | PNG 是 sRGB 编码、被当线性值直接参与乘法叠加（暗角、glow）；运算前 pow(tex.rgb, vec3(2.2)) 转线性，与 2.8 配方第一步互逆 |
