# 2.3 伪随机与图案：hash、格子与 voronoi 细胞

> Day 2 · 模块 3 · 约 50 分钟
> 理论对照：无直接章节——本篇是 shader 程序化图案的完整入门，参照 The Book of Shaders「Random / Noise」两章的深度展开（[Random](https://thebookofshaders.com/10/?lan=ch) / [Noise](https://thebookofshaders.com/11/?lan=ch)）

把 2.2 的每块瓷砖随机化，会发生什么？城市立面的窗灯亮暗参差、Orage 网格的数据包闪烁明灭、石头地面的斑驳深浅——**随机感是数字世界里的生命感的第一来源**。规则的东西一眼假，随机的东西活。这一讲把「随机」装进 shader：一个确定性函数 hash，两步走到 voronoi 细胞——自然界细胞、矿石、龟裂纹路的统一抽象。

## hash：每一帧都一致的 Math.random()

先回答为什么不能直接用真随机：fragment shader 是纯函数、无状态，GPU 并行调用它几百万次——真随机的每格每帧都换值，画面闪成雪花电视。**你要的从来不是随机，是「看起来随机的确定性」**：输入相同 → 输出相同；输入差一点 → 输出差很多。后者叫雪崩效应，是 hash 的灵魂：

```glsl
// 2D hash：课程标准版（Art of Code 的 fract 搅拌式；TBoS 的 sin 点积式是同族另一支）
float hash21(vec2 p) {
  p = fract(p * vec2(234.34, 435.345));
  p += dot(p, p + 34.23);
  return fract(p.x * p.y);
}
```

三行干了什么：先把坐标搅乱（大数相乘取 fract，把规整的格点撒到 0–1），再点积混一遍，最后取 fract 输出 0–1。它就是 shader 世界的 `Math.random()`，**但每一帧都一致**——这是动画能建立在它之上的前提。1.5 比喻库里那句「hash21 是每帧结果一致的 Math.random()」，今天正式兑现。

两个工程注意：一是精度——hash 依赖大数乘法后的尾数混沌，mediump（常见于部分移动端 float 精度）会把它截成常数（坑表第 1 行），所以片元着色器顶部的 `precision highp float;` 不是仪式，是 hash 的保命符。二是别在 hash 里循环或开数组——三行就是最优解，花式写法十有八九更贵更乱。

## 随机格子：闪烁的窗灯

hash 接上 2.2 的平铺，就是城市夜景：

```glsl
#version 300 es
precision highp float;

uniform vec2 u_resolution;
uniform float u_time;

out vec4 fragColor;

float hash21(vec2 p) {
  p = fract(p * vec2(234.34, 435.345));
  p += dot(p, p + 34.23);
  return fract(p.x * p.y);
}

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;
  vec2 p = uv * 2.0 - 1.0;

  // 平铺：窗灯格
  vec2 g = p * 8.0;
  vec2 id = floor(g);
  vec2 f = fract(g) - 0.5;

  // 每格一个 0–1 随机数：格子的「命运」
  float h = hash21(id);

  // 时间维度：每格按自己的相位呼吸（1.6 相位表的实战）
  // hash 值当相位偏移——格子们各转各的钟
  float blink = step(0.5, h + 0.1 * sin(u_time + h * 6.2831853));

  // 窗本体：格内一枚小方，亮格才画——SDF 先 smoothstep 成 0–1 遮罩再进 mix
  // （原始 SDF 直接当系数：窗内是负数，亮窗会被外推成黑块——2.1 坑表第 1 行的教训）
  float sd = sdBoxLite(f, vec2(0.28));
  float win = 1.0 - smoothstep(0.0, fwidth(sd) * 2.0, sd);
  vec3 col = mix(vec3(0.02), vec3(0.9, 0.75, 0.35), blink * win);

  fragColor = vec4(col, 1.0);
}

float sdBoxLite(vec2 p, vec2 b) { // 声明提前的知识：GLSL 要求先定义后用
  vec2 d = abs(p) - b;
  return length(max(d, 0.0)) + min(max(d.x, d.y), 0.0);
}
```

（真实文件里函数要放 `main` 之前——上面为了阅读顺序把实现放最后，敲的时候记得挪上去。）`hash21(id)` 给每格发了命运号码，`sin(u_time + h * TAU)` 让每格的钟从自己的相位起步：同时呼吸的是工厂，错峰呼吸的是城市。**错峰 = 输入参与相位**，这个手法在 2.4 的噪声、3.x 的粒子场里反复出现，值得现在就盯住。

## voronoi：离谁最近就是谁的领地

随机格子各画各的窗灯，还是「瓷砖感」。把随机点画进格子、再让每个像素问「我离哪个点最近」，就得到 voronoi——它没有任何格子边界残留，是自然界细胞图案的统一抽象。

算法三句话：给每格撒一个随机点（格内偏移也 hash 决定）；每个像素遍历自己所在格与 8 个邻居共 3×3 的点；找最近的。三行逻辑，一次 3×3 循环：

```glsl
// voronoi：三件产出——F1 最近、F2 次近、胜者格号（细胞壁要吃 F2 - F1，见下）
vec3 voronoi(vec2 g) { // 输入是格子域坐标（p * n 后的值）
  vec2 id = floor(g);
  float f1 = 8.0, f2 = 8.0;   // 最近与次近，先放到「无穷远」
  vec2 winner = vec2(0.0);

  for (int y = -1; y <= 1; y++)
  for (int x = -1; x <= 1; x++) {
    vec2 o = vec2(float(x), float(y));       // 邻居偏移
    vec2 h = hash22(id + o);                  // 邻居格的随机点（格内 0–1）
    vec2 point = id + o + h;                  // 点的世界坐标
    float d = length(g - point);
    if (d < f1) { f2 = f1; f1 = d; winner = id + o; } // 新王登基，旧王退居次近
    else if (d < f2) { f2 = d; }                       // 赢不了 f1，仍可能是次近
  }
  return vec3(f1, f2, winner.x * 7.0 + winner.y * 13.0);
}

// hash22：一次 hash 出两个数（x、y 各一）。真实文件里它的定义要排在 voronoi 之前——先声明后使用（1.3 的硬规则）
vec2 hash22(vec2 p) {
  p = fract(p * vec2(234.34, 435.345));
  p += dot(p, p + 34.23);
  return fract(vec2(p.x * p.y, p.x + p.y) * 998.0);
}
```

**为什么必须 3×3 而不是只看自己格**：点在格内的位置是随机的，你隔壁格的点完全可能比本格的更靠近你——只遍历 1 格，格线附近会发生「领主跳变」，画面出现幽灵接缝（坑表第 2 行）。3×3 在工程上足够：极端角点情形理论上能构造出 3×3 外的真最近点，但概率与视觉误差都小到不可见——Shadertoy 圈的通行做法就是 3×3。

**循环里别写 break**——部分驱动对动态 break 的展开很差，性能反而下滑；9 次迭代全跑完，比提前退出更快更稳（坑表第 3 行）。

一次遍历白拿三件产出，各自的视觉岗位先立成表——后面所有 voronoi 变体都是在这几件里挑货：

| 产出 | 数学含义 | 视觉岗位 | 典型用法 |
|------|---------|---------|---------|
| F1 | 到最近点的距离 | 细胞内部深度：核亮边沉 | `0.5 + 0.5 * f1` 或直接进 palette 当明暗 |
| F2 | 到次近点的距离 | 单独少用，多数与 F1 配对 | 减出边界场（下一节的主角） |
| F2 - F1 | 边界的距离场 | 细胞壁、石板缝、龟裂纹 | smoothstep 一刀切出缝 |
| winner | 最近点所在格号 | 细胞的身份：领地一色 | `hash21(winner)` 二次 hash 决定填色 |

挑哪个当 t，画面就换哪张脸：F1 染色是同心波纹（连续渐变），winner 染色是马赛克领地（色块分明）——demo 02 选了后者。这张表当 voronoi 的点菜单用，写效果之前先勾两格。

## 细胞壁与玻璃裂纹

voronoi 的第二产出藏在 F2——次近距离。`F2 - F1`（到最近两点的距离差）在细胞中央小、在边界上趋于零：它就是**细胞壁的距离场**，smoothstep 一下就是石板缝：

```glsl
// 细胞壁：F2 - F1 越小越靠近「两领主的边境线」
float wall = smoothstep(0.02, 0.06, f2 - f1);
vec3 col = mix(brightCell, darkMortar, 1.0 - wall);

// 壁宽要随格子尺寸缩放：fwidth(f2 - f1) 抗锯齿（坑表第 4 行）
```

石板、龟裂、大理石纹、玻璃冲击纹——这四样东西在 shader 里是同一个公式。把 F1 换成「到边缘的距离场」直接当描边，是 voronoi 最广为流传的用法；`F1` 本身当「离最近的细胞核多远」映射颜色，则得到细胞填充的深浅（demo 02 的主视觉）。

三件产出装配成完整画面——demo 02 剥掉鼠标视差与调色板后的最小骨架，可以直接跑：

```glsl
#version 300 es
precision highp float;

uniform vec2 u_resolution;

out vec4 fragColor;

vec2 hash22(vec2 p) { p = fract(p * vec2(234.34, 435.345)); p += dot(p, p + 34.23); return fract(vec2(p.x * p.y, p.x + p.y) * 998.0); }
float hash21(vec2 p) { p = fract(p * vec2(234.34, 435.345)); p += dot(p, p + 34.23); return fract(p.x * p.y); }

void main() {
  vec2 p = (gl_FragCoord.xy / u_resolution) * 2.0 - 1.0;
  vec2 g = p * 3.0, id = floor(g);         // 3×3 粗格：voronoi 要大格找邻居
  float f1 = 8.0, f2 = 8.0; vec2 winner = vec2(0.0);
  for (int y = -1; y <= 1; y++)
  for (int x = -1; x <= 1; x++) {
    vec2 o = vec2(float(x), float(y));
    float d = length(g - id - o - hash22(id + o)); // 换算到同一坐标系再比：跨界不能只看本格
    if (d < f1) { f2 = f1; f1 = d; winner = id + o; }
    else if (d < f2) { f2 = d; }
  }
  vec3 col = vec3(0.16, 0.62, 0.72) * (0.45 + 0.55 * hash21(winner)); // 胜者染色：领地一色
  col = mix(col, vec3(0.05), 1.0 - smoothstep(0.0, 0.05, f2 - f1));   // 壁走 F2 - F1：边界处两距离趋等
  fragColor = vec4(col, 1.0);
}
```

距离比较发生在 `g` 域（格子域的世界坐标）：`g - id - o - hash22(...)` 把邻居格的点换算回同一坐标系再比远近——直接拿 `f` 去减会漏掉跨格的整数坐标差，本格内看不出错、格线附近全歪（坑表给它留了行）。染色用 `hash21(winner)` 而不是 `hash21(id)`：像素问的是「我属于谁」，答案只有胜者知道。

## How：demo 02「voronoi 细胞」逐段精讲

demo 02 是本讲的完整装配：细胞填充色 + 细胞壁 + 鼠标视差。它的 fragment 主体浓缩为四段：

```glsl
// —— 段 1：坐标与格子（2.2 的骨架 + 本讲的格子数）——
vec2 g = p * 3.0;

// —— 段 2：voronoi 3×3 遍历（上面的完整实现，含 F1/F2/胜者）——
// f1 / f2 / winner 三件产出

// —— 段 3：填充色——胜者 hash 决定这个细胞「是谁」——
float cellH = hash21(winner);                       // 胜者格号的二次 hash
vec3 tint = palette(cellH * 0.7 + 0.15);            // 低饱和调色板（2.5 的钩子）
// F1 给一点由内向外的径向明暗：细胞核亮、边缘沉
vec3 cell = tint * (0.85 + 0.15 * smoothstep(0.5, 0.0, f1));

// —— 段 4：细胞壁 + 鼠标视差——
float wall = 1.0 - smoothstep(0.0, fwidth(f2 - f1) * 2.0 + 0.01, f2 - f1);
col = mix(cell, vec3(0.05, 0.06, 0.09), wall * 0.8); // 深灰壁，不抢戏
```

鼠标视差是唯一的 JS 侧加料：`g` 在进入 voronoi 前加上 `(u_mouse - 0.5) * 0.06` 的微偏——整片细胞随光标轻轻漂 3%，细节层就有了。视差只加在格子域、幅度压在 5% 以内，是「可感知但不喧宾」的定量翻译。

值得盯住的一处设计：`hash21(winner)` 用胜者编号做二次 hash 取色，而不是直接用 F1 距离染色——前者给的是「每个细胞一种颜色」（领地感），后者给的是「同心渐变」（波纹感）。**同一份 voronoi 产出，选择哪个当 t，决定了图案的气质**——这行选择术在 2.5 调色板一讲会正式展开。

## 常见坑

| 症状 | 原因 |
|------|------|
| hash 输出一片死黑或死灰 | mediump 精度把大数乘法的尾数截没了——`precision highp float;` 顶到片元着色器第一行；hash 的混沌全靠尾数 |
| voronoi 格线附近颜色「跳变」出幽灵缝 | 只遍历了本格 1×1：邻格的点可能更近。3×3 才是 2D 的完整安全域 |
| 循环里写了 break，帧率反而降 | 部分驱动对动态 break 展开很差；GPU 没有 CPU 式分支预测器，warp 整体步进（1.1 的分支发散）——9 次迭代全跑反而最快 |
| 细胞壁在近处细如发丝、远处粗成色块 | 壁宽写死绝对值；用 `fwidth(f2 - f1)` 依像素自适应（与 2.1 的抗锯齿同一机关） |
| 细胞是均匀的马赛克，没有「领地」的有机感 | 格点用了格心（`id + 0.5`）而不是 hash 随机偏移——voronoi 退化成方格；随机偏移才是有机形的来源 |
| 每帧图案全变 | 把 `u_time` 直接混进了点的位置 hash——点的 hash 只能来自 `id`，时间只能参与「展示层」（相位/颜色），种子层一动就闪 |
| 格子里全是细噪点，没有「一格一色」的块状感 | hash 的输入喂了 `f`（连续的格内坐标）而不是 `id`（离散格号）——连续输入让每个像素拿到不同的值；随机性永远挂在 id 上，f 只管几何 |
| 细胞壁在部分格线处错位、缺一块 | 距离算的是 `length(f - h)`——邻居的点要先换算回世界坐标 `g - id - o - h` 再比；只在自己格内看是对的，跨界比较全歪 |
| 个别相邻细胞颜色一模一样 | 把 2D 格号折叠成 1D 用了可分解系数（如 `id.x * 2.0 + id.y * 4.0`）：(1,0) 与 (0,2) 撞出同号——要折叠就用质数系数（7/13），更省事的是直接 `hash21(id)` 不折叠 |
