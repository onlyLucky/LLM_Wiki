# 2.8 电影感配方：收尾的四步

> Day 2 · 模块 8 · 约 40 分钟
> 理论对照：无直接章节——本篇是「把技术拼装成作品」的收尾课，参数全部可背

同一个 shader，加不加最后这四步，观感差一个档次——它们不改变「画了什么」，只改变「像不像电影」。摄影师管这叫调色与做旧，shader 工程管这叫**后处理配方**：grain（颗粒）、vignette（暗角）、合成模式、参数化顺序。今天把配方卡背下来，Day 3 的所有作品都靠它收尾。

## grain：颗粒

胶片的银盐颗粒是随机分布的亮度扰动，数字复刻只要一行：

```glsl
// 动态 grain：每帧换 seed（u_time 进 hash），静态画面也有呼吸感
float grain = hash21(gl_FragCoord.xy + u_time) - 0.5; // -0.5..0.5
col += grain * 0.04;                                   // 幅度 4%
```

两个手眼细节：**seed 要带 u_time**——不加的话颗粒冻结成「脏屏」（噪点不闪的胶片是坏胶片）；**幅度 4% 就够**——超过是噪点污染，低于 2% 看不见。4% 的数学出处：8bit 通道的 1/255 ≈ 0.4%，4% 是它的十倍——肉眼明确可见但不抢对比度，这是 2.6 dithering 的「修复带」放大十倍变成的「风格带」。

grain 还藏着一档风格选择：**亮度 grain 与彩色 grain**。本篇配方是亮度版（RGB 同加一个数，画面「脏」得均匀）；彩噪版让三通道各 hash 一次——胶片银盐颗粒本就是三层独立感光，**彩噪更「胶片」、亮噪更「干净」**。写法只差一行：`vec3 g = vec3(hash21(p), hash21(p + 7.7), hash21(p + 13.3)) - 0.5;`。你做复古叙事页用彩噪，现代暗色 hero 用亮噪。

## vignette：暗角

老镜头的边缘失光，把视线推向中心：

```glsl
// 幅度 k 与指数（平方）——比线性更贴近镜头的光学衰减
col *= 1.0 - 0.2 * pow(length(uv - 0.5), 2.0);
```

k 的三档表直接可背：

| k | 气质 | 适用 |
|---|------|------|
| 0.1 | 空气感 | 大面积背景、亮色 hero |
| 0.2 | 舞台聚光 | 霓虹、发光体、深色主视觉 |
| 0.3 | 老镜头 | 复古、胶片风、作品集叙事页 |

坑表第 2 行的老朋友：vignette 要用 `uv`（0–1，中心 0.5），忘了居中会得到一个偏心黑角——「四角里有一角特别暗」是它的签名症状。

k 之外你还有一个形状旋钮：`length(uv - 0.5)` 是圆形暗角，把向量压扁成 `length((uv - 0.5) * vec2(1.0, 1.4))` 就是椭圆——y 方向衰减更快，左右留得更宽，正贴 16:9 宽屏 hero 的边；圆形暗角在宽屏上会四角先黑、上下边还亮着，像「镜头没扣正」。

指数同样参与形状：平方是本课默认（衰减平缓、中心大面积不受影响），四次幂 `pow(d, 4.0)` 把暗角往角里收得更狠、中心留得更平——电影宽幅画面的暗角多是高次幂，你想要「影院黑」就往上调指数，想要「手机随手拍」就调 k。

## 合成模式：shader 里的 mix-blend-mode

CSS 的 `mix-blend-mode` 在 GLSL 里是几行算术，四种最常用的：

```glsl
// screen：漂白叠亮——发光体、辉光、光斑的叠加语义
vec3 screen(vec3 a, vec3 b) { return 1.0 - (1.0 - a) * (1.0 - b); }

// add：直接相加——光污染版 screen，更猛更危险（过曝红线）
vec3 add(vec3 a, vec3 b) { return a + b; }

// multiply：正片叠底——叠影、阴影、暗色纹理
vec3 multiply(vec3 a, vec3 b) { return a * b; }

// overlay：叠加——亮者更亮暗者更暗，胶片「洗印感」
vec3 overlay(vec3 a, vec3 b) {
  return mix(2.0 * a * b,                      // 暗区：multiply
             1.0 - 2.0 * (1.0 - a) * (1.0 - b), // 亮区：screen
             step(0.5, a));                    // 按底色亮度分流
}
```

选型口诀：**发光体用 screen，叠影用 multiply，胶片感用 overlay**。add 看起来和 screen 像兄弟，差别在极端值：add 会把 (0.9, 0.9, 0.9) + (0.8, 0.8, 0.8) 推到 1.7（过曝白块），screen 压在 0.98——**光要亮不要曝**，这是 2.6 坑表第 3 行的配方版。

四种模式在四组典型输入下的输出对照——数值直觉比口诀更抗忘，add 一列就是过曝红线的直观展示：

| 输入 a, b | add | screen | multiply | overlay |
|-----------|------|--------|----------|---------|
| 0.9, 0.8（双亮） | **1.7 过曝白块** | 0.98 | 0.72 | 0.96 |
| 0.5, 0.5（双中灰） | 1.0（正好满格） | 0.75 | 0.25 | 0.50 |
| 0.2, 0.3（双暗） | 0.50 | 0.44 | **0.06 接近黑** | 0.12 |
| 0.9, 0.1（亮压暗） | 1.0 | 0.91 | 0.09 | 0.82 |

读表锚定三点：**screen 永远不超 add**（双亮时 0.98 对 1.7，差值随亮度放大——这就是你选 screen 的全部理由）；**multiply 对暗部不留情面**（0.2 × 0.3 = 0.06，叠影「压得实」来自这里，两张暗图相乘直接死黑）；**overlay 以底色 0.5 为分水岭**——同一对 0.9 / 0.8 它给 0.96（亮上加亮），0.2 / 0.3 给 0.12（暗上压暗），「洗印感」的数学结构就是这条分流。

这张表顺便回答「你什么时候还敢用 add」：纯黑背景上的粒子、火花、光点——add 的过曝只在双亮处发生，黑底上一层亮源永远凑不齐双亮，危险自然解除；两个亮层想叠，就换 screen。

## 参数化模板：电影感配方卡

四步的**顺序**是配方的一半，固定下来：

```glsl
// —— 电影感配方卡（顺序不可换）——
// 0. 你的画面：col 此时在线性空间
vec3 col = /* ……整个 Day 2 的产出…… */;

// 1. gamma：线性 → 感知（2.5 的「收尾」指线性空间的计算到此为止；配方里随后的对比/饱和都在感知空间做——顺序不可换）
col = pow(col, vec3(0.4545));

// 2. 对比：绕中点 0.5 拉伸 6%
col = (col - 0.5) * 1.06 + 0.5;

// 3. 饱和：向灰度收 10%——去数码味的关键一步
float luma = dot(col, vec3(0.299, 0.587, 0.114)); // 感知亮度权重
col = mix(vec3(luma), col, 0.9);

// 4. grain：颗粒（在 gamma 后，否则被校正吃掉——坑表第 1 行）
col += (hash21(gl_FragCoord.xy + u_time) - 0.5) * 0.04;

// 5. vignette：暗角收边（永远最后，它定义「画框」）
col *= 1.0 - 0.2 * pow(length(uv - 0.5), 2.0);

fragColor = vec4(clamp(col, 0.0, 1.0), 1.0); // 收尾 clamp：配方的安全带
```

**顺序就是配方**——每一步的数学前提是上一步的输出空间：gamma 前的对比拉伸会被 0.4545 的非线性挤变形；grain 放 gamma 前会被校正吃掉一半幅度；vignette 不在最后，「画框」就压不到最终对比上。背下这五行顺序（gamma → 对比 → 饱和 → grain → vignette），你的画面从「技术 demo」升进「成片」。

五步各自的「关掉」签名症状，你在 demo 06 里逐个开开关关时对着这张表看：

| 只关这一步 | 你立刻看到的症状 | 病根 |
|-----------|------------------|------|
| gamma | 暗部糊成一团、整体像蒙灰纱 | 0.2 的线性亮度只占感知曲线的 48%，不校正暗部全挤在左端 |
| 对比 | 画面平、中调挤在一起、主体不立 | 中灰附近的层次没被拉开 |
| 饱和（收 10%） | 数码味重、像手机直出 | 三通道各自鲜艳，缺胶片统一的收敛 |
| grain | 干净得像渲染图 | 零噪点的画面会被视网膜直接标记为「CG」 |
| vignette | 视线没有落点、四角与中心抢戏 | 边缘同亮，构图失去聚光画框 |

gamma 那一行的数值走查你可以整段背下——线性值过 `pow(x, 0.4545)` 后的锚点：

| 线性 | 0.05 | 0.2 | 0.5 | 0.9 |
|------|------|-----|-----|-----|
| 感知 | 0.26 | 0.48 | 0.73 | 0.95 |

**暗部被抬得最多**（0.05 抬了五倍，0.9 只抬 6%）——「gamma 一开暗部就活了」的算术来源就在这张小表里。vignette 的数值也顺手走一遍：k = 0.2 时四角只压 10%（角上 `length(uv - 0.5)` 最大 0.707，平方后 0.5，1 − 0.2 × 0.5 = 0.9）——**聚光感来自梯度的收束，不是绝对暗度**，这也是 k 不敢超 0.3 的原因：再压，边缘就开始肉眼可见地脏。

五步的默认值各有微调档，你的第一轮迭代可以在这几格里打转：gamma 0.4545 基本不动（sRGB 标准值，动了就是错的）；对比 1.03–1.12（再高开始丢暗部细节）；饱和 0.85–0.95；grain 0.03–0.06；vignette 0.1–0.3（k 三档表）。**除 gamma 外，其余四个都是风格旋钮**——gamma 是对错题，别的全是口味题，你改参数时的心理负担应该完全不同。

## How：demo 06 的收尾段回放

demo 06 的 fragment 尾部就是这张配方卡的逐行实例，加上 A/B 开关：

```glsl
// demo 06 尾部：配方卡 + 开关（uniform 由键盘切换，1.7 的事件桥）
if (u_fx_gamma  > 0.5) col = pow(col, vec3(0.4545));
if (u_fx_contrast > 0.5) col = (col - 0.5) * 1.06 + 0.5;
if (u_fx_sat    > 0.5) col = mix(vec3(dot(col, vec3(0.299, 0.587, 0.114))), col, 0.9);
if (u_fx_grain  > 0.5) col += (hash21(gl_FragCoord.xy + u_time) - 0.5) * 0.04;
if (u_fx_vig    > 0.5) col *= 1.0 - 0.2 * pow(length(uv - 0.5), 2.0);

fragColor = vec4(clamp(col, 0.0, 1.0), 1.0);
```

**开关按顺序逐个打开**是 demo 06 的正确看法：全关是「毛坯」，gamma 一开暗部活了，对比一开主体立了，饱和一收数码味散了，grain 一加像胶片了，vignette 一收就是成片。五步各值多少分，你的眼睛当场打分——这比任何参数表都有说服力。观察点回链：实例网站清单里 Orage 的首页颗粒与 Noomo 的暗部处理，就是这张配方卡在真实站点上的样子（幅度与顺序或有微调，骨架同源）。

配方卡的单文件版——底图用 2.5 的余弦调色板，五行配方压在后面，你 Day 2 写出的任何 col 都能替换第 0 步：

```glsl
#version 300 es
precision highp float;

uniform vec2  u_resolution;
uniform float u_time;
out vec4 fragColor;

float hash21(vec2 p) {                     // grain 的 seed：像素级唯一 + 每帧换
    vec3 p3 = fract(vec3(p.xyx) * 0.1031);
    p3 += dot(p3, p3.yzx + 33.33);
    return fract((p3.x + p3.y) * p3.z);
}

void main() {
    vec2 uv = gl_FragCoord.xy / u_resolution;
    // 0. 毛坯：2.5 的余弦调色板，随时间缓移
    vec3 col = 0.5 + 0.5 * cos(6.2831 * (uv.x + vec2(0.0, 0.33, 0.67)) + u_time * 0.2);
    // 1–5. 配方卡（顺序不可换）
    col = pow(col, vec3(0.4545));                                  // 1 gamma
    col = (col - 0.5) * 1.06 + 0.5;                                // 2 对比 +6%
    col = mix(vec3(dot(col, vec3(0.299, 0.587, 0.114))), col, 0.9); // 3 饱和收 10%
    col += (hash21(gl_FragCoord.xy + u_time) - 0.5) * 0.04;         // 4 grain 4%
    col *= 1.0 - 0.2 * pow(length(uv - 0.5), 2.0);                 // 5 vignette k=0.2
    fragColor = vec4(clamp(col, 0.0, 1.0), 1.0);                    // 安全带
}
```

你拿它做练习台：把五行逐行注释掉再恢复，对照上面「关掉签名症状」表核对自己的眼睛——五个来回之后，配方卡就从「背下来的」变成「看得出」的。改参数也在这里改：对比 1.06 换 1.12、grain 0.04 换 0.07 各跑一次，**每改一个数、只改一个数**，五分钟建立五个数值的手感库。

## 常见坑

| 症状 | 原因 |
|------|------|
| grain 时有时无、幅度飘忽 | grain 放在 gamma 前——被 0.4545 的非线性校正吃掉一半；顺序纪律：gamma 是配方第一步 |
| 四角里有一角特别暗 | vignette 用了居中域 `p` 没用 `uv`：中心在 (0,0) 不在 (0.5,0.5)，暗角偏心；vignette 认 0–1 域 |
| 饱和度拉到 1.3，画面塑料感 | 数码味的来源——正确方向是**收**（0.85–0.95）：向灰度 mix 回去，不是向外拉 |
| 对比放在 grain 之后，颗粒变粗盐 | 对比会放大 grain 幅度：颗粒应该在「对比定型后」进场，否则被拉伸成粗盐粒 |
| 发光体叠 add 后一片死白 | add 无上限：换 screen（`1 - (1-a)(1-b)`），亮部自动压在 1 以内——光要亮不要曝 |
| 配方各行顺序随机 | 每步的前提是上一步的空间（线性/感知）：背下 gamma → 对比 → 饱和 → grain → vignette，别自由发挥 |
| Retina 屏上颗粒比外接屏细密一倍 | grain 的 seed 是 gl_FragCoord（物理像素），颗粒密度跟 DPR 走；跨设备观感要统一，seed 按 u_resolution 归一化，或接受差异 |
| 饱和一收整张图发紫 | luma 权重写成了三等分 (1/3, 1/3, 1/3)：等权灰度压低绿通道、抬高蓝通道；必须 (0.299, 0.587, 0.114) |
| 页面挂几小时后 grain 结成色块 | u_time 无界增长，hash 里 fract 的浮点精度被大数吃掉；给 u_time 收圈（JS 侧 % 60，或 shader 里 mod(u_time, 60.0)） |
