# 2.2 坐标变换：旋转矩阵、fract 平铺与极坐标图案

> Day 2 · 模块 2 · 约 50 分钟
> 理论对照：《WebGPU 三天实战课程》2.1「2D 与 3D 空间变换」——矩阵推导在那里逐个展开（[2.1-2D与3D空间变换.md](../../../webgpu/讲义/day2-渲染进阶与GPU计算/2.1-2D与3D空间变换.md)）；本篇只讲 2D 创意图最常用的三个套路；《GAMES101》03-变换是矩阵的数学原籍（[03-变换.md](../../../../计算机图形学/GAMES101/03-变换.md)）

形状会画了，但它们钉死在屏幕中央——一枚圆、一个方，孤零零地摆着。真实的图案世界是什么样？六边形网格铺满整屏、放射条纹绕中心旋转、十二重花瓣层层嵌套。差距不在形状库，在坐标：**变换的是坐标，不是形状**。这一句是本篇的全部主旨，读懂它，图案世界的大门就开了。

## 黄金法则：变换坐标，而不是变换形状

你写过无数遍 CSS `transform: translate(20px) rotate(45deg)`——变换的是元素，坐标系不动。GLSL 的方向反过来：形状函数一个字不动，喂给它的坐标先过一道变换。想让圆往右移 0.2，不是「把圆画到右边」，是「把坐标往左减 0.2 再问 SDF」：

```glsl
// 口诀：你想让形状往右，就把坐标往左
float d = sdCircle(p - vec2(0.2, 0.0), 0.3); // 圆心出现在 (0.2, 0)
```

为什么反着来？因为 fragment shader 里没有「元素」可以抓——每个像素是独立执行的函数调用，你唯一能改写的是它的输入 `p`。这不是别扭，是解放：坐标变换是纯函数，可以任意复合、嵌套、按格子重组，CSS transform 的思维搬过来反而是天花板。**坐标域是你的画布前的画布**——这句话在 2.4 domain warping 会升华为整套噪声美学。

## mat2 旋转：手写，就一次

2D 旋转矩阵四项三角函数，webgpu 课推导过（列主序的坑也在那边踩过），这里直接给课程版：

```glsl
// 2D 旋转矩阵：a 是弧度。手写这一次，之后全是调它
mat2 rot(float a) {
  float c = cos(a), s = sin(a);
  return mat2(c, -s,
              s,  c);   // 列主序 R(-a)：坐标顺时针转——正是 1.2 背的 R(θ) 的转置
}

// 用法：p 先顺时针转 45°（R(-a)），再喂给任何 SDF——形状看起来逆时针转 45°
vec2 pr = rot(0.7854) * p;
float d = sdBox(pr, vec2(0.2));
```

旋转随时间走，就是 1.6 的时间驱动：`rot(u_time * 0.5)` 让方块每秒转半圈。注意方向感：矩阵转的是坐标，画面上的形状朝反方向转——黄金法则的又一次显形。想让形状顺时针，坐标就逆时针。

你调图案时九成的旋转落在五个角度里，弧度值直接背下来，省得每次现算：

| 角度 | 弧度 | cos | sin | 典型用途 |
|------|------|-----|-----|---------|
| 15° | 0.2618 | 0.966 | 0.259 | 卡片微倾：打破横平竖直的模板感 |
| 30° | 0.5236 | 0.866 | 0.500 | 斜切分割线、条纹背景 |
| 45° | 0.7854 | 0.707 | 0.707 | 方块转菱形、米字纹 |
| 60° | 1.0472 | 0.500 | 0.866 | 三角网格的伴生角 |
| 90° | 1.5708 | 0.000 | 1.000 | 坐标轴互换：x 与 y 对调 |

90° 这行单独记：cos 归零、sin 归一，`rot(1.5708)` 退化成一次纯粹的轴交换——拿它验证矩阵写没写反最省事（转完 `pr.x` 应等于 `p.y`、`pr.y` 应等于 `-p.x`）。角度换弧度除以 57.2958（180/π），GLSL 的三角函数只吃弧度，这个换算你会用到课程结束。

## 平移与缩放

平移是减法，缩放是除法，两者各有一行和一个陷阱：

```glsl
// 平移：形状往 +center 方向挪，坐标减 center
float d = sdCircle(p - center, r);

// 缩放：想让形状放大 2 倍，坐标除 2——除法世界里一切都是反的
float d = sdBox(p / 2.0, b) * 2.0; // 乘回 2.0：距离场量纲要还原

// 镜像：abs 是最便宜的对称——x 轴对称只花一个绝对值
float d = sdCircle(vec2(abs(p.x), p.y) - vec2(0.3, 0.0), 0.15);
// 画一次，右边自动出现一份镜像——「半张画布画两份」
```

`p / 2.0` 后距离场的单位被拉宽了——除法之后的距离是「缩放后世界」的距离，想要真实世界量纲（描边、辉光不被放大），记得 `* 2.0` 乘回来。这个细节 2.6 讲光照带宽、2.8 讲收尾时还会回来咬人，先在这里立牌。

## fract 平铺：一块瓷砖铺满墙

单幅图案的世界观是「一张画」，平铺的世界观是「无限网格」。两行代码完成世界观切换：

```glsl
// 平铺三件套：乘频率 → 取格号 → 取格内坐标
float n = 6.0;                          // 6×6 的墙
vec2 g = p * n;                          // 世界坐标换成「格子域」
vec2 id = floor(g);                      // 格子编号：(0,0)(1,0)…(-2,3)…
vec2 f = fract(g) - 0.5;                 // 格内坐标：居中到 -0.5..0.5

// 每格画同样的圆 → 六六三十六枚圆
float d = sdCircle(f, 0.2);

// 每格画不同的圆 → 用 id 参与随机（2.3 的钩子）
float r = 0.1 + 0.15 * hash21(id);       // 半径由格号决定——「窗灯」
```

`id` 与 `f` 的分工是平铺的全部：`id` 是「这块瓷砖是谁」（决定随机性：颜色、半径、相位），`f` 是「瓷砖内部长什么样」（决定图案本身）。**先分格再画，图案的世界观从单幅变无限**——Orage 首页的网格数据包、城市立面的窗灯、六边形蜂窝，全部建立在这两行上。忘了 `fract(g) - 0.5` 的减 0.5，图案会集体贴在格子左下角（常见坑表第 2 行）。

格内坐标别忘了它仍是居中域的缩放版——`f` 的 -0.5..0.5 与外层 `p` 的 -1..1 是两个量纲，fwidth 抗锯齿在 `f` 上算出来的过渡带是格内像素宽，直接用不会错。

平铺、旋转、时间三件套拼成第一个完整可跑的程序——每块瓷砖独立旋转的「风车墙」：

```glsl
#version 300 es
precision highp float;

uniform vec2 u_resolution;
uniform float u_time;

out vec4 fragColor;

mat2 rot(float a) { float c = cos(a), s = sin(a); return mat2(c, -s, s, c); }
float hash21(vec2 p) { p = fract(p * vec2(234.34, 435.345)); p += dot(p, p + 34.23); return fract(p.x * p.y); }
float sdBox(vec2 p, vec2 b) { vec2 d = abs(p) - b; return length(max(d, 0.0)) + min(max(d.x, d.y), 0.0); }

void main() {
  vec2 p = (gl_FragCoord.xy / u_resolution) * 2.0 - 1.0;
  vec2 g = p * 5.0;                        // 5×5 瓷砖墙
  vec2 id = floor(g);
  vec2 f = fract(g) - 0.5;                 // 格内居中域：旋转发生在这里
  float h = hash21(id);                    // 每格的命运号：随机属性只能挂在 id 上（2.3 展开）
  vec2 pr = rot(u_time * 0.5 + h * 6.2831853) * f; // 相位错开：各转各的
  float d = sdBox(pr, vec2(0.2));
  vec3 col = vec3(0.93, 0.95, 0.9) * (1.0 - smoothstep(0.0, 0.015, abs(d)));
  fragColor = vec4(col, 1.0);
}
```

盯住旋转发生在哪一层域：`rot` 吃的是 `f` 不是 `p`——格内旋转，格子线纹丝不动。把 `rot` 挪到 `p` 上，整面墙连网格一起转，气质从「风车墙」变成「转动的屏幕」，变换挂在哪层域就是画面的哪种性格。`h * 6.2831853` 给每格发一个不同的起步角，25 个方块永远不同相——1.6 相位错峰在格子域的直接应用。描边用 `abs(d)`：距离场取绝对值后内外两侧一起亮，0.015 宽的过渡带天然抗锯齿。

## 极坐标：从方格到放射

把 `f` 换成 `(angle, radius)`，瓷砖从方的变成扇形——极坐标是平铺的孪生兄弟：

```glsl
// 极坐标换算：length 给半径，atan 给角度
float r = length(p);
float angle = atan(p.y, p.x);          // -π..π，圆心处无定义（坑表第 3 行）

// 放射条纹：角度域上的 step——N 根辐条
float spokes = step(0.5, fract(angle * 12.0 / 6.2831853));

// N 重扇区镜像：昨天 challenge 曼陀罗的公式，今天正式补课
float sector = 6.2831853 / 12.0;       // 12 重
float a = mod(angle, sector);          // 折进一个扇区
a = abs(a - sector * 0.5);             // 对扇区中线镜像
// 现在任何 f(a) 的图案自动重复 12 次——花瓣、辐条、齿轮
```

曼陀罗公式的直觉：`mod` 把整圈角度折进一个扇区（十二分之一圈），`abs` 再对扇区中线对折一次——你只画二十四分之一的图案，对称性替你复印十一份、再对折镜像十二份。昨天的 C 档作业里你手抄过这五行；今天的作业是理解它为什么成立：**对称 = 折叠，折叠 = mod + abs**，两个函数买无限对称。

五行公式接上形状，就是昨天 C 档的完整复刻——放射辐条 + 花瓣弧 + 圆心避让，一个可直接跑的极坐标图案：

```glsl
#version 300 es
precision highp float;

uniform vec2 u_resolution;

out vec4 fragColor;

void main() {
  vec2 p = (gl_FragCoord.xy / u_resolution) * 2.0 - 1.0;
  float r = length(p);
  float a = atan(p.y, p.x);               // -π..π：极坐标的第二根轴
  float sector = 6.2831853 / 12.0;        // 整圈折成十二分之一
  float fa = abs(mod(a, sector) - sector * 0.5); // 对扇区中线对折：对称的全部
  float spoke = (1.0 - smoothstep(0.0, 0.06, fa)) * (1.0 - smoothstep(0.55, 0.85, r));
  float petal = 1.0 - smoothstep(0.0, 0.08, abs(r - 0.5 - 0.12 * cos(fa * 6.0)));
  vec3 col = vec3(0.12, 0.5, 0.62) * (spoke + petal);
  col += vec3(0.95) * (1.0 - smoothstep(0.0, 0.04, r)); // 圆心盖实心点：兼遮 atan 无定义的拉丝
  fragColor = vec4(col, 1.0);
}
```

改一个数字就换一朵花：`fa * 6.0` 是花瓣在扇区内的起伏次数、`0.12` 是起伏幅度、`0.5` 是花瓣环的半径档——极坐标图案的调参就这三件，改之前先猜画面再验证，极坐标直觉是这么喂出来的。`cos(fa * 6.0)` 吃的是折叠后的角度：扇区内函数只写一遍，12 个扇区各自复印，这就是「买对称」的结算方式。

## How：demo 02 的平铺骨架精讲

demo 02「voronoi 细胞」的主菜在 2.3，但它的骨架——平铺格子——是本讲的直接产物。先看它的坐标段，voronoi 之前你就能看懂的前一半：

```glsl
// demo 02 fragment 的坐标准备段（voronoi 逻辑在 2.3 展开）
vec2 uv = gl_FragCoord.xy / u_resolution;
float aspect = u_resolution.x / u_resolution.y;
vec2 p = (uv * 2.0 - 1.0) * vec2(aspect, 1.0); // 先居中、再乘宽高比——顺序反了原点会偏离屏幕中心

// 平铺：格子域上再取 id/f 双坐标
float n = 3.0;                      // 3×3 大格——voronoi 要在粗格上找邻居
vec2 g = p * n;
vec2 id = floor(g);                  // 细胞编号：voronoi 的「领地」从这来
vec2 f = fract(g) - 0.5;             // 格内坐标：后续相对格心画距离
```

平铺的 `id/f` 双坐标分解在 voronoi 里承担了「领地编号 / 领地内几何」的分工——2.3 会在 `id` 上撒随机点、在 `f` 上算距离，本讲的骨架直接被扛走。这就是讲义排布的用意：**平铺是 voronoi 的地基，voronoi 是平铺的第一个客户**。

顺带看 demo 01「SDF 动物园」的分格（How 段写过的 `grid/g/id2/cell` 四行）——它也是本讲的平铺，只是格子数少（2×3）、格内画的是 SDF 形状而不是细胞。两份 demo 合起来，平铺的三种客户（陈列 / 细胞 / 瓷砖）你各过了一眼。

## 常见坑

| 症状 | 原因 |
|------|------|
| 形状旋转方向与预期相反 | mat2 乘的是坐标不是形状——坐标逆时针，画面顺时针；要么调矩阵符号，要么接受「反着写才对」的黄金法则 |
| 平铺图案全部贴在格子左下角 | `fract(g) - 0.5` 忘了减 0.5：fract 输出 0..1，原点在角上；SDF 全要居中域 |
| 画面中心一条拉丝 / 亮点 | 极坐标 `atan(p.y, p.x)` 在圆心 (0,0) 无定义——画一个避让半径（`r < 0.01` 时给固定角或直接不画） |
| 缩放后描边粗细全变了 | `p / s` 把距离场量纲也除了——SDF 结果要 `* s` 乘回来，否则 2.6 的光照带宽跟着缩放漂移 |
| 先平移再旋转，形状绕着奇怪的点转 | 变换顺序不可交换：想绕点 c 转，标准序是 `rot(a) * (p - c)`（先平到原点再转）；`rot(a) * p - c` 是绕原点转完再平走 |
| 12 重对称数出来是 11 或 13 | `mod(angle, sector)` 的 angle 没先做整体旋转（`angle - u_time * speed`），或者镜像用的中线算错半个 sector |
| 圆被压成椭圆、旋转后整幅图案被剪切斜掉 | 宽高比乘在了旋转之后——正确序是先 `p * vec2(aspect, 1.0)` 回到方形域再旋转；旋转后才拉伸等于往斜的方向拽，格子全变平行四边形 |
| 负半轴的格子编号和预想对不上 | `fract(-0.2)` 返回 0.8 而不是 -0.2 或 0（GLSL 定义 x - floor(x)，输出恒在 0..1）；floor 也向负无穷取整——JS 的 `parseInt`/`|0` 截断直觉在这里全错，负坐标格子其实工作正常，别按截断去修 |
| 极坐标图案整体转了 90° | `atan(p.x, p.y)` 参数写反——正确序先 y 后 x（atan2 语义）；反着写等于角度取了 π/2 - a，全部图案相位错四分之一圈 |

## Checkpoint

- 能手写 `mat2 rot(a)`，并解释为什么「变换坐标」与「变换形状」方向相反
- 能默写平铺三件套（`floor` 取号 / `fract` 取内 / 减 0.5 居中），并说出 `id` 与 `f` 各自决定什么
- 能用三行写出「N 重扇区镜像」（`mod` + `abs`），并解释它为什么等效于 2N 重视觉对称
- 能说出缩放后 SDF 量纲要乘回的原委，以及忘记时最先露馅的视觉症状
- 能画出「绕点 c 旋转」的正确复合顺序，并指出顺序反了会看到什么
