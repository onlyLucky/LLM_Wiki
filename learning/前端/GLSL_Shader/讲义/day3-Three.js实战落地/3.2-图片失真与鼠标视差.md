# 3.2 图片失真与鼠标视差：每一张获奖站图卡的下沉手法

> Day 3 · 模块 2 · 约 60 分钟
> 理论对照：[2.7 纹理：把图片交给GPU之后](../day2-片段着色器视觉算法/2.7-纹理：把图片交给GPU之后.md)——采样与失真的 GLSL 基础全在那一讲，本篇是它的工程完整版

CyD 的作品卡片、Orage 的网格视频格——鼠标滑过，图片像液体一样从光标下让开，边缘泛起一层色差，移开后一切归于平静。这种效果在获奖站的图卡上出现频率高到近乎标配，但拆开看只有三件事：**纹理**（图怎么进 GPU）、**失真量**（UV 怎么被掰弯）、**视差**（层与层怎么错速）。前两件 Day 2 已经备好了零件（2.7 的采样、2.4 的噪声），第三件只是 1.7 的 lerp 换个宿主。今天把工程侧全部接通。

## TextureLoader：Three.js 的一行上传

Day 1 你手写过纹理上传的五步仪式（createTexture → pixelStorei → texImage2D → 采样参数 → 绑定 uniform）。Three.js 把它压成一行：

```ts
const loader = new THREE.TextureLoader();
const texture = loader.load('/img/card.jpg', (tex) => {
  tex.colorSpace = THREE.SRGBColorSpace; // 照片类贴图必设，见下
  material.uniforms.u_tex.value = tex;
});
```

load 是异步的：回调触发前 uniform 里还没有有效纹理。demo 02 干脆绕开——**程序化海报离屏 canvas 直出 CanvasTexture**（同步、零加载态），把「先渲染黑块再突然出现」的尴尬掐死在源头；真用 TextureLoader 装真图时，就在全部回调到齐后再启动渲染循环。

两个必答的工程问题：

- **colorSpace**：three 0.152 之后，贴图默认被当作线性数据。不设 `tex.colorSpace = THREE.SRGBColorSpace`，照片会发灰——像素值被当成线性亮度直接进了渲染管线。这是 3.5 OutputPass 话题的伏笔，先记住「照片必设」。
- **CORS**：`file://` 直接双击打开 HTML 会因跨域读图失败；走 vite 的本地服务（`public/` 目录）没有此问题——课程所有 demo 都在 dev server 里跑，天然规避。

## 位移图思路：把 Day 2 噪声接到 UV 上

失真的全部本质是 2.7 讲过的那三行，改动只有一个——采样前把 UV 掰一下：

```glsl
vec2 flow = /* 从哪来：本节主角 */;
vec2 distortedUv = v_uv + flow * u_warp;
vec3 col = texture2D(u_tex, distortedUv).rgb;
```

`flow` 从哪来，是失真效果的选型题。三种方案各有领地：

| 方案 | flow 来源 | 手感 | 成本 |
|------|----------|------|------|
| 程序化噪声 | `fbm(v_uv * k + u_time * 0.1)` | 全图液体感——2.4 丝绸的图卡版 | 片元内 4–5 倍频 |
| 数据纹理 | displacement map 的 G 通道存方向 | 精确可控，美术可以用画笔参与 | 一张额外贴图 |
| 鼠标局部场 | 光标距离衰减 × 径向方向 | 波纹从光标辐射（demo 02 选它） | 最便宜，零贴图 |

方案三的核心一行——高斯衰减让失真只在光标邻域活着：

```glsl
float d = distance(aspectCorrect(v_uv), aspectCorrect(u_mouse));
float field = exp(-d * d * 14.0); // 光标邻域 1，远处 0
vec2 flow = (v_uv - u_mouse) * field;
```

`14.0` 不是拍脑袋的魔法数——你把 d 代几个值进 `exp(-d * d * 14.0)`，影响半径自己现形：

| d（光标距离，uv 单位） | field | 视觉状态 |
|------|------|------|
| 0.0 | 1.00 | 光标正下方，全力失真 |
| 0.15 | 0.73 | 主失真区 |
| 0.30 | 0.29 | 过渡带 |
| 0.50 | 0.03 | 基本归零 |
| 0.70 | 0.001 | 完全无感 |

表里读出两个结论。**影响半径约半个 uv 宽**：0.5 处只剩 3%，再远可当零。**标定手法是「先定半径、再解 k」**：把 field 跌到 5% 的距离定义为影响半径 R，解出 k ≈ 3 / R²——想要 R = 0.35 的紧凑光斑就取 k = 25，想要整图流动感就取 k = 4。手感不对时你调的从来不是失真量 u_warp，是这张表上的 k。

然后是 **hover 语义**——图卡失真有没有质感，九成取决于这个 uniform 的管理方式。`u_hover` 是 0→1 的**渐进值**，不是布尔开关：

```ts
// three 侧的 lerp：1.7 的手感原样搬运，宿主从 gl.uniform1f 换成 .value
hoverGoal = hovered ? 1 : 0;
hover += (hoverGoal - hover) * 0.08; // 帧循环里，进 shader 的永远是这个值
material.uniforms.u_hover.value = hover;
```

「hover 是强度，不是开关」——把这句写进肌肉记忆，图卡交互就赢了一半。

0.08 这个系数值多少秒，你要会算：60fps 下每帧追掉剩余距离的 8%，到达 95% 需要 ln(0.05) / ln(0.92) ≈ 36 帧——约 0.6 秒。通用换算是「**到位帧数 ≈ 3 / lerp 系数**」：0.05 → 60 帧（1 秒，跟手偏粘）、0.08 → 36 帧（从容）、0.15 → 20 帧（0.33 秒，果断）。这笔账三天通用——3.3 的 Lenis `lerp: 0.1`（约 30 帧到位）、3.4 的粒子回流，都是同一张换算表的换行。你定手感时先定秒数、再反查系数，比盲调快十倍。

## RGB shift：色差三行的生意

2.7 的色差三行原样迁移，只多一个联动——shift 量乘上 hover 强度：

```glsl
float shift = 0.012 * u_hover; // 最大 1.2%，hover 按多深歪多远
float r = texture2D(u_tex, distortedUv + vec2(shift, 0.0)).r;
float g = texture2D(u_tex, distortedUv).g;              // 中心不动，作锚
float b = texture2D(u_tex, distortedUv - vec2(shift, 0.0)).b;
vec3 col = vec3(r, g, b);
```

g 通道取中心采样是刻意的：三个通道里总要有一个锚定原位，色差才读作「镜头色散」而不是「整体糊掉」。「失真是一种强调」——shift 常驻是坏屏，shift 乘 hover 是按下快门的呼吸感。两者差一个乘法，差的是整个质感层级。

## 视差层：三层速度差

视差的参数表直接复用 Day 2 challenge 的定标：**前景图 5% / 标题反方向 3% / 背景 2%**——1:2 幅度比是「分层可感」的下限，再小眼睛分辨不出层次。

正确的实现姿势又双叒是 lerp——**偏移目标值，而不是直接偏移**：

```ts
// 前景：目标是鼠标偏移的 5%，实际值每帧追 8%
const targetX = (mouse.x - 0.5) * 0.05;
parallaxX += (targetX - parallaxX) * 0.08;
material.uniforms.u_parallax.value = parallaxX;
```

三层共用同一个鼠标输入、系数带符号（前景正、标题负）——速度差就是层次本身。落地时两层宿主：DOM 层（页头标题）用 `transform: translate3d`，shader 层（图卡内容）传 `u_parallax` uniform——demo 02 两者都用了，你可以对照着看同一份输入怎么长成两种偏移。

## DPR 与纹理尺寸

两条性能与画质的老规矩，在纹理场景下再确认一遍：

- **DPR 红线**：`renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`——总纲性能红线，图卡场景没有任何豁免理由。
- **各向异性过滤**：一行的事，斜视角清晰度天差地别（图卡墙滚动时尤其明显）：

```ts
tex.anisotropy = renderer.capabilities.getMaxAnisotropy();
```

- **尺寸**：WebGL1 时代非 2 的幂贴图不能开 mipmap / repeat；WebGL2 已完整支持（demo 02 自己就是 1024×1280）。对齐 2 的幂如今只是惯例，不再是硬约束。

## How：demo 02「hover 失真图卡」逐段精讲

规格：4:5 图卡居中、hover 时 fbm 波纹从光标扩散（0.8s easeOutCubic）、RGB shift 最大 1.2%、暗角 12% + grain 3%、离开时缓动回零。逐段拆：

**几何与分工**：PerspectiveCamera + PlaneGeometry(3, 3.75)（严格 4:5），页头与角标仍是 DOM——「3D 只画图卡本体，DOM 管版式」。plane 尺寸按图片比例定，从根上避开拉伸坑。

**波纹扩散**：波纹半径是一个由 JS 驱动的 uniform——触发 hover 时记下 t0，之后每帧：

```ts
const p = Math.min((now - t0) / 800, 1);          // 0.8s 归一
const eased = 1 - Math.pow(1 - p, 3);             // easeOutCubic
material.uniforms.u_ripple.value = eased * 0.9;   // 波纹最大扫过 90% 半径
```

shader 侧把半径转成环形失真场，边缘用 fbm 抖出液体感：

```glsl
float d = distance(ac(v_uv), ac(u_mouse));        // ac()：4:5 的宽高比修正
float ring = smoothstep(u_ripple, u_ripple - 0.18, d) * step(d, u_ripple);
vec2 flow = normalize(v_uv - u_mouse + 1e-4)
          * ring * fbm(v_uv * 6.0 + u_time * 0.3) * 0.35 * u_hover;
```

`ring` 是「以光标为圆心、半径随时间扩张的环带」，`fbm` 给环带边缘注入噪声——两者相乘，波纹就既是几何的（从光标扩散）又是液体的（边缘不规则）。

**离开回零**：hovered 翻 false 后，`u_hover` 以 0.08 的 lerp 慢慢归零，`u_ripple` 保持不动——波纹不再扩张、失真随 hover 淡出，两组节奏叠加出「潮水退去」的收尾。

**边缘微光**：图卡矩形 sdBox 距离 + glow（2.6 手法原样复用），hover 时亮度乘 `0.5 + u_hover * 0.5`——微光也是 hover 联动的一环。

**收尾两步**：grain 3% + vignette 12%（2.8 配方卡的其中两步）——图卡场景不需要全套五步，两步足够把「数字味」压下去。

**hover 判定的正路是帧内 raycast，不是指针事件**。`mouseenter`/`mouseleave` 在指针快速划出 canvas、窗口失焦、指针被别的元素捕获时会漏发——漏发一次，hover 焊死在 1，失真永不退场。demo 02 的做法是把判定搬进帧循环，每帧重判，事件只负责报坐标：

```ts
const raycaster = new THREE.Raycaster();
const ndc = new THREE.Vector2(-2, -2); // 屏外初值：未移动前必不命中
let hovered = false;
let t0 = 0;

addEventListener('pointermove', (e) => {
  // 像素 → NDC（raycaster 吃这个）；uv 版本给 shader，y 要翻——uv 左下原点、clientY 顶部原点
  ndc.set((e.clientX / innerWidth) * 2 - 1, -(e.clientY / innerHeight) * 2 + 1);
  material.uniforms.u_mouse.value.set(e.clientX / innerWidth, 1 - e.clientY / innerHeight);
});

// 帧循环内：命中与否每帧现算，漏一次事件也只错一帧
raycaster.setFromCamera(ndc, camera);
const hit = raycaster.intersectObject(card).length > 0;
if (hit && !hovered) t0 = performance.now(); // 边沿触发：进入的那帧才记波纹起点
hovered = hit;
```

状态归属帧循环之后，漏事件的最坏后果从「焊死」降级为「错一帧」——同一份纪律 3.4 会再演一遍（那边连状态都没有，鼠标避让纯函数直算）。

**fragment 的完整出口**把本讲零件串成一条链（GLSL1 风格，3.1 风格表：varying 接收、texture2D 采样、gl_FragColor 出口）：

```glsl
varying vec2 v_uv;
uniform sampler2D u_tex;
uniform vec2 u_mouse;
uniform float u_hover;
uniform float u_ripple;
uniform float u_time;

/* fbm / ac / hash 定义在前——GLSL 无函数提升（1.3），main 之前必须就位 */

void main() {
  // 失真链：波纹环带 × fbm 液体感 × hover 强度（How 节四行原样）
  float d = distance(ac(v_uv), ac(u_mouse));
  float ring = smoothstep(u_ripple, u_ripple - 0.18, d) * step(d, u_ripple);
  vec2 flow = normalize(v_uv - u_mouse + 1e-4)
            * ring * fbm(v_uv * 6.0 + u_time * 0.3) * 0.35 * u_hover;
  vec2 duv = v_uv + flow;

  // RGB shift：g 通道锚定中心，r/b 差动（本讲第 3 节三行）
  float shift = 0.012 * u_hover;
  vec3 col = vec3(
    texture2D(u_tex, duv + vec2(shift, 0.0)).r,
    texture2D(u_tex, duv).g,
    texture2D(u_tex, duv - vec2(shift, 0.0)).b);

  // 收尾两步：grain 3% + vignette 12%（2.8 数值原样）
  float vig = 1.0 - smoothstep(0.4, 0.95, distance(v_uv, vec2(0.5))) * 0.12;
  col = (col + (hash(v_uv * 512.0 + u_time * 60.0) - 0.5) * 0.03) * vig;

  gl_FragColor = vec4(col, 1.0);
}
```

从上往下读是「失真 → 色差 → 收尾」三幕，每一幕的零件都能在前文与 2.4 / 2.8 找到出处。你写自己的图卡时改的只有三处：flow 的来源、shift 的方向、收尾的配比——链路本身是通用的。

## 常见坑

| 症状 | 原因 |
|------|------|
| hover 一闪而过、生硬 | `u_hover` 直接 0/1 切换——必须 lerp 渐进，进 shader 的永远是浮点强度 |
| 图片平时就有细碎扭曲 | 失真量没乘 hover 强度——常驻失真像坏屏，失真必须乘 `u_hover` |
| 图被拉扁 | PlaneGeometry 宽高比与纹理宽高比不一致——plane 尺寸按图片比例定 |
| 图片上下颠倒 | three 的 TextureLoader 默认 `flipY = true`（与原生 WebGL 的 flipY false 相反）——正着用就别动它；从原生迁来的直觉会说反 |
| 照片发灰 | 忘设 `tex.colorSpace = THREE.SRGBColorSpace`——0.152+ 贴图默认按线性数据处理 |
| 斜视角下图卡糊 | 没设 anisotropy——一行换来的清晰度别省 |
| 波纹在 4:5 图卡上变成椭圆 | distance 直接拿 v_uv 与 u_mouse 算——uv 归一化后横纵各 0.1 的实际长度不等，横向坐标先除 aspect 再算距离（ac 的职责） |
| 色差时图卡左右边缘拉出彩条 | 偏移后 UV 越出 [0,1]，THREE 默认 ClampToEdge 把边缘一列像素拉成条纹——进采样器前 clamp UV，或纹理设 RepeatWrapping |
| 切走标签再回来、失真焊在半程 | rAF 停摆期间 lerp 冻结在切走瞬间的值——帧循环把 dt 封顶（如 0.05s），跳帧只丢时间不丢状态 |

## Checkpoint

- 能默写「噪声→UV 偏移→采样」三行链路，并说出 flow 的三种来源与各自领地
- 能背视差三层参数表（5 / 3 / 2）与「目标位 lerp」的正确实现
- 能解释 hover 为什么必须 lerp：强度语义（失真量要连续）+ 视觉连贯（跳变像故障）
- 能说出 flipY 与 colorSpace 在 three 与原生里的默认值差异
- 能换算 lerp 手感账：到位帧数 ≈ 3 / 系数，0.08 ≈ 0.6 秒——先定秒数再反查系数
