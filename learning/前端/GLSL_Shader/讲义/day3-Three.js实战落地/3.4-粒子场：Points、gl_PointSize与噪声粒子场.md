# 3.4 粒子场：Day 2 噪声的 3D 化身

> Day 3 · 模块 4 · 约 55 分钟
> 理论对照：[WebGPU 3.3「TSL计算与数据流」](../../../webgpu/讲义/day3-Three.js桥接/3.3-TSL计算与数据流.md)——GPGPU 路线的粒子（计算着色器驱动）；本课讲 GLSL 顶点着色器路线（无状态、更简单，中小规模首选）

iyO 首页的标题文字由几万个粒子聚合而成，igloo 的 footer 是一整片会呼吸的星尘。实现路线有两条：**GPU 计算状态**（webgpu 课的 3.3 见过：两份 buffer ping-pong 反馈，粒子有「记忆」）和**顶点着色器即时计算**（本课）：每个粒子每帧只拿「出生位置 + 当前时间」算出当下位置——不需要 ping-pong、没有历史状态，两万粒子轻松跑满 60fps。代价是粒子不能「记住」自己上一帧在哪，但创意粒子场九成场景根本不需要记忆。

## Points：一个几何类型，两种着色器分工

`THREE.Points` 是与 Mesh 并列的绘制类型：Mesh 把顶点连成三角形，Points 把每个顶点画成一个点精灵。它的 vertexShader / fragmentShader 分工很干净：

- **顶点着色器**：决定每个粒子「在哪、多大」——即时计算噪声位移，输出 `gl_Position` 与 `gl_PointSize`；
- **片元着色器**：决定每个点精灵「长什么样」——裁圆、调色、透明度。

position attribute 里存的不是最终位置，而是**出生位置**（一次性生成、永不更新）：

```ts
const N = 20000;
const positions = new Float32Array(N * 3);
for (let i = 0; i < N; i++) {
  // 球壳偏内分布：方向随机 + 半径带偏置（中心密外围疏）
  const dir = new THREE.Vector3().randomDirection();
  const r = 0.55 + Math.pow(Math.random(), 2.2) * 0.65;
  positions.set([dir.x * r, dir.y * r, dir.z * r], i * 3);
}
const geometry = new THREE.BufferGeometry();
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3));
```

这就是 1.6 纯函数哲学的 3D 完全体：**无状态动画**——每帧的输入只有（出生位，u_time，u_mouse），输出是当下位置，没有历史包袱。断帧、跳帧、回到过去都无所谓，画面永远自洽。

## gl_PointSize：粒子的体积感

顶点着色器多了一个可写输出：`gl_PointSize`（像素直径）。直接写常量是新手姿势——远近一样大，一眼假。透视衰减一行：

```glsl
vec4 mvPosition = modelViewMatrix * vec4(pos, 1.0);
gl_PointSize = u_size * (300.0 / -mvPosition.z); // 近大远小
gl_Position = projectionMatrix * mvPosition;
```

`300.0` 是标定常数：把典型观看距离（mvPosition.z 的绝对值）代进去，让近处粒子落在目标像素直径上，再按手感微调。它和 u_size 一起构成「基准尺寸」，但只有衰减项负责空间感。

片元里把方点裁成圆点——`gl_PointCoord` 是点精灵内部的 0–1 坐标（左上原点）：

```glsl
float d = length(gl_PointCoord - 0.5);
float alpha = smoothstep(0.5, 0.32, d); // 裁圆 + 软边（不是硬边 if）
if (alpha < 0.01) discard;
gl_FragColor = vec4(u_color, alpha * u_opacity);
```

`smoothstep(0.5, 0.32, d)` 同时完成两件事：d > 0.5 处裁掉（圆），0.32–0.5 之间渐隐（软边）。软边是 additive 发光的前提——硬边圆点叠起来会有明显颗粒感。

### 内置对照：PointsMaterial 的 sizeAttenuation

从内置 PointsMaterial 迁过来的你，最需要对齐的就是这个开关：内置的 `sizeAttenuation: true` 与你手写的衰减行是**同一条公式**。three 源码里 points 顶点着色器写的是 `gl_PointSize = size * (scale / -mvPosition.z)`，其中 `scale = 0.5 × 画布高`、由渲染器维护。逐项对照：

| | PointsMaterial（内置） | ShaderMaterial（手写） |
|---|---|---|
| 尺寸入口 | `size` + `sizeAttenuation: true` | `u_size` × 衰减项 |
| 衰减公式 | `size * (0.5 × 画布高 / -mvPosition.z)` | `u_size * (300.0 / -mvPosition.z)` |
| 标定来源 | scale 跟画布高自动更新 | 300.0 固定，不随 resize 变 |
| 每粒子异尺寸 | 做不到——size 是全体一致的 uniform | 加一个 `a_scale` attribute 即可逐粒子变化 |
| 正交相机 | 自动失效（内置 isPerspective 判断） | 要自己分支——正交的 -z 无深度意义 |

两个迁移要点。其一，**300.0 的出身是「600 逻辑高的画布」**：内置公式代入 0.5 × 600 = 300，正是你的标定常数——它不是任意数，是内置公式在典型屏上的固化。想要任何分辨率下都与内置数值等价，把常数换成随 resize 更新的 uniform：

```ts
// resize 纪律：手写标定跟随画布高——内置材质的 scale 就是这么维护的
function onResize() {
  renderer.setSize(innerWidth, innerHeight);
  material.uniforms.u_scale.value = renderer.domElement.height * 0.5;
}
```

不换也站得住：300.0 固定意味着窗口变化时点大小恒定，星云类效果往往更接近设计意图。其二，**`sizeAttenuation: false` 等价于删掉衰减行**——正交相机或「远近一样大」的风格化场景，两种写法殊途同归。

## 噪声位移：把 fbm 接到 xyz

理想很丰满：curl noise（散度为零的向量场）能让粒子像流体一样打旋。现实很骨感：curl 需要三维噪声求偏导，两万粒子顶点着色器里算不动。课程工程取舍——**三路 2D 噪声组合出伪向量场**：

```glsl
// vertex shader 里（Day 2 的 noise 原样搬来，按 3.1 风格表换口）
vec3 pos = position; // 先声明、后采样——GLSL 没有函数提升也没有变量提升，顺序反了直接编译失败（1.3）
float n1 = noise(pos.xy * 1.5 + u_time * 0.20);
float n2 = noise(pos.yz * 1.5 - u_time * 0.17);
float n3 = noise(pos.zx * 1.5 + u_time * 0.13);
pos += (vec3(n1, n2, n3) - 0.5) * u_amp; // -0.5 居中：位移绕原点呼吸，星云不会整体漂移
```

三路采样取的是 position 的三个不同投影面（xy / yz / zx），相位差让三个分量不相关——效果接近随机向量场，成本只有单倍频噪声的三次调用。三个时间偏移系数故意不等（0.20 / 0.17 / 0.13），场会缓慢「错动」而不是整体平移。

时间让场呼吸：u_time 进噪声偏移项，粒子场就永不停歇地流动——**粒子场就是三维的丝绸**（2.4 的 domain warping 搬进空间）：同一条 fbm 思路，从屏幕像素搬到空间顶点。唯一的纪律：顶点噪声把 octave 压到 2–3（两万粒子 × 5 倍频是帧率刺客，见坑表）。

## 交互：粒子避让鼠标

鼠标在 3D 里不再是一个 uniform 坐标，要先变到粒子所在的平面（raycaster 射向 z=0 平面——具体做法属于 [Threejs创意3D 第 5 课「相机与控制」](../../../Threejs创意3D/课程笔记/第5课-相机与控制.md)的领地，demo 03 骨架已提供工具函数）。拿到鼠标世界坐标后，避让就是距离衰减推力：

```glsl
float d = distance(pos.xy, u_mouse3.xy);
float push = exp(-d * d * 6.0) * u_push;      // 高斯衰减：光标邻域强推，远处无感
pos.xy += normalize(pos.xy - u_mouse3.xy + 1e-4) * push;
```

设计要点是「避让不是弹开，是让路」：推力随距离指数衰减，只在光标邻域生效，粒子被推开后随噪声场自然回流——没有一个 if 在维护「推开状态」，依然是纯函数。`1e-4` 防 normalize 零向量（正好悬在光标正上的那颗粒子）。

## 加法混合发光：particles + additive = 星系

```ts
new THREE.ShaderMaterial({
  blending: THREE.AdditiveBlending, // 叠加发光：2.6 的 add 合成，三维再现
  depthWrite: false,                // 配套件：粒子不写深度
  transparent: true,
});
```

原理在 2.6 讲过：add 模式下重叠处亮度累加——粒子越密的地方越亮，星云核心的光是「数密度」自己画出来的，不需要任何光源。`depthWrite: false` 是**成对纪律**：additive 开了它不关，先画的粒子会写深度、挡住后画的粒子——叠加失效，星云出现黑洞般的遮挡黑框。「发光体之间互相不遮挡」是 additive 世界的物理直觉，代码上就是这两个参数绑定出现。

## How：demo 03「粒子星云与bloom」逐段精讲

demo 03 是 Day 2 全部知识的 3D 汇报演出——噪声（2.4）+ add 合成（2.6）+ 配方卡（2.8）+ 粒子（本讲）+ bloom（下一讲）。逐段拆：

- **分布**：两万粒子，球壳偏内分布（第 2 节的生成代码）——中心密外围疏，给「玫红核心、天青外围」的配色打底；
- **顶点**：出生位 + 三路噪声位移（3 octave）+ 鼠标扰动 + `gl_PointSize` 透视衰减；
- **片元**：`gl_PointCoord` 裁圆软边 + 按出生半径 mix 两色（`mix(玫红, 天青, smoothstep(0.6, 1.1, r))`）+ additive；
- **后期**：EffectComposer 四 pass 挂在渲染循环上——bloom strength 1.2 / radius 0.6 / threshold 0.35 + 配方 ShaderPass + OutputPass 收尾（完整拆解在 3.5，这里只见效果：核心亮部自动晕开）；
- **帧循环**：`renderer.setAnimationLoop` 一处，更新 u_time / u_mouse / u_scroll 三个 uniform，`composer.render()` 收工。

打开 demo 03 拖动鼠标：星云被搅开又回流，核心始终亮着——这就是「无状态 + 噪声场 + additive」三件事的合力。

**顶点着色器的完整出口**，把出生位 → 噪声 → 避让 → 衰减串成一整条链（GLSL1 风格，3.1 风格表：`position`/`modelViewMatrix`/`projectionMatrix` 由 ShaderMaterial 注入，不声明）：

```glsl
uniform float u_time;
uniform float u_size;
uniform float u_amp;
uniform vec3 u_mouse3;
uniform float u_push;
varying float v_r; // 出生半径传片元——配色按它算，位移不应影响颜色

// 2.4 的 value noise 原函数，按 3.1 风格表换 GLSL1 口——必须写在 main 之前（1.3）
float hash(vec2 p) {
  return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}
float noise(vec2 p) {
  vec2 i = floor(p);
  vec2 f = fract(p);
  vec2 u = f * f * (3.0 - 2.0 * f); // smoothstep 权重：值噪声连续性的来源（2.4）
  return mix(
    mix(hash(i), hash(i + vec2(1.0, 0.0)), u.x),
    mix(hash(i + vec2(0.0, 1.0)), hash(i + vec2(1.0, 1.0)), u.x),
    u.y);
}

void main() {
  vec3 pos = position;

  // 三路投影面噪声：相位差让三分量不相关（本讲第 4 节）
  float n1 = noise(pos.xy * 1.5 + u_time * 0.20);
  float n2 = noise(pos.yz * 1.5 - u_time * 0.17);
  float n3 = noise(pos.zx * 1.5 + u_time * 0.13);
  pos += (vec3(n1, n2, n3) - 0.5) * u_amp;

  // 鼠标避让：高斯衰减推力（本讲第 5 节两行原样）
  float d = distance(pos.xy, u_mouse3.xy);
  float push = exp(-d * d * 6.0) * u_push;
  pos.xy += normalize(pos.xy - u_mouse3.xy + 1e-4) * push;

  // 配色锚点取出生半径：按 pos 算会让「被推开的粒子变色」，颜色跟着扰动闪
  v_r = length(position);

  vec4 mvPosition = modelViewMatrix * vec4(pos, 1.0);
  gl_PointSize = u_size * (300.0 / -mvPosition.z); // 透视衰减红线公式
  gl_Position = projectionMatrix * mvPosition;
}
```

片元侧接住 `varying float v_r`，双色 mix 照 How 节的配方（`mix(玫红, 天青, smoothstep(0.6, 1.1, v_r))`）。TS 侧装配别漏一件与着色器无关的开关：

```ts
const points = new THREE.Points(geometry, material);
points.frustumCulled = false; // 顶点位移在 GPU，CPU 侧包围球还停在出生位——不关剔除，相机一拉远整片消失
scene.add(points);
```

`frustumCulled = false` 是顶点位移类效果的固定动作：剔除判断用的是 CPU 手里的旧包围球，shader 里挪过的位置它一概不知。你抄任何顶点位移工程（包括 demo 03）时，留意这一行别在「精简」时顺手删掉——删掉的报错方式不是异常，是相机拉远后一片空白。

## 常见坑

| 症状 | 原因 |
|------|------|
| 远近粒子一样大（假） | `gl_PointSize` 忘乘透视衰减——补 `u_size * (300.0 / -mvPosition.z)` |
| 粒子是方块 | 片元忘用 `gl_PointCoord` 裁圆——点精灵默认就是方形 |
| 星云出现黑框 / 遮挡错乱 | additive 开了但 `depthWrite: false` 没关——深度写入挡掉叠加 |
| 帧率崩 | fbm 5 倍频 × 两万粒子每帧全算——顶点噪声降 octave 到 2–3；噪声一定算在顶点着色器（N 次）而不是片元（N × 屏幕覆盖率 次） |
| 核心过曝糊成灯泡 | 点尺寸没衰减 + 高密度叠加——additive 场景 size 宁小勿大，亮度交给密度 |
| 粒子抖成雪花 | 噪声时间系数过大——u_time 偏移项乘 0.1 量级的系数，让场缓慢流动 |
| 相机一动、粒子整片消失 | 顶点位移在 GPU，CPU 侧包围球仍停在出生位——`points.frustumCulled = false` 关剔除 |
| 粒子整体不显示或缩成一团 | `setAttribute` 的 key 写成复数 positions——注入的 attribute 名固定是单数 position，对不上就是空 buffer |
| 粒子像坏电视一样狂闪 | u_time 喂了 performance.now() 的毫秒——0.2 量级系数按秒标定，基准差 1000 倍——用 `clock.getElapsedTime()` 喂秒 |
