# 3.3 滚动驱动 shader：把叙事交给滚轮

> Day 3 · 模块 3 · 约 60 分钟
> 理论对照：[Threejs创意3D 第 17 课「滚动驱动动画」](../../../Threejs创意3D/课程笔记/第17课-滚动驱动动画.md)——Lenis/GSAP 的系统性用法在那边；[第 5 课「相机与控制」](../../../Threejs创意3D/课程笔记/第5课-相机与控制.md)——滚动与相机联动的另一条路线。本课只讲「滚动进度如何变成 uniform」这一段桥

2026 年的 awwwards 年度报告把 scroll-driven storytelling 列为第一大趋势：Cartier 用六个滚动房间讲完一个系列，Shopify Editions 靠滚动揭示产品页。这些站的共同技术核心只有一句话——**把页面滚动进度归一化成 0–1 的 float，喂给 shader**。剩下的全部是两天已学的存货：区间 smoothstep（1.3 的函数）、噪声（2.4）、lerp（1.7）。本讲补的只是桥：滚动条 → float → uniform → 画面。

## u_scroll：一个 float 的叙事学

归一化一行，除数是「总可滚动距离」：

```ts
const progress = scrollY / (document.documentElement.scrollHeight - innerHeight);
material.uniforms.u_scroll.value = Math.min(Math.max(progress, 0), 1); // clamp 是保险丝
```

拿到 0–1 之后，先做一件事：**分段**。这本质上是剪辑思维——滚动条是时间轴，uniform 是轨道上的滑块，页面被切成一个个「镜头」：

| 区间 | 段落 | shader 侧 |
|------|------|----------|
| 0 – 0.3 | hero：粒子聚集成主视觉 | `smoothstep(0.0, 0.3, u_scroll)` 驱动聚合度 |
| 0.3 – 0.7 | 转场：噪声揭幕换背景 | fbm 阈值揭幕（本讲第 4 节） |
| 0.7 – 1.0 | 定格：文字聚合、参数冻结 | 第二组聚合度 + bloom 微抬 |

分段动画的通用构件只有一行——区间进度函数：

```glsl
float t = smoothstep(u_s1, u_s2, u_scroll); // 区间 [s1, s2] 内 0→1，区间外恒 0 或 1
```

把 (s1, s2) 当「起止站名」，t 就是本站进度。三段滚动叙事 = 三次调用 + 每段只动两三个参数。**分段不是写更多代码，是少写代码**：每段参数各自冻结，改一段不会牵动全片。

## Lenis：平滑滚动的标准件

为什么原生滚动直接喂 uniform 会抖？滚动事件是离散触发的（滚轮一格可能一跳 100px），而 shader 每帧都在渲染——离散值直接进 uniform，画面一顿一顿，100Hz 屏幕上尤其明显。

Lenis 的药方还是老朋友 lerp：它把离散的目标滚动位换算成每帧逼近的平滑值。五行集成：

```ts
import Lenis from 'lenis';

const lenis = new Lenis({ lerp: 0.1 }); // 又是 0.1——1.7 的手感常数换个战场
function raf(time: number) {
  lenis.raf(time);                    // 喂时间，它更新内部平滑值
  const p = lenis.scroll / (document.documentElement.scrollHeight - innerHeight);
  material.uniforms.u_scroll.value = Math.min(Math.max(p, 0), 1);
  renderer.render(scene, camera);
  requestAnimationFrame(raf);
}
requestAnimationFrame(raf);
```

两个接线纪律：`lenis.raf(time)` 必须每帧被调（它只在被喂时工作，忘了调就是「装了但不滚」）；`lenis.scroll` 取的是**平滑后**的值——这正是它存在的意义。「滚动界的手感 = 鼠标界的手感」，同一个 lerp，换了输入源。

接线熟了，你还能从 Lenis 身上白拿两个输入：**progress 与 velocity**。`lenis.on('scroll')` 的回调参数就是 lenis 实例本身，两个字段现成挂在上头：

```ts
lenis.on('scroll', (e) => {
  // e 即 lenis 实例：progress = scroll / limit，归一化它已替你算好
  // clamp 仍然不能省——惯性收尾的浮点误差可能让值擦过边界（红线：u_scroll 必归一 + clamp）
  material.uniforms.u_scroll.value = Math.min(Math.max(e.progress, 0), 1);

  // velocity：本帧滚动增量（已平滑）——滚得越快越大，静止为 0
  // 除以 200 是标定：常规滚动落在 0–0.3，一次极限甩动接近 1，按手感再调
  material.uniforms.u_vel.value = Math.min(Math.abs(e.velocity) / 200, 1);
});
```

velocity 是「速度驱动失真」的钥匙——快速滚动时图卡纵向拉伸、文字拖出 motion blur 假象，获奖站的「滚动模糊感」九成是它而不是真 blur。shader 侧一行接住：

```glsl
// 滚得越快纵向采样越拉长：静止时 u_vel 为 0，采样回到原位
vec2 uv = v_uv * vec2(1.0, 1.0 + u_vel * 0.35);
```

语义要分清：u_scroll 是**位置**（滚到哪了），管叙事分段；u_vel 是**速度**（滚得多快），管瞬时质感。两个 uniform 各司其职，别拿一个值凑合两件事。scroll 回调里的纪律不变：只有 uniform 赋值，任何重活（DOM 查询、几何重建）都不许出现在这里。

## GSAP timeline：编排 uniform 的一生

滚动是连续输入，但页面上还有离散时刻：按钮点击、进入视口、章节切换。这些「一次性动画」交给 GSAP：

```ts
import { gsap } from 'gsap';

gsap.to(material.uniforms.u_progress, { value: 1, duration: 1.2, ease: 'power2.inOut' });
```

`gsap.to` 直接对 uniform 对象属性做补间——`.value` 被 GSAP 每帧改写，shader 侧无感知，它只管读数。取舍表：

| 场景 | 谁驱动 | 理由 |
|------|--------|------|
| 连续滚动（滚动条位置） | shader 内 smoothstep | 连续输入无状态自算，最便宜 |
| 离散切换（点击、进入视口） | GSAP timeline | 需要 ease 曲线、序列编排、可倒放 |
| 两者混合 | GSAP 改 goal、帧循环 lerp 追 | 各管一半，用 goal 隔离 |

这是把 1.6 的缓动讨论搬到了 JS 侧：GLSL 里 smoothstep 是最便宜的缓动，但 timeline 要暂停、倒放、串联——那是编排器的领地。两种驱动**不要同时管同一个 uniform**（见坑表第 4 行）。

用了 GSAP 就别再自建 rAF 去喂 Lenis——官方集成是挂 ticker，循环只留一个：

```ts
// 单循环纪律：lenis 更新与渲染都在 GSAP ticker 里，顺序天然可控
gsap.ticker.add((time) => {
  lenis.raf(time * 1000); // ticker 的 time 是秒，Lenis 要毫秒
  composer.render();
});
```

你若一边 `gsap.ticker.add` 喂 Lenis、一边自己的 `requestAnimationFrame` 里渲染，就是两个相位不保证的循环在赛跑——u_scroll 偶尔落后一帧，画面间歇性顿挫且极难复现（坑表新行）。循环只有一个，顺序才有一个。

## 转场遮罩：两页之间的一片噪声

转场遮罩是 Day 2 噪声与 Day 3 进度的合体，思想一句话：**噪声当 mask，progress 当阈值**。

```glsl
float n = fbm(v_uv * 3.0); // 一片静态噪声场（Day 2 存货）
// 揭幕：progress 推高阈值，噪声值低的区域先被"淹没"
float reveal = smoothstep(u_progress - 0.12, u_progress + 0.12, n);
vec3 col = mix(sceneB, sceneA, reveal);
```

- `step(n, u_progress)` 是硬边版——刀切式揭幕，利落但生硬；
- `smoothstep(u_progress - 0.12, u_progress + 0.12, n)` 是柔边版——阈值附近 ±0.12 的过渡带让揭幕边缘像墨水洇开。边缘的形状就是噪声的等值线，这正是它比圆形擦除高级的地方：**不规则、有机、每次看都有细节**。
- 进阶一步：让噪声随时间缓动（`fbm(v_uv * 3.0 + u_time * 0.05)`），揭幕边缘会自己「游动」，转场就从「翻页」变成「潮水」。

转场遮罩的完整出口（GLSL1 风格，3.1 风格表：varying 接收、texture2D、gl_FragColor）——challenge 转场那段的骨架：

```glsl
varying vec2 v_uv;
uniform sampler2D t_a; // 场景 A：暗紫（挑战里的「旧页」）
uniform sampler2D t_b; // 场景 B：近黑（挑战里的「新页」）
uniform float u_progress;
uniform float u_time;

/* fbm 定义在前——GLSL 无函数提升（1.3） */

void main() {
  // 噪声随时间缓动：揭幕边缘自己游动（潮水版）
  float n = fbm(v_uv * 3.0 + u_time * 0.05);
  // ±0.12 过渡带：边缘像墨水洇开，「带有多宽」就是这 0.24
  float reveal = smoothstep(u_progress - 0.12, u_progress + 0.12, n);
  vec3 a = texture2D(t_a, v_uv).rgb;
  vec3 b = texture2D(t_b, v_uv).rgb;
  gl_FragColor = vec4(mix(b, a, reveal), 1.0);
}
```

两个「页」都是纹理时这段直接可用；challenge 的两个页其实是两群粒子的形态——把 texture2D 两行换成两套颜色的 mix，遮罩逻辑一行不改。**mask 是可复用的模具，往里填什么料是另一件事**。

## 性能：滚动渲染的帧预算

滚动进行中，主线程忙着布局与合成，留给 shader 的帧预算比静止时更紧。三条纪律：

- **滚动段降 octave**：fbm 从 5 倍频降到 3——滚动中的画面在动，细节损失肉眼不敏感；
- **defer 非关键 pass**：grain、暗角这类低频细节可以半分辨率或隔帧；
- **监听只记目标值**：scroll 事件回调里做任何重活都是错的——事件里只更新一个 float，所有计算留给帧循环。

## How：以作业 challenge「滚动驱动的英雄时刻」为蓝本的前置精讲

**本讲不配独立 demo——本讲的完整实现直接长在 homework challenge「滚动驱动的英雄时刻」与它的 solution 里**，solution 就是可对照运行的完整工程参考。这里先把三段式时间轴拆好，你做作业时按图索骥：

- **0–0.3 粒子聚集**：`t1 = smoothstep(0.0, 0.3, u_scroll)`；粒子位 = `mix(噪声散位, 目标图形位, t1)`；噪声幅度从 1.0 降到 0.1——粒子从乱流收束成 hero 图形（采样函数由骨架提供）；
- **0.3–0.7 噪声揭幕转场**：`t2 = smoothstep(0.3, 0.7, u_scroll)`；fbm 阈值揭幕把背景从暗紫切到近黑，转场边缘带时间缓动；
- **0.7–1 文字聚合定格**：`t3 = smoothstep(0.7, 1.0, u_scroll)`；第二组粒子从页头文字采样点聚合；bloom strength 随 t3 从 0.9 微抬到 1.2——画面「落定」时给一点光晕提气。

每段一个 smoothstep、每段只动两三个参数。验收标准也在这条时间轴上：三段过渡全部无跳变、0.3 处粒子可辨认出图形、转场噪声边缘自然。

「无跳变」不是许愿，是把三个 smoothstep 的起止值列成表就能验证的数字：

| u_scroll | t1 = smoothstep(0.0, 0.3, s) | t2 = smoothstep(0.3, 0.7, s) | t3 = smoothstep(0.7, 1.0, s) | 画面状态 |
|------|------|------|------|------|
| 0.15 | 0.50 | 0 | 0 | 粒子收束半程 |
| 0.30 | **1.00** | **0.00** | 0 | 边界：t1 交棒 t2 |
| 0.50 | 1.00 | 0.50 | 0 | 转场揭幕半程 |
| 0.70 | 1.00 | **1.00** | **0.00** | 边界：t2 交棒 t3 |
| 0.90 | 1.00 | 1.00 | 0.74 | 文字聚合后段 |
| 1.00 | 1.00 | 1.00 | 1.00 | 定格 |

表里读出两个结论。**边界即接力**：0.3 处 t1 恰好走完 1、t2 恰好未出发 0——前段的终点瞬间就是后段的起点，既无缝隙也无重叠，这就是「区间首尾相接」在数值上的长相。**中段是缓动不是线性**：0.5 处 t2 = 0.5（smoothstep 的对称中点），但 0.35 处只有约 0.04——前四分之一爬得极慢；你的段要是「起势太肉」，把区间起点从 0.3 挪到 0.25，比在别处加缓动函数便宜。

反例也在表上：把 t2 的起点写成 0.35（「怕重叠」而错开），0.3–0.35 之间 t1 已到 1、t2 还是 0——这五分之一的滚动里画面纹丝不动，用户以为滚轮断了。**错开区间制造的不是不重叠，是死区**；正确写法永远是共边界——0.3 与 0.7 这两个数字被相邻两段共用。

## 常见坑

| 症状 | 原因 |
|------|------|
| 滚动时画面一顿一顿 | scroll 事件把离散 scrollY 直接喂 uniform——接 Lenis，或至少在帧循环里对 u_scroll 做 lerp |
| Lenis 装了但页面不滚 | 忘了在 rAF 里调 `lenis.raf(time)`——Lenis 只在每帧被喂时才工作 |
| 滚到底转场闪一下 | u_scroll 没 clamp——浮点误差让值穿过 1.0，smoothstep 区间外反向；收口 `clamp(x, 0.0, 1.0)` |
| 动画忽快忽慢互相打架 | GSAP 与帧循环 lerp 同时驱动同一 uniform——选一个主人：连续段 shader 自算，离散段 GSAP，别叠加 |
| 滚过头参数又变了 | 分段 smoothstep 区间重叠——区间要首尾相接（0.3 / 0.7 共用边界），不重叠 |
| 换设备滚动距离不一样 | 归一化只算了一次——resize 后 docHeight 会变，归一化每帧现算（一行的事，别缓存） |
| 刷新后首帧画面跳一下 | 浏览器 scrollRestoration 默认 auto：刷新恢复上次滚动位，uniform 却从 0 初始化——`history.scrollRestoration = 'manual'`，或首帧先把当前进度同步进 uniform |
| 移动端滚动又抖回离散感 | Lenis 默认 `syncTouch: false`，触摸走原生滚动、离散值直进 shader——要么开 `syncTouch: true`，要么移动端只保 clamp 不跳 |
| 页面滚了、u_scroll 恒为 0 | 滚动发生在某个 overflow 容器里，而 Lenis 默认只接 window——构造时传 `wrapper`/`content`，归一化分母同步换成容器的 scrollHeight - clientHeight |
| 画面间歇性顿挫、极难复现 | lenis.raf 挂 GSAP ticker、渲染挂自建 rAF——两个循环相位不保证，u_scroll 偶尔落后一帧；合成单循环（ticker 里 raf + render 一起） |
