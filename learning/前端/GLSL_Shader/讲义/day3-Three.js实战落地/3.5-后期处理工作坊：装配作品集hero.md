# 3.5 后期处理工作坊：从「画面」到「作品」的最后一层

> Day 3 · 模块 5 · 约 70 分钟
> 理论对照：[WebGPU 3.4「后处理与性能调优」](../../../webgpu/讲义/day3-Three.js桥接/3.4-后处理与性能调优.md)——同一概念在 WebGPU 栈的实现；本课走 three addons 的 WebGL 路线

bloom 一加，霓虹从「贴图感」变成「发光体」；颗粒一加，数字的干净感退场，胶片的呼吸感进场。后期处理是电影的调色台——前四讲产出的所有画面，都在这里完成最后一道工序。它同时是**装配课**：三天的零件（丝绸、SDF、失真、滚动、粒子）在这一讲拼成完整作品。今天之后，「画面」与「作品」之间隔着的就是这一层。

## EffectComposer：帧缓存的中转站

先回答为什么需要它。直接渲染是「拍完直接印」——渲染管线的输出直写屏幕，写完就没了。后期要的是「先拍到底片，再洗」：画面先存进一块**可反复读写的帧缓存**（render target），每一道后期工序从上一道的结果里读入、加工、写出，最后一道才印到屏幕。

链路全景：

![后期处理链路图：顶部主链从左到右五节点——「场景渲染 RenderPass」深色卡（scene+camera 拍底片，输出 render target）、玫红描边卡「UnrealBloomPass」（提亮部→降采样模糊→叠加，参数三件 strength/radius/threshold）、天青描边卡「自定义 ShaderPass」（配方卡 grain/vignette 全局最后一道，tDiffuse 接上一道输出）、琥珀卡「OutputPass」（色彩空间与色调映射，sRGB 输出）、终点「屏幕」；箭头上标注每个 pass 都是全屏一遍；中部三张参数卡分别列出 bloom 三参数的手感与 demo 03 取值（strength 1.2 / radius 0.6 / threshold 0.35）；底部通栏性能红线卡：pass 数 × 全屏成本、移动端砍 bloom 或降 DPR、resize 必须 composer.setSize 同步](../../assets/diagrams/postprocess-chain.svg)

对着图，五行组装：

```ts
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { OutputPass } from 'three/addons/postprocessing/OutputPass.js';

const composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera)); // 第一道：拍底片
composer.addPass(bloomPass);                     // 中间道：加工（下节）
composer.addPass(new OutputPass());              // 最后一道：印片
```

帧循环里唯一的改动：`renderer.render(scene, camera)` 换成 `composer.render()`——其余一概不动。

## UnrealBloomPass：辉光的工业化

三参数决定一切，手感先行：

| 参数 | 手感 | demo 03 取值 |
|------|------|-------------|
| `strength` | 辉光强度——直接决定「发光体还是荧光棒」 | 1.2 |
| `radius` | 光晕扩散半径——大则柔、小则锐，太大会糊掉结构 | 0.6 |
| `threshold` | 提亮门槛——只有高于它的亮度参与 bloom | 0.35 |

threshold 的设计价值常被低估：它划出「哪些像素够格发光」。设 0.35，星云的暗部外围不参与 bloom，核心亮部自动晕开——**画面的明暗结构保留，只有高光获得了呼吸**。设 0 则全屏发光，白成一片（坑表第 2 行）。

与 2.6 手写 glow 的对照：

| | 手写 glow（2.6） | UnrealBloomPass |
|---|-----------------|-----------------|
| 原理 | 单 pass 内 SDF 距离衰减，数学造光 | 真多 pass：提取亮部 → 逐级降采样模糊 → 叠回 |
| 成本 | 一次距离计算 | 三级降采样（全屏 × 多遍） |
| 适用 | 目标明确（霓虹管、描边、字） | 全画面提亮部（星云、粒子、高光） |

「手写够用 90%，bloom 是高光时刻的重武器」——粒子星云这类「没有明确 SDF 可挂」的画面，bloom 是唯一正解；徽章描边这种「知道光该长在哪」的画面，手写反而更准。

## 自定义 ShaderPass：把 Day 2 电影感配方搬进后期

2.8 的配方卡在 Day 2 是「每个材质自己抄一遍的收尾代码」，从今天起它有了更好的归宿——**全局最后一道工序**：

```ts
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';

const gradePass = new ShaderPass({
  uniforms: { tDiffuse: { value: null }, u_time: { value: 0 } },
  vertexShader: `varying vec2 v_uv;
    void main(){ v_uv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
  fragmentShader: gradeFrag, // 2.8 配方卡迁移：tDiffuse 就是"上一道工序的画面"
});
```

`ShaderPass` 的接线约定只有一个：fragment 里从 `tDiffuse` 采样，拿到上一道的画面，处理后输出。2.8 配方卡原样可用——`texture2D(tDiffuse, v_uv)` 替换原来的自绘画面，其余 grain / vignette 一行不改。

架构上的减法才是重点：**配方卡从每个材质里抽出，变成全局最后一道**——场景材质只管造型，色调统一在 pass 里调。改一次 grain，全场景生效；新加一个材质，自动继承电影感。这就是后期链的分工美学。

OutputPass 一句收口：three 0.186 的色彩空间输出（线性 → sRGB）与色调映射由 `OutputPass` 负责，放在链尾。注意连锁反应——**配方 pass 里的 gamma 步要删掉**（2.8 五步的最后一步），否则双重校正（坑表第 4 行）。

配方 pass 的完整 fragment，2.8 的卡搬进后期链后长这样（GLSL1 出口，tDiffuse 接上一道画面）：

```glsl
varying vec2 v_uv;
uniform sampler2D tDiffuse;
uniform float u_time;

/* hash 定义在前——GLSL 无函数提升（1.3） */

void main() {
  // grain 3%：噪声随时间抖，压数字感不脏画面（2.8 数值原样）
  float g = hash(v_uv * 512.0 + u_time * 60.0) - 0.5;
  vec3 col = texture2D(tDiffuse, v_uv).rgb + g * 0.03;

  // vignette 0.2：径向压角，视线聚向中心
  float d = distance(v_uv, vec2(0.5));
  col *= 1.0 - smoothstep(0.35, 0.85, d) * 0.2;

  // 没有 gamma：色彩空间归链尾 OutputPass（坑表第 4 行的双重校正）
  gl_FragColor = vec4(col, 1.0);
}
```

写这段最容易踩的接线细节：`tDiffuse` 这个名字是 ShaderPass 的硬约定——它内部按这个 key 把上一道输出注入进来，你改成 u_tex 就接到 null、全屏黑（坑表新行）。想自定义名字可以，但要把它作为构造器第二个参数传入：`new ShaderPass(shader, 'u_tex')`。

## 装配车间：作品集 hero 的完整清单

三天课程的全部零件，点名入册：

| 层 | 零件 | 出处 |
|----|------|------|
| 背景氛围 | 丝绸 fbm / 域扭曲 | 2.4 |
| 前景主体 | SDF 徽章 / 霓虹 glow | 2.1 / 2.6 |
| 图卡模块 | hover 失真 + RGB shift + 视差 | 3.2 |
| 叙事驱动 | u_scroll + Lenis + 转场遮罩 | 3.3 |
| 点睛粒子 | Points + 噪声位移 + additive | 3.4 |
| 全局收尾 | bloom + 配方 ShaderPass + OutputPass | 本讲 |

但克制原则压在清单之上：「**一个作品一个主角，其余全部降透明度**」。2026 年 awwwards 获奖站的共同气质是单点狠活——hero 只需要表中两三件，做深做透；件件都上就是素材堆场。装配表不是采购清单，是货架陈列：先选主角，再挑配菜，最后用本讲的后期链统一灯光。

六层各自的成本与降级路径，你选主角前要过一遍这张账：

| 层 | 全速成本 | 当主角的条件 | 当配角的降级手段 | 砍掉的代价 |
|----|----------|--------------|------------------|-----------|
| 背景丝绸 fbm | 全屏 × 4–5 octave | 域扭曲即主视觉（2.4 全套） | octave 降到 2、半分辨率 | 背景空洞，没有「场」 |
| SDF 主体 | 全屏一遍距离场 | 徽章/文字是 hero 锚点 | 砍 glow 步数、距离复用 | 无视觉锚点 |
| 图卡失真 | 图卡面积 × RGB 三采样 | 作品墙即叙事 | 只留 RGB shift、去视差 | 回到静态 portfolio |
| 滚动叙事 | Lenis 常驻（极便宜） | 长滚动叙事页 | 只用 u_scroll 做视差、不转场 | 变单屏站 |
| 粒子 | 2 万顶点 × 噪声 | 星云/文字聚合即主角 | 降到 2000、去鼠标避让 | 少了「活物」 |
| 后期链 | 2–4 个全屏 pass | 电影感定调 | 砍 bloom 留 OutputPass | 数字感回归 |

这张表里藏着一个不对称：**唯一不能砍的是 OutputPass**。其余五层都是风格选择，砍了只是换气质；OutputPass 管的是色彩空间正确性（线性 → sRGB），砍它不是「少了电影感」，是「颜色全错了」——性能再紧，降 DPR 也轮不到砍它。bloom 的可砍性正好相反：它是链上最贵的一层，也是最好替代的（2.6 手写 glow 覆盖它九成场景）。

## How：demo 03 的 pass 链逐段精讲

demo 03 的完整后期链与参数推敲过程：

```ts
// 组装顺序即数据流向
const composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera));

const bloomPass = new UnrealBloomPass(
  new THREE.Vector2(innerWidth, innerHeight), 1.2, 0.6, 0.35); // strength/radius/threshold
composer.addPass(bloomPass);

composer.addPass(gradePass);      // grain 3% + vignette 0.2（配方卡两步，无 gamma）
composer.addPass(new OutputPass()); // sRGB 输出 + 色调映射
```

- **threshold 0.35 的推敲**：粒子暗部外围的 alpha 叠加后亮度不高，低于门槛不 bloom——星云才有「核心亮、边缘收」的结构感；试过 0.2，整个画面糊成灯泡；
- **strength 1.2 的推敲**：低于 1.0 星云像蒙灰，高于 1.5 核心过曝吞掉粒子形状——1.2 是「发光体成立、结构还在」的平衡点；
- **配方 pass 只做 grain + vignette**：gamma 交给 OutputPass，grain 3% 与 vignette 0.2 复用 2.8 的数值——demo 03 的「胶片感」与 Day 2 的霓虹徽章是同一张配方卡；
- **resize 纪律**：`composer.setSize(innerWidth, innerHeight)` 与 renderer 同步调——composer 有自己的缓冲，只调 renderer 的一边会拉伸（坑表第 1 行）。

完整的 resize 函数，五件事一次到位：

```ts
function onResize() {
  const w = innerWidth, h = innerHeight;
  const dpr = Math.min(devicePixelRatio, 2); // DPR 红线：封顶 2

  renderer.setPixelRatio(dpr);
  renderer.setSize(w, h);
  composer.setPixelRatio(dpr); // composer 有独立缓冲——pixelRatio 两处都要设
  composer.setSize(w, h);      // bloom 的模糊分级随 setSize 重建

  camera.aspect = w / h;
  camera.updateProjectionMatrix();
}
addEventListener('resize', onResize);
```

五件套的顺序无所谓，漏一件才要命：DPR 两处、尺寸两处、相机一处。`camera.updateProjectionMatrix()` 是最常被忘的第五件——忘了它，resize 后的画面是「旧投影矩阵拍新尺寸」，透视全歪。

## 性能红线复述

后期链的账本很简单也很残酷：**每个 pass 都是全屏一遍**——四 pass（render / bloom / 配方 / output）就是四遍全屏成本，加 bloom 的降采样还要再乘系数。移动端策略：

- 砍 bloom（strength 0 或整条 pass 摘掉）或降 DPR（`Math.min(devicePixelRatio, 1.5)`）；
- 探测手段：`renderer.info.render.calls` 看调用数，帧率长期低于 55 就降档；
- 这是总纲「设计质量六条」性能条款在 Day 3 的收口：60fps 是底线，效果是变量，先保底线。

滚动场景还有一档主动降级可用——**bloom 跟着滚动状态动**。3.3 讲过滚动进行中主线程吃紧，你可以在帧预算最紧的时段主动把最贵的 pass 调轻：

```ts
// 滚动中 strength 减半：画面高速位移，辉光细节肉眼不敏感（与 3.3 滚动段降 octave 同理）
bloomPass.strength = Math.abs(lenis.velocity) > 20 ? 0.6 : 1.2;
```

被动降档（帧率掉了再砍）保底，主动降档（可预测的吃紧时段先让路）保流畅——两条一起用，60fps 的账才稳。

## 常见坑

| 症状 | 原因 |
|------|------|
| resize 后画面拉伸 | 只调了 `renderer.setSize` 没调 `composer.setSize`——composer 有独立的缓冲尺寸 |
| 全屏一片白光 | bloom `threshold` 设了 0——所有像素参与提亮，画面过曝；门槛卡在 0.3–0.4 |
| 颜色发灰 / 发暗 | 缺 `OutputPass`——0.186 的线性 → sRGB 输出靠它，缺了画面按线性直出 |
| 画面灰脏、对比丢失 | 配方 ShaderPass 里还留着 gamma 步——OutputPass 已做色彩校正，双重校正，配方里删掉 |
| bloom 后结构糊掉 | `radius` 太大 + `strength` 太高——先降 radius 保结构，再微调 strength |
| 帧率掉一半 | pass 数失控——每个 pass 全屏一遍，移动端砍 bloom 或降 DPR |
| 降了 DPR 画面还是糊 | 只调 `renderer.setPixelRatio` 没调 `composer.setPixelRatio`——composer 有自己的 render target，两处都要设 |
| ShaderPass 全屏黑 | tDiffuse 名字被改——ShaderPass 按这个 key 注入上一道输出，改名就接 null；自定义名要作为第二参数传入构造器 |
| 想让 DOM 文字也发光、怎么都不行 | composer 只覆盖 WebGL canvas——DOM 在合成层之上，后期链根本读不到它；要参与后期就得先进 WebGL（SDF 文字/纹理化） |

## Checkpoint

- 能组装 composer 四 pass（RenderPass / bloom / 配方 / OutputPass）并说出顺序理由：底片 → 加工 → 印片
- 能背 bloom 三参数手感：strength 强度、radius 柔度、threshold 门槛（卡 0.3–0.4）
- 能把 2.8 配方卡搬进 ShaderPass：tDiffuse 接线 + 删 gamma 步（交给 OutputPass）
- 能背装配清单六层与克制原则：一个作品一个主角，其余全部降透明度
- 能算后期链的性能账：pass 数 × 全屏成本，移动端的两个降档手段
- 能按六层取舍表挑主角并说出配角的降级手段，且知道唯一不可砍的是 OutputPass（正确性，不是风格）
