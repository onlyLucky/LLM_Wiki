# 1.5 数据流与全屏四边形：varying 插值与 UV 坐标系

> Day 1 · 模块 5 · 约 55 分钟
> 理论对照：《WebGPU 三天实战课程》1.5「顶点缓冲与几何数据」——插值语义完全同构，本篇补 GLSL 侧的 in/out 语法与 UV 工程约定（[1.5-顶点缓冲与几何数据.md](../../../webgpu/讲义/day1-原生WebGPU基础/1.5-顶点缓冲与几何数据.md)）

demo 01 的渐变三角形只有三个顶点、三种颜色，中间那几万个像素的渐变是谁算的？答案是光栅化阶段的免费服务：插值。你在 webgpu 1.5 已经见过它的语义——顶点数据在图元内部连续取值；这一模块把它的 GLSL 形态讲透，名字叫 varying。理解 varying，你就拿到了 fragment shader 最重要的输入：UV。本模块交付两件事：一条数据从 JS 流到每个像素的完整路径，和一块你能亲手跑起来的 UV 仪表盘。

## attribute → varying → fragment：一条数据的两次交接

渐变不是你的 shader 算出来的，是光栅化送上门的。一条数据从 JS 到达每个像素要交接两次：第一次是 attribute——VBO 里的顶点数据按 location 喂给顶点着色器，仪式在 1.4 已经走通；第二次是 varying——顶点着色器的输出交给光栅化，光栅化把三个顶点值插值成几十万份，逐像素流进片元着色器。GLSL ES 3.00 把 attribute / varying 两个老关键字废弃了，数据方向统一用 in / out 表达：

```glsl
// vertex.glsl —— 数据的出口：顶点着色器用自己的 out 声明要交接什么
out vec2 v_uv;              // 三个顶点各领一份，中间的空档交给光栅化填满

void main() {
  v_uv = a_position * 0.5 + 0.5; // clip space (-1..1) 压进 UV 域 (0..1)
  // ...
}

// fragment.glsl —— 数据的入口：片元着色器用自己的 in 接住
in vec2 v_uv;               // 名字必须与 vertex 的 out 逐字一致——这是接头暗号
```

交接规则只有一条，但违反的代价是整个 program 链接失败：vertex 的 out 与 fragment 的 in 名字必须逐字相同，类型也必须相同。你在 1.4 读过 chrome 错误面板对 LINK ERROR 的修复提示——「varying 是接头暗号」，说的就是这里。与 WGSL 对照着记：WGSL 用 `@location(N)` 让管线自动配对，GLSL 要求你亲手保证两边一致——麻烦一点，但报错信息会直接告诉你哪边没接上。

三条数据通路的全景在这张图里，本篇它首次亮相：

![GLSL 三条数据通路接线图：左侧虚线框住 JS / CPU 侧的两个数据源——上方是玫红描边的 VBO 节点（顶点数据），下方是天青描边的 uniforms 节点（u_time / u_mouse）；attribute 通路（玫红箭头）从 VBO 指向顶点着色器节点（标注 VERTEX · 每顶点 1 次）；varying 通路（玫红箭头）从顶点着色器出发，先经过琥珀描边的「光栅化 · 插值」节点（标注「varying 免费平均」），再以「插值结果」的名义进入右侧玫红描边的片元着色器节点（FRAGMENT · 每像素 1 次）；uniform 通路（天青箭头）从 uniforms 节点横向贯穿全图直达片元着色器底部，沿线标注「uniform · 全局广播——每次 draw，所有像素拿到同一个值」；片元着色器节点内列出两行输入：in v_color（插值来的）与 in u_time（广播来的）；图底部印着两行字：uniform 是广播，varying 是插值——传给所有像素同一个值，还是传三个顶点值让硬件帮你平均，这就是两条通路的分工](../../assets/diagrams/glsl-data-flow.svg)

对着图从左到右过一遍：数据在 JS 侧就分了岔——顶点数据走玫红的 attribute 通路，全局量走天青的 uniform 通路；两条路在片元着色器里会合，但待遇完全不同。最值得盯住的是玫红通路中间那次琥珀色的拐弯：三个顶点值在那里变成几十万个插值结果，你的代码一行都不用写，GPU 硬件白送。

插值的手感用数值钉住：demo 01 里顶部顶点的颜色是玫红 (1.0, 0.302, 0.427)，左下顶点是天青 (0.298, 0.624, 0.941)，两点连线正中间的像素拿到的就是两个向量的算术中点——每个分量各平均一次，没有玄学。插值的全部本质是逐分量的加权平均：离哪个顶点近，哪个顶点的权重大；三个顶点围出的三角形内部，每个像素都按自己的位置自动分配权重。demo 01 那枚渐变三角形的「渐变感」，就是这几十万次加权平均叠出来的视觉结果。

**uniform 是广播，varying 是插值。** 前者每次 draw 给所有像素发同一个值，像 props 传给整棵子树，人人拿到同一份；后者只给三个顶点各发一份，中间几十万个值由硬件按位置免费平均，像父组件只定三个锚点，子组件按自己的位置连续取值。怎么选只用问一个问题：这个数据是每个像素都要「自己的版本」（uv、插值色），还是全场共享一份（时间、鼠标、分辨率）？

## 插值是线性的，屏幕上的世界是非线性的

光栅化的默认插值在屏幕空间做线性平均，而屏幕空间对三维世界是个说谎者。透视投影让近处像素密、远处像素疏，直接对屏幕坐标做线性平均，插出来的纹理会「弯」——修正方案叫透视校正插值（perspective-correct interpolation），GPU 默认帮你做：每个 varying 先按 w 加权再插值、插完乘回来，完整推导在 [WebGPU 2.2「光栅化与片元插值」](../../../webgpu/讲义/day2-渲染进阶与GPU计算/2.2-光栅化与片元插值.md)，这里只借结论。

本课的边界要先划清：2D 全屏四边形的四个顶点 gl_Position.w 恒为 1，w 加权等于没加权，插值就是教科书式的线性——所以你可以在 uv 上放心算距离、画圆。什么时候要紧张？把四边形顶进三维空间斜着放的时候（Day 3 的图片失真就会遇到），透视弯曲会让逐像素的距离场变形，那时你会回来感谢这句话。

## UV：像素的身份证

UV 是每个像素的归一化身份证：不管画布是 1920 像素还是 380 像素宽，右上角的身份证永远是 (1, 1)。有了它，你的视觉算法与分辨率、与设备彻底解耦——同一份 fragment，手机和 4K 显示器上行为一致。这行代码你已经在前端写了一百遍，只是这次由 GPU 逐像素执行：

```glsl
vec2 uv = gl_FragCoord.xy / u_resolution; // 像素 → UV：与你熟悉的 getBoundingClientRect 归一化同构
vec2 p  = uv * 2.0 - 1.0;                 // UV → 居中域：中心变 (0, 0)，负数出现了
p.x *= u_resolution.x / u_resolution.y;   // 宽高比矫正：x 方向展开到真实比例
```

三行代码对应三个坐标域，一张表钉死它们的关系：

| 坐标域 | 值域 | 原点 | 从 UV 出发的换算 | 谁的主场 |
|--------|------|------|-----------------|---------|
| gl_FragCoord | 像素值，如 (960, 540) | 左下 | uv × u_resolution（反推） | 想按物理像素做事：像素化、glitch 抖动 |
| UV | 0–1 | 左下 | 它就是基准 | 创意 shader 的默认工作域 |
| 居中域 | -1..1 | 中心 | uv * 2.0 - 1.0 | SDF、旋转、极坐标——对称运算都爱 0 在中心 |

宽高比是 UV 域埋的唯一陷阱，也是新手前三天最常撞的墙。UV 把两条边都归一化到 0–1，代价是抹掉了形状：1920×1080 的画布上，同样 0.1 的步长，x 方向跨 192 像素、y 方向只跨 108 像素——你想画圆，`length(uv - 0.5)` 给你一枚横躺的椭圆。修正就是三行代码的第三行：x 从 -1..1 展开到约 -1.78..1.78，两个方向上「1 个单位」恢复等长，圆才是圆。取舍很明确：效果与方向无关（纯垂直渐变、噪点）时省掉这三行无妨；只要涉及距离、圆形、旋转，aspect 矫正必须跟上——本课所有 demo 统一带上，宁多勿漏。

三种坐标域的换算关系看这张图，一图抵十行文字：

![三种坐标域并列对比图：三个面板画同一块画布。面板 1（灰描边）gl_FragCoord：像素坐标系，左下角红点标注「(0,0) 左下原点」，画布中一个琥珀点标 (960,540)，右上角标 (1920,1080)，说明文字「像素值 · 左下原点 · y 向上，除以 u_resolution 才有下一站」；面板 2（玫红描边）UV：四角标 (0,0) / (1,0) / (0,1) / (1,1)，中心天青点标 (0.5, 0.5)，说明「归一化 0–1 · 左下原点，创意 shader 的主力坐标系」；面板 3（天青描边）居中域：四角标 (-1,-1) / (1,-1) / (-1,1) / (1,1)，中心天青点标「(0,0) 中心」，面板下方画着宽高比矫正前后对比——琥珀色椭圆标「未矫正」，天青色正圆标「p.x *= aspect」，说明「uv * 2.0 - 1.0 · SDF 与旋转的主场，宽屏拉伸 → p.x *= u_aspect 矫正」；底部通栏一行：记住换算口诀——除以分辨率得 UV，乘 2 减 1 得居中域，其余变体都从这里出发](../../assets/diagrams/uv-coordinate.svg)

## 全屏四边形：创意网站的地基

awwwards 站点上那些全屏 shader 背景，几何朴素得可笑：一个大四边形，两个三角形，占满视口。原因在于 fragment 效果的本质是「uv → 颜色」的纯函数，它需要的不是模型，是一张铺满屏幕的纸——几何越少，顶点阶段越可忽略，成本全部落在片元。噪声流动、光线步进、调色板渐变，载体全是这两只三角形，区别只在片元代码。

同一个四边形有两种喂法，区别在顶点数量与重复度：

```ts
// 画法 A · TRIANGLES × 6 顶点：两个独立三角形，对角线上的两点各写两遍
new Float32Array([
  -1, -1,   1, -1,   1,  1,   // 下三角
  -1, -1,   1,  1,  -1,  1,   // 上三角（前两点是重复数据）
]);

// 画法 B · TRIANGLE_STRIP × 4 顶点：GPU 沿折线自动补出第二个三角形（课程约定）
new Float32Array([
  -1, -1,   1, -1,  -1,  1,   1,  1,  // 左下 → 右下 → 左上 → 右上
]);
```

课程约定 TRIANGLE_STRIP：少写两个顶点是小事，顶点顺序即几何走向、没有重复数据要维护才是大事——demo 稍多之后，这种「读顺序就读懂图形」的性质会持续帮你省脑力。

顶点坐标直接写 clip space（-1..1），是全屏四边形送你的第二份免费午餐。webgpu 课里你喂的是模型坐标，还要过 MVP 矩阵才到屏幕；这里没有模型、没有相机，四边形就是视口本身——vertex shader 退化成搬运工，一行矩阵都不用写。省掉矩阵的代价是放弃三维感，而这恰恰是「全屏背景」这种效果的全部语义。

多知道一个流派没有坏处：业界还有更极端的画法——一个顶点数据都不喂，在 vertex shader 里硬编码一个超出 clip space 的大三角形铺满全屏，光栅化开销再省一档（少一只三角形）。课程不采用它：四边形的 v_uv 四角语义清晰、对称好读，而真实创意网站的性能瓶颈从来不在这一只三角形上。省一档光栅化的收益，抵不过可读性上的损失——知道它存在，将来在别人的代码里撞见时不必慌张。

## How：demo 02「UV 观测台」逐段精讲

demo 02 把本篇全部概念装进一台测量仪器：网格是刻度盘，鼠标是测头，取样环内该像素的 UV 身份色直接显影。chrome 接入只改四个字段：

| 参数 | 值 |
|------|-----|
| title | UV OBSERVATORY |
| tags | WEBGL2 / GLSL / UV |
| hint | 移动鼠标：测头取样 UV，环内显影该像素的身份色 |
| 动效 | 无——静态观测台，画面只随鼠标动 |

vertex.glsl 全文如下，比 demo 01 还短——连 varying 都省了：

```glsl
#version 300 es

layout(location = 0) in vec2 a_position; // 数据本身就是 clip space 坐标（-1..1）

void main() {
  // 没有 MVP 矩阵：四边形就是视口本身，写了矩阵反而多此一举
  gl_Position = vec4(a_position, 0.0, 1.0);
}
```

为什么不给 fragment 递 UV？因为本篇有两条 UV 路可选：demo 01 走 varying 路（顶点 out、光栅化插值、片元 in），本 demo 走现算路——每个像素自己用 `gl_FragCoord.xy / u_resolution` 算出身份证。两条路数值一致（gl_FragCoord 是像素中心坐标，与插值结果差半像素，肉眼不可见）。观测台选现算路，是为了把 vertex 缩到极简，也让「UV 从哪来」这个问题的两条答案并排摆着——下一台机器用到 varying 时你会立刻认出它是老朋友。

fragment.glsl 是整台仪器的测量车间，七层视觉逐层叠加。先看头部的工具函数——后面每一层都靠它们画线：

```glsl
#version 300 es
precision highp float;

uniform vec2 u_resolution; // 物理像素（与 gl_FragCoord 同域）
uniform vec2 u_mouse;      // 0-1，已翻转为左下原点——与 uv 同域，直接可比

out vec4 fragColor;

const vec3 BG   = vec3(0.043, 0.055, 0.078); // #0B0E14
const vec3 ROSE = vec3(1.000, 0.302, 0.427); // #FF4D6D
const vec3 CYAN = vec3(0.298, 0.788, 0.941); // #4CC9F0
const vec3 GRID = vec3(0.224, 0.286, 0.376); // 刻度盘暗青

const float LENS_R = 0.075; // 取样环半径（x 已做宽高比校正 → 屏幕真圆）

float gPx; // 1 物理像素对应的 uv 长度 = 1 / u_resolution.y，供描边函数抗锯齿

// 到最近网格线的距离场：n = 每行格数
float gridDist(vec2 p, float n) {
  vec2 g = abs(fract(p * n) - 0.5) / n;
  return min(g.x, g.y);
}
// 1.5px 半宽描边：在距离场 d 过零处画线
float stroke(float d) {
  return 1.0 - smoothstep(0.0, gPx * 1.5, abs(d));
}
// 1.5px 抗锯齿实心
float fill(float d) {
  return 1.0 - smoothstep(0.0, gPx * 1.5, d);
}
```

gPx 值得单独说：它是「1 物理像素折合多少 uv」，`smoothstep(0.0, gPx * 1.5, ...)` 在任何分辨率的画布上都给出 1.5 物理像素宽的过渡带——抗锯齿宽度不写死在 uv 域，而是跟着分辨率走，这就是恒定细线的全部秘密。demo 01 的渐变用不上它（渐变没有「线」），从这台观测台起，课程里凡是画线都走 stroke / fill 这一对。

main 函数的前三段定下全局：UV 的来历、身份色、测头距离场：

```glsl
void main() {
  // —— UV 的来历只有一行：gl_FragCoord 左下原点物理像素 ÷ 同域分辨率 = 0-1
  vec2 uv = gl_FragCoord.xy / u_resolution;
  float aspect = u_resolution.x / u_resolution.y;
  gPx = 1.0 / u_resolution.y;

  // —— 身份色调色板：R = uv.x、G = uv.y（B 垫 0.12 免得原点全黑）
  vec3 palette = vec3(uv.x, uv.y, 0.12);

  // 测头：x 乘 aspect 校正屏幕等距——否则「圆」在宽屏被拉成椭圆（1.5 的宽高比陷阱）
  vec2 toM = (uv - u_mouse) * vec2(aspect, 1.0);
  float dM = length(toM);

  vec3 col = BG;
```

之后的七层视觉全部遵循同一个节奏——「距离场 → stroke/fill 变系数 → mix 上色」，每层一行 mix：

1. **调色板底片**：环外 10% 暗显成「底片」，取样环内 85% 显影——`mix(col, palette, 0.10 + 0.75 * lens)`，mix 的系数是一个表达式而不是常数，这是本 demo 最值得抄的一手
2. **刻度盘**：`gridDist` 距离场 + stroke，0.1 细网格与 0.5 主网格两档粗细
3. **四边刻度尺**：先算「离边多近」（`min(uv.y, 1.0 - uv.y)`），再用 smoothstep 裁出贴边的短刻与长刻
4. **游标虚线**：`stroke(uv.y - u_mouse.y)` 是贯穿全屏的水平线，`step(0.55, fract(uv.x * 70.0))` 把它打断成虚线——游标跟着测头走，随时读出取样坐标
5. **中心取景十字**：smoothstep 双门槛（0.052–0.058）挖掉中段，像取景器
6. **原点标记**：0,0 处一枚玫红点——调色板左下角必须全黑，它就是 y 轴方向的试金石
7. **测头本体**：`stroke(dM - LENS_R)` 环线 + 环上四向刻 + `fill` 中心点

七层听起来多，写起来只有三十行——每层都是同一个模式的复用。挑第 1、4 层读透，其余扫一眼即可。

main.ts 仍然是 demo 01 骨架的瘦身版，新增了一段 DOM 读数——shader 负责显影，DOM 负责报数：

```ts
import '../../../shared/demo.css';
import { createChrome, initGL, createProgram } from '../../../shared/chrome.ts';
import vsSource from './shaders/vertex.glsl?raw';
import fsSource from './shaders/fragment.glsl?raw';

const chrome = createChrome({
  day: 1,
  index: '02',
  title: 'UV OBSERVATORY',
  tags: ['WEBGL2', 'GLSL', 'UV'],
  hint: '移动鼠标：测头取样 UV，环内显影该像素的身份色',
});

const gl = initGL(chrome);
if (!gl) throw new Error('WebGL2 初始化失败，详情见页面错误面板');

const program = createProgram(gl, vsSource, fsSource, chrome);
if (!program) throw new Error('着色器编译失败，详情见页面错误面板');

// ---- 几何：TRIANGLE_STRIP 四顶点，直接写 clip space，无矩阵可乘 ----------
const vertices = new Float32Array([
  -1.0, -1.0, // 左下
   1.0, -1.0, // 右下
  -1.0,  1.0, // 左上
   1.0,  1.0, // 右上
]);

const vao = gl.createVertexArray()!;
gl.bindVertexArray(vao);
const vbo = gl.createBuffer()!;
gl.bindBuffer(gl.ARRAY_BUFFER, vbo);
gl.bufferData(gl.ARRAY_BUFFER, vertices, gl.STATIC_DRAW);

// 只有位置一个属性：2 分量 float，stride 8 字节（2 float × 4 byte）
gl.enableVertexAttribArray(0);
gl.vertexAttribPointer(0, 2, gl.FLOAT, false, 8, 0);

// ---- uniform：分辨率 / 鼠标 ---------------------------------------------
const uResolution = gl.getUniformLocation(program, 'u_resolution');
const uMouse = gl.getUniformLocation(program, 'u_mouse');

// ---- 观测读数：DOM 角标实时报出取样点坐标 --------------------------------
// shader 负责显影，DOM 负责数字——同一份 pointer 状态，两种读法
const readout = document.createElement('div');
readout.style.cssText =
  'position:absolute;right:16px;bottom:46px;font:500 11px/1.4 ui-monospace,monospace;' +
  'color:#4cc9f0;letter-spacing:0.12em;pointer-events:none;opacity:.85;';
readout.textContent = 'UV 0.500 / 0.500';
chrome.canvas.parentElement!.appendChild(readout);
let lastReadout = readout.textContent ?? '';

// ---- 帧循环：观测台无动画，唯一变量是鼠标 --------------------------------
chrome.startLoop(() => {
  gl.viewport(0, 0, chrome.width, chrome.height);
  gl.useProgram(program);
  // 物理像素尺寸：gl_FragCoord 也是物理像素，两边同域才能除出 0-1
  gl.uniform2f(uResolution, chrome.width, chrome.height);
  // sx/sy 已是 0–1 且左下原点：归一化、y 翻转、lerp 三件事 chrome.pointer 全做完
  gl.uniform2f(uMouse, chrome.pointer.sx, chrome.pointer.sy);
  gl.clearColor(0.043, 0.055, 0.078, 1.0);
  gl.clear(gl.COLOR_BUFFER_BIT);
  gl.drawArrays(gl.TRIANGLE_STRIP, 0, 4); // 四个顶点，条带模式

  // 读数只在变化时写 DOM，避免每帧 textContent 触发无谓布局
  const text = `UV ${chrome.pointer.sx.toFixed(3)} / ${chrome.pointer.sy.toFixed(3)}`;
  if (text !== lastReadout) {
    lastReadout = text;
    readout.textContent = text;
  }
});
```

三处值得盯住的变化：几何段从 demo 01 的 interleaved 五 float 瘦身为纯坐标两 float，`vertexAttribPointer` 的 stride 从 0 写成 8——每个顶点恰好 2 float × 4 字节，没有颜色要插，颜色的事全权交给 UV；uniform 段没有 u_time——观测台是静态仪器，画面唯一变量是鼠标；帧循环尾部多了一段 DOM 读数——同一份 `chrome.pointer` 喂给 shader 显影、喂给 `textContent` 报数，而且只在字符串变化时写 DOM，避免每帧触发布局。至于 `chrome.pointer.sx / sy` 直传：事件桥已经把归一化、y 翻转、lerp 阻尼 0.08 三件事做完，shader 拿到的就是 UV 域里的鼠标——事件桥的完整展开在 1.7，这里你只需要确认：测头跟手但不生硬，那 0.08 的阻尼已经在上游生效。

现在动笔夺回所有权，两处改动都不用碰 JS：先把调色板一行改成 `vec3(uv.y, uv.x, 0.12)`，保存——红绿互换，原本「横红竖绿」的显影原地转了九十度，你亲眼确认了 uv.x 管横轴、uv.y 管纵轴；再把 stroke 里的 `gPx * 1.5` 改成 `gPx * 6.0`，全台刻度一夜变粗——把乘数试到 `0.8`，你会看到细线在抗锯齿预算耗尽时开始闪烁。改完的这台观测台别急着收，明天写噪声时它是你的第一块试纸——任何算法先贴进 demo 02 的 fragment 跑一遍，坐标问题当场现形。

## 常见坑

| 症状 | 原因 |
|------|------|
| 圆画成椭圆、图案在宽屏上横向拉伸 | uv 或居中域忘乘 aspect：x 方向的 0–1 跨的像素比 y 方向多，`p.x *= u_resolution.x / u_resolution.y` 不可省 |
| LINK ERROR：unresolved symbol 之类链接报错 | vertex 的 out 与 fragment 的 in 名字或类型不一致——varying 是接头暗号，必须逐字相同，错误面板会直接给出修复提示 |
| SDF 的半径「看起来对」但形状压扁 | 用 0–1 的 uv 直接算距离，它不是正方形域：先进居中域再乘 aspect，距离才有几何意义 |
| 鼠标标点上下颠倒、反着走 | gl_FragCoord 原点在左下，鼠标事件原点在左上——y 要翻转；chrome.pointer 的 ny / sy 已处理，自己手写事件时最容易漏这步 |
| 编译报错 `cannot convert from 'const int' to 'float'` | int 与 float 不隐式转换：`1` 是 int、`1.0` 才是 float，赋值与函数实参处必炸；`vec2(1)` 这类构造器恰好合法，别被它惯坏手感 |

## Checkpoint

- 能徒手画出 attribute → varying → fragment 的数据流图，标出插值发生在哪个阶段、由谁完成
- 能默写等比居中坐标三行（uv → `uv * 2.0 - 1.0` → `p.x *= aspect`），并解释第三行为什么不可省
- 能解释全屏四边形为什么不需要 MVP 矩阵，以及省掉矩阵的语义代价是什么
- 能复述「uniform 是广播，varying 是插值」，并给两条通路各举一个本课 demo 里的真实数据
- 能说出 v_uv 与 `gl_FragCoord.xy / u_resolution` 两条 UV 路的差异，和各自更适合的场景
