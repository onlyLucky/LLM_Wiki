## 1. 流水线阶段

```
push → 安装依赖 → Lint/类型检查 → 测试 → 构建 → 部署 → 冒烟测试
```

| 阶段 | 命令 | 失败处理 |
|------|------|----------|
| Lint | [命令] | 阻止合并 |
| 类型检查 | [命令] | 阻止合并 |
| 测试 | [命令] | 阻止合并 |
| 构建 | [命令] | 阻止部署 |
| 部署 | [命令] | 触发回滚 |

## 2. 触发规则

| 事件 | 分支 | 行为 |
|------|------|------|
| pull_request | 任意 | 运行检查，不部署 |
| push | `main` | 检查通过后部署 production |
| push | `feature/*` | 仅运行检查 |

## 3. 流水线文件

| 文件 | 用途 |
|------|------|
| `.github/workflows/ci.yml` | 检查与测试 |
| `.github/workflows/deploy.yml` | 构建与部署 |

## 4. AI 协作约定

- 构建失败时，AI 可读取日志定位原因，但**不得跳过检查**（禁止 `--no-verify` 等绕过手段）
- 修复后重新推送触发流水线，不得手动覆盖结果

## 5. 常见失败排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 本地通过、CI 失败 | 环境差异 / 依赖未锁定 | 对齐版本、检查锁文件 |
| 部署超时 | 平台限制 / 构建过慢 | 优化构建、查看平台日志 |
