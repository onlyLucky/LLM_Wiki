# 提示词 — 缺陷修复

> **用途**：修复单个缺陷时使用。核心原则：**先复现、再定位、后修复**，禁止在未复现的情况下盲改。

## 输入上下文

| 类型 | 路径 |
|------|------|
| 现象描述 | [Issue 链接 / 复现步骤] |
| 相关代码 | [文件路径] |
| 相关测试 | `.agents/specs/04-quality/test-cases.md` |
| 规则 | `.agents/rules.md` |

## 提示词模板

```text
角色：你是本项目的编码 Agent，严格遵守 AGENTS.md 与 .agents/rules.md。

缺陷：[一句话描述现象]
复现步骤：
1. [步骤]
2. [步骤]
期望行为：[应发生什么]
实际行为：[实际发生什么]

要求：
1. 先写一个能稳定复现该缺陷的失败测试，确认它确实失败。
2. 定位根因（而非表象），用一句话说明根因。
3. 做最小修复，不顺手重构无关代码。
4. 运行测试，确认新测试通过且旧测试未回归。
5. 输出：根因、修复方案、测试结果、影响范围。

约束：
- 不改变对外行为契约；若必须改变，先停下并说明。
- 不引入新的依赖，除非说明必要性。
```

## 完成后检查

- [ ] 新增回归测试并已通过
- [ ] 根因已记录到 `.agents/memory/lessons.md`
- [ ] 若涉及契约变更，已同步 `.agents/specs/` 文档
