# 编码、提交与测试规则

> **给 AI**：动手写代码前必读。本文件定义本项目的编码风格、提交规范、分支策略与质量红线，优先级高于模型的默认习惯。

| 阶段 | 优先级 | 状态 | 负责人 | 最后更新 |
|------|--------|------|--------|----------|
| 全程 | 极高 | 草稿 | [@维护者] | YYYY-MM-DD |

## 1. 编码规范

- 语言与版本：[如 TypeScript 5.x / Python 3.12]
- 格式化工具：[如 Prettier / Black]，提交前必须格式化
- 静态检查：[如 ESLint / Ruff / mypy]，**零告警**方可提交
- 命名约定：[如 组件 PascalCase、函数 camelCase、常量 UPPER_SNAKE]
- 模块化：单文件不超过 [N] 行，禁止"单体巨文件"
- 注释：只写解释"为什么"的注释，不复述代码做了什么

## 2. 提交规范（Conventional Commits）

```
<type>(<scope>): <subject>
```

| type | 用途 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档变更 |
| `refactor` | 重构（不改行为） |
| `test` | 测试 |
| `chore` | 构建 / 依赖 / 杂项 |

- 提交信息使用中文描述，主题不超过 50 字
- 一个提交只做一件事；禁止提交未通过测试的代码

## 3. 分支策略

| 分支 | 用途 |
|------|------|
| `main` | 可发布分支，禁止直接推送 |
| `feature/<name>` | 功能开发 |
| `fix/<name>` | 缺陷修复 |
| `docs/<name>` | 文档 |

- 合并前必须通过 CI 与代码评审（Review Agent）

## 4. 测试要求

- 新功能必须附带对应测试；缺陷修复必须先补一个失败用例
- 测试命名：`should <行为> when <条件>`
- 覆盖率红线：核心模块 [≥ 80%]
- 提交前本地运行全部测试

## 5. 安全红线

- 禁止硬编码密钥、Token、密码
- 所有外部输入必须校验（类型守卫 / Schema 校验）
- 依赖新增需说明理由；禁止引入未维护的包
- 涉及鉴权、支付、隐私的改动必须走安全清单

## 6. 上下文管理

- 会话过长时主动压缩上下文，避免"记忆过载"
- 每完成一个任务更新 `.agents/context.md`
- 重要决策写入 `.agents/memory/decisions.md`
