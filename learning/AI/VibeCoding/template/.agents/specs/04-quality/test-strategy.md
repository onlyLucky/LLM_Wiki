## 1. 测试分层

| 层级 | 范围 | 工具 | 覆盖目标 | 运行时机 |
|------|------|------|----------|----------|
| 单元测试 | 函数 / 模块 | [如 Vitest] | 核心逻辑 ≥ 80% | 每次提交 |
| 集成测试 | 模块间 / API | [如 Supertest] | 关键链路全覆盖 | 每次提交 |
| 端到端（E2E） | 用户流程 | [如 Playwright] | 主流程全覆盖 | 合并前 |
| 人工验收 | 体验 / 边界 | 人工 | 高风险场景 | 发布前 |

## 2. 测试原则

- 测试应验证**行为**而非实现细节
- 缺陷修复必须先补一个失败用例（回归测试）
- 测试之间相互独立，可重复运行
- 禁止依赖真实外部服务；用 mock / 沙箱替代

## 3. 命名与组织

```
tests/
├── unit/         # 单元测试
├── integration/  # 集成测试
└── e2e/          # 端到端测试
```

- 命名：`should <行为> when <条件>`
- 一个测试文件对应一个被测模块

## 4. AI 生成测试的要求

- 以 `acceptance-criteria.md` 的验收项为输入生成用例
- 必须覆盖：正常路径、边界条件、异常路径
- 生成的用例需人工确认后才纳入基线

## 5. 质量红线（CI 强制）

- [ ] 全部测试通过
