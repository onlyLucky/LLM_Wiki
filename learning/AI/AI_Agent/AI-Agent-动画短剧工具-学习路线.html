1八大知识模块

模块一 · LLM 与 Agent 基础（筑基）

作用：所有 Agent 的「大脑与手脚」
  • Python 工程能力 — 虚拟环境（uv/conda）、异步编程 asyncio、类型注解、HTTP 客户端
  • LLM 工作原理（概念级） — Token、上下文窗口、温度/采样参数、幻觉成因
  • Transformer 架构 — 注意力机制的直觉理解（不必推数学公式）
  • Prompt 工程 — 系统提示词、few-shot、思维链（CoT）、角色设定
  • 结构化输出 — JSON Schema 约束输出、Pydantic 解析、失败重试
  • 模型接入 — 主流云端 API、本地部署 Ollama/vLLM、开源模型生态
  • Agent 循环 — 感知 → 规划 → 行动 → 观察 的基本范式

模块二 · 多智能体系统与智能分工

作用：导演 / 编剧 / 分镜 / 动画 / 剪辑的协作体系
  • 角色化 Agent 设计 — 用提示词定义职责边界、产出物格式、禁止事项
  • 编排模式 — 中心化 Orchestrator-Worker、层级式、去中心化 Swarm
  • 主流框架 — LangGraph（图状态机，生产级）、CrewAI（角色式快速原型）、AutoGen/AG2 与 Microsoft Agent Framework、MetaGPT（软件公司角色模拟）
  • 通信机制 — 消息传递、结构化任务交接（handoff）、共享状态/黑板模式
  • 任务分解 — 目标 → DAG 子任务、并行执行、依赖管理
  • 一致性与冲突处理 — 上下文对齐、版本仲裁、投票与裁决

模块三 · 工作流模块化与编排（可拆分、可组合）

作用：整条「剧本→分镜→动画→渲染→合成」管线成为可插拔积木
  • 节点式架构思想 — 研究 ComfyUI、n8n、Houdini 的节点图设计：节点 = 输入 Schema + 处理 + 输出 Schema
  • DAG 工作流 — 依赖图、拓扑排序、条件分支、循环、并行扇入扇出
  • 状态机 — 有限状态机（FSM）建模任务生命周期
  • 接口标准化 — Pydantic 定义节点 I/O、版本兼容、数据契约
  • 插件系统 — 注册机制、动态加载、第三方扩展
  • 异步与队列 — Celery/Redis 任务队列、消息队列解耦、断点重跑与幂等设计

模块四 · 记忆系统

作用：角色设定库、剧本连续性、镜头风格记忆、用户偏好
  • 短期记忆 — 会话上下文管理、滑动窗口、超出窗口时的摘要压缩
  • Embedding — 文本向量化原理、嵌入模型选择（bge / text-embedding 系列）
  • 向量数据库 — Chroma（入门）→ Qdrant / Milvus（生产）、相似度检索
  • RAG 检索增强 — 分块策略、检索、重排（rerank）、引用溯源
  • 记忆分层 — 工作记忆 / 情景记忆 / 语义记忆 / 程序记忆的设计
  • 写入与遗忘策略 — 何时存、存什么、相关性评分、去重与衰减

模块五 · 决策引擎（Trae System One 决策模型）

作用：总编排器的「大脑」，决定下一步做什么、不合格时如何返工
  • Trae System One 决策模型（核心） — 「System One（系统一）」判断模型：不生成文本，输入「状态 + 类型化问题」直接返回带概率与置信度的结构化判定；三种原语接口：Choice（选项，最多 255 项）、Score（评分，2–10 级有序量表）、Noul（是非概率，0.5 视为弃权分支）
  • 系统一/系统二分工 — LLM（系统二）负责规划与生成，System One 决策模型（系统一）负责高频判断，硬约束兜底用规则引擎
  • 决策点设计 — 把业务判断翻译成类型化问题：任务路由（Choice）、质量门控（Score）、重试决策（Noul）、置信度阈值与降级路径
  • LLM 任务规划 — Planner 模式：把用户需求翻译成执行计划
  • 质量门控 — Score 原语给剧本/分镜打分 + Critic Agent 评审，不达标自动返工
  • 反思与自修正 — Reflection / Reflexion 模式、多轮迭代改进
  • 重试与降级 — Noul 原语判断是否重渲染、失败分级处理、备选模型/节点切换
  • 预算控制 — Token/算力/时间预算下的调度决策
  • 规划算法（了解） — 搜索、启发式、MCTS 的基本思想

模块六 · 自训练闭环

作用：让工具「越用越好」——风格一致性、剧本偏好、动作质量持续进化
  • 数据回流管道 — 生产日志埋点、成功/失败案例自动采集、用户反馈收集
  • 数据工程 — 清洗、去重、标注、SFT 指令数据集构建
  • 微调实操 — LoRA / QLoRA（消费级显卡可跑）、全参微调概念
  • 偏好对齐 — RLHF 概念、DPO 直接偏好优化实操
  • 评估体系 — Eval 数据集、自动化回归测试、A/B 对比、主动学习
  • 风格专项 — 角色风格 LoRA 训练（保持短剧画风一致）

模块七 · 动画领域专业（2D 骨骼 + 3D 渲染）

作用：工具的「手艺」层，决定成片质量上限
  • 2D 骨骼动画原理 — 骨骼层级、蒙皮权重、IK/FK、网格变形（研究 Spine / Live2D 的机制：把 2D 角色切块绑在骨骼上）
  • 3D 基础 — 坐标系、网格与材质、骨骼绑定、动画曲线、约束
  • 程序化 3D — Blender Python API（bpy）脚本化建模/绑定/渲染；Three.js / Unity / UE 选型
  • 3渲2（NPR 非真实感渲染） — 卡通渲染 Toon Shading、描边、色阶、风格化后处理，实现「3D 骨骼驱动 + 2D 画面」
  • 动画十二法则 — 挤压拉伸、预备动作、缓入缓出、弧线运动等（写进提示词与动作库）
  • AIGC 内容管线 — 剧本：LLM 结构化分镜 JSON；角色：Stable Diffusion + ControlNet + IP-Adapter 保一致性；动作：Text-to-Motion、图生视频、动作重定向；声音：TTS 配音、口型同步（Wav2Lip 类）
  • 合成 — FFmpeg 剪辑合成、字幕、转场、自动出片

模块八 · 工程化与产品化

作用：把 Demo 变成可用的工具
  • 前端 — React + React Flow 节点式流程编辑器、WebSocket 实时进度推送
  • 后端 — FastAPI、PostgreSQL、Redis、任务队列
  • 推理优化 — vLLM 批量推理、量化（GGUF/AWQ）、显存管理
  • MLOps — 实验跟踪（MLflow/W&B）、模型版本、数据/产物管理
  • 部署 — Docker、GPU 调度、任务优先级
