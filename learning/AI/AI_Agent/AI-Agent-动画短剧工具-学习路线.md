## 1. 八大知识模块

### 模块一 · LLM 与 Agent 基础（筑基）

**作用：所有 Agent 的「大脑与手脚」**

- **Python 工程能力** — 虚拟环境（uv/conda）、异步编程 asyncio、类型注解、HTTP 客户端
- **LLM 工作原理（概念级）** — Token、上下文窗口、温度/采样参数、幻觉成因
- **Transformer 架构** — 注意力机制的直觉理解（不必推数学公式）
- **Prompt 工程** — 系统提示词、few-shot、思维链（CoT）、角色设定
- **结构化输出** — JSON Schema 约束输出、Pydantic 解析、失败重试
- **模型接入** — 主流云端 API、本地部署 Ollama/vLLM、开源模型生态
- **Agent 循环** — 感知 → 规划 → 行动 → 观察 的基本范式

### 模块二 · 多智能体系统与智能分工

**作用：导演 / 编剧 / 分镜 / 动画 / 剪辑的协作体系**

- **角色化 Agent 设计** — 用提示词定义职责边界、产出物格式、禁止事项
- **编排模式** — 中心化 Orchestrator-Worker、层级式、去中心化 Swarm
- **主流框架** — LangGraph（图状态机，生产级）、CrewAI（角色式快速原型）、AG2 与 Microsoft Agent Framework（AutoGen 系）、MetaGPT（软件公司角色模拟）
- **通信机制** — 消息传递、结构化任务交接（handoff）、共享状态/黑板模式
- **任务分解** — 目标 → DAG 子任务、并行执行、依赖管理
- **一致性与冲突处理** — 上下文对齐、版本仲裁、投票与裁决

### 模块三 · 工作流模块化与编排（可拆分、可组合）

**作用：整条「剧本→分镜→动画→渲染→合成」管线成为可插拔积木**

- **节点式架构思想** — 研究 ComfyUI、n8n、Houdini 的节点图设计：节点 = 输入 Schema + 处理 + 输出 Schema
- **DAG 工作流** — 依赖图、拓扑排序、条件分支、循环、并行扇入扇出
- **状态机** — 有限状态机（FSM）建模任务生命周期
- **接口标准化** — Pydantic 定义节点 I/O、版本兼容、数据契约
- **插件系统** — 注册机制、动态加载、第三方扩展
- **异步与队列** — Celery/Redis 任务队列、消息队列解耦、断点重跑与幂等设计

### 模块四 · 记忆系统

**作用：角色设定库、剧本连续性、镜头风格记忆、用户偏好**

- **短期记忆** — 会话上下文管理、滑动窗口、超出窗口时的摘要压缩
- **Embedding** — 文本向量化原理、嵌入模型选择（bge / text-embedding 系列）
- **向量数据库** — Chroma（入门）→ Qdrant / Milvus（生产）、相似度检索
- **RAG 检索增强** — 分块策略、检索、重排（rerank）、引用溯源
- **记忆分层** — 工作记忆 / 情景记忆 / 语义记忆 / 程序记忆的设计
- **写入与遗忘策略** — 何时存、存什么、相关性评分、去重与衰减

### 模块五 · 决策引擎（Trae System One 决策模型）

**作用：总编排器的「大脑」，决定下一步做什么、不合格时如何返工**

- **Trae System One 决策模型（核心）** — 「System One（系统一）」判断模型：不生成任何文本，输入「状态 + 类型化问题」，直接返回带概率与置信度的结构化判定；三种原语接口：Choice（选项，最多 255 项）、Score（评分，2–10 级有序量表）、Noul（是非概率，0.5 视为弃权分支）
- **系统一 / 系统二分工** — LLM（系统二）负责规划与生成，System One 决策模型（系统一）负责高频判断，硬约束兜底用规则引擎
- **决策点设计** — 把业务判断翻译成类型化问题：任务路由（Choice）、质量门控（Score）、重试决策（Noul）、置信度阈值与降级路径
- **LLM 任务规划** — Planner 模式：把用户需求翻译成执行计划
- **质量门控** — Score 原语给剧本/分镜打分 + Critic Agent 评审，不达标自动返工
- **反思与自修正** — Reflection / Reflexion 模式、多轮迭代改进
- **重试与降级** — Noul 原语判断是否重渲染、失败分级处理、备选模型/节点切换
- **预算控制** — Token/算力/时间预算下的调度决策
- **规划算法（了解）** — 搜索、启发式、MCTS 的基本思想

### 模块六 · 自训练闭环

**作用：让工具「越用越好」——风格一致性、剧本偏好、动作质量持续进化**

- **数据回流管道** — 生产日志埋点、成功/失败案例自动采集、用户反馈收集
- **数据工程** — 清洗、去重、标注、SFT 指令数据集构建
- **微调实操** — LoRA / QLoRA（消费级显卡可跑）、全参微调概念
- **偏好对齐** — RLHF 概念、DPO 直接偏好优化实操
- **评估体系** — Eval 数据集、自动化回归测试、A/B 对比、主动学习
- **风格专项** — 角色风格 LoRA 训练（保持短剧画风一致）

### 模块七 · 动画领域专业（2D 骨骼 + 3D 渲染）

**作用：工具的「手艺」层，决定成片质量上限**

- **2D 骨骼动画原理** — 骨骼层级、蒙皮权重、IK/FK、网格变形（研究 Spine / Live2D 的机制：把 2D 角色切块绑在骨骼上）
- **3D 基础** — 坐标系、网格与材质、骨骼绑定、动画曲线、约束
- **程序化 3D** — Blender Python API（bpy）脚本化建模/绑定/渲染；Three.js / Unity / UE 选型
- **3渲2（NPR 非真实感渲染）** — 卡通渲染 Toon Shading、描边、色阶、风格化后处理，实现「3D 骨骼驱动 + 2D 画面」
- **动画十二法则** — 挤压拉伸、预备动作、缓入缓出、弧线运动等（写进提示词与动作库）
- **AIGC 内容管线** — 剧本：LLM 结构化分镜 JSON；角色：Stable Diffusion + ControlNet + IP-Adapter 保一致性；动作：Text-to-Motion、图生视频、动作重定向；声音：TTS 配音、口型同步（Wav2Lip 类）
- **合成** — FFmpeg 剪辑合成、字幕、转场、自动出片

### 模块八 · 工程化与产品化

**作用：把 Demo 变成可用的工具**

- **前端** — React + React Flow 节点式流程编辑器、WebSocket 实时进度推送
- **后端** — FastAPI、PostgreSQL、Redis、任务队列
- **推理优化** — vLLM 批量推理、量化（GGUF/AWQ）、显存管理
- **MLOps** — 实验跟踪（MLflow/W&B）、模型版本、数据/产物管理
- **部署** — Docker、GPU 调度、任务优先级

## 3. 开源框架快速入门

### pi（Pi Coding Agent）· 极简 Agent Harness ★

- **是什么**：极简的终端编程 Agent 脚手架（minimal agent harness），理念是「Adapt Pi to your workflows, not the other way around」——核心保持小巧，通过 TypeScript 扩展、Skill、提示词模板、主题与 Pi Package 扩展能力
- **学习价值**：内核极小、源码可通读，是理解 Agent 内核（agent loop、工具注册、上下文管理、扩展机制）的最佳教材；与重框架互补——先用 pi 看懂「Agent 的最小骨架」，再用重框架做工程
- **快速入门三步**：
  1. 安装：`curl -fsSL https://pi.dev/install.sh | sh`（或 `npm install -g @earendil-works/pi-coding-agent`）
  2. 启动后先玩默认四工具：`read` / `write` / `edit` / `bash`——观察一个最小 Agent 循环如何运转
  3. 写一个自定义扩展/Skill，体会「harness + 扩展」的模块化思想（可直接迁移到你的节点式架构设计）
- **官方资源**：<https://pi.dev>（Quickstart 文档）；中文社区指南：<https://pi-agent.org/docs>

### LangGraph · 生产级工作流编排

- **是什么**：把 Agent 工作流建模为带类型状态的有向图：节点 = Agent/函数，边 = 状态转移（含条件分支），支持 checkpointer 持久化与恢复
- **何时用**：你的短剧管线主框架——需要精确控制、断点重跑、多 Agent 状态共享
- **快速入门三步**：定义 StateGraph 状态 → 添加节点与边 → 编译运行 + 接入 checkpointer；先复现「编剧 → 评审 → 返工」双节点图

### CrewAI · 角色式多智能体

- **是什么**：以「团队角色」心智模型（Agent / Task / Crew）快速搭建多智能体协作
- **何时用**：快速原型验证分工模式（导演/编剧/分镜/评审），几天出 demo
- **快速入门三步**：定义 Agent 角色与目标 → 定义 Task 与期望产出 → 组成 Crew 按流程执行

### AG2 / Microsoft Agent Framework · AutoGen 系

- **是什么**：AutoGen 演进出的多智能体对话框架；Microsoft Agent Framework 整合了 AutoGen 与 Semantic Kernel
- **何时用**：研究多 Agent 对话式协作与群聊裁决模式
- **快速入门三步**：安装 → 用 AutoGen Studio 拖拽两个 Agent 对话 → 导出代码研究其消息循环

### MetaGPT · SOP 化多智能体

- **是什么**：把软件公司角色（产品经理/架构师/工程师）的 SOP 标准作业程序编码进多 Agent 协作
- **学习价值**：体会「把工作流写成 SOP 交给角色」的设计范式——与你的短剧组（导演/编剧/分镜/动画/剪辑）分工同构
- **快速入门**：安装后跑官方「创业公司」示例 → 研究其角色提示词与产出物 Schema 设计

### ComfyUI · 动画域节点式工作流

- **是什么**：节点式 AIGC 工作流引擎——既是你的「模块化工作流」UI/交互范本，也是动画 AIGC 管线的现成执行器
- **何时用**：阶段四动画域；同时把它的节点注册/连线/缓存机制当作你自研节点引擎的参考架构
- **快速入门三步**：装 ComfyUI Manager → 跑通 SD 文生图工作流 → 拆解「角色一致性管线」（特征提取 → IP-Adapter → ControlNet → 图生视频）

## 5. 终极总体项目（第 11 项）：从零制作 2D 骨骼动画短剧 AI Agent 工具

> 本项目只讲实现流程与相关知识点，不展开代码实现。

### 5.1 项目目标与验收标准

**目标**：输入一句话创意 → 自动产出多镜头、2D 骨骼（3D 模型渲染）的动画短剧成片（含配音、口型、字幕），全流程满足五大能力要求：工作流程模块化、可拆分、可组合、智能分工、记忆储存、支持数据自训练、System One 决策。

**验收标准**：

- 一句话输入产出 ≥60 秒、≥5 镜头成片
- 管线节点可插拔：替换任一节点后端（换 TTS / 换视频模型）不影响全局
- 分镜与剧本经质量门控自动返工至少 1 轮，通过才放行
- 同一角色跨镜头一致（复用骨骼资产 + 风格 LoRA）
- 用户反馈自动回流进训练数据集，模型可迭代升级

### 5.2 总体架构（四层）

```
决策编排层    Planner（LLM · 系统二）｜ System One 决策模型（系统一）｜ 规则引擎兜底
多智能体层    编剧 Agent ｜ 分镜 Agent ｜ 绑定动画 Agent ｜ 渲染剪辑 Agent
工作流节点层  DAG 节点库（Schema 化 I/O）｜ 插件注册 ｜ 任务队列 ｜ 断点重跑
支撑层        记忆库（向量/RAG）｜ 资产管理 ｜ 数据回流 ｜ 微调管线 ｜ 评估
```

- **决策编排层**：LLM 把创意翻译成执行计划；System One 决策模型以三原语接管所有高频判断——Choice 做任务路由、Score 做质量门控、Noul 做重试决策；确定性约束用规则引擎兜底
- **多智能体层**：四个专业 Agent 按结构化产物交接（剧本 JSON → 分镜 JSON → 骨骼动作数据 → 成片）
- **工作流节点层**：每个节点输入/输出 Pydantic Schema 化，可注册、可替换、可组合；Celery 执行、失败幂等重跑
- **支撑层**：向量记忆库（角色设定/风格记忆）、资产库（骨骼/动作/风格 LoRA）、数据回流与训练闭环

### 5.3 实现流程（四期十步）

**第一期 M0 · 最小闭环**

1. **数据结构设计**：定义剧本/分镜/镜头三级 JSON Schema（角色、台词、动作、运镜、时长）——知识点：结构化输出、Pydantic（模块一）
2. **单管线跑通**：一句话 → 剧本 JSON → 单镜头静态图 → TTS → FFmpeg 合成 30 秒——知识点：LLM API、SD 生图、TTS、FFmpeg（模块一/七）

**第二期 M1 · 骨骼动画域**

3. **角色资产管线**：角色立绘 PNG 切块 → 骨骼绑定（Spine 思路）→ 蒙皮权重 → 动作库——知识点：骨骼绑定、蒙皮、IK/FK、动画十二法则（模块七）
4. **3渲2 渲染节点**：Blender bpy 驱动骨骼动画 + Toon Shader/NPR 渲染 2D 风格帧——知识点：bpy、NPR、描边色阶（模块七）
5. **口型与配音节点**：TTS 音频 → 音素/特征 → 骨骼口型驱动——知识点：口型同步、音频驱动（模块七）

**第三期 M2 · 多 Agent 与模块化**

6. **节点式工作流引擎**：节点注册 + DAG 调度 + 断点重跑 + 前端 React Flow 编辑器——知识点：插件系统、DAG、幂等、任务队列（模块三/八）
7. **智能分工**：编排器拆解任务 → 编剧/分镜/动画/剪辑 Agent 结构化交接——知识点：编排模式、handoff、任务分解（模块二）
8. **决策引擎接入**：每个关键节点接 System One 判断（路由 Choice / 门控 Score / 重试 Noul），LLM 退到规划位——知识点：系统一/系统二分工、类型化问题设计、置信度阈值（模块五）

**第四期 M3 · 记忆与自训练**

9. **记忆系统**：角色设定库/镜头风格库入向量库，RAG 注入各 Agent 上下文——知识点：Embedding、RAG、记忆分层（模块四）
10. **自训练闭环**：埋点采集成败案例 → 构建 SFT/DPO 数据集 → LoRA 微调（风格一致性 + 剧本偏好）→ 自动评估回归上线——知识点：数据回流、LoRA、DPO、Eval（模块六）

### 5.4 五大需求落实对照

| 需求 | 落实方式 | 知识模块 |
|---|---|---|
| 工作流模块化、可拆分可组合 | 节点 I/O Schema 化 + DAG 引擎 + 插件注册 | 模块三 |
| 智能分工 | 编排器 + 四个专业 Agent + 结构化交接 | 模块二 |
| 记忆储存 | 向量库 + RAG + 角色/风格资产复用 | 模块四 |
| 数据自训练 | 埋点回流 + LoRA/DPO 微调 + 评估回归 | 模块六 |
| System One 决策 | 三原语接管路由/门控/重试，LLM 只做规划 | 模块五 |

### 5.5 建议节奏

按 M0 → M1 → M2 → M3 顺序推进，每期结束都有「可演示的成品」；M1 动画域可与 M0 后期并行。完成 M0–M2 即为可用 MVP，M3 使工具具备持续进化能力。

## 7. 起步建议

- **今天就能做** — 安装 Python（uv）+ 申请一个模型 API Key / 安装 Ollama，跑通第一个「输入 → 结构化 JSON 输出」脚本；顺手装上 pi，跑一次它的默认 Agent 循环
- **以终为始** — 每学一个知识点，回到终极项目（第 11 项）的架构图看它落在哪一层，学完即点亮一格
- **以项目收口** — 每个阶段必须完成对应里程碑项目，不追求知识点 100% 覆盖再动手
- **先纵后横** — 先打通 M0「一句话 → 30 秒单镜头动画」最小闭环，再横向扩展模块化、记忆、自训练
- **动画域穿插学习** — 模块七内容量大，建议从阶段二起每周固定投入几小时，与 Agent 学习并行
