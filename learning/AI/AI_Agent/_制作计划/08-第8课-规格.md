## 讲义 8.1 规格 · StateGraph：状态、节点与边

```markdown
# 8.1 StateGraph：把手写 while 升级成一张图

> 第 8 课 · 模块 1 · 约 55 分钟
> 理论对照：《学习路线》模块二「LangGraph」——生产级编排的入场券
```

**章节大纲**：

- 导语：第 3–5 课你手写的循环跑得很好，但「流程硬编码在 while 里」——加一个评审节点要改三处代码；图把它变成加一个节点连两条边
- `## 从 while 到图`：对照表三行（流程在哪定义 / 加节点成本 / 可恢复性）——结论「while 是代码，图是数据；数据可以被存档、恢复、可视化」
- `## State：图的 store`：TypedDict 定义（draft / score / comments / rounds 四个键）；节点签名 `def node(state: State) -> dict`（返回 partial 更新）；「节点不互相 import，只读写 store——组件化纪律，违反即返工」
- `## 三件套接线`：add_node / add_edge / compile 代码段；START 与 END 常量；mermaid 图（writer → critic → END）
- `## How：demo 08 的图定义逐行`
- `## 常见坑`（5 行）：节点返回整包 state 而不是增量（覆盖并发更新）/ State 键没在 TypedDict 声明（静默丢）/ 节点里做 IO 副作用又没幂等（重放时炸）/ 忘 compile 直接调用 / 把外部可变量塞进 State（图要可重放）
- `## Checkpoint`：能写出 State 与节点签名；能对照 while 版说出图版的三个优势；能解释「节点只读写 store」

## 讲义 8.2 规格 · 条件边与并行：编剧→评审→返工图

```markdown
# 8.2 条件边：让「不达标就打回」变成一条边

> 第 8 课 · 模块 2 · 约 55 分钟
> 理论对照：《学习路线》模块二「编排模式」——中心化编排的图实现
```

**章节大纲**：

- 导语：线性图跑不出返工循环；条件边让图有了判断力——它就是你在第 5 课 ReAct 里手写的 if，搬进了框架
- `## 条件边`：add_conditional_edges(critic, router, {"rework": writer, "pass": END}) 代码段；router 是纯函数（state → 边名），「router 里不许有副作用」
- `## 防死循环三件`：MAX_ROUNDS=2 计数进 State；超限强制放行并打 flag（`forced_pass: bool`）；放行原因写进 state——「生产管线必须有逃生门，结营标准第 3 条（自动返工至少一轮）的另一面是：不许无限返工」
- `## 并行扇出预告`：两个评审节点同时给分的图形态（本课讲义只画图，作业 A 档实现）；fan-in 合并策略一句话（第 12 课质检会用到）
- `## How：demo 08 的 router 与强制放行段`
- `## 常见坑`（5 行）：router 里有 LLM 调用（每次边判定都花钱且不可重放）/ MAX_ROUNDS 计数不进 State（恢复后清零）/ 条件边映射表写错边名（运行时才炸）/ 循环边没终点（靠步数兜底的管线都是裸奔）/ forced_pass 不留痕（审计时说不清为什么放行）
- `## Checkpoint`：能写出 router 纯函数；能配置条件边映射；能说清逃生门三件各自的作用

## 讲义 8.3 规格 · checkpointer：断点恢复与重放

```markdown
# 8.3 checkpointer：kill -9 是图管线的体检方式

> 第 8 课 · 模块 3 · 约 50 分钟
> 理论对照：《学习路线》模块二「LangGraph 进阶」——对照第 1 课 /save 与第 6 课 MemoryStore
```

**章节大纲**：

- 导语：第 1 课你存的是消息、第 6 课存的是记忆条目——这次存的是「整张图走到哪了」
- `## 三代持久化对照`：/save（消息级）→ MemoryStore（业务记忆）→ checkpointer（流程状态级）三层表；各自救不了什么
- `## 接入`：SqliteSaver 落盘位置（`assets/08/checkpoints.sqlite`）；compile(checkpointer=...)；thread_id 的意义（一次任务一条线）
- `## 恢复与重放`：中断后按 thread_id 恢复；历史状态可枚举——「时间旅行调试器」；与第 6 课 C 档探针方法的呼应
- `## How：demo 08 的 kill-and-resume 演示脚本`
- `## 常见坑`（5 行）：thread_id 用随机值（永远恢复不了——要用业务 id 如任务名）/ checkpointer 落库文件进 git / 节点不幂等导致重放炸 / 忘记把 checkpointer 传给 compile / sqlite 文件锁（上一进程未退）
- `## Checkpoint`：能说出三层持久化各自救什么；能写出 thread_id 策略；能演示 kill -9 恢复

## demo 规格 · 08-剧本流水线

| 项 | 规格 |
|---|---|
| 路径 | `demos/08-剧本流水线/`（README.md / run.py / tests/test_run.py） |
| 行为目标 | `--idea 一句话` 跑图：writer 产出 Script（第 2 课合同复用）→ critic 打分并给意见（mock 分数序列：首轮 6.5、返工后 8.5）→ score ≥ 8 放行，否则返工 writer（带 comments）→ 两轮后强制放行并标 forced_pass；全程 checkpointer 落盘，支持 `--resume <thread_id>` 从中断点继续；`--mock` 全离线 |
| 接口约束 | `State(TypedDict)`：`idea: str / draft: dict / score: float / comments: list[str] / rounds: int / forced_pass: bool`；`writer_node(state) -> {"draft": dict}`、`critic_node(state) -> {"score": float, "comments": list}`（真实模式 LLM、mock 模式脚本序列）、`router(state) -> Literal["rework","pass"]`（纯函数）；`build_graph(client, checkpointer=None) -> CompiledGraph`（checkpointer 参数化供测试注入内存版） |
| 分段结构 | S1 State 与合同接线（Script 校验进 writer_node）→ S2 三节点定义 → S3 条件边 + MAX_ROUNDS 强制放行 → S4 checkpointer 接入与 --resume → S5 mock 分数序列驱动 |
| 验收测试 | `test_graph_passes_first_round`（首轮 9 分 → 无返工、rounds==1）/ `test_rework_loop`（6.5 → 8.5 → rounds==2 且 score==8.5）/ `test_force_release_after_max_rounds`（恒 6 分 → forced_pass 为真且 rounds==2+1）/ `test_checkpoint_resume`（内存 checkpointer：执行到 critic 后中断，resume 后 state 与完整执行等价）/ `test_router_is_pure`（同 state 两次调用结果一致且无网络副作用——用 mock client 计数为零佐证） |

**README 关键点 4 条**：① while 版（第 2 课）与图版并列对照表 ② router 纯函数纪律的验收方法 ③ thread_id 策略（任务名+时间戳）④ mock 分数序列注释先行。

**常见报错预填**：TypedDict 键漏声明 / 条件边映射表边名拼写 / sqlite 文件锁 / resume 后 mock 序列错位（先看序列设计注释）/ 节点返回整包 state 导致字段互相覆盖。
