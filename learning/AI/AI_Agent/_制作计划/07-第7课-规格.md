## 第 7 课目标能力清单

1. 解释 embedding 空间直觉（语义近 = 距离近），手算两条文本的 cosine 相似度
2. Chroma 三连：入库（add）/ 查询（query）/ 元数据过滤（where），并说明 id 重复的静默覆盖风险
3. 实现分块（定长 + 重叠）与 top_k 检索，并加一层简单重排
4. 跑通 RAG 五段式：检索 → 拼接 → 生成 → 引用 → 评估，回答必须带 [N] 编号引用
5. 换分块粒度（150 / 300 / 600 字）出检索质量对比报告

## 讲义 7.1 规格 · Embedding：把文字变成坐标

```markdown
# 7.1 Embedding：给每句话发一个有语义的 IP 地址

> 第 7 课 · 模块 1 · 约 50 分钟
> 理论对照：《学习路线》模块四「Embedding」——比喻与机制在这里合流
```

**章节大纲**：

- 导语：第 6 课的关键词评分翻车现场——「口头禅」和「常说的话」关键词对不上，语义检索要的是「意思相近」而不是「字面相同」
- `## 空间直觉`：同义句距离近、无关句距离远的二维示意图（mermaid）；cosine 相似度手算示例（两条 4 维小向量，分步算）
- `## 嵌入从哪来`：嵌入模型是「只读编码器」（对照生成模型的差异一行表）；中文选型三条（维度 / 部署 / 成本），本课走「API 或 mock 哈希向量」双通道
- `## mock 哈希向量`：确定性哈希 64 维向量代码段——离线环境的保底，也让你看清「向量库不关心向量怎么来」
- `## 常见坑`（5 行）：真实与 mock 向量混库（空间不同，检索全乱）/ 维度不匹配静默报错 / 长文本一次嵌入（语义被稀释）/ 相似度阈值当万能闸（0.7 不是圣数）/ 忘保存原文本（只有向量查了也白查）
- `## Checkpoint`：能手算 cosine；能说清编码器与生成器的差异；能解释为什么 mock 与真实不能混库

## 讲义 7.2 规格 · Chroma：入库、检索与元数据过滤

```markdown
# 7.2 Chroma：向量库三连与「静默覆盖」陷阱

> 第 7 课 · 模块 2 · 约 55 分钟
> 理论对照：《学习路线》模块四「向量数据库」
```

**章节大纲**：

- 导语：向量库本质是「高维空间建索引」——你只管存、查、过滤三件事
- `## 三连`：PersistentClient 落盘位置约定（`assets/07/chroma/`）；add（ids / embeddings / documents / metadatas）与 query（query_embeddings / n_results / where）代码段；元数据过滤实战：`where={"character": "主角"}` 只在主角设定里查
- `## 静默覆盖陷阱`：add 同 id 不报错直接覆盖——「向量库的第一课是备份你的 id 策略」；id 生成规范（`来源.md#chunk-N`）
- `## 距离与相似度`：distance 与 similarity 的换算一行；top_k=5 的默认值理由
- `## How：demo 07 的 RagStore.add / ask`
- `## 常见坑`（5 行）：id 重复覆盖 / where 字段名与入库 metadata 不一致（查空）/ 每次运行重复入库（先 count 再 add 的幂等习惯）/ 落盘路径进 git（应忽略）/ n_results 大于库存量
- `## Checkpoint`：能写出三连代码段；能说出 id 策略为什么重要；能写出主角过滤的 where

## 讲义 7.3 规格 · RAG：分块、检索、重排与引用

```markdown
# 7.3 RAG：答案质量的上限由检索决定，模型只是发言人

> 第 7 课 · 模块 3 · 约 65 分钟
> 理论对照：《学习路线》模块四「RAG 检索增强」——五段式的完整版
```

**章节大纲**：

- 导语：把设定文档喂给模型的两种死法——整篇塞进去（贵且稀释）、切太碎（检索到半句话）；分块是门手艺
- `## 分块策略`：定长 300 字 + 重叠 50 的实现；为什么重叠（答案横跨切口时不至于断头）；按标题切分作为对照——作业 A 档做粒度对比
- `## 检索与重排`：top_k=5 粗召回 → 关键词命中率精排（第 6 课评分器复用！）取 top 3；「粗召回交给向量，精排交给规则——重排器是性价比之王」
- `## 拼接与生成`：prompt 结构（问题 + 带 [N] 编号的片段 + 回答要求）；引用格式约定（每句事实后跟 [N]）
- `## 评估`：探针问题集（第 6 课 C 档方法回收）；两类失败模式——检索不到（幻觉风险）与检索噪声（跑题风险），各自的探测法
- `## How：demo 07 的 ask 全链路`
- `## 常见坑`（6 行）：分块无重叠断头 / 片段不带编号（引用无从谈起）/ 重排放过了噪声 / 检索为空仍硬答（应答「设定库中没有」）/ 只评估不记录（第 15 课埋点从今天开始攒样本）/ 把检索结果当圣旨（模型仍需判断相关性）
- `## Checkpoint`：能写出带重叠的分块；能说出粗排与精排各交给了谁；能设计三个探针问题

## demo 规格 · 07-角色设定知识库

| 项 | 规格 |
|---|---|
| 路径 | `demos/07-角色设定知识库/`（README.md / run.py / worldbuilding.md / tests/test_run.py）；核心沉淀 `src/deltaagent/rag.py` |
| 预置素材 | `worldbuilding.md`：世界观设定文档（执行侧按本规格生成）：主角设定段（含口头禅「稳住，能赢」）、配角两段（各含专属习惯）、场景两段（学校 / 深夜便利店，各含可用道具）、规则一段（世界里的物理限制）——共 6 段、每段 150–250 字，供分块入库；每段开头有 `## 人物：名字` / `## 场景：名字` 式标题行 |
| 行为目标 | 首次运行入库 worldbuilding.md（幂等：已入库则跳过）；`/ask <问题>` → 检索 top 5 → 重排取 3 → 生成带 [N] 引用的回答；`--mock` 全链路离线（哈希向量 + 脚本回答）；检索为空时明确回答「设定库中没有相关内容」 |
| 接口约束 | `rag.py`：`chunk_text(text: str, size: int = 300, overlap: int = 50) -> list[str]`（保留标题归属：块内首行带来源标题）；`embed(texts: list[str]) -> list[list[float]]`（真实 API 或 `--mock` 下 64 维确定性哈希，通道选择写死在构造参数）；`RagStore(persist_dir: Path)`：`add(doc_path: Path) -> int`（返回新增块数，重复入库返回 0）、`ask(question: str, client: ChatClient, top_k: int = 3) -> AnswerWithSources(answer: str, sources: list[str])`（sources 为 `文件名#块号` 列表，按引用顺序） |
| 分段结构 | S1 素材与入库幂等 → S2 分块与嵌入（双通道）→ S3 检索 + 重排（复用第 6 课命中率评分）→ S4 拼接生成与引用 → S5 空结果分支与评估记录落盘（每次问答追加 `assets/07/eval_log.jsonl`：问题 / 命中块 / 引用数） |
| 验收测试 | `test_chunk_with_overlap`（相邻块重叠 50 字且首行带来源标题）/ `test_mock_embed_deterministic`（同文本两次嵌入结果逐位相等）/ `test_idempotent_add`（第二次 add 返回 0 且库存不变）/ `test_ask_returns_sources`（回答中每个 [N] 都有对应 source）/ `test_empty_result_explicit`（问无关问题时回答含「设定库中没有」） |

**README 关键点 4 条**：① 幂等入库的 count-first 习惯 ② 双通道嵌入的切换方式与「不混库」红线 ③ 粗排（向量）与精排（规则）的分工 ④ eval_log 与第 15 课埋点的血缘关系。

**常见报错预填**：Chroma 落盘目录被锁（上次进程未退）/ where 过滤查空（metadata 键名不一致）/ 哈希向量维度写错导致 query 报错 / 引用编号越界（重排后 sources 数与 [N] 不对应）/ 重复入库后检索出双份。
