## 讲义 9.1 规格 · CrewAI 三件套

```markdown
# 9.1 CrewAI 三件套：把剧组写成配置

> 第 9 课 · 模块 1 · 约 55 分钟
> 理论对照：《学习路线》第 3 章「开源框架快速入门 · CrewAI」
```

**章节大纲**：

- 导语：LangGraph 是给你「自己搭发动机」的；CrewAI 是给你「整车」——三件套声明完，流程引擎自转
- `## 三件套`：Agent（角色卡）/ Task（工单：description + expected_output）/ Crew（班组：agents + tasks + process=sequential）；最小可跑代码段（双角色两任务）
- `## 执行语义`：sequential 的串行交接——上一任务的 output 作为下一任务上下文；与第 8 课条件边的能力差对照表（路由 / 并行 / 恢复三行）
- `## 复用接线`：Crew 的 LLM 通道怎么接第 1 课 ChatClient 约定的模型配置（环境变量直通）；mock 模式的注入点
- `## How：demo 09 的 crew 定义段`
- `## 常见坑`（5 行）：expected_output 写成一句话（产出物自由发挥）/ 角色重叠互抢活（backstory 要划边界）/ 忘开 verbose 丢失轨迹 / 串行顺序写反（评审先于编剧）/ 把 CrewAI 当 LangGraph 用（硬塞流程逻辑进 description）
- `## Checkpoint`：能写出三件套最小配置；能说出 sequential 的交接语义；能列出两框架三处能力差

## 讲义 9.2 规格 · 角色提示词与产出物约束

```markdown
# 9.2 角色卡与工单：五要素人设的框架化

> 第 9 课 · 模块 2 · 约 45 分钟
> 理论对照：第 2 课 2.1「五要素人设」——同一套方法论换个壳
```

**章节大纲**：

- 导语：第 2 课你手写 system 提示词五要素；CrewAI 把五要素拆进 role / goal / backstory 三个键——分工表：身份→role、职责+输出→goal、风格+经历→backstory
- `## 五要素映射表`：五行对照 + 一段示例角色卡全文（编剧）；「backstory 写两句话的剧情医生角色卡」反例展示太长的代价
- `## expected_output 锁产`：把 Pydantic 合同的字段说明翻译成 expected_output 文案（给模型看的 schema 说明书）；与第 2 课「schema 内嵌提示」的等价性说明
- `## 评审角色怎么写`：评分标尺（1–10 + 维度）+ 意见格式（每条一行、可执行）；「评审说『不够好』就是失职——意见必须能被编剧直接执行」
- `## How：demo 09 的两张角色卡`
- `## 常见坑`（4 行）：backstory 抒情化 / expected_output 与真实合同字段不一致（校验必炸）/ 评审无标尺（分数无分布）/ 角色卡里写流程指令（框架的事不要写在人设里）
- `## Checkpoint`：能按映射表改写第 2 课人设为角色卡；能写出带标尺的评审卡；能指出一张烂卡违反了哪条

## 讲义 9.3 规格 · 整合课：双 Agent 剧本生成器

```markdown
# 9.3 整合课：从「能对话」到「能生产」——组二收口

> 第 9 课 · 模块 3 · 约 65 分钟
> 理论对照：00 计划组二验收线——逐条给实现路径
```

**章节大纲**：

- 导语：组二四课攒的是「记忆 + 编排」两条腿；今天产出分镜 JSON——它是第 10–12 课节点引擎的第一批真实货币
- `## 分镜合同 v2`：Storyboard 模型全文（`script: Script` + `shots: list[Shot]`，Shot：`camera / duration / note`——第 2 课 C 档设计的正式启用）；「合同字段为下游服务：duration 供第 13 课帧数、note 供第 14 课分镜图」
- `## 返工循环的两种做法`：CrewAI 内自管循环（评分 < 8 重跑编剧任务一次）与借 LangGraph 边——本课选前者并说明理由（三行取舍）
- `## 两版对照`：LangGraph 版（第 8 课）vs CrewAI 版跑同一创意：token / 轮次 / 可恢复 / 控制粒度四行表；结论「原型用 CrewAI，管线用 LangGraph，生产各取所长」
- `## How：demo 09 的组装段与对照开关`
- `## 常见坑`（4 行）：分镜字段忘了给 duration 单位（秒）/ 两版对照没控变量（同一创意同温度）/ 返工不带评审意见（白返）/ 合同校验失败没走第 2 课重试机制（复用而不是重写）
- `## Checkpoint`：能默写 Storyboard 字段与用途；能运行两版对照；能说清组二验收线各自的实现位置

## demo 规格 · 09-双Agent剧本生成器

| 项 | 规格 |
|---|---|
| 路径 | `demos/09-双Agent剧本生成器/`（README.md / run.py / crew_setup.py / tests/test_run.py）；Storyboard v2 合同沉淀 `src/deltaagent/storyboard.py` |
| 行为目标 | `--idea 一句话` → 编剧 Agent 产出剧本初稿（Script v2）→ 评审 Agent 打分（mock：首轮 6.5、意见两条）→ 意见回灌重写一轮 → 二稿过审（mock 8.5）→ 生成 shots（每场 2–3 个镜头，camera 从枚举选取）→ `assets/09/storyboard.json` 落盘并通过 v2 校验；`--backend crew|graph` 双实现对照开关（graph 版复用第 8 课 build_graph）；`--mock` 全离线 |
| 接口约束 | `storyboard.py`：`Shot(camera: Literal["远景","中景","近景","特写"], duration: float = Field(gt=0, le=30), note: str)`；`Storyboard(script: Script, shots: list[Shot] = Field(min_length=2))`；crew_setup.py：`build_crew(client) -> Crew`（两 Agent 角色卡按 9.2 规格、两 Task 的 expected_output 与合同字段一一对应）；`run_pipeline(idea, backend, client, max_rework=1) -> Storyboard` |
| 分段结构 | S1 角色卡与工单定义（expected_output 锁产）→ S2 返工循环（分数 + 意见回灌，一轮即止）→ S3 shots 生成与 v2 校验（复用第 2 课重试机制）→ S4 双后端开关与对照数据收集（token / 轮次写 `assets/09/compare.md`）→ S5 mock 序列驱动 |
| 验收测试 | `test_crew_produces_valid_storyboard`（mock 下 storyboard.json 通过 v2 校验且 shots ≥2）/ `test_rework_injects_comments`（首轮意见出现在重写 prompt 中——mock 断言）/ `test_reviewer_score_in_trace`（轨迹含两轮分数）/ `test_backend_graph_equivalent_output`（graph 后端同样产出合法 Storyboard）/ `test_camera_enum_rejects`（枚举外镜头被合同拒绝） |

**README 关键点 4 条**：① expected_output 与合同字段的对应表 ② 返工一轮即止的理由（第 5 课 Reflection 结论回收）③ 双后端对照开关用法 ④ compare.md 与组二审计的对接。

**常见报错预填**：CrewAI 版本 API 漂移（先实测）/ expected_output 与合同不一致导致校验炸 / duration 单位漏写 / mock 序列与轮次错位 / graph 后端 checkpointer 路径冲突（各用各的线程 id）。
