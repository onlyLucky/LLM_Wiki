## 讲义 6.1 规格 · 会话上下文：滑动窗口与摘要压缩

```markdown
# 6.1 会话上下文：窗口是记忆的下限方案，不是记忆本身

> 第 6 课 · 模块 1 · 约 55 分钟
> 理论对照：《学习路线》模块四「短期记忆」——第 1 课 1.4 埋的钩子在这里回收
```

**章节大纲**：

- 导语：第 1 课你的窗口把老对话直接扔掉——扔掉的其实是模型对你的全部了解；本课给扔掉的对话盖一个「摘要戳」再扔
- `## 为什么要摘要`：三个场景（长会话 / 多任务 / 第 9 课剧组交接）；「摘要是有损压缩——保事实与结论，不保语气与废话」
- `## 摘要触发与生成`：触发条件（窗口裁剪发生时）；摘要提示词全文（输入被裁片段 + 上一版摘要 → 输出一行 ≤80 字）；mock 模式下摘要由脚本给定
- `## 摘要注入`：system 追加一行 `历史摘要：...` 的消息结构；与窗口内消息的先后关系图
- `## How：demo 06 的 compress_window 逐段`（对照 S2 分段）
- `## 常见坑`（5 行）：摘要滚雪球（每轮把旧摘要再摘一遍越摘越长——解法：单行上限 + 定期重摘）/ 摘要吞掉关键约束（人设、任务目标被裁时必须显式保留）/ 摘要当万能（检索类需求该走第 7 课向量库）/ 触发条件写成「每轮都摘」（浪费）/ mock 下摘要质量不评判
- `## Checkpoint`：能写出摘要提示词；能解释有损压缩保什么弃什么；能说出单行上限的工程理由

## 讲义 6.2 规格 · 记忆分层：工作、情景、语义、程序

```markdown
# 6.2 记忆分层：给「记得住」画一张四层地图

> 第 6 课 · 模块 2 · 约 45 分钟
> 理论对照：《学习路线》模块四「记忆分层」——本篇同时是第 7–10 课的路标
```

**章节大纲**：

- 导语：人不会把每句话都背下来，Agent 也不该——分层是为了让每层用最便宜的方式存最合适的东西
- `## 四层地图`：表格四行 ×（存什么 / 生命周期 / 本课程谁实现 / 存储形态）——工作记忆=messages（第 1–5 课已实现）/ 情景记忆=会话存档（本课）/ 语义记忆=向量库（第 7 课）/ 程序记忆=SOP 与节点（第 10 课）；mermaid 四层图
- `## 情景记忆落地`：会话存档=带时间与任务标签的对话切片；检索时按标签召回——本课用关键词评分，第 7 课换向量
- `## 分层的意义`：成本表（token 窗口最贵、磁盘最便宜）与检索质量表；「第 9 课剧组要共享的不是聊天记录，是设定库——这就是分层给多 Agent 留的接口」
- `## 常见坑`（4 行）：把四层混在一个列表里 / 工作记忆塞进长期存储（敏感信息泄漏面）/ 分层没有检索入口（存了但没人查）/ 层与层的更新不同步
- `## Checkpoint`：能背四层各自存什么；能说出本课与第 7、10 课的分工线；能解释为什么剧组共享的是语义层而不是工作层

## 讲义 6.3 规格 · 写入与遗忘：何时存、存什么

```markdown
# 6.3 写入与遗忘：记忆不是越多越好

> 第 6 课 · 模块 3 · 约 50 分钟
> 理论对照：《学习路线》模块四「写入与遗忘策略」
```

**章节大纲**：

- 导语：存什么比怎么存更早决定检索质量——「检索质量决定一切」这句话下节课用向量再证明一遍
- `## 何时存`：显式写入（`/remember`）与隐式写入（任务完成时存结论摘要）两条路；「存结论不存过程」
- `## 去重与合并`：同主题写入时合并策略（保留最新 + 计数）；简单指纹（首行 hash）判重
- `## 遗忘`：容量上限（MAX_ENTRIES=50）+ 简单相关性评分淘汰（本课用关键词命中率）；「遗忘策略就是检索策略的镜像」
- `## How：demo 06 的 MemoryStore 写入路径`
- `## 常见坑`（5 行）：每轮全量入库（垃圾山）/ 存过程日志而不是结论 / 去重只看完全相等 / 上限满了 FIFO 淘汰（丢掉的恰是最早的人设）/ 不给出库入口（存进去就失踪）
- `## Checkpoint`：能说出显式与隐式写入的分工；能写出指纹判重一行码；能解释为什么 FIFO 淘汰不合适

## demo 规格 · 06-会话管理器

| 项 | 规格 |
|---|---|
| 路径 | `demos/06-会话管理器/`（README.md / run.py / tests/test_run.py）；核心实现沉淀 `src/deltaagent/memory.py` |
| 行为目标 | CLI 对话：窗口满 20 条时自动裁剪并生成一行摘要注入 system（mock 摘要走脚本）；`/remember <内容>` 显式写入长期记忆；任务完成时隐式存「任务结论」；`/memory` 列出库存并显示评分；`/recall <问题>` 返回 top_k=5 命中；`--mock` 驱动一段长对话（30 轮）完整演示双轨与入库 |
| 接口约束 | `memory.py`：`MemoryEntry(kind: str, content: str, meta: dict, fingerprint: str)`；`MemoryStore(max_entries: int = 50)`：`remember(kind, content, meta) -> None`（指纹判重：同 kind+指纹合并计数）、`recall(query, top_k=5) -> list[MemoryEntry]`（关键词命中率评分）、`save(path)` / `load(path)`（JSONL）；`compress_window(messages: list[dict], client: ChatClient, max_history: int = 20) -> tuple[list[dict], str]`（返回裁剪后窗口与摘要行，system 永不裁，人设与任务目标行显式保留） |
| 分段结构 | S1 MemoryStore 实现（remember / recall / 持久化）→ S2 compress_window（裁剪 + 摘要 + 注入）→ S3 对话主循环接线（替换第 1 课裸窗口）→ S4 /memory 与 /recall 命令 → S5 mock 长对话脚本 |
| 验收测试 | `test_compression_produces_summary`（30 轮 mock 后 system 含摘要行且窗口 ≤ 20 条）/ `test_summary_injected_as_system`（摘要行以「历史摘要：」开头注入）/ `test_remember_dedup_merges`（同内容写两次条目数 == 1 且计数 == 2）/ `test_recall_topk_order`（按命中率降序）/ `test_persistence_roundtrip`（save→load 条目逐条相等） |

**README 关键点 4 条**：① 双轨窗口与第 1 课纯窗口的行为差异对照 ② 四层地图中本 demo 落的是哪两层 ③ 「存结论不存过程」的隐式写入演示 ④ mock 摘要与真实摘要的评判差异说明。

**常见报错预填**：摘要行超 80 字未截断 / 裁剪把 system 也裁了（回归第 1 课红线）/ 指纹字段缺失导致判重失效 / JSONL 载入时旧版本条目缺字段 / recall 空库返回空列表未提示。
