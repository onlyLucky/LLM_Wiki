## 讲义 1.3 规格 · 模型接入

> 第 1 课 · 模块 3 · 约 55 分钟

**章节大纲**：

- 导语：云端 API、Ollama、自建兼容端点——三家 SDK 的对话接口几乎同构，封装一次，换遍天下
- `## 三种通道各花一分钟`：云端 API（按 token 计价、要管 Key）；Ollama（`ollama pull` 一个小模型、`localhost:11434`）；兼容端点（OpenAI 协议已成事实标准，`base_url` 一改全通）

- `## 常见坑`（表格 5 行）：base_url 忘带 `/v1` / Ollama 没 serve / Key 硬编码进 run.py（审计红线）/ 旧教程的 openai<1 接口（`openai.ChatCompletion` 已死，新接口是 `client.chat.completions.create`）/ 网络代理没配导致超时
- `## Checkpoint`：能写出 ChatClient 骨架签名；能说出 mock 模式的两个用途（测试 + 离线）；能背 Key 三条红线

## 讲义 1.4 规格 · Token、上下文与采样

```markdown
# 1.4 Token、上下文与采样：一次对话里钱花在哪、记忆存在哪

> 第 1 课 · 模块 4 · 约 50 分钟
> 理论对照：《学习路线》模块四「记忆系统」——本篇是第 6 课记忆分层的前哨站
```

**章节大纲**：

- 导语：今天你在 demo 里打印的每个数字，都是后面 14 课要优化的账单与记忆问题的第一现场
- `## Token：模型的计量单位`：分词直觉（中文 1 字 ≈ 1–2 token）；一次调用的账单三行怎么从 API 响应里读出来（usage.prompt_tokens / completion_tokens）
- `## 上下文窗口：最贵的内存条`：窗口是什么、满了会怎样（截断或报错）；滑动窗口直觉——「为什么 demo 01 的 MAX_HISTORY 是 20 条而不是 200 条」；为第 6 课埋钩子：「窗口是记忆的下限方案，不是记忆本身」
- `## 温度与采样`：temperature / top_p 对照表（创作场景 0.7–0.9 / 结构化场景 0.1–0.3——第 2 课 JSON 生成用 0.2）；「温度调的是分布，不是质量」
- `## max_tokens 与截断`：被截断的 JSON 长什么样（第 2 课返工机制的伏笔）；怎么从 finish_reason=read 判断截断
- `## How：给 demo 01 加 usage 打印`（每轮 `[tokens: in→out]` 角标怎么接进 S3 主循环）
- `## 常见坑`（表格 5 行）：把上下文窗口当持久记忆 / 温度拉满求「聪明」/ 忽略 usage（月底账单惊魂）/ max_tokens 默认值陷阱 / 中文 token 比英文贵的心算偏差
- `## Checkpoint`：能从一次 API 响应里报出三行账单；能解释 MAX_HISTORY=20 的取舍；能说出结构化输出的温度该设多少、为什么

## demo 规格 · 01-第一个对话脚本

| 项 | 规格 |
|---|---|
| 路径 | `demos/01-第一个对话脚本/`（README.md / run.py / tests/test_run.py），共享封装在 `src/deltaagent/chat_client.py` |
| 行为目标 | CLI 多轮对话：输入 → 回复循环；`/exit` 退出；`/save <路径>` 与 `/load <路径>` 会话持久化（JSONL，一行一条 message）；超过 MAX_HISTORY=20 条自动裁剪最早 2 条并打印提示；`/cost` 打印累计 token；每轮回复末尾带 `[tokens: in→out]` 角标 |
| 接口约束 | `ChatClient.__init__(self, base_url: str, api_key: str, model: str, system_prompt: str = "你是 DeltaAgent 课程的课程助手。")`；`chat(self, messages: list[dict]) -> tuple[str, Usage]`（返回回复与本次用量）；`MockChatClient` 同签名，回复固定样例并模拟 usage；Key 缺失 → 打印「.env 未配置，见 .env.example」退出码 2 |
| 分段结构 | S1 配置加载（dotenv → ChatClient/MockChatClient 构造，`--mock` 判断）→ S2 封装层（讲义 1.3 的 chat_client.py 引用与补充）→ S3 主循环（input → 命令分发 → chat → print 角标）→ S4 持久化（save/load JSONL）→ S5 滑动窗口（裁剪 + 提示） |

**验收测试**（`tests/test_run.py`，MockChatClient 注入，不花真钱）：

| 用例 | 断言 |
|---|---|
| `test_chat_accumulates_history` | 连发 3 轮，messages 长度按 system+2N 增长 |
| `test_sliding_window_trims` | 预置 24 条历史后对话，最早 2 条被裁、system 永不裁 |
| `test_save_load_roundtrip` | save 后新实例 load，messages 逐条相等 |
| `test_cost_tracks_usage` | 3 轮后 /cost 汇总 = 各轮 in/out 之和 |
| `test_missing_key_exit_code` | 删掉环境变量运行，capsys 捕获中文指引 + SystemExit code 2 |

**README 关键点 4 条**：① 为什么封装进 src 而不是写在 run.py（第 2 课要复用）② mock 模式的两个用途 ③ 滑动窗口为什么裁偶数条（保 user/assistant 成对）④ 角标里 in/out 与 1.4 讲义账单的对应。

## 升级预案

- 网络不可用 / 无 Key：全部产物必须过 `--mock` 冒烟（ChatClient 注入 MockChatClient），真实模式留到学员本地验证——执行侧不许因无 Key 跳过冒烟
- openai ≥ 1.x 接口与旧教程差异大：讲义 1.3 的代码段以新接口为准（`from openai import OpenAI` + `client.chat.completions.create`），执行侧发现讲义与实现不符即升级
- python-dotenv 与 pydantic-settings 二选一：本课统一 python-dotenv（少一个概念），pydantic-settings 留给第 10 课配置系统再引入——不要「顺手优化」
- 实验环境差异（macOS 与 Linux 的 uv 安装命令）：README 只写 macOS 主路径，其他平台标注「见 uv 官方文档」
