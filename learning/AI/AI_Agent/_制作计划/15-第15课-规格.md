## 讲义 15.1 规格 · 埋点与数据集构建

```markdown
# 15.1 埋点：每一次出片都在攒训练数据

> 第 15 课 · 模块 1 · 约 50 分钟
> 理论对照：《学习路线》模块六「数据回流管道」——全课程埋点的总回收
```

**章节大纲**：

- 导语：「支持数据自训练」是工具五大需求的最后一块；好消息是数据早就在攒——第 7 课 eval_log、第 12 课 run 历史、第 14 课 decisions.jsonl，今天只是让它们会师
- `## 三类样本地图`：表格（样本类型 / 采集点 / 喂法）——决策日志（noul 问题+结果+人工复核 → SFT「判断样本」）；质检对（返工前产物 vs 通过产物 + 分数 → DPO 的 chosen/rejected）；用户改稿（学员手工改过的剧本 → DPO）；「第 14 课 C 档仪表盘的『低置信度复盘』就是人工标注现场」
- `## 数据清洗`：去重（指纹）、脱敏（Key 与个人信息扫描）、脏数据率统计；「数据集体检不过关，训练就是垃圾进垃圾出」
- `## 导出格式`：SFT jsonl（`{"prompt", "completion"}`）与 DPO jsonl（`{"prompt", "chosen", "rejected"}`）字段约定；样本量下限与配比直觉
- `## How：demo 15 的 dataset_export 段`
- `## 常见坑`（5 行）：把用户 Key/隐私扫进样本集（脱敏先行）/ 决策日志原样导出（没经人工复核的 noul 是噪声）/ 质检对不配对（chosen/rejected 必须同题）/ 全是正样本（DPO 需要反例，返工档案就是反例库）/ 导出无版本（数据集带日期与指纹）
- `## Checkpoint`：能说出三类样本的采集课次；能写出脱敏扫描清单；能解释质检对为什么要同题

## 讲义 15.2 规格 · LoRA 微调与评估回归

```markdown
# 15.2 LoRA 与评估回归：没有评估的微调是玄学

> 第 15 课 · 模块 2 · 约 55 分钟
> 理论对照：《学习路线》模块六「微调实操 / 偏好对齐 / 评估体系」
```

**章节大纲**：

- 导语：LoRA 的直觉在第 2 课比喻库就埋了——给大模型外挂一层 CSS 变量主题包；今天把它跑起来，重点不是调参精度，是「评估回归」的纪律
- `## LoRA 原理十分钟`：全参微调 vs 低秩旁路（W + BA，B×A 秩极小）；「只训主题包不动原文件——回滚零成本」；PEFT 训练循环骨架（trainer 配置项一段）
- `## 评估回归纪律`：eval 集（从第 14 课探针与质检题中抽固定 20 题）→ 微调前跑一遍存基线 → 微调后同题复跑 → 三指标对比（命中率 / 分数 / 翻车清单）；「结营标准第 6 条的『评估回归』不是跑一次，是能反复跑」
- `## 成本与调度`：小参数模型（本课走通流程）与真模型（云端，结营后升级）两档说明；决策层的预算控制在哪接（预算原语留口）
- `## How：demo 15 的 train_smoke 与 eval_regression 段`
- `## 常见坑`（5 行）：eval 集混进训练集（泄漏）/ 基线没存就开训（无法回归对比）/ 数据集 < 50 条硬训（过拟合噪声）/ 只看总分不看翻车清单（均值掩盖恶化）/ 训练产物不进版本管理
- `## Checkpoint`：能说清 LoRA 秩的取舍直觉；能写出评估回归的固定流程四步；能指出 eval 泄漏为什么致命

## 升级预案

- 无 GPU / 无训练环境：`--train-smoke` 降级为「数据管道真实 + 训练循环空转冒烟 + 评估回归用 mock 分数演练」，README 与 PROGRESS 如实标注两档口径；真实训练列「结营后升级」，禁止假装

- 合体阶段对旧模块的任何需求变更：一律走升级单，由制定侧评估「改旧模块」还是「加适配层」——`test_no_source_modules_modified` 是本课的自动化红线
