- `## How：demo 10 的任务清单数据结构`（TaskSpec：目标节点 + 输入引用）

- `## Checkpoint`：能背三模式的失败面；能说出本工具选中心化的三条理由；能判断一段流程该拓扑化还是现拆

## 讲义 10.2 规格 · 节点即函数：Schema 化 I/O

```markdown
# 10.2 节点即函数：Pydantic 合同的全面回收

> 第 10 课 · 模块 2 · 约 55 分钟
> 理论对照：《学习路线》模块三「接口标准化」——可拆分可组合的技术核心
```

**章节大纲**：

- 导语：第 2 课合同管的是「模型输出」，第 9 课合同管的是「剧本资产」；今天的合同管「一切节点交接」——全课程的合同体系在这里合流
- `## Node 基类设计`：抽象三要素代码段——`name: ClassVar[str]`、`description: ClassVar[str]`（写给编排器看的文档，呼应 4.1）、`run(self, data: InputModel) -> OutputModel`；`input_model` / `output_model` 两个 ClassVar 挂合同
- `## 为什么 Schema 化是拆分的前提`：反例先行——无合同节点对接的三种死（字段名靠猜 / 类型靠蒙 / 改动靠全局搜索）；「TypeScript interface 即合约，Pydantic 就是运行时强制的 interface」
- `## 版本兼容`：合同加字段的兼容规则（新增可选、不改既有语义）；第 2 课 C 档 MIGRATION.md 的规则正式化
- `## How：demo 10 的 ScriptGenNode 与 SummaryCardNode`（第 2 课、第 9 课能力的节点化包装——复用不重写）
- `## 常见坑`（5 行）：run 里做与合同无关的副作用 / 节点输出塞了超大对象（帧序列应存文件、合同里只放路径）/ input/output 合同裸写 dict / description 空着（编排器瞎调）/ 复用旧函数时顺手改了旧模块（禁改红线）
- `## Checkpoint`：能写出基类三要素；能说出三个合同的管辖范围；能判断哪些改动是兼容的

## 讲义 10.3 规格 · 插件注册与动态加载

```markdown
# 10.3 注册器：从 pi 的扩展机制到你自己的节点生态

> 第 10 课 · 模块 3 · 约 45 分钟
> 理论对照：第 3 课 3.3 pi 解剖的回收 + ComfyUI 参照
```

**章节大纲**：

- 导语：第 3 课你解剖过 pi 怎么挂工具；今天同一套思想做节点——注册表让「加节点」和「改引擎」变成两件事
- `## @register_node 装饰器`：注册进全局字典 + 唯一名校验 + 重复注册报错（对照第 7 课 id 静默覆盖的反例——「注册失败要炸得早」）
- `## manifest`：`registry.to_manifest() -> dict`（name / description / input schema / output schema）——「manifest 是节点生态的 npm 页面，第 12 课编辑器的节点面板直接吃它」
- `## 动态加载`：importlib 扫描 `nodes/extra/` 目录自动注册；「新增节点文件 = 扩展生态，引擎零改动」——开闭原则的可测试形态
- `## 三方对照表`：ToolRegistry（第 3 课）/ pi 扩展 / NodeRegistry 三行（注册方式 / 校验 / 消费方）
- `## 常见坑`（5 行）：注册表用可变默认参数 / 动态加载吞 import 异常（节点坏了静默消失）/ manifest 里塞函数对象（不可序列化）/ 节点重名静默覆盖 / 扫描目录没有 `__init__.py`
- `## Checkpoint`：能写出注册装饰器；能解释 manifest 给谁吃；能做「新增节点不改引擎」的演示

## demo 规格 · 10-节点注册器

| 项 | 规格 |
|---|---|
| 路径 | `demos/10-节点注册器/`（README.md / run.py / nodes/extra/hello_node.py / tests/test_run.py）；核心沉淀 `src/deltaagent/nodes.py` |
| 行为目标 | `--manifest` 打印全部已注册节点的清单（name / 一句话职责 / 输入输出合同名）；`--run <节点名> --input <json>` 单节点执行（输入走合同校验）；`nodes/extra/hello_node.py` 是动态加载示例（EchoNode：原样返回输入并加时间戳）；`--mock` 下 ScriptGenNode 走第 2 课固定样例 |
| 接口约束 | `nodes.py`：`class Node(ABC)`：`name: ClassVar[str]`、`description: ClassVar[str]`、`input_model: ClassVar[type[BaseModel]]`、`output_model: ClassVar[type[BaseModel]]`、`run(self, data) -> BaseModel`；`@register_node(cls)`：重复名抛 `DuplicateNodeError`；`NodeRegistry.all() -> list[type[Node]]`、`.get(name) -> type[Node]`、`.to_manifest() -> list[dict]`（含 `model_json_schema()` 摘要）；`discover(package_dir: Path) -> int`（importlib 自动扫描，返回加载数，import 异常原样抛出）；内置节点：`ScriptGenNode`（包装第 2 课 `generate_script`，输入 `IdeaIn(idea: str)`、输出 Script）、`SummaryCardNode`（Script → `SummaryOut(markdown: str)`：标题 + logline + 每场一行概要） |
| 分段结构 | S1 Node 基类与合同挂钩 → S2 注册装饰器与唯一性校验 → S3 内置两节点（复用第 2/9 课模块，禁改旧码）→ S4 manifest 导出 → S5 动态加载 discover 与 CLI |
| 验收测试 | `test_register_and_get`（注册两个节点后 get 按名取回）/ `test_duplicate_name_raises`（重名注册抛错）/ `test_manifest_serializable`（manifest 可 json.dumps 且含 input/output schema 名）/ `test_dynamic_load_new_node`（discover 加载 nodes/extra 后新节点可执行且引擎文件未改动——用文件 mtime 或 hash 断言不变）/ `test_input_validation_rejects_bad`（IdeaIn 缺字段时给出可读 ValidationError） |

**README 关键点 4 条**：① 三个合同体系的管辖范围表 ② 「新增节点不改引擎」的验证方法 ③ manifest 与第 12 课编辑器面板的对接约定 ④ 内置节点复用了哪两个旧模块（复用清单）。

**常见报错预填**：ClassVar 忘写导致实例属性 / discover 目录无 `__init__.py` / manifest 序列化遇 BaseModel / 动态加载的节点 import 旧模块路径错 / 单节点执行时输入 JSON 缺字段的长相。
