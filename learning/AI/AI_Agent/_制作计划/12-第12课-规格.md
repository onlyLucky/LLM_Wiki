## 讲义 12.1 规格 · React Flow 节点编辑器

```markdown
# 12.1 React Flow：你的老地盘，新东西只有「映射」

> 第 12 课 · 模块 1 · 约 60 分钟
> 理论对照：《学习路线》模块八「前端」——节点式编辑器的落点
```

**章节大纲**：

- 导语：写 React 组件你五年天天干；今天唯一的难点是把「画布上的点线」翻译成「引擎的邻接表」——数据结构映射
- `## 三分钟上手`：nodes（id/position/data）与 edges（source/target）两个状态数组；onConnect 添加边；NodeType 注册自定义节点组件
- `## panel.json → 节点面板`：启动时 fetch panel.json（第 10 课 C 档产物），拖拽添加节点实例——「面板来自后端 manifest，前端不硬编码节点，加节点零前端改动」（呼应第 10 课开闭原则）
- `## 映射表`：前端 `edges: [{source,target}]` ↔ 后端 `deps: dict[str, list[str]]`；方向约定谁指向谁（本工具：edge = 「target 依赖 source」）——写死方向、双向转换函数各一段
- `## 节点状态角标`：data 里挂 status 字段（idle/running/done/failed/skipped），CSS 类切换；「角标状态只由 WS 消息驱动，前端不自算」
- `## How：demo 12 前端 src 的三个关键组件`（Panel / Canvas / NodeCard）
- `## 常见坑`（5 行）：方向约定两头写反（连线变成反向依赖）/ 节点重名（实例 id 要 `名字#序号`）/ 删边漏同步 deps / 拖拽时 React Flow 的 position 不受控警告 / 面板 fetch 失败整页白（要兜底）
- `## Checkpoint`：能写出双向转换函数；能说出面板数据从哪来；能解释角标为什么只听 WS 的

## 讲义 12.2 规格 · WebSocket 进度推送与联调

```markdown
# 12.2 WebSocket：让管线的心电图跳到界面上

> 第 12 课 · 模块 2 · 约 50 分钟
> 理论对照：《学习路线》模块八「WebSocket 实时进度」——与第 11 课 GET 轮询的分工
```

**章节大纲**：

- 导语：GET 轮询是「每小时看一眼」，WS 推送是「心电图」；引擎状态机的每次迁移都是一条推送
- `## 后端`：`/ws/{run_id}` 端点；引擎事件桥（RunStatus 变更时回调 broadcast）；消息格式 `{node, status, artifact?, score?}`——「格式是前后端合同，改格式两边一起改」
- `## 前端`：单条 WS 连接按 run_id 订阅；onMessage 更新对应 NodeCard 角标；断线重连一句话策略（重连后先 GET 一次全量再续订增量）
- `## 联调姿势`：先 curl 提交拿 run_id，再开 WS 看推送流；「后端事件桥接进第 11 课引擎用回调注入，不改 engine 源码」（禁改红线的解法：依赖注入）
- `## How：demo 12 的 ws 桥段`
- `## 常见坑`（5 行）：消息格式两头不一致（先写合同注释）/ 引擎循环里阻塞 broadcast（推送要 fire-and-forget）/ run_id 订阅错房间 / 前端重复开连接（React StrictMode 双开）/ WS 异常静默吞（要有重连日志）
- `## Checkpoint`：能写出消息合同；能解释注入式事件桥为什么不改 engine；能演示断线重连后的状态对齐

## 讲义 12.3 规格 · Critic 与 Score 门控

```markdown
# 12.3 质检门控：评审角色退役，评审节点上岗

> 第 12 课 · 模块 3 · 约 55 分钟
> 理论对照：《学习路线》模块五「质量门控」——第 8 课 critic_node 的节点化回归
```

**章节大纲**：

- 导语：第 8 课评审住在图框架里、第 9 课评审住在 Crew 里；今天它变成一个可拖拽的节点——谁都能被质检，质检也能被替换
- `## CriticNode 设计`：输入任意产物 + 评分标尺（1–10 + 维度清单进合同）；输出 `CritiqueOut(score: float, comments: list[str], passed: bool)`；`passed` 由阈值在节点内判定（阈值进输入合同——可调）
- `## 门控边怎么表达`：管线层加「返工边」约定——CriticNode 输出 passed=false 时把上游节点标红、触发 `rerun(subtree)`（复用第 11 课 rerun）；「门控不是 if，是边」
- `## 两版对照`：硬编码 if 版（第 8 课前）vs 节点门控版对照表三行（复用 / 可视化 / 可替换）；「第 14 课三原语把阈值判断升级成决策模型——门控的位置不变，住户升级」
- `## How：demo 12 的 CriticNode 与标红逻辑`
- `## 常见坑`（5 行）：阈值写死在代码而不是合同 / Critic 评自己的上游却拿到了缓存产物（指纹含输入——门控重跑要绕缓存，节点版本号 +1 的用法）/ 返工循环没有上限（第 8 课 MAX_ROUNDS 回收）/ 标红状态不进 RunStatus（刷新就丢）/ comments 不结构化（下游没法用）
- `## Checkpoint`：能写出 CriticNode 合同；能说出门控边与 if 的区别；能解释标红为什么要进 RunStatus

## demo 规格 · 12-节点编辑器

| 项 | 规格 |
|---|---|
| 路径 | `demos/12-节点编辑器/`：后端 `server.py`（FastAPI：POST /pipeline、GET /pipeline/{id}、/ws/{run_id}）+ `critic_node.py`（CriticNode 按第 10 课合同注册）；前端 `web/`（Vite + React + React Flow：Panel / Canvas / NodeCard 三组件），pnpm 脚手架；后端测试 `tests/test_run.py` |
| 行为目标 | 打开页面：左侧面板列 panel.json 全部节点 → 拖「ScriptGen → SummaryCard → LinesNode + CriticNode」连线 → 点运行 → 逐节点角标实时变（WS 推送）→ Critic 打分（mock：SummaryCard 产物 6.0 分 → 标红上游并触发一次 subtree rerun，二轮 8.0 过）→ 全绿完成；产物路径在 NodeCard 可见 |
| 接口约束 | 后端复用 `src/deltaagent/engine.py` 与 `nodes.py`，事件桥用构造注入（`Pipeline(..., on_event=callback)` 若 engine 无此参数则在 server 层包一层执行器，禁改 engine）；WS 消息合同 `{ "run_id": str, "node": str, "status": str, "artifact": str|None, "score": float|None }`；CriticNode：输入 `CritiqueIn(target_artifact: str, rubric: list[str], threshold: float = 8.0)`、输出 `CritiqueOut(score, comments, passed)`，mock 分数序列 6.0 → 8.0 |
| 分段结构 | 后端 S1 API 端点与内存任务表 → S2 引擎事件桥（注入式）→ S3 WS 广播 → S4 CriticNode 注册与门控 rerun；前端 S1 Panel（吃 panel.json）→ S2 Canvas 与连线 → S3 双向映射转换 → S4 NodeCard 角标与 WS 订阅 → S5 运行按钮与 run_id 流转 |
| 验收测试 | `test_graph_maps_to_dag`（前端 edges 样例 → 后端 deps 转换：三个边对应邻接表逐位相等，反向转换往返一致）/ `test_ws_broadcast_status`（TestClient websocket：提交后按序收到 started/done 消息且字段合同齐全）/ `test_critic_gate_triggers_subtree_rerun`（首轮 6.0 → SummaryCard 与其上游标红重跑一轮，二轮 8.0 全绿；rerun 计数断言）/ `test_gate_respects_max_rounds`（恒低分 → 强制放行带 flag，不无限循环） |
| 前端验收 | `pnpm build` 通过（tsc 零报错）为批内验收；浏览器实测体验由学员执行并在 PROGRESS 备注「前端实测由学员完成」——执行侧不留「未测标 ✅」的假证据 |

**README 关键点 4 条**：① 方向约定（edge = target 依赖 source）一行写死 ② WS 消息合同全文 ③ 注入式事件桥与「禁改 engine」的关系 ④ 前后端各自验收口径（pytest vs build）。

**常见报错预填**：React Flow position 受控警告 / WS StrictMode 双连接 / panel.json fetch 404（路径大小写）/ 邻接表方向反了（症状：拓扑序倒挂）/ uvicorn 与前端 dev 端口跨域（vite proxy 配置片段）。
