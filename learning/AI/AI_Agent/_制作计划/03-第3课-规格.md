## 第 3 课目标能力清单

学员在第 3 课结束时能：

1. 徒手写出 Agent 循环的完整状态流（感知 → 规划 → 行动 → 观察），并说出循环的三个终止条件
2. 安装 pi 并跑通默认四工具（read / write / edit / bash），解释 harness「核心小、能力靠扩展」的设计
3. 读 pi 源码回答三问：agent loop 的终止条件怎么实现 / 工具 schema 怎么声明 / 扩展点在哪个文件
4. 自己实现 ToolRegistry：注册装饰器、schema 生成、按名分发、异常兜底
5. 把「模型返回工具调用」与「模型返回闲聊」两种情况都处理干净，且步数上限防失控

## 讲义 3.1 规格 · Agent 循环

```markdown
# 3.1 Agent 循环：感知→规划→行动→观察，一个 while 的自白

> 第 3 课 · 模块 1 · 约 55 分钟
> 理论对照：《学习路线》模块一「Agent 循环」——路线给范式，本篇把它写成代码
```

**章节大纲**：

- 导语：前两课你的程序是「一问一答」的直线；今天把直线掰成环——环一转起来，模型就有了「动手」的机会
- `## 直线到环差了什么`：mermaid 状态图（user 输入 → 模型 → 有工具调用？→ 执行工具 → 结果回灌 → 模型…… → 无工具调用即答）；「demo 是单趟公交，Agent 是环线」
- `## 三个终止条件`：模型明确说「完成」（无工具调用的自然语答）/ 步数上限 MAX_STEPS=8（防失控红线）/ 用户中断；各配一段判断代码
- `## 观察：最容易偷工减料的一环`：工具结果怎么回灌（role=tool 的消息结构）；截断超长输出（工具 stdout > 2000 字符截中段）——「喂模型的观察要的是判决书，不是卷宗全文」
- `## 状态放哪`：messages 列表就是状态（对照第 1 课窗口管理）；为第 8 课 LangGraph 埋钩子：「LangGraph 把这个 while 变成了图上的边——先手写再上框架」
- `## How：demo 03 的 run_agent 循环逐段精讲`
- `## 常见坑`（6 行）：忘把工具结果回灌（模型原地打转）/ 终止只有步数上限（永远答不出结论）/ MAX_STEPS 设太大烧钱 / 观察不截断撑爆窗口 / 工具异常直接炸循环（应转成错误观察）/ 把模型闲聊当工具调用解析
- `## Checkpoint`：能默画循环状态图；能说出三个终止条件；能写出工具结果的回灌消息

## 讲义 3.2 规格 · pi 实测

```markdown
# 3.2 pi 实测：五十行就能跑的最小 harness

> 第 3 课 · 模块 2 · 约 45 分钟
> 理论对照：《学习路线》第 3 章「开源框架快速入门 · pi」——本篇是它的实测版
```

**章节大纲**：

- 导语：装一个「别人的 Agent」，用它干一件你自己的事——然后再拆开看它凭什么这么小
- `## 安装与首跑`：`curl -fsSL https://pi.dev/install.sh | sh`（或 npm 全局装）；`pi` 启动；让它读一个文件再改一个文件——四工具各试一次，记录每步它自己打了什么「工具牌」
- `## 四工具盘点`：read / write / edit / bash 一行表（输入 / 能力 / 危险度）；「bash 一个工具顶千军，也顶一千种翻车」——为第 4 课错误处理埋钩
- `## harness 是什么`：对照表「pi 做的 / pi 不做的」（不做记忆持久化、不做多 Agent、不做工作流）；结论句「harness 是方向盘不是发动机——发动机（模型）和路（你的工作流）都是你的」
- `## 与你的第 1 课 CLI 对比`：五分钟对照表（对话循环 / 工具 / 终止条件 / 持久化）——你缺的就是工具层，今天补上
- `## 常见坑`（4 行）：npm 全局安装的网络问题（换 pnpm/nvm 环境变量）/ bash 工具误删文件（先在测试目录玩）/ 模型 Key 未配置 pi 报错长什么样 / 把 pi 当框架套娃（pi 里跑 pi）
- `## Checkpoint`：能装能跑；能说出 pi 的四工具与「不做的事」；能对照出自己的 CLI 缺什么

## 讲义 3.3 规格 · pi 源码通读

```markdown
# 3.3 pi 源码通读：agent loop 的解剖课

> 第 3 课 · 模块 3 · 约 60 分钟
> 理论对照：无——本篇是全课程唯一一次源码解剖，方法比结论重要
```

**章节大纲**：

- 导语：上一讲你用了 pi；这一讲把它放上解剖台——读完你会发现自己第 3.1 讲写的循环和它惊人地像，差异全在工程细节
- `## 导读单（先抄题再翻书）`：三问全文——① loop 的终止条件在哪一行、怎么实现；② 工具的 schema 在哪里声明、怎么转成模型可读的 tools 参数；③ 想加一个自定义工具，动哪个文件、写什么接口
- `## 解剖一：循环本体`：源码位置指引（以安装版本为准，讲义写「定位方法」而非行号——`grep -n "while" src/`）；循环骨架贴出并逐段对照 3.1 的状态图；「它比你多做了什么」清单（流式输出 / 中断处理 / usage 统计）
- `## 解剖二：工具注册`：工具定义 → schema 生成 → 注册表的三段流水；与 demo 03 的 ToolRegistry 对照表（三行：声明方式 / 校验 / 分发）
- `## 解剖三：扩展点`：TypeScript 扩展与 Skill 的接入位置；「扩展机制的存在本身就是 00 计划里『可拆分可组合』的活例子——第 10 课你的节点注册器长它的样」
- `## 源码阅读方法三则`：从入口文件顺藤摸瓜 / grep 行为关键词 / 带着问题读而不是通读——这三则写给后面 12 次课所有「读源码」环节
- `## 常见坑`（4 行）：对着旧版本源码读（版本漂移）/ 只看不看跑（改一行跑一遍）/ 在 node_modules 里改源码做实验（改完不还原）/ 找不到入口文件（看 package.json bin 字段）
- `## Checkpoint`：三问全答；能对照画出 pi 循环与 demo 03 循环的差异表；能说出「定位方法」三件套

## demo 规格 · 03-手写mini-agent

| 项 | 规格 |
|---|---|
| 路径 | `demos/03-手写mini-agent/`（README.md / run.py / tools.py / tests/test_run.py） |
| 行为目标 | CLI：输入任务 → 模型选择工具 → 执行 → 回灌 → 直到给出最终回答；三个内置工具 `now()`（返回当前时间）、`calc(expr)`（安全算术）、`echo(text)`；`--mock` 走脚本化工具调用序列（先 calc 后无调用）验证全循环 |
| 接口约束 | `tools.py`：`ToolSpec(name: str, description: str, func: Callable)`；`ToolRegistry`：`register(spec: ToolSpec) -> None`、`dispatch(name: str, raw_args: str) -> str`（异常一律转成 `工具执行失败: <原因>` 的观察文本，不许炸循环）、`schemas() -> list[dict]`（生成 OpenAI 风格 tools 参数）；`run_agent(task: str, client: ChatClient, registry: ToolRegistry, max_steps: int = 8) -> AgentResult`（`AgentResult(answer: str, steps: int, usage_total: Usage)`）；`calc` 用 `ast.literal_eval` 白名单实现，严禁 `eval` |
| 分段结构 | S1 工具注册表（ToolSpec + 装饰器 `@tool(name, description)`）→ S2 内置三工具（calc 的 ast 安全段）→ S3 循环（3.1 状态图直译：判断工具调用 / 执行 / 回灌 / 三终止条件）→ S4 结果汇总（AgentResult 与 /cost 汇报）→ S5 mock 脚本驱动 |
| 验收测试 | `test_registry_dispatch`（注册两个工具按名调用各得正确结果）/ `test_tool_error_becomes_observation`（工具抛 ValueError，循环收到错误文本且不崩溃）/ `test_loop_stops_without_tool`（mock 第二步无工具调用 → steps==2 且 answer 非空）/ `test_max_steps_guard`（mock 恒返回工具调用 → 第 9 次强制终止并带「已达步数上限」标记）/ `test_calc_is_safe`（`calc("__import__('os')")` 返回失败观察而非执行） |

**README 关键点 4 条**：① ToolRegistry 与 pi 工具注册的对照行 ② calc 为什么 ast 白名单而不是 eval ③ 错误即观察的设计（对照 3.1 坑表第 5 行）④ MAX_STEPS=8 的账单视角。

**常见报错预填**：模型把参数拼成字符串导致 json.loads 失败（观察里回灌格式要求）/ ast.literal_eval 拒绝 `2^3`（白名单加 pow 映射）/ 工具名大小写不一致（注册表统一小写）/ mock 序列步数对不上（先读 mock 设计注释）。

### 课级 README 三档总览

| 档 | 目录 | 考点 | 前置讲义 | 参考时长 |
|---|---|---|---|---|
| B | basic-翻译工具 | 新增一个工具：注册 + schema + 分发 | 3.1 | 30 min |
| A | advanced-多工具路由 | 两个工具按任务自动选择 + 参数错误转观察 | 3.1、3.2 | 60 min |
| C | challenge-自纠错循环 | 工具失败后让模型自己换参数重试（观察驱动纠错） | 3.1、3.3 | 90 min |

递进逻辑：B 的注册是 A 的路由前置；A 的「错误转观察」是 C 的「模型读观察自纠错」前置。为什么是这三题：B 对标任何 Agent 接新工具的日常；A 对标工具多了之后的调度；C 对标《学习路线》模块五「重试与自修正」的最小可运行版。

### B 档 · basic-翻译工具

- 目标：新增 `translate(text, to_lang)` 工具（内部调 ChatClient），注册后 mini-agent 能在任务里调用它
- 任务清单：`TODO(03-b-1)` ToolSpec 与装饰器；`TODO(03-b-2)` translate 实现（复用 ChatClient，system 一句话约束）；`TODO(03-b-3)` 注册进 main 的 registry 并在 schema 里可见
- 验收：mock 下任务「把你好译成英文」触发一次 translate 调用；结果进入最终回答

### A 档 · advanced-多工具路由

- 目标：`word_count(text)` 与 `calc(expr)` 双工具，模型按任务选择；参数解析失败转成观察由模型自改
- 任务清单：`TODO(03-a-1)` word_count 实现；`TODO(03-a-2)` 双工具 schema 共存；`TODO(03-a-3)` dispatch 的参数解析错误包装；`TODO(03-a-4)` 记录每次调用的工具名序列并打印
- 验收：mock 下「数一下这句话几个词」与「算 12*7」各命中正确工具；错参一次后模型在下一步自行修正

### C 档 · challenge-自纠错循环

- 目标：给 `read_file(path)` 工具喂一个不存在的路径，模型读观察后自己换正确路径重试并完成任务的完整轨迹
- 任务清单：`TODO(03-c-1)` read_file 实现（异常转观察）；`TODO(03-c-2)` 纠错轮数统计与循环上限联动；`TODO(03-c-3)` 轨迹留痕（每步 thought/action/observation 写 `trace.md`）；`TODO(03-c-4)` 对比实验：不给错误观察（直接抛异常）时循环必死——两组各跑一次，报告写差异
- 验收：错误观察版在 ≤3 次重试内完成；trace.md 三段式可读；对比结论一段（错误观察的价值）
- 升级预告：本档的 trace 格式即第 5 课 ReAct 日志的前身

### solution 规格

四段式；C 档必含「异常 vs 观察对照」的实现取舍段。除 TODO 外与骨架逐字一致。
