## 第 5 课目标能力清单

1. 写出 ReAct 三段式（Thought / Action / Observation）并让日志里三段肉眼可辨
2. 说清 ReAct 与 Plan-and-Execute 的取舍（走一步看一步 vs 先全盘规划）及各自适合的任务
3. 用 Reflection 给产出加一轮「自评 + 修订」，并解释为什么一轮就该停
4. 把 ChatClient（第 1 课）、结构化合同（第 2 课）、ToolRegistry 与循环（第 3 课）、Function Calling 与重试（第 4 课）组装成留痕完整的 CLI 助手
5. 达成 00 计划组一验收线：一条指令 → 查资料 + 读写文件 + 自动重试一轮 + 全程日志

## 讲义 5.1 规格 · ReAct：推理与行动交替

```markdown
# 5.1 ReAct：让模型把「想」和「做」写在同一张草稿纸上

> 第 5 课 · 模块 1 · 约 55 分钟
> 理论对照：《学习路线》模块一「经典模式」——ReAct 的提示层实现
```

**章节大纲**：

- 导语：第 4 课的循环里模型「默默」调工具；ReAct 要求它把理由喊出来——Thought 不是花架子，是给你调试用的仪表盘
- `## 三段式模板`：Thought（我该做什么、为什么）→ Action（工具调用）→ Observation（执行结果）；一段真实 trace 全文展示
- `## ReAct 与 Function Calling 的关系`：对照表——ReAct 是提示层模式（要求模型显式写推理），FC 是协议层能力（结构化调用）；两者叠加不冲突：本课 demo 里 thought 写进回答文本、调用走 FC
- `## 终止与失控`：Final Answer 终止词 / MAX_STEPS 兜底（第 3 课回收）；「Thought 每步一句就够——写小作文的 ReAct 是账单刺客」
- `## How：demo 05 的 ReAct 日志格式逐段`（trace.md 的三段式渲染）
- `## 常见坑`（5 行）：Thought 冗长烧 token / Observation 缺失（模型假装看到了结果）/ 没有终止词（永远在准备）/ 把 Observation 硬编成固定文案 / 日志不分段（三段糊成一坨没法审计）
- `## Checkpoint`：能写出三段式提示模板；能说出 ReAct 与 FC 各自所在的层；能从一段 trace 里指出失控征兆

## 讲义 5.2 规格 · Plan-and-Execute 与 Reflection

```markdown
# 5.2 Plan-and-Execute 与 Reflection：先画路线图，再出门；回来再复盘

> 第 5 课 · 模块 2 · 约 50 分钟
> 理论对照：《学习路线》模块一「Plan-and-Execute / Reflection」
```

**章节大纲**：

- 导语：ReAct 走一步看一步，遇到多步任务容易绕路；Plan-and-Execute 先出路线图——它也是第 11 课 DAG 的思想前身
- `## Planner 与 Executor 分工`：两角色提示词对照；plan 输出为编号步骤列表（结构化——第 2 课合同方法回收）；执行时逐步核对
- `## 取舍表`：ReAct / Plan-Execute 两行 ×（适合任务 / 失败模式 / token 前置成本 / 本课程谁用它）——结论「探索型任务 ReAct，确定性管线 Plan-Execute」
- `## Reflection：一轮就停`：产出 → 自评（对照任务要求的 checklist）→ 修订一次；为什么不做多轮（成本曲线陡升、边际收益骤减）；与第 12 课 Score 门控的血缘
- `## How：demo 05 的 --plan 模式与 reflection 开关`
- `## 常见坑`（5 行）：plan 写成口号没有可执行步骤 / plan 与实际执行两张皮（没人核对）/ Reflection 无标准（自评要给 checklist 否则全说好）/ 多轮反思烧穿预算 / plan 步骤间藏依赖不声明
- `## Checkpoint`：能写出 plan 的结构化 schema；能按取舍表为任务选模式；能解释 Reflection 为什么一轮即停

## demo 规格 · 05-CLI助手

| 项 | 规格 |
|---|---|
| 路径 | `demos/05-CLI助手/`（README.md / run.py / tests/test_run.py） |
| 行为目标 | CLI 助手：`/task 查一下上海天气并写进 notes.md` 之类复合指令 → ReAct 循环（Thought 可见）→ 工具执行（Function Calling + RetryOnce）→ 最终回答 + `assets/05/trace/trace.md` 三段式轨迹 + TaskReport；`--mock` 走脚本化任务（一次天气 + 一次写文件 + 一次内置超时重试） |
| 接口约束 | `run_task(task: str, client: ChatClient, registry: ToolRegistry, max_steps: int = 10, mode: Literal["react","plan"] = "react", reflect: bool = False) -> TaskReport`；`TaskReport(success: bool, answer: str, tool_sequence: list[str], retries: int, steps: int, usage: Usage)`；trace 落盘格式：`## Step N` + `**Thought**` / `**Action**` / `**Observation**` 三行（第 3 课 C 档 trace 的升级版） |
| 分段结构 | S1 命令分发与 /task 解析 → S2 模式选择（react / plan：planner 出步骤后逐步执行）→ S3 循环主体（第 3 课循环 + FC 调用 + RetryOnce）→ S4 可选 Reflection（自评 checklist + 修订一次）→ S5 TaskReport 与 trace 落盘 |
| 验收测试 | `test_react_trace_three_sections`（trace.md 里 Step 段落含 Thought/Action/Observation 三标记）/ `test_retry_budget_recorded`（注入一次超时后 retries == 1 且 success 为真）/ `test_plan_mode_lists_steps`（plan 模式的报告含编号步骤列表）/ `test_report_summarizes`（tool_sequence 与 usage 与 mock 脚本一致） |

**README 关键点 4 条**：① 总装图 mermaid 与零件来源标注 ② plan 与 react 两种模式的切换说明 ③ TaskReport 字段与组一验收线的对应 ④ mock 脚本的设计注释（先读再跑）。

**常见报错预填**：plan 模式步骤解析失败（步骤不是合法 JSON 列表）/ trace 写盘路径未建 / reflection 自评无 checklist 时全判好 / mock 脚本步数对不上 / 工具序列为空（任务被模型直接闲聊掉——提示词加了「必须行动」约束）。

### 课级 README 三档总览

| 档 | 目录 | 考点 | 前置讲义 | 参考时长 |
|---|---|---|---|---|
| B | basic-单任务轨迹 | ReAct 三段式跑通一个复合任务 | 5.1 | 30 min |
| A | advanced-计划派助手 | plan 模式拆步骤 + 逐步执行核对 | 5.2 | 60 min |
| C | challenge-复盘一轮 | Reflection 自评修订 + 前后两版对比报告 | 5.1–5.2 | 90 min |

递进逻辑：B 的三段式轨迹是 A 的「plan 步骤与实际执行对账」前置；A 的执行记录是 C 的「自评依据」前置。为什么是这三题：B 对标日常调试 Agent 的最小观测能力；A 对标第 11 课 DAG 的任务拆解雏形；C 对标第 12 课 Score 门控的前身——三门课的伏笔都在今晚埋下。

### B 档 · basic-单任务轨迹

- 任务清单：`TODO(05-b-1)` ReAct 提示模板（含 Final Answer 终止约定）；`TODO(05-b-2)` 三段式 trace 落盘；`TODO(05-b-3)` 任务完成后打印工具序列
- 验收：mock 任务轨迹 ≥3 步、三标记齐全；最终回答引用了观察内容

### A 档 · advanced-计划派助手

- 任务清单：`TODO(05-a-1)` planner 提示与步骤 schema（编号列表）；`TODO(05-a-2)` 逐步执行与对账（完成一步勾一步，失败步骤标红）；`TODO(05-a-3)` 计划修订（某步失败后允许 planner 重排一次）
- 验收：三步任务全链路执行；一步失败后重排仍完成；报告含「计划 vs 实际」对照

### C 档 · challenge-复盘一轮

- 任务清单：`TODO(05-c-1)` 自评 checklist 生成（从任务描述提取 3–5 条验收点）；`TODO(05-c-2)` 修订循环一轮（对照 checklist 补作业）；`TODO(05-c-3)` 前后两版输出与自评分数写进 `compare.md`；`TODO(05-c-4)` 成本列（reflection 花掉的额外 token）
- 验收：修订后自评分数高于修订前；compare.md 有真实（或 mock）数据；成本列不为零且被讨论
- 升级预告：compare.md 格式即第 14 课决策留痕的雏形

### solution 规格

四段式；C 档必含「为什么一轮即停」的实现注脚。除 TODO 外与骨架逐字一致。
