## 第 11 课目标能力清单

1. 用邻接表表示 DAG，实现 Kahn 拓扑排序与环检测（有环即拒绝编译）
2. 并行执行无依赖节点（asyncio.gather），并解释「并行度省的是墙钟时间不是 token 账单」
3. 实现幂等重跑：节点产物指纹（node + input_hash）缓存，失败后重跑只补失败节点及其下游
4. FastAPI 两个端点（POST 提交 / GET 查询状态）+ 后台任务执行，任务状态可轮询
5. 把第 10 课手动管道改写成声明式 DAG，痛点逐条消除

## 讲义 11.2 规格 · 失败重跑与幂等设计

```markdown
# 11.2 幂等：重跑只补失败的那一块积木

> 第 11 课 · 模块 2 · 约 45 分钟
> 理论对照：《学习路线》模块三「失败重跑与幂等设计」
```

**章节大纲**：

- 导语：第 8 课你体验过 kill -9 恢复；今天把「恢复」做成管线级——代价是每个节点都要讲幂等
- `## 产物指纹`：`fingerprint = sha256(节点名 + 输入 json)`；缓存目录 `assets/cache/<fingerprint>/` 存产物副本；重跑时命中指纹 → 直接复用
- `## 三种幂等姿势`：指纹缓存（结果可复用）/ 自然幂等（写覆盖式）/ 补丁式重跑（失败节点把产物写临时目录，全链通过才落正式目录）——本引擎用第一种
- `## 失败传播`：失败节点的下游标 skipped 而不是 failed（「没轮到它，不算它的错」）；重跑入口 `rerun(only_failed=True)` 只重执行 failed 链路
- `## How：demo 11 的 cache 与 rerun 段`
- `## 常见坑`（5 行）：指纹只算输入不算节点代码版本（改码后吃到旧缓存——版本号入指纹）/ 缓存目录进 git / skipped 当 failed 重跑（白烧）/ 下游依赖 failed 的产物路径直接读崩（重跑顺序仍按拓扑）/ 忘清空半截产物（先写临时再原子挪）
- `## Checkpoint`：能写出指纹计算；能解释 skipped 与 failed 的区别；能说清「版本号入指纹」解决什么

## 讲义 11.3 规格 · FastAPI 服务化与队列解耦

```markdown
# 11.3 服务化：从脚本到服务，管线挂在 HTTP 背后

> 第 11 课 · 模块 3 · 约 60 分钟
> 理论对照：《学习路线》模块三「异步与队列」+ 模块八「后端」
```

**章节大纲**：

- 导语：管线现在是「你敲一下跑一下」；第 12 课编辑器要隔着 HTTP 点按钮跑——本课把引擎装进 FastAPI
- `## 两个端点`：POST `/pipeline`（body：DAG 定义 + 输入，返回 run_id）/ GET `/pipeline/{run_id}`（返回五态状态表）；端点只做提交与查询，绝不内联执行——「API 层不搬砖」
- `## 后台任务`：asyncio.create_task 跑管线、内存 dict 存状态；「内存版是课堂版：重启即失忆——生产换 Redis / DB，接口不变」；为队列解耦留的口子（真队列 = 状态外移 + 任务外移两步走，本课只做第一步）
- `## 调用方演示`：curl 两连（提交 → 轮询）；与第 12 课 WebSocket 的分工（GET 轮询查询、WS 收推送）
- `## How：demo 11 的 api 段`
- `## 常见坑`（5 行）：端点里直接 await 管线（请求超时、管线被 HTTP 生命周期绑死）/ run_id 用随机数但状态在内存（重启后 id 还在、状态没了）/ 并发两个 run 共享一个 Pipeline 实例（互踩）/ 异常没进状态（永远 running）/ uvicorn 端口占用
- `## Checkpoint`：能写出两端点骨架；能说清 API 层不内联执行的理由；能指出课堂版离生产差哪两步

## demo 规格 · 11-pipeline引擎

| 项 | 规格 |
|---|---|
| 路径 | `demos/11-pipeline引擎/`（README.md / run.py / api.py / tests/test_run.py）；核心沉淀 `src/deltaagent/engine.py` |
| 行为目标 | CLI：`--dag demo_dag.json --run`（三节点：ScriptGen → SummaryCard → LinesNode（第 10 课三节点串联）），支持 `--rerun`（只补失败链）；`--inject-fail summary` 注入失败供验证；`--serve` 启动 FastAPI（uvicorn），提供 POST /pipeline 与 GET /pipeline/{id}；`--mock` 全离线（ScriptGen 走固定样例）；缓存目录 `assets/11/cache/` |
| 接口约束 | `engine.py`：`Pipeline(nodes: dict[str, Node], deps: dict[str, list[str]])`：`.validate() -> None`（环检测 + 依赖节点存在性，非法抛 `CycleError` / `MissingNodeError`）、`.topo_order() -> list[str]`（Kahn，tie-break 按名字排序保证稳定）、`async run(run_id: str, fail_inject: set[str] = frozenset()) -> RunStatus`、`async rerun(run_id: str, only_failed: bool = True) -> RunStatus`；`RunStatus(run_id: str, states: dict[str, Literal["pending","running","done","failed","skipped"]], artifacts: dict[str, Path], usage: Usage)`；缓存：`fingerprint(node_name, input_model, node_version: int = 1) -> str`，命中即复用并跳过执行；失败节点的下游一律 skipped |
| 分段结构 | S1 DAG 定义与校验（环 / 缺节点）→ S2 拓扑排序与并行执行层（asyncio.gather 同层并发）→ S3 指纹缓存与幂等重跑 → S4 RunStatus 与失败注入 → S5 FastAPI 端点与内存任务表（api.py） |
| 验收测试 | `test_topo_order_stable`（三节点依赖给定，输出顺序确定且合法拓扑序）/ `test_cycle_detected`（A→B→A 抛 CycleError 且报出环节点名）/ `test_failed_downstream_skipped`（注入 SummaryCard 失败 → LinesNode 为 skipped 不是 failed）/ `test_rerun_only_failed_chain`（rerun 后 ScriptGen 命中缓存不再执行——用执行计数器断言只有 SummaryCard 与 LinesNode 重跑）/ `test_api_submit_and_poll`（fastapi TestClient：提交返回 run_id，轮询到终态且状态表完整） |

**README 关键点 4 条**：① 第 10 课 A 档痛点表逐条对照「DAG 怎么解决」② 指纹含节点版本号的原因 ③ skipped 与 failed 的语义差 ④ 内存状态版与生产（Redis/DB）的两步差距说明。

**常见报错预填**：deps 写成「我依赖谁的逆序」方向搞反 / 缓存命中但产物文件被人删（命中校验补文件存在检查）/ asyncio 事件循环在 pytest 里的写法 / uvicorn 端口占用 / 并发 run 互踩（demo 限制单 run 或加锁，说明取舍）。

## 升级预案

- asyncio 在 pytest（同步测试）下的运行方式（pytest-asyncio 或 asyncio.run 包装）：先实测选一种写进 README，两种写法混用即返工
- fastapi TestClient 与后台 asyncio.create_task 的组合在测试里可能不等任务完成：测试用轮询等待终态（带超时），不许 sleep 魔法数——若测试框架行为怪异即升级
- 并发多 run 互踩：demo 明确「单 run 版」并在 README 标注生产差异；不做半吊子锁
