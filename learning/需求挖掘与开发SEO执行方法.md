# 需求挖掘、开发与SEO优化执行方法

> 本文整理自多位独立开发者的实战经验，覆盖从需求发现到产品开发再到SEO流量获取的完整链路。

***

## 一、需求挖掘

### 1.1 付费率反推法

**核心思路：** 用户愿意付费的产品才是好需求，用数据估算付费意愿强度。

**操作步骤：**

| 步骤 | 动作                             | 工具/数据源                                                    |
| -- | ------------------------------ | --------------------------------------------------------- |
| 1  | 查看 Stripe 引荐流量榜                | [seo.web.cafe/referring](https://seo.web.cafe/referring/) |
| 2  | 计算到达付费页比例 = 网站访问量 / Stripe页面流量 | —                                                         |
| 3  | 估算月收入：访问量 × 到达率 × 支付成功率 × 客单价  | —                                                         |
| 4  | 用保守值（1%）做最差情况估算                | —                                                         |

**示例：** Higgsfield 到达付费页比例约 8.6%（269万÷3131万），说明每100次访问约8.6次进入收银台。

### 1.2 广告消耗反推法

**核心思路：** 一直投放或突然加大投放的产品，ROI一定大于1，可以直接对标。

**数据平台：**

- **小红书聚光 / 抖音巨量** — 筛选关注领域的热门投放素材，打破信息差

- **Sensor Tower**（app.sensortower.com）— 查看应用下载量与收入，数值不完全准确但趋势范围可信（如显示50K月收入，真实区间约40K-60K）

- **七麦数据 / 点点数据** — 类似的应用市场数据分析

### 1.3 电商销售数据验证法

**核心思路：** 淘宝、闲鱼上的销量直接反映用户付费意愿和具体痛点。

**操作要点：**

- 搜索竞品或相关工具的安装包/教程销量

- 与店主交流挖掘真实使用场景（如研究生翻译论文的需求）

- 关注「免费开源但百度搜不到」的信息差机会（如 Zotero 在淘宝卖安装包月销几万份）

- 结合搜索引擎搜索数据交叉验证需求强度

### 1.4 大厂会员功能拆解法

**核心思路：** WPS等大厂的付费会员功能本身就是被验证的需求。

**选择优先级：**

- 优先选择**高级会员才能用**的功能

- 优先选择**限制次数、限制用量**的功能

- 这些功能通常有免费开源方案或API实现，但对非技术用户仍有付费价值

**典型方向：** PDF转Word、图片OCR、录音转文字等。

### 1.5 高分享量内容判断法

**核心思路：** 分享量 > 点赞量的内容具有强传播力，做相关产品可降低营销成本。

**判断标准：** 如果点赞量1万但分享量2万，说明用户愿意主动传播，这类需求适合做产品。

### 1.6 应用商店付费榜 + 差评挖掘法

**核心思路：** 付费榜产品已被市场验证；差评直接暴露未满足的需求。

**操作路径：**

| 平台          | 链接                              | 方法        |
| ----------- | ------------------------------- | --------- |
| Google Play | play.google.com/store/apps      | 看付费榜 + 差评 |
| iOS Store   | apps.apple.com/us/iphone/charts | 看付费榜 + 差评 |
| 七麦数据        | qimai.cn                        | 深挖付费榜排名变化 |

**差评挖掘要点：** 整理用户多次提到的差评痛点，这些就是新产品的切入点。

### 1.7 长尾支付网关反查法

**核心思路：** 不只盯Stripe/PayPal，重点反查 Creem、LemonSqueezy 等小微商户支付网关的入站流量。

**原因：** 使用这类支付网关的多为个人开发者或极小团队，他们的流量中藏着可直接对标、快速复刻的利基产品。

### 1.8 竞品 Sitemap 监控法

**核心思路：** 定期爬取竞品或头部站点的 `sitemap.xml`，第一时间发现新布局的长尾词页面或新子产品线。

**效果：** 直接获取对方花重金调研出来的流量需求，零成本蹭情报。

### 1.9 社区与内容平台挖掘法

**平台与操作：**

| 平台           | 挖掘方式                   |
| ------------ | ---------------------- |
| V2EX         | 「分享创造」「发现」板块，提取出站链接    |
| Product Hunt | 新上线产品，关注趋势             |
| 小红书 / 即刻     | 搜索「求推荐」等痛点关键词，看爆款笔记评论区 |
| Reddit / X   | 搜产品差评和用户抱怨             |
| 客座博客         | 看100刀左右价位的发帖人都在做什么站    |

### 1.10 GitHub / X Skill 反搜法

**核心思路：** 别人分享的 SKILL.md 背后对应的是真实工作中反复出现的问题。

**操作步骤：**

1. GitHub 搜索 `filename:SKILL.md` 或 `path:skills SKILL.md`，按最近更新排序
2. 不只看Star数，新提交、低Star的个人仓库更容易发现新鲜需求
3. 进入作者主页看最近的自动化工具提交
4. X 上搜索 `"SKILL.md"` `"my skill"` `"Claude skill"` `"Codex skill"`
5. 让 Codex 每天筛选并中文总结功能
6. 把功能关键词放到 Semrush 等工具搜流量验证

### 1.11 词找词 / 词找站 / 站找词 / 站找站

**\[找词] — 去持续涌现新词的平台：**

| 领域       | 平台                                                        |
| -------- | --------------------------------------------------------- |
| 游戏       | steamdb.info / igdb.com / itch.io/games/newest / poki.com |
| AI工具     | toolify.ai / theresanaiforthat.com                        |
| 收入数据     | trustmrr.com                                              |
| 外链       | columbus.tools                                            |
| 视频资源     | bxkp.org                                                  |
| Chrome插件 | chrome-stats.com                                          |

**放大技巧：** 用AI推荐同类平台，提示词参考：

> 推荐几个类似 <https://steamdb.info/> 的网站，辅助我上站

**\[找站] — 善用AI做批量分析：**

- 让AI抓取100个同类网站，分析不同站点的付费功能

- 每个付费点背后都映射一个用户需求

### 1.12 产品上下线机会捕捉法

| 场景    | 操作                                         |
| ----- | ------------------------------------------ |
| 大产品爆火 | 如DeepSeek上线时，闲鱼卖套壳网站10万+店铺；腾讯元宝趁机占据用户心智    |
| 大产品关停 | 几千万存量用户 → 数据迁移成强时效刚需 → 做一个极简Export工具吃到几万用户 |

### 1.13 站群拆解法

**核心思路：** 拆解已验证的10万美元级站群，借鉴其关键词、需求、页面框架、定价策略与外链渠道。

**参考站群（flux-ai团队）：**

```
bestimage.ai / videoweb.ai / fylia.ai / musicmaker.im
aimusicchecker.org / see3d.art / aitryon.art
ugcmaker.org / heydream.im / scholargpt.ai
agenthunt.io / freeimgen.com / freetinypng.com
fluxia.pro / seevido.com / freevideoai.org / freemusicai.org
```

**拆解重点：** 首页结构、功能内页、关键词布局、站内互链、流量入口、商业化方式。

**注意事项：** "抄"不是原封不动复制代码品牌内容，而是拆解已验证的关键词、需求、框架、定价、转化路径，再结合自己产品重新设计。

## 二、开发方法论

### 2.1 五条核心认知

| 认知             | 要点                                       |
| -------------- | ---------------------------------------- |
| 伟大的技术，原始的需求    | AI技术迭代快，但用户需求迭代慢。Web时代/移动时代的产品用AI重做照样能赚钱 |
| 大模型能做 ≠ 用户会用   | 批量生成文章、发言稿等，大模型都能做，但相关产品APP照样很多在赚钱       |
| 先有用户，再开发       | 写第一行代码前先验证需求，不要先做产品再找推广                  |
| 便宜是坏生意         | 卖积分吸引价格敏感型用户；卖月/年订阅固定价格，卖不出去先想理由不是降价     |
| 烂产品有人付费 = 需求极强 | 看到粗糙产品还有人夸奖，说明需求真的很痛，应该敬畏和学习             |

### 2.2 先验证后开发流程

```
Vibe Coding 做页面 → 假装已有产品 → 宣传获取用户 → 验证需求 → 再开发
```

**三个关键动作：**

1. **宣传验证：** 拿demo去宣传，看1个月内能否获得几百几千用户
2. **按钮设计：** 页面上写「立即购买」而非「立即预约」（哪怕暂时没接支付）
3. **最小交付：** 不开发完整功能，用户扫码个人微信付款，手动搓给用户交付

**功能选择策略：** 每个功能做几个不同demo页面，分发宣传看哪个功能点能吸引用户注意力，再按吸引力排序开发。

### 2.3 已有站点的需求扩展法

**适用场景：** 已有产品站点，需要发现新需求并上线内页。

**操作步骤：**

1. 找到同类别榜单站点（toolify、taaft 等），看200名以后的
2. 批量抓取这些站点的 sitemap
3. 将 sitemap 和站点统一喂给AI，分析功能差异
4. 对比自己站点缺少哪些功能
5. 让AI批量复刻上线内页

**实际效果：** 有开发者通过此方法将站点流量从每日100点击提升到1000点击。

### 2.4 定价策略

| 做法       | 推荐度     | 原因                  |
| -------- | ------- | ------------------- |
| 月/年固定订阅  | 推荐      | 吸引价值导向用户，收入可预期      |
| 卖积分/按量计费 | 仅限AI生成类 | 视频生成、图片生成等按量计费合理    |
| 降价促销     | 不推荐     | 卖不出去先想是否没给用户合适的付费理由 |

## 三、SEO优化方法

### 3.1 GSC 搜索词分析

**操作：**

1. 查看自己站点后台的 Google Search Console
2. 让AI分析所有搜索词
3. 找出未被满足的需求
4. 让AI深入调研后实现对应功能/页面

### 3.2 Sitemap 监控获取长尾词

**操作：**

- 定期爬取竞品 `sitemap.xml`

- 发现新布局的长尾词页面或新子产品线

- 零成本获取对方花重金调研的流量需求

### 3.3 关键词布局策略

**词找词放大法：**

- 在持续涌现新词的平台（如 steamdb、igdb）找新词

- 新游/新工具 = 新词 = 新需求 = 新内页

- 用AI推荐同类平台扩大词源

**站找站分析法：**

- 在AI导航站（toolify、taaft）找同类站点

- 让AI批量分析100个同类站点的付费功能

- 每个付费功能对应一个关键词方向

### 3.4 站群互链策略

**参考做法：** 同一团队运营多个站点，通过 `UTM_SOURCE` 参数互链。

**拆解要点：**

- 站内互链结构

- UTM参数传递

- 多站点覆盖不同赛道（图片、视频、音乐、3D、学术工具等）

- 每个站点聚焦一个细分需求

### 3.5 AI辅助SEO工作流

| 环节      | AI用法                         |
| ------- | ---------------------------- |
| 找平台     | 让AI推荐同类流量平台                  |
| 批量分析    | 让AI抓取100个站点分析付费功能            |
| 功能对比    | 让AI对比自己站点与竞品的功能差异            |
| 搜索词分析   | 让AI分析GSC所有搜索词找未满足需求          |
| 内容生成    | 让AI批量复刻竞品已验证的内页功能            |
| Skill筛选 | 让Codex每天筛GitHub/X新Skill并中文总结 |

### 3.6 流量获取渠道汇总

| 渠道                | 类型    | 适合场景            |
| ----------------- | ----- | --------------- |
| Stripe引荐榜         | 付费验证  | 找高付费率产品对标       |
| 应用商店付费榜           | 付费验证  | iOS/Android需求发现 |
| 小红书聚光/抖音巨量        | 广告反推  | 找正在投放赚钱的产品      |
| Sensor Tower/七麦   | 数据分析  | 应用下载量与收入趋势      |
| 淘宝/闲鱼             | 电商验证  | 国内用户付费意愿验证      |
| toolify/taaft     | AI导航站 | 找同类站点和功能        |
| steamdb/igdb      | 新词发现  | 游戏类新需求发现        |
| V2EX/Product Hunt | 社区    | 新产品趋势           |
| Reddit/X          | 社区    | 差评和抱怨挖掘         |
| GitHub            | 开源项目  | Skill反搜真实需求     |
| GSC               | 自有数据  | 已有站点需求缺口分析      |
